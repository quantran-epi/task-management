# Quick 261116-e63: AI tools for Mermaid diagrams — Summary

Three DB tools let the AI list, create, and update Mermaid diagrams (Notes of `type: 'diagram'` whose body is the mermaid source), with the source omitted from listings by default and every write gated by the approval card.

## What Was Built

- `query_diagrams` — read tool. Lists diagram notes with filters for `tags` (any match), `title` (case-insensitive substring), `entityType`, `entityId`; `includeBody` (default false) is the only way the mermaid source is returned. Rows carry `id`, wrapped `title`, `tags`, `updatedAt`; sorted `updatedAt` desc; `limit` default 20 / max 50. Title and body go through `wrapField` (T-e63-01).
- `create_diagram` — writes via `createNote` with `type: 'diagram'`; tag `diagram` always merged; body normalized through `extractMermaidBlocks` then `stripAnsiSequences` fallback, trimmed; rejects a missing/empty body.
- `update_diagram` — writes via `updateNote`; loads the target first and refuses when it is absent, not a diagram, or soft-deleted (T-e63-02), so `updateNote` cannot overwrite a document body with mermaid source. Body normalized the same way on update; tags left verbatim.
- Both writers are in `MUTATION_TOOLS` and have Vietnamese `describeToolMutation` labels. `query_diagrams` is not a mutation.
