# Quick Task 261020-d6r: Align Telegram Chat with AI Chat Drawer Intent and Grounded Pipeline

## Goal
Align the headless Telegram worker with the AI Chat Drawer's architecture:
1. Use `routeIntent` LLM classification instead of naive token heuristics.
2. Enforce `dataScope` access control at the intent level (refuse mismatched requests safely).
3. Remove arbitrary document extraction fallback (`notes.slice(0, 3)`) when asking about tasks.
4. Adopt strict anti-hallucination rules and temperature 0.1 for high factual accuracy.

## Tasks

### Task 1: Integrate routeIntent & Scope Security Gate in telegramHeadlessWorker
- Call `routeIntent` on incoming chat messages before context assembly.
- If intent is `clarify`, return `clarify_question` immediately.
- Enforce `dataScope`:
  - `pure_llm`: Strip all context and tools.
  - `tasks_only`: Block `query_knowledge` intents with clear scope refusal message.
  - `knowledge_only`: Block `query_taskmate` and `operate_taskmate` intents with clear scope refusal message.
- Remove `notes.slice(0, 3)` blind fallback in `resolveScopedContext`. When querying knowledge, only include actual BM25 matches. If none match, report no relevant documents found.
- Apply `CRITICAL ANTI-HALLUCINATION RULES` matching `AIChatDrawer.tsx`.
- Lower `temperature` to `0.1` for grounded responses.

### Task 2: Update and Add Tests
- Update `tests/telegram/telegramHeadlessWorker.test.ts` to mock/test `routeIntent`.
- Add tests for:
  - Intent classification routing (query_taskmate vs query_knowledge).
  - Scope security enforcement (tasks_only attempting query_knowledge, knowledge_only attempting query_taskmate).
  - No bogus doc fallback when query has no matching notes.
  - Clarify question returned when intent is `clarify`.
