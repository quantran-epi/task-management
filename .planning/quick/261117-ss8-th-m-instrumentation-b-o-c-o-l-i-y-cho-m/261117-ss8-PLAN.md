<objective>
Add full, additive instrumentation/error reporting for every agent/leader run so that each tool call is logged with timestamp, abort source, tool name, duration, error code/detail and outcome — and record the unresolved UAT abort `31fc8015`.

Root cause of the gap (verified in `.planning/debug/explore-repo-headless-not-logged-in.md`): report `31fc8015` ended with `detail: 'aborted'` from the turn's AbortSignal, but "there is no abort timestamp in the log tied to report 31fc8015", so the fired source (user stop / batch deadline / dispose / turn end) could not be pinned. All intentional sources exist in code but nothing correlates them to the in-flight tool call.

Purpose: make this diagnosable without changing a single execution path. Existing surfaces already carry part of the data (`ChatTurnToolEvent` at `chatTurnRuntime.ts:33-41`, `AgentLiveStep` at `aiOffice.ts:265-283`, `structuredLog` at `log.ts:48-88`) — this task only ADDS structured log lines and a runtime-only in-flight map at the one shared choke point, plus source-stamping calls beside the existing abort markers. Nothing that decides abort/timeout/retry/tool-result or UI is edited.

OWNER HARD CONSTRAINT: instrumentation is ADDITIVE ONLY. Do not change abort/timeout/retry/tool-result behavior, UI flow, or schema/validation beyond what is already committed. Every abort source keeps its exact current behavior. Any change that would force a behavior change goes to `<deferred_items>`, not into code.
</objective>
