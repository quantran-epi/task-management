# Quick 261116-e64 Summary: Configurable System Type List

System type is no longer a hardcoded five-value union. A single `system_type_options` settings row holds the user's taxonomy; every UI surface, the form validator, backup import and the AI tools accept any `^[A-Z][A-Z0-9_]*$` value up to 40 characters.

## What was built

**Source of truth** — `src/services/system/systemTypeSettings.ts` owns the setting key, the regex, the five defaults (Parent System/#722ed1, Service/#13c2c2, DB Schema/#1890ff, Frontend UI/#eb2f96, Worker/#fa8c16), `normalizeSystemTypeOptions` (type-check, de-dupe by value, defaults fallback), async get/set, `ensureSystemTypeOption` (append-once for a freshly typed value) and the `useSystemTypeOptions` / `useSystemTypeLookup` live hooks. Reading a fresh DB returns the defaults and writes nothing.

**Validation** — `SystemType = string` in `src/types/models.ts`. `SystemTypeSchema` is now a trimmed, length-bounded regex schema; `SYSTEM_TYPES` is gone from `src` entirely. `BackupSystemRecordSchema.type` reuses that same schema so a backup carrying a custom type restores; `BackupSettingRecordSchema.value` stays `z.unknown()` and the settings payload is re-normalized on every read.

**Surfaces** — SystemModal swaps the fixed `Select` for `AutoComplete` over live options, uppercases/trims input, and calls `ensureSystemTypeOption` before `onSave` so a brand-new type survives `SystemInputSchema`. SystemTable takes an optional `typeOptions` prop and keeps only an icon map for the built-ins. SystemCatalogView builds its filter from live options plus any orphaned system types still present in loaded rows. SystemDetailView (three render sites) and TargetSystemsSelector read through `useSystemTypeLookup`; every local label/color map is deleted.

**Settings** — `SystemTypeOptionsCard` lists live options with a color swatch, supports add/edit/delete through `setSystemTypeOptions` (so all live queries refresh at once), rejects invalid or duplicate values, disables rename/delete for `LOGICAL_GROUP` with a Vietnamese tooltip, and names how many systems still carry a type in the delete confirmation. Mounted in the existing Remote SSH tab.

**AI tools** — `query_systems` drops its fixed enum for a regex-validated string; `create_system` / `update_system` (added by 261116-e62) got the same treatment, so all three accept custom types. Tool count is unchanged at 79.

**Untouched invariants** — `isLogicalParent` / `isSubsystem`, repo parent/cycle guards, backup stage-4 `LOGICAL_GROUP` checks, and `refineSystemShape` are byte-identical. No Dexie schema version bump.
