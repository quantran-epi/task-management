</objective>

  <action>
Create `src/services/system/systemTypeSettings.ts` as the only module that knows the setting key, following the shape of `src/services/ai/budgetWarnSettings.ts`:
- `export interface SystemTypeOption { value: string; label: string; color: string }`.
- `SYSTEM_TYPE_OPTIONS_SETTING_KEY = 'system_type_options'`; `SYSTEM_TYPE_VALUE_PATTERN = /^[A-Z][A-Z0-9_]*$/`; `SYSTEM_TYPE_VALUE_MAX_LENGTH = 40`; `LOGICAL_GROUP_TYPE = 'LOGICAL_GROUP'`.
- `DEFAULT_SYSTEM_TYPE_OPTIONS: readonly SystemTypeOption[]` with the five built-ins using the labels and colors currently in SystemTable's config map (Parent System/#722ed1, Service/#13c2c2, DB Schema/#1890ff, Frontend UI/#eb2f96, Worker/#fa8c16). This is the pure fallback; nothing is written to the DB on read.
- `isValidSystemTypeValue(value: string): boolean` — regex + length + trimmed equality.
- `normalizeSystemTypeOptions(raw: unknown): SystemTypeOption[]` — accept unknown, keep only entries with a valid `value`, `label` string fallback to value, `color` string fallback `#8c8c8c`, de-dupe by value, return defaults when result is empty.
- `getSystemTypeOptions(db = defaultDb): Promise<SystemTypeOption[]>` — `db.settings.get(key)`, pass `rec?.value` through normalize. Async only; never touch `db.settings` synchronously (constraint: DAL must not block render).
- `setSystemTypeOptions(options, db = defaultDb)` — normalize then `db.settings.put({ key, value })`.
- `ensureSystemTypeOption(value: string, db = defaultDb)` — read, skip if present, else append `{ value, label: value, color: '#8c8c8c' }` and write.
- `useSystemTypeOptions(db = defaultDb): SystemTypeOption[]` — `useLiveQuery(() => getSystemTypeOptions(db), [db]) ?? DEFAULT_SYSTEM_TYPE_OPTIONS` (import from `dexie-react-hooks`).
- `useSystemTypeLookup(db = defaultDb): (value: string) => { label: string; color: string }` — derive from the hook result, fallback `{ label: value, color: '#8c8c8c' }` for unknown values so deleted types still render.

| user input → settings row | free-typed type value becomes app-wide config persisted and re-exported |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-e64-01 | Tampering | `BackupSystemRecordSchema.type` | medium | mitigate | Validate with a bounded regex (`^[A-Z][A-Z0-9_]*$`, max 40) instead of loosening to `z.string()`; settings payload still validated by `normalizeSystemTypeOptions` on read so a crafted backup cannot inject non-string/garbage option entries into every UI surface |
| T-e64-02 | Tampering | `system_type_options` setting restore | medium | mitigate | Re-normalize on every read (dedupe, type-check, defaults fallback) rather than trusting the stored shape; no code path evaluates the stored value |
| T-e64-03 | Elevation of privilege | type deletion breaking parent invariant | low | mitigate | `LOGICAL_GROUP` rename/delete disabled in the management card; `isLogicalParent`/`isSubsystem` and the repo/backup parent guards are untouched and keep comparing the literal |
| T-e64-04 | Denial of service | unbounded option list growth | low | accept | Single-user local app; growth is self-inflicted and bounded by the regex+length rules; no external input path |
</threat_model>
