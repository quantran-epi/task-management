# Quick Task 261027-rv3: Mid-loop compaction + sandbox timeout

## Problem

- `compactThreadContext` runs once **before** a turn (`AIChatDrawer.tsx:691`). Nothing compacts during `runAiOrchestratorLoop`'s 30 rounds.
- `pruneToolOutputsInMessages` bounds message **count**, not characters. Analysis mode passes `keepRecentToolOutputs: 20` / `maxOldToolChars: 100_000`, so a long turn can exceed any context window.
- `executeDynamicFileScript` ran AI-generated code with no timeout — a hung script froze the UI.

## Changes

1. **`src/services/ai/inLoopCompaction.ts` (new)** — `compactMessagesInLoop()` summarizes the middle of the in-memory message list into one system message, keeping the head (system prompt) and a tail that never orphans `tool` messages from their `tool_calls`. Returns `compacted: false` unchanged on any failure (best-effort).
2. **`aiOrchestratorLoop.ts`** — new option `contextTokenBudget`. Tracks `currentPromptTokens` from the latest `usage` chunk (not the turn cumulative sum) and compacts before the next round when it exceeds the budget. Status notice in Vietnamese. Baseline resets after a successful compaction so it does not fire every round.
3. **`AIChatDrawer.tsx`** — passes `contextTokenBudget: Math.max(1000, floor(config.charLimit / 4))`. `charLimit` is the existing in-app setting shown in Settings → 9router as "Giới hạn ký tự ngữ cảnh", with the UI already documenting `1 token ≈ 4 chars`.
4. **`dynamicFileSandbox.ts`** — `SCRIPT_TIMEOUT_MS = 60_000`; runner wrapped in `Promise.race` with a timer that is always cleared.

Skipped: a separate max-token UI field. The app already exposes one context budget; deriving tokens from it keeps a single knob, per the constraint.
