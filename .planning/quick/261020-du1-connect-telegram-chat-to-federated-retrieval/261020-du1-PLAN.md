# Quick Task 261020-du1: Connect Telegram Chat to Federated Retrieval Pipeline with Intent Pre-Gating

## Goal
Connect the Telegram worker to the authentic `runGroundedTurn` federated retrieval pipeline (Fulltext, Vector, Graphiti Neo4j) used by AI Chat Drawer, while maintaining strict isolation:
1. Zero changes to `AIChatDrawer.tsx` or core AI files.
2. Pre-gate with `routeIntent`: if a `tasks_only` user asks a knowledge query, refuse immediately before any retrieval call occurs.
3. For authorized knowledge queries, invoke `runGroundedTurn` and format the synthesized claims and citations cleanly for Telegram.
4. For operational task queries, maintain strict anti-hallucination rules and temperature 0.1.

## Tasks

### Task 1: Integrate runGroundedTurn with Pre-Gating in telegramHeadlessWorker.ts
- Run `routeIntent` first.
- Pre-gate scope check: refuse immediately if scope does not permit the intent.
- If intent is `query_knowledge` (and scope permits):
  - Load knowledge server config from DB.
  - Call `runGroundedTurn` with `createDefaultGroundedTurnDeps`.
  - Format result via `formatGroundedAnswerForTelegram` and reply.
- If intent is `query_taskmate` or `operate_taskmate`:
  - Run operational branch with task DB context and `CRITICAL ANTI-HALLUCINATION RULES`.

### Task 2: Add Comprehensive Tests in tests/telegram/telegramHeadlessWorker.test.ts
- Test pre-gating: ensure `runGroundedTurn` is NOT called when `tasks_only` user asks knowledge question.
- Test federated grounded turn: ensure `runGroundedTurn` is called for authorized user asking knowledge query, and synthesized answer with citations is delivered.
- Test fallback/no-evidence: ensure friendly message when no evidence exists.

### Task 3: Verify and Commit
- Run `npx tsc --noEmit` and `npx vitest run tests/telegram/`.
- Update `SUMMARY.md` and `STATE.md`, commit atomically.
