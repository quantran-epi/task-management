  <files>src-tauri/src/ai_proxy.rs, src-tauri/src/lib.rs</files>
  <behavior>
    - Allows `http://localhost:20128/v1/models`, `http://127.0.0.1:20128/v1/models`, and `https://example.test/v1/models`.
    - Rejects `http://192.168.1.5:20128/v1/models`, `file:///tmp/key`, malformed URLs, and URLs whose path does not start with `/v1/`.
    - Forwards only GET and POST with caller-provided safe headers and optional string body.
    - Returns `{ status, headers, body }` with response body as text, matching Jira proxy response shape.
  </behavior>
  <action>
Create `src-tauri/src/ai_proxy.rs` using the existing `src-tauri/src/jira_proxy.rs` command shape: serde response struct with `status`, `headers`, and `body`; `#[tauri::command] async fn ai_proxy_request(method, url, headers, body)`; reqwest client; method allowlist GET/POST; response headers copied to `HashMap<String, String>`; body read as text. Add `is_allowed_ai_target` in the same file: allow `https:` targets whose path starts with `/v1/`; allow `http:` only for loopback hosts `localhost`, `127.0.0.1`, and `::1` with `/v1/` paths; reject every other scheme, host, and path. Strip hop-by-hop and browser-origin headers before forwarding: `host`, `origin`, `referer`, `connection`, `transfer-encoding`, `content-length`, `accept-encoding`, `cookie`, `priority`, `user-agent`, and any `sec-*`; set `user-agent` to `PlannerMateAIProxy/1.0`. Add Rust unit tests in this file for the allowed and rejected targets above. Register `ai_proxy_request` in `src-tauri/src/lib.rs` alongside `jira_proxy::jira_proxy_request`.
  </action>
