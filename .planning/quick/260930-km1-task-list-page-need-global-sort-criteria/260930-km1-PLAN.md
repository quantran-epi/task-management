    Extend the sort engine, hook, and TaskTable toolbar to support a global sort criterion. Reuse existing Ant Design `Select`. Vietnamese labels only. No new dependencies.

    1) In `src/utils/filter.ts`:
       - Export `TASK_SORT_KEYS` union type covering: `'createdAt_desc' | 'createdAt_asc' | 'updatedAt_desc' | 'updatedAt_asc' | 'deadline_asc' | 'deadline_desc' | 'priority_desc' | 'priority_asc' | 'name_asc' | 'name_desc'`.
       - Export `TASK_SORT_OPTIONS: ReadonlyArray<{ value: TaskSortKey; label: string }>` with Vietnamese labels: 'Mới tạo', 'Tạo cũ nhất', 'Vừa cập nhật', 'Ít cập nhật gần đây', 'Hạn gần nhất', 'Hạn xa nhất', 'Ưu tiên cao → thấp', 'Ưu tiên thấp → cao', 'Tên A → Z', 'Tên Z → A' — in that order.
       - Export `DEFAULT_TASK_SORT: TaskSortKey = 'deadline_asc'` to match the current implicit UX (deadline ascending, nulls last).
       - Change `sortTasks` signature to `sortTasks(tasks: Task[], sortField?: string, sortOrder?: 'ascend' | 'descend', globalSort?: TaskSortKey)`.
       - Behavior: if `sortField` provided, keep the existing per-column branch untouched (backwards compatible). Otherwise, use `globalSort` (falling back to `DEFAULT_TASK_SORT` when undefined) to order. Add handlers for `createdAt` / `updatedAt` using `localeCompare` on ISO strings; `deadline` reuses existing nulls-last semantics; `priority` uses `PRIORITY_WEIGHTS`; `name` uses `localeCompare(a.name, b.name, 'vi', { sensitivity: 'base' })`. Tiebreaker: `a.name.localeCompare(b.name)`.

    2) In `src/hooks/useTaskFilters.ts`:
       - Add `globalSort: TaskSortKey` state, initialized synchronously from `localStorage.getItem('planner:task_table_sort')` with try/catch and validation against `TASK_SORT_OPTIONS` values; fall back to `DEFAULT_TASK_SORT`. Match the FOUC-safe pattern used for `planner:task_table_columns`.
       - Add `setGlobalSort(key: TaskSortKey)` that writes to state and mirrors to localStorage (wrap `setItem` in try/catch with `console.warn`).
       - Add `STORAGE_SORT_KEY = 'planner:task_table_sort'` module constant and export it for tests/reuse.
       - Extend `UseTaskFiltersReturn` with `globalSort` and `setGlobalSort`.
       - Pass `globalSort` as the fourth argument to `sortTasks(matched, sortField, sortOrder, globalSort)` inside the `filteredTasks` `useMemo`; add `globalSort` to the dependency array.
       - `resetFilters` MUST NOT reset `globalSort` (persistence intent — filter reset should not throw away sort preference; document with inline comment).

    3) In `src/views/TasksView.tsx`:
       - Destructure `globalSort` and `setGlobalSort` from `useTaskFilters`.
       - Pass them as new props `globalSort` and `onGlobalSortChange` to `<TaskTable>`.

    4) In `src/components/tasks/TaskTable.tsx`:
       - Extend `TaskTableProps` with `globalSort?: TaskSortKey` and `onGlobalSortChange?: (key: TaskSortKey) => void`. Import `TASK_SORT_OPTIONS`, `TaskSortKey`, `DEFAULT_TASK_SORT` from `../../utils/filter`.
       - In the existing toolbar `<Space size="middle">` (the row containing `Popover` "Tùy biến cột" and `Sao chép Standup`), insert BEFORE the Popover a labeled Ant `Select`:
         - Prefix `<span>` label 'Sắp xếp theo' with `token.colorTextSecondary`, `fontSize: 13`.
         - `Select` `size="middle"`, `style={{ width: 200 }}`, `value={globalSort ?? DEFAULT_TASK_SORT}`, `onChange={(v) => onGlobalSortChange?.(v)}`, `options={TASK_SORT_OPTIONS}`, `aria-label="Sắp xếp danh sách tác vụ"`.
       - Do NOT remove existing per-column `sorter` handlers; Ant Table's internal sortOrder will override the pre-sorted `dataSource` when a column header is active. Add a short JSDoc-style code comment above the Select stating: "Global sort applies to the pre-sorted dataSource; per-column sorter clicks override for that render."

    Do not touch other views, filter bar, planner, drawer, or backup/restore code paths. No new dependencies. Preserve `exactOptionalPropertyTypes` — use conditional assignment for optional props.
