<context>
1. Bug 1: Stale body closure on paste in `DocEditorPane.tsx`:
`handlePaste` triggers asynchronous metadata extraction and entity detection. When user pastes, `onChange` updates `body` and initiates debounced auto-save. However, `handlePaste` captures `body` from its initial render closure before the paste. Once the async operations complete, `handlePaste` calls `triggerAutoSave(nextTitle, body, nextTags)` with that stale `body`, resetting the debounce timer and saving outdated text to IndexedDB, clobbering the pasted text.
Fix: Maintain `latestValuesRef` tracking the latest `title`, `body`, and `tags`. In `handlePaste`, only invoke `triggerAutoSave` if `nextTitle` or `nextTags` actually changed, and pass `latestValuesRef.current.body`. If only body changed, let `onChange` manage debounced saving cleanly.

2. Bug 2: Missing `[[` wiki-link autocomplete popup:
Typing `[[` in the textarea should open an autocomplete popup querying active docs (`db.notes`), tasks (`db.tasks`), and projects (`db.projects`). As the user types query text after `[[`, filter candidates by case-insensitive name/title match. Support keyboard navigation (`ArrowUp`, `ArrowDown`, `Enter`, `Tab`, `Escape`) and click selection. When selected, replace the `[[query` trigger with `[[type:id|Title]]` (e.g. `[[doc:uuid|Doc Title]]`, `[[task:uuid|Task Title]]`, `[[project:uuid|Project Title]]`), position the cursor after `]]`, update textarea value, and trigger debounced autosave.
</context>
