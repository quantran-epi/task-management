# Shared anti-fabrication block + read-only Oracle tools for team agents

Two gaps, one theme: team agents assert data they never read.

- **Anti-fabrication:** neither `buildEmployeeTurnRequest` nor `buildLeadTurnRequest` has any grounding rule. The AI Chat panel has one (`AIChatDrawer.tsx:1770-1774`) but it is absolute — "NEVER GUESS, ASSUME, OR INVENT DATA" — with no carve-out for the proposals and forecasts a planner is asked for. Team agents never pass through `groundedTurn`/intent router, so `speculation_requested` never reaches them; the carve-out must be prompt-level and self-judged.
- **Oracle:** `EMPLOYEE_READ_ONLY_ALLOWLIST` and `LEAD_TOOL_ALLOWLIST` contain no `oracle_query`/`oracle_describe`, so team agents cannot read the Oracle DB the rest of the app can. Oracle must be advertised only when `getOracleToolConfig(db).enabled` is true, or a disabled Oracle reappears as the "model calls unrelated tools" problem.

Out of scope: AI Chat panel prompt (team-only change), `oracle_query` read-only enforcement (already `SET TRANSACTION READ ONLY`), new dependencies, new Dexie tables.
