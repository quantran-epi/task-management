# CR-linked systems are valid git repos for AI Office

`resolveGitRepo` (src/services/ai/office/teamTools.ts) currently builds its candidate set only
from team links whose `itemType === 'system'`. A team that links a Change Request instead gets
no usable repo, so `git_read` and `explore_repo` refuse even though the CR's `targets` name
real, configured subsystems. This quick task widens the candidate set to include those targets.

Locked scope (confirmed directly by the user — do not re-ask, do not widen):

- The permission-scope change is intentional and approved. A linked CR grants its target
  `systemId`s as git-readable repos for this team.
- `systemId` stays an INDEX into the resolved linked set. It can never name a repo the team
  did not reach through a link (direct system link or linked CR target).
- Keep the SSH-profile / `remoteRepoPath` configuration gate and every existing refusal code
  and message unchanged. This task only changes how the candidate set is ASSEMBLED.
- No schema change, no Dexie version bump, no new dependency, no allowlist change.

Out of scope: transient / unlinked systems, CRs that are not linked to the team, changing any
refusal wording, touching the pre-existing uncommitted changes in this worktree.
