<objective>
Land the atomic persistence unit for the new `aiSkillVersions` table: Dexie V19 → every coordinated list → backup export/validate/restore → TS SQLite list → Rust allowlist → envelope v12, in one executable change set.

Purpose: AIO-DATA-01 requires one additive table wired into every coordinated list at once; research (`36-RESEARCH.md` §Coordinated-file inventory A) counts nine source lists plus four derived places in `restoreBackup.ts` alone. Split across plans, the tree would be inconsistent between them (a restore list naming a table the schema does not declare, or an export promising a count the validator rejects). This plan exists to keep that unit whole. It also fixes the live TS↔Rust drift (`chatTabs`, `systems`, `changeRequests` are missing from the Rust allowlist today) and closes the envelope at v12 (D-22/AIO-DATA-04, research R-02).

Output: `SCHEMA_V19`, `AiSkillVersion`/`AiSkillVersionStatus`, `AiSkillVersionInputSchema`, backup types + Zod record, export/validate/restore wiring, SQLite TS list + Rust allowlist entries, the version-literal sweep across every test that hardcodes the wire number, and two new test files. The `aiSkillVersionRepo` contract and the D-19 unfinished-turn reader are 36-05's tasks; the V19 table is empty until then, which is exactly the additive contract.

File-count justification (checker scope_sanity, 25 declared files vs the 15-file threshold): the count is contractual, not exploratory. One table name lands in ~9 coordinated source lists (backup types, Zod record, export destructure/Promise.all/tables/counts, validate per-table/envelope, restore's five places, TS SQLite list, Rust allowlist), and the envelope bump touches ~9 test files whose literals move together. Splitting mid-unit would leave the tree inconsistent between plans (a restore list naming a table the schema does not declare) — exactly what this plan exists to prevent. Execution must stay on the declared file list; any file outside it is a signal the unit was mis-scoped, not a licence to widen.
</objective>
