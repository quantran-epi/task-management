> Per-phase validation contract for feedback sampling during execution. Phase 19.1 adds a 9router query-planner adapter in `knowledge-server`, persists Neo4j status counts and quarantines, and ships two Kubernetes manifests. Planner refines the Per-Task Verification Map once PLAN.md tasks exist.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest (`knowledge-server`) + vitest (`taskmate`) |
| **Config file** | `knowledge-server/vitest.config.ts`, `vitest.config.ts` |
| **Quick run command** | `npm --prefix knowledge-server test -- --run <changed-file>` |
| **Full suite command** | `npm --prefix knowledge-server test -- --run && npm test -- --run` |
| **Estimated runtime** | ~60s per package quick run, ~5m full suite |

Live acceptance (five smoke cases + restart proof) runs against a real Kubernetes cluster through TaskMate UI and the metadata-only smoke runner; it is NOT part of the vitest suite but IS gated on vitest green.

---

## Sampling Rate

- **After every task commit:** Run quick vitest against modified file(s)
- **After every plan wave:** Run full `knowledge-server` suite plus any TaskMate suites touched
- **Before `/gsd-verify-work`:** Full suite green AND five live smoke cases pass pre- and post-restart
- **Max feedback latency:** 120 seconds for quick vitest; 10 minutes for the live-smoke runner
