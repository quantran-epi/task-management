## What was built

1. **Multi-stage Dockerfile (`knowledge-server/Dockerfile`)**:
   - Uses `node:24-alpine` for both build and runtime stages.
   - Compiles TypeScript using `npm run build`.
   - Runs under non-root `node` user in production with only production dependencies (`npm ci --omit=dev`).
   - Exposes port 3001 and executes `node dist/main.js`.

2. **Neo4j Kubernetes Manifest (`k8s/neo4j.yaml`)**:
   - ClusterIP Service exposing ports `7687` and `7474` exclusively inside the cluster network.
   - StatefulSet deploying `neo4j:5.26-community` with 1 replica.
   - Mounts 10Gi `PersistentVolumeClaim` at `/data`.
   - Ingests auth credentials via `secretKeyRef` from `neo4j-credentials`.
   - Configures `/ready` HTTP probe on port 7474.

3. **Knowledge Server Kubernetes Manifest (`k8s/knowledge-server.yaml`)**:
   - ConfigMap (`knowledge-server-config`) holding non-sensitive configuration: host, port, CORS origin, internal Neo4j URI (`bolt://neo4j:7687`), and remote planner settings.
   - NodePort Service exposing port 3001 via nodePort `30080`.
   - Deployment referencing ConfigMap and secrets (`knowledge-server-secrets` and `neo4j-credentials`).
   - Probes `/api/v1/health` with Bearer auth header.

4. **Deployment Runbook (`k8s/README.md`)**:
   - Exact `kubectl create secret generic` commands for `neo4j-credentials` and `knowledge-server-secrets`.
   - Strict apply ordering: Secrets -> `k8s/neo4j.yaml` -> Readiness Verification -> `k8s/knowledge-server.yaml`.
   - Verification curl check and TaskMate UI integration instructions.

5. **Manifest Security & Syntax Test (`knowledge-server/tests/k8sManifests.test.ts`)**:
   - Validates existence and YAML structural compliance.
   - Asserts Neo4j Service type is strictly `ClusterIP`.
   - Asserts knowledge-server Service type is `NodePort` with `30080`.
   - Asserts absence of raw tokens, passwords, or Base64 secret strings.
