    - `ssh_pty_start` opens channel, requests PTY with `request_pty("xterm-256color")`, sets extended data mode to Merge, and starts remote shell.
    - Spawns dedicated OS thread reading chunks and emitting `ssh-pty:data:<session_id>` events; emits `ssh-pty:exit:<session_id>` on EOF/close.
    - Spawns dedicated OS thread processing `stdin_tx` channel writes.

  </acceptance_criteria>
  <action>
    Implement native SSH PTY streaming in Tauri:
    1. Create `src-tauri/src/ssh_pty_service.rs`:
       - Define state registry `SshPtyRegistry` wrapping `std::sync::Mutex<std::collections::HashMap<String, SshPtySession>>`.
       - In `SshPtySession`: store `session_id: String`, `stdin_tx: tokio::sync::mpsc::Sender<Vec<u8>>`, `is_closed: std::sync::Arc<std::sync::atomic::AtomicBool>`, and `channel: std::sync::Arc<std::sync::Mutex<ssh2::Channel>>`.
       - Command `ssh_pty_start(app: AppHandle, config: SshConfig, secret: Option<String>, session_id: String, working_dir: Option<String>, cols: u32, rows: u32) -> Result<String, String>`:
         * Authenticate SSH session via `ssh_service::connect_and_auth(&config, secret.as_deref())`.
         * Open channel session `session.channel_session()`.
         * Request PTY: `channel.request_pty("xterm-256color", None, Some((cols, rows, 0, 0)))`.
         * Configure `channel.handle_extended_data(ssh2::ExtendedDataMode::Merge)`.
         * Start remote shell `channel.shell()`.
         * If `working_dir` is provided, write `cd <working_dir>\n` and flush immediately.
         * Spawn dedicated OS thread for non-blocking stdout reading: reads chunks into buffer, emits Tauri event `ssh-pty:data:<session_id>` with UTF-8 text; on EOF or error emits `ssh-pty:exit:<session_id>`. Avoid blocking Tokio worker threads.
         * Spawn dedicated OS thread for stdin writing: receives `Vec<u8>` from channel `stdin_rx`, writes to channel, and flushes.
       - Command `ssh_pty_write(session_id: String, data: String) -> Result<(), String>`:
         * Send bytes to `stdin_tx`.
       - Command `ssh_pty_resize(session_id: String, cols: u32, rows: u32) -> Result<(), String>`:
         * Call `channel.request_pty_size(cols, rows, None, None)` on active channel.
       - Command `ssh_pty_close(session_id: String) -> Result<(), String>`:
         * Set `is_closed` flag, drop channel, and remove from registry.
    2. Register `SshPtyRegistry` state and commands in `src-tauri/src/lib.rs`:
       - Add `mod ssh_pty_service;`
       - Add `ssh_pty_start`, `ssh_pty_write`, `ssh_pty_resize`, `ssh_pty_close` to `invoke_handler!`.
       - Manage `SshPtyRegistry::default()` state in builder.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend → Tauri IPC | Renderer sends repo path, branch ref, and terminal input to Rust backend |
| Rust Backend → SSH Remote Server | SSH TCP socket and PTY channel to remote host / WSL |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29.1-01 | Tampering | `gitRemoteTreeService.ts` | high | mitigate | Strictly use `escapeShellArg` for all repo paths, branch refs, and file paths passed to git commands. |
| T-29.1-02 | Denial of Service | `ssh_pty_service.rs` | medium | mitigate | Spawn dedicated OS threads for blocking SSH channel I/O so Tokio async runtime thread pool is never starved. |
| T-29.1-03 | Information Disclosure | `ssh_pty_service.rs` | medium | mitigate | Session credentials (passwords/keys) passed ephemerally via memory; never logged to stderr/stdout. |
| T-29.1-SC | Tampering | npm dependencies | high | mitigate | Zero new native crates added; frontend only uses verified `@xterm/xterm` packages in later plans. |
</threat_model>
