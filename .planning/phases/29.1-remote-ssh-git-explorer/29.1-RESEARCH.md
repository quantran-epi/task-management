### Pattern 1: Strictly Read-Only Git Tree Listing (`git ls-tree`)
**What:** Query directory structure without modifying or checking out anything in the remote working tree.  
**Command:** `git -C <repo> ls-tree -l <ref>:<dir_path>`  
**Format:** `<mode> <type> <object> <size>\t<file>`  
**Example:**
```typescript
// [VERIFIED: src/services/gitRemoteService.ts:13-29]
export interface RemoteGitTreeNode {
  key: string;       // relative path e.g. "src/index.ts"
  title: string;     // file/folder name e.g. "index.ts"
  isLeaf: boolean;   // true if blob, false if tree
  size?: number;     // byte size for blobs
  sha: string;       // git object SHA
}

export async function getRemoteTree(
  config: SshConfig,
  repoPath: string,
  ref: string,
  dirPath: string = '',
  secret?: string
): Promise<RemoteGitTreeNode[]> {
  const target = dirPath ? `${ref}:${dirPath}` : ref;
  const output = await runGitCommand(
    config,
    repoPath,
    ['ls-tree', '-l', escapeShellArg(target)],
    secret
  );
  
  // Format: "<mode> <type> <object_sha> <object_size>\t<path>"
  const entries: RemoteGitTreeNode[] = [];
  for (const line of output.split('\n')) {
    if (!line.trim()) continue;
    const tabIdx = line.indexOf('\t');
    if (tabIdx === -1) continue;
    const meta = line.slice(0, tabIdx).trim().split(/\s+/);
    const name = line.slice(tabIdx + 1).trim();
    const type = meta[1]; // 'tree' | 'blob'
    const sha = meta[2] ?? '';
    const sizeStr = meta[3] ?? '0';
    const isLeaf = type === 'blob';
    const key = dirPath ? `${dirPath}/${name}` : name;
    entries.push({
      key,
      title: name,
      isLeaf,
      size: isLeaf ? parseInt(sizeStr, 10) || 0 : undefined,
      sha,
    });
  }
  return entries.sort((a, b) => {
    if (a.isLeaf === b.isLeaf) return a.title.localeCompare(b.title);
    return a.isLeaf ? 1 : -1; // folders first
  });
}
```

### Pattern 2: Read-Only File Retrieval by Ref (`git show <ref>:<path>`)
**What:** Fetch exact content for a file at any branch, commit, or tag without altering the working directory.  
**Example:**

```typescript
export async function getRemoteFileContent(
  config: SshConfig,
  repoPath: string,
  ref: string,
  filePath: string,
  secret?: string
): Promise<string> {
  const targetArg = escapeShellArg(`${ref}:${filePath}`);
  return runGitCommand(config, repoPath, ['show', targetArg], secret);
}
```

### Pattern 3: Headless Claude Code Tracing over SSH
**What:** Invoke remote `claude` CLI via SSH exec channel with specific directory/file context and instructions to produce architectural flow / sequence diagrams in Mermaid.  
**Example:**
```typescript
export interface ClaudeTraceRequest {
  sshConfig: SshConfig;
  repoPath: string;
  targetPaths: string[]; // e.g. ["src/services/auth.ts", "src/controllers/"]
  model: 'claude-sonnet-5-5' | 'claude-haiku-5-5' | 'claude-opus-5-5';
  userPrompt: string;
  secret?: string;
}

export async function runClaudeHeadlessTrace(req: ClaudeTraceRequest): Promise<string> {
  const contextPaths = req.targetPaths.map(p => escapeShellArg(p)).join(' ');
  const prompt = [
    `Analyze the execution and data flow for: ${req.targetPaths.join(', ')}.`,
    req.userPrompt ? `User instructions: ${req.userPrompt}` : '',
    'Generate a detailed, valid Mermaid diagram (sequenceDiagram or flowchart TD) representing this architectural flow.',
    'Enclose the diagram inside ```mermaid ... ``` code blocks.',
  ].filter(Boolean).join('\n');

  // Command to run claude non-interactively in repository root
  const cmd = `cd ${escapeShellArg(req.repoPath)} && claude -p ${escapeShellArg(prompt)} --model ${escapeShellArg(req.model)}`;
  
  const res = await execRemoteCommand(req.sshConfig, cmd, req.secret);
  if (res.exitStatus !== 0) {
    throw new Error(res.stderr || `Claude CLI exited with code ${res.exitStatus}`);
  }
  return res.stdout;
}
```

## Common Pitfalls

### Pitfall 1: Remote Working Tree Modification
**What goes wrong:** Calling `git checkout <branch>` changes files on the user's remote machine or WSL worktree, creating merge conflicts, breaking uncommitted edits, or interfering with active development.  
**Why it happens:** Habit of using working-copy git commands instead of ref-based queries.  
**How to avoid:** Enforce invariant: NEVER use `git checkout`. Always use `git ls-tree <ref>` and `git show <ref>:<path>`.

### Pitfall 2: Shell Escaping Bugs with Remote Paths
**What goes wrong:** Paths with spaces, parentheses, or quotes (e.g. `src/My File (1).ts`) break the SSH bash execution or cause command injection vulnerabilities.  
**Why it happens:** String concatenation (`"git -C " + repo + " ..."`) instead of strict shell escaping.  
**How to avoid:** Always wrap arguments with `escapeShellArg(arg)` from `gitRemoteService.ts` [VERIFIED: src/services/gitRemoteService.ts:13-15].

### Pitfall 3: Large File Output Overwhelming SSH Exec Buffer
**What goes wrong:** Calling `git show` on a 50MB binary or huge log file causes SSH buffer exhaustion or browser memory lockup.  
**Why it happens:** Git object is read into a single memory buffer.  
**How to avoid:** Check `size` in `git ls-tree -l` before opening. If size > 1MB, display warning and truncate or read head slice (`git show <ref>:<path> | head -n 1000`).

### Pitfall 4: Claude Headless CLI Hanging or Asking for Prompts
**What goes wrong:** Headless invocation hangs indefinitely waiting for stdin confirmation.  
**Why it happens:** Running without `-p` (print/headless mode) or running an interactive prompt.  
**How to avoid:** Ensure `-p` flag is passed, and set execution timeout (e.g. 120s) with clear error handling.

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
