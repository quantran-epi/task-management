<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-memory profile → exported JSON file | A user-authored profile crosses to a portable file that may be shared; secrets must not travel. |
| imported JSON file → Dexie settings | Untrusted file content crosses into the canonical local store at `applyConfigProfile`. |
| profile import → OS keyring | The keyring must never be a write target of a profile; secrets are re-entered by the recipient. |
| profile list row → plaintext backup | `configuration_profiles` holds blank secrets and machine paths and must be excluded from backup export. |
| imported profile → db.telegramSettings | Telegram config is owner-machine-only; no profile code path may read or write this table. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
