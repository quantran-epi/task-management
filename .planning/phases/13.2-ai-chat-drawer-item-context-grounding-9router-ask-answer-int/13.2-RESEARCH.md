### Locked Decisions

#### Drawer Layout & Docking
- **D-01:** Drawer hiển thị theo cơ chế **Docked Side-by-Side** khi pinned: `Content` của AppShell tự động co hẹp chiều rộng (`marginRight = drawerWidth`), không che khuất bảng biểu hay nội dung làm việc chính.
- **D-02:** Chiều rộng drawer có thể kéo giãn tùy ý bằng chuột (**Resizable**) từ 320px đến 650px qua thanh chia viền trái (drag handle). Độ rộng mặc định 380px và được lưu vào `localStorage` (`planner:ai_chat_width`).
- **D-03:** Các drawer khác (`TaskDrawer`, `NotificationDrawer`) hoạt động với **z-index cao hơn (overlay)** đè lên AI Chat Drawer khi được mở; đóng lại thì AI Chat Drawer vẫn duy trì trạng thái docked.
- **D-04:** Điểm kích hoạt mở/đóng drawer: Nút icon AI trên Header chính (kế bên Notification Bell) và hỗ trợ phím tắt toàn cục `Cmd+J` (macOS) / `Ctrl+J` (Windows).

#### Scoping & Session Lifecycle
- **D-05:** Cơ chế liên kết ngữ cảnh là **Auto-follow Focus**: Chat Drawer tự động chuyển scope sang Task/Project/Milestone đang active gần nhất, hiển thị chip định danh scope trên header chat. Có nút bấm "Detach / Standalone" để quay về phiên chat toàn cục.
- **D-06:** Mỗi scope duy trì **Single Thread** duy nhất trong IndexedDB. Hỗ trợ lệnh `/clear` hoặc nút "Clear Context": chèn vạch ngăn ngữ cảnh `--- Ngữ cảnh đã được đặt lại ---`, transcript cũ vẫn hiển thị trên UI nhưng prompt gửi lên LLM chỉ lấy các tin nhắn sau vạch `/clear` (kèm trần an toàn tối đa 20 tin nhắn).
- **D-07:** Khi xóa vĩnh viễn Task/Project/Milestone, hệ thống tự động **Cascade Delete** toàn bộ thread và messages liên kết của entity đó trong IndexedDB để chống rác dữ liệu.
- **D-08:** Trạng thái mở/đóng và trạng thái Ghim (Pinned) của Drawer được lưu vào `localStorage` (`planner:ai_chat_open`, `planner:ai_chat_pinned`) để duy trì sau khi tải lại trang F5. Ô nhập liệu (Draft text) không persist để tránh gửi nhầm sau reload.

#### Context Grounding & Document Depth
- **D-09:** Cấu trúc thông tin Task/Project/Milestone được tuần tự hóa theo định dạng **XML Tags `<item_context>` + Markdown có cấu trúc** (Headings, Checklist, Tags, Dates, Estimates, Status, Priority, Owners, BA).
- **D-10:** Trích xuất toàn bộ trường `task.notes` + toàn bộ nội dung Markdown của tất cả Sticky Notes gắn với task (kèm caption của ảnh chụp màn hình đính kèm nếu có), áp dụng trần an toàn tối đa 12.000 ký tự.
- **D-11:** Xử lý file đính kèm cục bộ (`documentLinks`): Áp dụng chuẩn **Claude Code**: Trên Tauri đọc tối đa 2.000 dòng đầu tiên đối với các file văn bản thuần (.txt, .md, .json, .log, source code); file nhị phân chỉ trích xuất metadata (tên file, kích thước, định dạng). Trên Web/PWA hiển thị metadata đường dẫn tham chiếu.
- **D-12:** Xử lý URL web bên ngoài (`https://...`): Gửi URL và domain làm metadata tham chiếu trong prompt; không tự động cào trang web để tránh lỗi CORS hoặc trang yêu cầu xác thực.
- **D-13:** **Claude Code CLI Integration:** Hỗ trợ nút "Chạy với Claude Code" (Open in Claude Code) trên Desktop Tauri (tự động mở Terminal.app / iTerm2 / cmd của hệ điều hành với lệnh `claude "..."` đã nhúng sẵn ngữ cảnh task); trên Web/PWA cung cấp nút "Copy CLI Command" để người dùng dán vào terminal ngoài.

#### 9router API & Message UX
- **D-14:** Kết nối 9router qua endpoint chuẩn OpenAI-compatible `/v1/chat/completions` bằng native browser `fetch()` (zero new npm dependencies).

## Project Constraints (from CLAUDE.md)

- **Audience:** Single personal user — no server-side auth or multi-user roles.
- **Runtime:** 100% local application behavior — no application backend server.
- **Hosting:** GitHub Pages static hosting compatible (relative/base-path clean).
- **Persistence:** IndexedDB via Dexie is durable working store. No `localStorage` as domain database.
- **Data safety:** Never overwrite local data without validation. Clean cascade deletion.

- **Secret Safety:** Never commit or hardcode API keys or secrets. Dual-tier credential model (OS Keychain in Tauri, IndexedDB settings in Web).
- **Zero New External Dependencies:** Connect to 9router via native `fetch()`, `ReadableStream`, and `TextDecoder`. Use Ant Design 6.6.5 and bundled `@ant-design/icons`.

## Summary

Phase 13.2 introduces a docked, resizable AI Chat Drawer and 9router API integration with context grounding into the Personal Task & Workload Planner. The assistant operates either as a standalone chat or automatically grounded in the active Task, Project, or Milestone.

All network streaming uses native Web APIs (`fetch`, `ReadableStream`, `TextDecoder`) without adding heavy AI SDKs or third-party packages. Local secrets adhere to the established dual-tier pattern: OS Keychain via Tauri's Rust `keyring` crate when running on desktop, and Dexie `settings` table on Web/PWA. Conversations are persisted in IndexedDB under `SCHEMA_V8` (`chatThreads` and `chatMessages`) with single-thread-per-scope semantics and automated cascade deletion when entities are deleted. Context grounding serializes item fields, notes, checklists, and local file contents (up to 2,000 lines on desktop) into structured XML tags with safe character budgeting. In addition, deep reasoning tasks can be spawned directly into the user's OS terminal via Claude Code CLI.

**Primary recommendation:** Implement a pure TypeScript `nineRouterClient` using native `ReadableStream` line buffering, wire the drawer into `AppShell` with CSS margin transition docking, extend Dexie with `SCHEMA_V8`, and reuse the existing `keyringService` and `cascadeRepo` patterns.

### Pattern 1: SSE Streaming with Line Buffering & AbortController
**What:** Reading chunked HTTP response bodies and parsing SSE `data: {...}` lines reliably across arbitrary network fragmentation.  
**When to use:** All 9router chat completion requests.  
**Example:**
```typescript
// Source: Web Standards / MDN ReadableStream & OpenAI SSE specification
export async function* streamChatCompletion(
  endpoint: string,
  apiKey: string,
  payload: { model: string; messages: Array<{ role: string; content: string }>; temperature?: number },
  signal?: AbortSignal
): AsyncGenerator<string, void, unknown> {
  const response = await fetch(`${endpoint.replace(/\/+$/, '')}/chat/completions`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${apiKey}`,
    },
    body: JSON.stringify({ ...payload, stream: true }),
    signal,
  });

  if (!response.ok) {
    const errorText = await response.text();
    throw new Error(`API Error (${response.status}): ${errorText || response.statusText}`);
  }

  if (!response.body) {
    throw new Error('Response body is empty');
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder('utf-8');
  let lineBuffer = '';

  try {
    while (true) {
      const { done, value } = await reader.read();
      if (done) break;

      lineBuffer += decoder.decode(value, { stream: true });
      const lines = lineBuffer.split(/\r?\n/);
      // Keep last partial segment in buffer
      lineBuffer = lines.pop() ?? '';

      for (const line of lines) {
        const trimmed = line.trim();
        if (!trimmed || trimmed.startsWith(':')) continue; // Ignore empty lines & SSE comments

        if (trimmed.startsWith('data:')) {
          const dataContent = trimmed.slice(5).trim();
          if (dataContent === '[DONE]') return;

          try {
            const parsed = JSON.parse(dataContent);
            const deltaText = parsed.choices?.[0]?.delta?.content;
            if (deltaText) {
              yield deltaText;
            }
          } catch {
            // Incomplete JSON chunk across SSE split — skip
          }
        }
      }
    }
  } finally {
    reader.releaseLock();
  }
}
```

### Pattern 2: Dual-Tier Secret Storage (Tauri Keyring + Dexie Settings Fallback)
**What:** Store API Key in macOS Keychain / Windows Credential Vault on desktop, and in Dexie `db.settings` on Web.  
**When to use:** Saving and loading 9router API key. Mirrors the battle-tested `jiraTokenService.ts`.  
**Example:**
```typescript
// Source: src/services/jiraTokenService.ts pattern
export async function getNineRouterApiKey(db: TaskPlannerDatabase): Promise<string> {
  if (isTauriApp()) {
    const key = await getKeyringCredential(KEYRING_KEYS.NINEROUTER_API_KEY);
    if (key) return key;
  }
  const setting = await db.settings.get('ninerouter_api_key');
  return typeof setting?.value === 'string' ? setting.value : '';
}

export async function setNineRouterApiKey(key: string, db: TaskPlannerDatabase): Promise<void> {
  const trimmed = key.trim();
  if (isTauriApp()) {
    if (trimmed) {
      await storeKeyringCredential(KEYRING_KEYS.NINEROUTER_API_KEY, trimmed);
    } else {
      await deleteKeyringCredential(KEYRING_KEYS.NINEROUTER_API_KEY);
    }
    await db.settings.delete('ninerouter_api_key');
  } else {
    if (trimmed) {
      await db.settings.put({ key: 'ninerouter_api_key', value: trimmed });
    } else {
      await db.settings.delete('ninerouter_api_key');
    }
  }
}
```

### Anti-Patterns to Avoid
- **Hardcoding AI prompt secrets or tokens in code:** Always read via `nineRouterTokenService`.
- **Parsing SSE without line buffering:** Relying on `value` chunks matching line boundaries fails on slow/fragmented network connections.
- **Scraping external URLs in browser:** Violates CORS and risks stalling the UI thread. Use metadata only (`D-12`).
- **Persisting draft text across reloads:** Creates accidental submission of stale prompts after reload (`D-08`).
- **Storing full multi-megabyte local files in context:** Bloats token limits and increases costs. Limit to first 2,000 lines for text files, metadata only for binaries (`D-11`).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |

## Common Pitfalls

### Pitfall 1: Network Chunk Fragmentation in SSE
**What goes wrong:** Stream parsing crashes with `JSON.parse` syntax error or drops tokens.  
**Why it happens:** Network packets don't align with SSE `data: {...}` lines; a single JSON object can arrive split across two chunks.  
**How to avoid:** Use line buffering (`lineBuffer += decoder.decode(...)`, split on `\n`, pop the remainder back to buffer). Only parse lines that begin with `data: ` and are complete.  
**Warning signs:** Sporadic truncated words or JSON parse errors in browser console during rapid streaming.

### Pitfall 2: Memory Leak with Orphaned Chat Threads on Entity Deletion
**What goes wrong:** Deleting a task or project leaves orphaned threads and messages in IndexedDB, growing database size indefinitely.  
**Why it happens:** Entity deletion only removed tasks, milestones, and allocations.  
**How to avoid:** Wire `deleteTaskWithAllocations`, `deleteProjectWithCascade`, and `deleteMilestoneWithCascade` in `cascadeRepo.ts` to delete associated `chatThreads` and `chatMessages` atomically in the same Dexie transaction (`D-07`).  
**Warning signs:** Unreferenced `chatThreads` found when inspecting IndexedDB tables in DevTools.

### Pitfall 3: Context Overflow Exceeding Token Limits
**What goes wrong:** Sending large task notes, multiple sticky notes, and huge source code files causes 9router/LLM to return 400 Bad Request (context length exceeded).  
**Why it happens:** Unbounded string concatenation of notes and local files.  
**How to avoid:** Enforce strict 12,000-character safe ceiling in `contextGrounding.ts`. Truncate gracefully with a clear visual notice `[Nội dung đã được cắt bớt để bảo đảm an toàn giới hạn ngữ cảnh]`. Limit local text files to 2,000 lines.  
**Warning signs:** API errors with status 400 or HTTP 413 during chat generation.

### Pitfall 4: Window Resize / Responsive Layout Breakage
**What goes wrong:** On mobile screens, docked margin shrinks the content area to unusable width or negative margin.  
**Why it happens:** Applying `marginRight: 380px` when screen width is < 768px.  
**How to avoid:** Check `Grid.useBreakpoint().md`. If on mobile (`screens.md === false`), force `isPinned = false` and render as overlay drawer with standard mask (`D-01`, `UI-SPEC`).

### 2. Context Grounding XML Formatter
```typescript
// In src/services/ai/contextGrounding.ts
export interface GroundingContextInput {
  entityType: 'task' | 'project' | 'milestone';
  entity: Task | Project | Milestone;
  notes?: Note[];
  project?: Project;
  milestone?: Milestone;
  fileSnippets?: Array<{ path: string; content?: string; isBinary?: boolean }>;
}

export function buildSystemPromptWithGrounding(
  input: GroundingContextInput,
  charLimit = 12000
): string {
  let context = `<item_context type="${input.entityType}">\n`;
  context += `## Tiêu đề: ${input.entity.name}\n`;
  context += `## Trạng thái: ${input.entity.status}\n`;

  if ('priority' in input.entity) {
    context += `## Mức ưu tiên: ${input.entity.priority}\n`;
  }
  if ('estimateMinutes' in input.entity) {
    context += `## Ước lượng: ${input.entity.estimateMinutes} phút (~${(input.entity.estimateMinutes / 60).toFixed(1)}h)\n`;
  }
  if (input.entity.deadline) {
    context += `## Hạn hoàn thành: ${input.entity.deadline}\n`;
  }
  if (input.entity.opsOwners?.length) {
    context += `## Ops Owners: ${input.entity.opsOwners.join(', ')}\n`;
  }
  if (input.entity.businessAnalysts?.length) {
    context += `## Business Analysts: ${input.entity.businessAnalysts.join(', ')}\n`;
  }

  // Checklist
  if ('checklist' in input.entity && input.entity.checklist?.length) {
    context += `\n### Checklist:\n`;
    for (const item of input.entity.checklist) {
      context += `- [${item.done ? 'x' : ' '}] ${item.text}\n`;
    }
  }

  // Notes
  if (input.entity.notes) {
    context += `\n### Ghi chú:\n${input.entity.notes}\n`;
  }

  // Sticky notes
  if (input.notes?.length) {
    context += `\n### Sticky Notes liên kết:\n`;
    for (const n of input.notes) {
      context += `#### ${n.title || 'Ghi chú'}\n${n.body}\n`;
    }
  }

  // File snippets
  if (input.fileSnippets?.length) {
    context += `\n### Tài liệu & Đường dẫn đính kèm:\n`;
    for (const f of input.fileSnippets) {
      if (f.isBinary) {
        context += `- Tập tin nhị phân: ${f.path}\n`;
      } else if (f.content) {
        context += `- Đường dẫn: ${f.path}\n\`\`\`\n${f.content}\n\`\`\`\n`;
      } else {
        context += `- Đường dẫn: ${f.path}\n`;
      }
    }
  }

  context += `</item_context>\n`;

  // Enforce safety budget
  if (context.length > charLimit) {
    context = context.slice(0, charLimit) + '\n... [Nội dung đã được cắt bớt để bảo đảm an toàn giới hạn ngữ cảnh]\n</item_context>\n';
  }

  return `Bạn là Trợ lý AI cá nhân chuyên nghiệp được tích hợp trong ứng dụng Task Planner.
Dưới đây là ngữ cảnh chi tiết của mục người dùng đang làm việc:

${context}

Hãy trả lời ngắn gọn, chính xác, bám sát thông tin ngữ cảnh trên. Khi đưa ra gợi ý chia nhỏ công việc, hãy dùng định dạng checklist (- [ ]) để người dùng có thể thêm nhanh vào tác vụ.`;
}
```

```rust
// In src-tauri/src/ai_assistant.rs
#[tauri::command]
pub fn launch_claude_terminal(command_str: String) -> Result<(), String> {
    let trimmed = command_str.trim();
    if trimmed.is_empty() {
        return Err("Command cannot be empty".to_string());
    }

    #[cfg(target_os = "macos")]
    {
        // AppleScript escaping
        let escaped = trimmed.replace('\\', "\\\\").replace('\"', "\\\"");
        let script = format!("tell application \"Terminal\" to do script \"{}\"", escaped);
        std::process::Command::new("osascript")
            .arg("-e")
            .arg(&script)
            .spawn()
            .map_err(|e| format!("Không thể mở Terminal.app: {}", e))?;
        Ok(())
    }

    #[cfg(target_os = "windows")]
    {
        std::process::Command::new("cmd")
            .args(["/c", "start", "cmd.exe", "/k", trimmed])
            .spawn()
            .map_err(|e| format!("Không thể mở cmd.exe: {}", e))?;
        Ok(())
    }

    #[cfg(not(any(target_os = "macos", target_os = "windows")))]
    {
        Err("Hệ điều hành hiện tại không hỗ trợ khởi chạy terminal tự động".to_string())
    }
}
```

### Known Threat Patterns for AI Integration

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| API Key Exposure in Bundles | Information Disclosure | Store key at runtime in OS Keychain (Tauri) or Dexie `settings` (Web). Never use `VITE_*` env vars for user secrets. |
| Prompt Injection via Malicious Notes | Tampering | Encapsulate user context within explicit `<item_context>` boundaries and clear system instructions. |

| Malicious Markdown Rendering (XSS) | Tampering | Use `renderSafeMarkdown` which strictly escapes all HTML tags (`<`, `>`, `&`, `"`) before parsing markdown tokens, and disallows `javascript:` URI schemes in links. |
