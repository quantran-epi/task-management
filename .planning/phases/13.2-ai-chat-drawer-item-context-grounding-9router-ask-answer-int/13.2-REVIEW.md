## Summary

Phase 13.2 introduces docked side-by-side AI Chat Drawer, context grounding serialization, 9router API client with SSE streaming, and Claude Code CLI launcher. While the core LLM streaming and Dexie repositories are cleanly structured, two blocker issues must be resolved before shipping:
1. Command injection vulnerability in Tauri `launch_claude_terminal` command allowing arbitrary shell execution across platforms (specifically Windows `cmd.exe` metacharacter breakout and unescaped macOS AppleScript).
2. Dexie Schema V8 migration broke existing regression test suites (`tests/db.test.ts` and `tests/timerSegments.test.ts`).

Additionally, several warnings were identified regarding API key redaction failure on untrimmed keys, dead configuration for character limits, and stream resource leaks.

## Critical Issues

### CR-01: Command Injection and Metacharacter Execution in `launch_claude_terminal`

**File:** `/Users/tranducquan/Working/Personal/task-management/src-tauri/src/jira_proxy.rs:168-223`
**Issue:** `launch_claude_terminal` accepts an arbitrary `command_str: String` via Tauri IPC and only checks `if !trimmed.starts_with("claude ") && trimmed != "claude"`.
- On Windows: `cmd /c start cmd /k <trimmed>` is invoked directly. `cmd.exe` does not recognize Unix single quotes `'...'` generated by `escapeShellArg` in `claudeCliService.ts`. Any metacharacter (`&`, `|`, `^`, `%`, `<`, `>`, or newlines) present in task fields or custom payloads will break out of quotes and execute arbitrary shell commands.
- On macOS: Terminal `do script` executes the unescaped script in the default shell. If `trimmed` contains `\n` or `&&` or `;`, Terminal executes chained commands.
- An attacker with task access or any payload starting with `claude & <cmd>` achieves arbitrary code execution.

**Fix:** Avoid passing raw unparsed shell commands across IPC. Pass structured parameters (e.g. `{ prompt: String }`) and reject shell metacharacters, or sanitize and escape arguments specifically for the target operating system:

```rust
#[tauri::command]
pub fn launch_claude_terminal(prompt: String) -> Result<(), String> {
    let trimmed = prompt.trim();
    if trimmed.is_empty() {
        return Err("Prompt cannot be empty".to_string());
    }

    #[cfg(target_os = "macos")]
    {
        // Escape for AppleScript string literal and single-quote argument
        let shell_arg = trimmed.replace('\'', "'\\''");
        let command = format!("claude '{}'", shell_arg);
        let escaped = command.replace('\\', "\\\\").replace('"', "\\\"");
        let script = format!(
            "tell application \"Terminal\"\nactivate\ndo script \"{}\"\nend tell",
            escaped
        );
        std::process::Command::new("osascript")
            .arg("-e")
            .arg(&script)
            .spawn()
            .map_err(|e| format!("Failed to spawn Terminal on macOS: {}", e))?;
    }

    #[cfg(target_os = "windows")]
    {
        // Escape caret, percent, and quotes for Windows cmd /k
        let sanitized = trimmed.replace('"', "\"\"").replace('%', "%%");
        std::process::Command::new("cmd")
            .args(["/c", "start", "cmd", "/k", &format!("claude \"{}\"", sanitized)])
            .spawn()
            .map_err(|e| format!("Failed to spawn cmd.exe on Windows: {}", e))?;
    }

    #[cfg(not(any(target_os = "macos", target_os = "windows")))]
    {
        let shell_arg = trimmed.replace('\'', "'\\''");
        std::process::Command::new("x-terminal-emulator")
            .args(["-e", "sh", "-c", &format!("claude '{}'", shell_arg)])
            .spawn()
            .map_err(|e| format!("Failed to spawn terminal on Linux: {}", e))?;
    }

    Ok(())
}
```

### WR-01: API Key Leakage in Error Handlers When Key Has Whitespace

**File:** `/Users/tranducquan/Working/Personal/task-management/src/services/ai/nineRouterClient.ts:7-10`
**Issue:** `redactApiKey` searches for `apiKey` using `text.replaceAll(apiKey, '***')` without trimming. Meanwhile, `fetch` headers use `Authorization: Bearer ${options.apiKey.trim()}`. If an API key was entered with leading or trailing whitespace, any server response or network error containing the trimmed key will NOT be redacted, leaking the credential in UI error cards or logs.
**Fix:**
```typescript
export function redactApiKey(text: string, apiKey?: string): string {
  const trimmed = apiKey?.trim();
  if (!trimmed || trimmed.length < 4) return text;
  return text.replaceAll(trimmed, '***');
}
```

### WR-02: Configured Character Limit Budget Is Dead Configuration

**File:** `/Users/tranducquan/Working/Personal/task-management/src/services/ai/contextGrounding.ts:6, 167` and `/Users/tranducquan/Working/Personal/task-management/src/components/ai/AIChatDrawer.tsx:238-251`
**Issue:** `NineRouterConfigCard` provides a configuration input for "Giới hạn ký tự ngữ cảnh (Safe Character Budget)" (range 2000–32000), saved as `ninerouter_char_limit`. However, `buildItemContextPrompt` hardcodes `MAX_CONTEXT_CHAR_LIMIT = 12000`, does not accept a custom limit in its options, and `AIChatDrawer.tsx` never passes `config.charLimit`. The user setting has zero effect.
**Fix:** Add `charLimit?: number` to `BuildItemContextPromptOptions`:
```typescript
export interface BuildItemContextPromptOptions {
  entityType: 'task' | 'project' | 'milestone';
  item: Task | Project | Milestone;
  db?: TaskPlannerDatabase;
  fileReader?: (filePath: string, maxLines?: number) => Promise<string | null>;
  charLimit?: number;
}
```
And in `AIChatDrawer.tsx`:
```typescript
systemInstruction = await buildItemContextPrompt({
  entityType: 'task',
  item: t,
  db,
  charLimit: config.charLimit,
});
```

### WR-03: Reader Lock Release Without Stream Cancellation

**File:** `/Users/tranducquan/Working/Personal/task-management/src/services/ai/nineRouterClient.ts:119-172`
**Issue:** In `streamChatCompletion`, `reader.releaseLock()` is called in `finally`, but `reader.cancel()` is never called when the generator aborts or when the consumer exits the loop early. The underlying HTTP connection may remain open. Additionally, if the SSE stream finishes without a trailing newline, remaining buffer in `lineBuffer` is dropped without being checked.
**Fix:** Ensure `reader.cancel()` is called on abort or abnormal termination, and flush remaining `lineBuffer` after the read loop finishes if `done` is true:
```typescript
  } catch (err: any) {
    await reader.cancel().catch(() => {});
    // ...
  } finally {
    reader.releaseLock();
  }
```

### WR-04: Missing Unmount Abort Cleanup in `AIChatDrawer`

**File:** `/Users/tranducquan/Working/Personal/task-management/src/components/ai/AIChatDrawer.tsx:180-184`
**Issue:** The effect only checks `!open`. If the user navigates away or the parent component unmounts `AIChatDrawer` while SSE streaming is in progress, the generator continues running in the background, updating unmounted state and committing `saveMessage` to Dexie.
**Fix:**
```typescript
  useEffect(() => {
    if (!open && abortControllerRef.current) {
      abortControllerRef.current.abort();
    }
    return () => {
      abortControllerRef.current?.abort();
    };
  }, [open]);
```

### WR-05: `InlineApiErrorCard` Suppressed If `onOpenSettings` Is Not Provided

**File:** `/Users/tranducquan/Working/Personal/task-management/src/components/ai/ChatMessageList.tsx:127-133`
**Issue:** The error card render condition is `{error && onRetry && onOpenSettings && <InlineApiErrorCard ... />}`. Since `onOpenSettings?: () => void` is optional in `AIChatDrawerProps`, if a consumer or modal renders the chat drawer without `onOpenSettings`, API errors are completely hidden, leaving the user with no error feedback.
**Fix:** Make `onOpenSettings` optional in `InlineApiErrorCard` and render the error card whenever `error && onRetry` are present.
