## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Timer Lifecycle & Hierarchy Context
- **D-01:** Lưu từng **running segment** với `startTime` và `endTime`. `Pause` đóng segment hiện tại; `Resume` mở segment mới; `Finish` tổng hợp segments thành một `WorkSession`.
- **D-02:** `Start`/`Resume` chỉ tự đổi `Task.status` từ `Open` sang `In Progress`. Không ghi đè `In Review`, `Resolved`, `Done` hoặc `Cancelled`; `Pause`/`Finish` không tự hoàn thành task.
- **D-03:** Khi `Finish` timer đang `paused`, dùng timestamp của lần `Pause` cuối làm `WorkSession.endTime`, không dùng thời điểm bấm Finish.
- **D-04:** Timer UI hiển thị subtitle `Project › Milestone` dưới task name; bỏ phần không tồn tại. Áp dụng cho Header widget, dropdown và Timer pop-out.

#### Jira Epic Mapping & Local-Authoritative Status
- **D-05:** Local `Project` tương đương Jira **Epic**, không phải Jira Project container. Mỗi Project có optional `jiraEpicKey`.
- **D-06:** Project UI hỗ trợ **Link existing Jira Epic** và **Create Jira Epic from Project**. Task con khi tạo Jira issue mặc định gắn Epic của Project; Create Issue modal vẫn cho override.
- **D-07:** `Task.status` trong app là authoritative. Jira status được persist riêng (`statusId`, `statusName`, `statusCategory`, `syncedAt`) để hiển thị và phát hiện lệch trạng thái; Jira thay đổi bên ngoài không tự đổi `Task.status`.
- **D-08:** Status mapping là **one-to-many** từ mỗi local `Task.status` tới nhiều Jira status IDs. Ví dụ `In Review` có thể map tới `Code Review` và `Peer Review`.
- **D-09:** Khi local status đổi, app lấy các Jira target đã map và còn reachable qua available Jira Transitions. Nếu có nhiều target, người dùng chọn; nếu có một target, chọn sẵn. Luôn xác nhận trước API call.
- **D-10:** Nếu không có Transition phù hợp, Transition yêu cầu unsupported Screen fields hoặc Jira update lỗi, local change vẫn giữ; UI báo local/Jira mismatch và cung cấp `Open in Jira`.
- **D-11:** Jira status chưa map không được đoán bằng keyword. Giữ local status, hiển thị Jira badge và cảnh báo cấu hình mapping. `statusCategory` chỉ được dùng để đề xuất mapping ban đầu.
- **D-12:** Jira status chỉ refresh khi mở Task và khi người dùng bấm `Refresh`; không polling định kỳ.
- **D-13:** Tauri tự động gọi Jira qua built-in Rust command/proxy và mở Jira links bằng system browser. Web/PWA dùng configured CORS Proxy và mở link trong tab mới.

#### Sticky Notes, Attachments & Notes Window
- **D-14:** Mỗi note gắn tối đa một entity qua optional `entityType` + `entityId` (`task`, `project`, `milestone`). Không có reference thì là **standalone note**. Một entity có nhiều notes.
- **D-15:** Có top-level **Notes view** để search/filter toàn bộ notes; Task/Project/Milestone có section hiển thị notes liên quan. Dùng cùng records, không duplicate data.
- **D-16:** Nội dung note lưu dưới dạng Markdown source. Render Common Markdown (heading, list, checklist, emphasis, code, link) nhưng cấm raw HTML. External links dùng safe opener theo runtime.
- **D-17:** Screenshot lưu dạng `Blob` trong attachment store riêng. Search theo note text, filename và user-entered caption; không OCR.
- **D-18:** Tối đa 5 ảnh/note và 5 MB/ảnh. Validate image MIME và size trước khi lưu; không tự resize/compress.
- **D-19:** Backup/restore phải bao gồm attachments để phục hồi đầy đủ; attachment lifecycle phải đồng bộ với note lifecycle.
- **D-20:** Chỉ có **một reusable Notes list pop-out window**, không mở một window cho mỗi note. Window hỗ trợ search/filter, chọn và chỉnh note.
- **D-21:** Tauri dùng resizable native window với `Always on Top`; Web/PWA dùng reusable `window.open` popup, không cam kết always-on-top.
- **D-22:** Mở Notes window từ entity sẽ áp dụng entity filter; người dùng có thể clear filter để xem tất cả. Mở từ Notes view hiển thị toàn bộ.
- **D-23:** Nhớ size, position và pinned state ở Notes-window level; clamp position vào màn hình hiện tại khi monitor/layout thay đổi.
- **D-24:** Mỗi note có `isPinned`; pinned notes đứng đầu, sau đó sort theo `updatedAt` giảm dần.
- **D-25:** Khi xóa Task/Project/Milestone, attached notes được chuyển thành standalone và giữ screenshots; không cascade-delete note data.

#### Actual Worklog Planner
- **D-26:** Tạo weekly planned-vs-actual view theo ngày và task, tái dùng `WeekNavigator`. Mỗi cell/row hiển thị `Planned`, `Actual`, `Variance` và cho CRUD `WorkSession` inline.
- **D-27:** Mặc định chỉ hiển thị task có `PlannedAllocation` hoặc `WorkSession` trong tuần. Có searchable `Add Task` để thêm task khác vào entry flow.
- **D-28:** `WorkSession` là nguồn sự thật duy nhất cho Actual time; không tạo aggregate actual field thứ hai.
- **D-29:** Quick entry cho phép nhập số phút trên task/day và tạo manual `WorkSession`. Optional detail modal cho chỉnh `startTime`, `endTime`, note và segments.
- **D-30:** WorkSession qua nửa đêm được aggregate bằng cách split từng running segment tại local midnight. Paused time không tính; WorkSession vẫn là một record.
- **D-31:** `Variance = Actual - Planned`. Giá trị âm hiển thị trung tính; giá trị dương dùng warning. Khi Planned bằng 0, vẫn hiển thị Actual và `+Xm`.
- **D-32:** Actual Worklog chỉ local. Không push hoặc auto-sync WorkSession sang Jira Worklog trong phase này.

#### Secure Credential Persistence
- **D-33:** Trên Tauri, GitHub PAT, backup passphrase và Jira API token được persist trong OS credential store (Windows Credential Manager/macOS Keychain) và tự load khi mở app.
- **D-34:** Trên Web/PWA, không persist secret plaintext trong IndexedDB, localStorage hoặc SQLite; credential forms hỗ trợ browser password manager/autofill.
- **D-35:** Secrets không được đưa vào SQLite mirror, backup payload hoặc logs.
- **D-36:** Legacy Jira token trên Tauri được move sang OS keychain, verify write/read thành công rồi mới purge khỏi IndexedDB, SQLite queue và SQLite mirror. Nếu keychain write/verification lỗi, giữ legacy token và báo lỗi để tránh mất credential.
- **D-37:** Settings chỉ hiển thị `Stored`/`Not stored`; có `Replace` và `Forget` riêng cho GitHub PAT, backup passphrase và Jira token. Không show/copy secret. `Forget` cần confirm và dừng scheduler/integration phụ thuộc.

#### GitHub Recurring Auto-Sync Recovery & Visibility
- **D-38:** Network/timeout/5xx dùng exponential backoff `1 → 5 → 15 → 30 → 60 phút`, sau đó giữ tối đa 60 phút giữa các lần thử.
- **D-39:** Browser `online` event và manual `Sync now` được phép thử ngay. `401/403` và remote conflict không auto-retry.
- **D-40:** Persist retry state qua restart. Daily run bị lỡ khi app đóng sẽ catch up khi mở lại nếu data vẫn `dirty`.
- **D-41:** Sync thành công clear `dirtySince`, retry state và lỗi cũ. Không phát desktop notification cho mỗi success.
- **D-42:** Remote SHA conflict pause scheduler, giữ local dirty state và hiển thị conflict. Chỉ resume sau khi người dùng hoàn tất safe Pull hoặc confirmed Force Push; không auto-merge/overwrite.
- **D-43:** Settings hiển thị Last success, Next run, Dirty since, retry/error/conflict state. Header chỉ hiển thị indicator nhỏ khi pending, error hoặc conflict.

## Project Constraints (from CLAUDE.md)
- **Architecture**: 100% offline-first, no backend app server. IndexedDB (Dexie) is working data store.
- **Desktop/Hosting**: Tauri for desktop, GitHub Pages for Web/PWA.
- **Security & Secrets**: Never bundle or log secrets. Never store secrets in plaintext in IndexedDB, localStorage, or SQLite mirror. Tauri uses OS Credential Manager/macOS Keychain.
- **UI System**: Fixed to Ant Design 6.6.5 and `@ant-design/icons`. No other component library or rich-text framework.
- **Identifiers & Dates**: Native `crypto.randomUUID()`. Persist calendar dates as `YYYY-MM-DD` strings.
- **Backup & Data Safety**: Backup envelope must include new tables (notes, attachments). Do not overwrite without explicit confirmation.

## Summary

Phase 13.1 deepens personal workflow execution across five cohesive domains: (1) high-fidelity timer segments and status automation; (2) Jira Epic mapping and local-authoritative status reconciliation with built-in desktop proxy; (3) offline-first Sticky Notes with attachments and a dedicated floating pop-out window; (4) weekly Actual Worklog Planner with variance analysis and inline session adjustments; and (5) OS keychain credential management with resilient recurring sync recovery.

All data remains strictly offline-first in IndexedDB (Dexie), while Tauri Rust extensions provide desktop capabilities: native OS keychain access (`keyring` crate), built-in Jira HTTP proxy (`reqwest` crate), system default browser link opening, and secondary floating utility windows. Web/PWA retains clean fallbacks (session credentials with password manager autofill, CORS proxy, browser popups).

**Primary recommendation:** Increment Dexie schema to `SCHEMA_V7` with tables `notes` and `noteAttachments`; update `ActiveTimer` and `WorkSession` with structured segment arrays; build Tauri commands for keychain and HTTP proxy in `src-tauri`; and maintain strict separation between local authoritative domain state and remote sync/Jira layers.

### Pattern 1: High-Fidelity Timer Running Segments (SCHEMA_V7)
**What:** `ActiveTimer` and `WorkSession` store an array of continuous execution intervals:
```typescript
export interface TimerSegment {
  startTime: string; // ISO 8601
  endTime?: string | undefined; // ISO 8601 (undefined while running)
}

export interface ActiveTimer {
  taskId: string;
  status: 'running' | 'paused';
  startedAt: number; // Unix epoch ms of current active run
  accumulatedMs: number; // Sum of closed segments prior to current run
  sessionStartTime: string; // ISO 8601 of first segment
  segments: TimerSegment[];
}
```
**When to use:** On Pause, close open segment (`segment.endTime = nowIso`). On Resume, push `{ startTime: nowIso }`. On Finish, set last segment `endTime`. If finished while paused, use last pause timestamp (`segments[last].endTime`).

### Pattern 2: Safe Status Automation
**What:** Status transitions must protect terminal and reviewed states:
```typescript
if (task.status === 'Open') {
  task.status = 'In Progress';
  task.updatedAt = new Date().toISOString();
  await database.tasks.put(task);
}
// Do NOT overwrite 'In Review', 'Resolved', 'Done', or 'Cancelled'
```

### Pattern 3: Local-Authoritative Jira Sync & Reachable Transitions
**What:** Local status change checks configured mapping.
- Local `Project` holds `jiraEpicKey`.
- Setting `jira_status_mappings` holds `Record<TaskStatus, string[]>`.
- When local task status changes, fetch available transitions for linked issue: `GET /rest/api/3/issue/{key}/transitions`.
- Filter available transitions where `transition.to.id` is in mapped target IDs.
- Present user confirmation Modal with reachable target options.
- If transition succeeds, update cached Jira status (`statusId`, `statusName`, `statusCategory`, `syncedAt`).
- If transition fails or screen requires extra fields, keep local status and display mismatch Tag.

### Pattern 4: Offline-First Sticky Notes & Attachments Store
**What:** Two new Dexie tables:
1. `notes`: `id, entityType, entityId, isPinned, createdAt, updatedAt`
2. `noteAttachments`: `id, noteId, fileName, mimeType, sizeBytes, createdAt` (holds `data: Blob`)
- When parent entity (Task/Project/Milestone) is deleted:
```typescript
await db.notes.where({ entityType, entityId }).modify({
  entityType: undefined,
  entityId: undefined,
  updatedAt: new Date().toISOString()
});
```
- Notes become standalone; screenshots are preserved.

### Pattern 5: Desktop OS Keychain Persistence (Tauri)
**What:** Store secrets securely via Rust:
```rust
// In src-tauri/src/keyring_store.rs
#[tauri::command]
pub fn store_credential(service: &str, key: &str, secret: &str) -> Result<(), String> {
    let entry = keyring::Entry::new(service, key).map_err(|e| e.to_string())?;
    entry.set_password(secret).map_err(|e| e.to_string())
}

#[tauri::command]
pub fn get_credential(service: &str, key: &str) -> Result<Option<String>, String> {
    let entry = keyring::Entry::new(service, key).map_err(|e| e.to_string())?;
    match entry.get_password() {
        Ok(pwd) => Ok(Some(pwd)),
        Err(keyring::Error::NoEntry) => Ok(None),
        Err(e) => Err(e.to_string()),
    }
}
```

## Common Pitfalls

### Pitfall 1: Truncating Finished Timers That Were Paused
**What goes wrong:** User pauses timer at 10:00 AM, returns at 11:30 AM and clicks "Finish". Session records 90 minutes instead of the actual worked time up to 10:00 AM.
**Why it happens:** Using click time as `endTime`.
**How to avoid:** D-03: When finishing while paused, use the `endTime` of the last paused segment as `WorkSession.endTime`.

### Pitfall 2: Overwriting Non-Open Task Status on Timer Start
**What goes wrong:** User starts timer on a task in "In Review" or "Resolved"; task jumps back to "In Progress".
**Why it happens:** Naive `task.status = 'In Progress'` assignment.
**How to avoid:** D-02: Only automate status when `task.status === 'Open'`.

### Pitfall 3: Storing Raw Blobs in SQLite Mirror
**What goes wrong:** SQLite mirror attempts to serialize 5MB image Blobs into JSON string, crashing memory or corrupting queue.
**Why it happens:** Unfiltered table replication.
**How to avoid:** Exclude `noteAttachments` from SQLite mirror, or serialize note metadata only, keeping binary blobs in IndexedDB and backup payload.

### Pitfall 4: Exponential Backoff Loop Locking Sync Forever
**What goes wrong:** Sync fails once on network hiccup, and app gets stuck waiting 60 minutes.
**Why it happens:** Backoff not reset on manual trigger or network reconnect.
**How to avoid:** D-39: Listen to `window.addEventListener('online')` and reset backoff immediately. Reset backoff on manual "Sync now".

## Code Examples

### 1. Midnight Segment Splitting for Actual Worklog
```typescript
// Split a running segment crossing local midnight into calendar day buckets
export function splitSegmentByMidnight(
  startIso: string,
  endIso: string
): Array<{ date: string; minutes: number }> {
  const start = new Date(startIso);
  const end = new Date(endIso);
  const results: Array<{ date: string; minutes: number }> = [];

  let current = new Date(start);
  while (current < end) {
    const nextMidnight = new Date(current.getFullYear(), current.getMonth(), current.getDate() + 1);
    const segmentEnd = end < nextMidnight ? end : nextMidnight;
    const diffMinutes = Math.max(1, Math.round((segmentEnd.getTime() - current.getTime()) / 60000));
    
    const year = current.getFullYear();
    const month = String(current.getMonth() + 1).padStart(2, '0');
    const day = String(current.getDate()).padStart(2, '0');
    results.push({ date: `${year}-${month}-${day}`, minutes: diffMinutes });

    current = segmentEnd;
  }
  return results;
}
```

```typescript
// Safe Markdown rendering without raw HTML
export function renderSafeMarkdown(source: string): string {
  // Escape raw HTML entities
  const escaped = source
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;');

  // Process headers, bold, italics, checklists, lists, inline code, and safe links
  return escaped
    .replace(/^### (.*$)/gim, '<h3>$1</h3>')
    .replace(/^## (.*$)/gim, '<h2>$1</h2>')
    .replace(/^# (.*$)/gim, '<h1>$1</h1>')
    .replace(/\*\*(.*?)\*\*/gim, '<strong>$1</strong>')
    .replace(/\*(.*?)\*/gim, '<em>$1</em>')
    .replace(/`([^`]+)`/gim, '<code>$1</code>')
    .replace(/\[ \]/g, '<input type="checkbox" disabled />')
    .replace(/\[x\]/g, '<input type="checkbox" checked disabled />')
    .replace(/\[(.*?)\]\((https?:\/\/.*?)\)/gim, '<a href="$2" target="_blank" rel="noopener noreferrer">$1</a>');
}
```
