<objective>
Add `explore_repo`: a team tool that runs Claude Code headless **on the remote host** over SSH and
returns a bounded structured report.

Purpose: `git_read` puts file contents into the calling model's context. For a broad question that
costs many reads, the cheaper shape is to let a model with its own context window do the reading and
return only conclusions. This is the second tier — `git_read` stays the first.
Output: a service module with a testable command builder and parser, the team tool, and a prompt line
telling the model when to reach for it.
</objective>

<verified_cli_contract>
These were probed against the real `claude` binary before this plan was written. Do not re-derive them.

- `claude -p <prompt> --output-format json` prints ONE JSON object on stdout whose `result` field is
  the assistant's final text.
- With `--json-schema <inline-json>`, the same object also carries `structured_output` (the parsed
  value). `result` remains the raw string.
- `--allowedTools "Read,Grep,Glob"` restricts the tool set. Without it a headless run that reaches
  for a tool outside the set blocks on a permission prompt nobody can answer.
- `--max-turns <n>` is enforced. On exhaustion the object has `is_error: true`,
  `subtype: 'error_max_turns'`, `result: null` — and `errors` is populated.
- `--no-session-persistence` keeps the remote from accumulating session files.
- `--tools ""` disables all built-in tools; `--tools "default"` restores them. `--allowedTools` is
  the narrower, per-run control and is what this plan uses.
- `timeout(1)` is NOT guaranteed on the remote (absent on stock macOS). Do not build the command
  around it; bound the run on the JS side and cancel through the stream handle.
</verified_cli_contract>

    Create `src/services/remoteExploreService.ts`. Everything here is pure or takes injected
    functions so it is testable without SSH.

    ```ts
    export const EXPLORE_REPORT_MAX_CHARS = 12_000;
    export const EXPLORE_DEFAULT_TIMEOUT_MS = 300_000;
    export const EXPLORE_DEFAULT_MAX_TURNS = 20;
    export const EXPLORE_MAX_TURNS_CAP = 40;

    export interface ExploreRequest {
      repoPath: string;
      question: string;
      model: string;
      maxTurns: number;
    }

    export interface ExploreOutcome {
      report: string;
      truncated: boolean;
      /** 'success' | 'max-turns' | 'error' — what the remote run actually did. */
      outcome: 'success' | 'max-turns' | 'error';
      detail?: string;
    }
    ```

    `buildExploreCommand(request: ExploreRequest): string` — one shell string, every
    model-supplied value through `escapeShellArg`:

    ```
    cd <escaped repoPath> && claude -p <escaped question> \
      --output-format json --allowedTools Read,Grep,Glob \
      --model <escaped model> --max-turns <n> --no-session-persistence \
      --append-system-prompt <escaped REPORT_CONTRACT>
    ```

    `REPORT_CONTRACT` (module constant, Vietnamese) instructs: answer only from files actually read;
    every finding cites `path:line`; list files read; list what could not be verified; keep the
    whole answer under 1500 words; output plain text, no markdown tables.

    `parseExploreResult(stdout: string): ExploreOutcome` — parse the last non-empty line as JSON.
    - Parse failure → `{ report: stdout.trim(), truncated: false, outcome: 'error', detail:
      'unparseable-output' }` (raw text is still useful).
    - `is_error === true` and `subtype === 'error_max_turns'` → `outcome: 'max-turns'`, report from
      `result ?? ''`, `detail` from `errors` joined.
    - `is_error === true` otherwise → `outcome: 'error'`, `detail` from `errors` or `subtype`.
    - Otherwise `outcome: 'success'`, report from `structured_output` if it is a string, else
      `result`, else `''`.
    - Apply the cap: if `report.length > EXPLORE_REPORT_MAX_CHARS`, slice and set `truncated: true`.

    `probeRemoteClaude(config, secret, deps?)` — runs `command -v claude >/dev/null 2>&1` through
    `execRemoteCommand`; returns `boolean` (exit 0). Cache per `config.id` in a module-level `Map`
    so a turn with several explore calls probes once. Export `resetRemoteClaudeProbeCache()` for
    tests.

    `runRemoteExplore(config, secret, request, deps?)` — `deps` is an optional seam
    `{ stream?: typeof execRemoteCommandStream; now?: () => number }` defaulting to the real
    functions. It:
    1. Calls `execRemoteCommandStream` with a `crypto.randomUUID()` session id.
    2. Accumulates stdout lines into a buffer (cap the buffer at 4 × the report cap so a runaway
       remote cannot exhaust memory; mark `truncated` when it overflows).
    3. Arms a `setTimeout(EXPLORE_DEFAULT_TIMEOUT_MS)` that calls the returned cancel handle and
       resolves with `outcome: 'error'`, `detail: 'timeout'`.
    4. Resolves on the exit event by calling `parseExploreResult(buffer)`; a non-zero exit status
       with an empty buffer resolves as `outcome: 'error'` with the stderr text as `detail`.
    5. Clears the timer and unsubscribes on every path.

    Do not add a Rust command. `ssh_exec_stream` and `ssh_kill_process` already exist and are the
    transport.

    Tests in `tests/services/remoteExploreService.test.ts` (`// @vitest-environment node`):
    - `buildExploreCommand` escapes a question containing `"`, `'`, `$(`, `;` — assert the WHOLE
      string equals the expected escaped form (the project's D-08 precedent: a containment check is
      vacuous because escaping preserves the payload text).
    - `buildExploreCommand` clamps `maxTurns` to `EXPLORE_MAX_TURNS_CAP` and floors below 1.
    - `buildExploreCommand` contains `--allowedTools Read,Grep,Glob`, `--no-session-persistence`,
      and `--output-format json`.
    - `parseExploreResult` for a success payload returns the `result` text.
    - `parseExploreResult` for `error_max_turns` returns `outcome: 'max-turns'`.
    - `parseExploreResult` caps an oversized report and sets `truncated: true`.
    - `parseExploreResult` on non-JSON returns the raw text with `outcome: 'error'`.
    - `runRemoteExplore` with a fake stream that emits two lines then exits resolves with the
      parsed report; the timer is cleared (assert with fake timers that no pending timer remains).
    - `runRemoteExplore` with a fake stream that never exits resolves after the timeout with
      `detail: 'timeout'` and calls the cancel handle (fake timers).
