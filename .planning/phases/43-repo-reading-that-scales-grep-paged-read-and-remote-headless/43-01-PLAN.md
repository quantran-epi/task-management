    Add to `src/services/gitRemoteService.ts` an exported function:

    ```ts
    export interface GrepRemoteRefOptions {
      pattern: string;
      /** Single repo-relative path or directory. Absent = whole tree. */
      path?: string | undefined;
      caseSensitive?: boolean | undefined;
      /** Default 50, clamped 1..200. */
      limit?: number | undefined;
      /** Literal string match (`-F`) instead of a basic regex. Default false. */
      literal?: boolean | undefined;
    }

    export async function grepRemoteRef(
      config: SshConfig,
      repoPath: string,
      ref: string,
      options: GrepRemoteRefOptions,
      secret?: string
    ): Promise<{ hits: RemoteGrepHit[]; truncated: boolean }>
    ```

    Build the command as ONE string and run it through `execRemoteCommand` (not `runGitCommand` —
    that helper throws on any non-zero exit and `git grep` exits 1 for "no matches", which is a
    valid empty result):

    ```
    git -C <escaped repoPath> -c core.fsmonitor=false --no-pager grep \
      -z -n -I --no-color [-F] [--no-ignore-case] -e <escaped pattern> \
      --end-of-options <escaped ref> [-- <escaped path>] | head -c 262144
    ```

    Details that matter, each verified against real git:
    - `-z` emits `path\0line\0content\n` per hit. Split stdout on `\0` in groups of three; the
      third element of each group ends with `\n` — strip it. A trailing incomplete group (the
      `head -c` cap) is dropped and sets `truncated: true`.
    - `--end-of-options` before the ref so a ref beginning with `-` is a revision, never an option.
    - `-e <pattern>` so a pattern beginning with `-` is a pattern.
    - `--no-ignore-case` when `caseSensitive` is true (the default); `-i` when false.
    - `-I` skips binary blobs.
    - Exit status 0 and 1 are both success. Any other status throws
      `new Error(res.stderr.trim() || 'git grep thất bại với exit code N')`.
    - Cap `limit` with `Math.min(Math.max(1, Math.floor(Number(limit)) || 50), 200)` and slice
      `hits` to it; a slice that dropped records also sets `truncated: true`.
    - `line` is parsed with `parseInt(..., 10)`; a record whose line is not a finite number is
      dropped rather than emitted as `NaN`.

    Do not add a second parser for the same output shape elsewhere.

    ```ts
      filePath: string;
      offset: number;
      limit: number;
      linesRead: number;
      totalLines: number;
      hasMore: boolean;
      isBinary: boolean;
      /** `cat -n` style: `<n>: <text>`, one entry per line. Empty when `isBinary`. */
      lines: string[];
    }
    ```

    Add to `src/services/gitRemoteTreeService.ts`:

    ```ts
    export async function readRemoteFilePage(
      config: SshConfig,
      repoPath: string,
      ref: string,
      filePath: string,
      offset: number,
      limit: number,
      secret?: string
    ): Promise<RemoteFilePage>
    ```

    Confinement and fallback reuse the existing code path — do not reimplement them:
    - `const cleanPath = confineRepoPath(filePath, 'Đường dẫn tệp');`
    - `const objectSpec = `${ref}:${cleanPath}`;`
    - Try the paged `cat-file` pipeline. On failure, if `isNotInRef(err, cleanPath, ref)` is true,
      run the same `ls-files --error-unmatch` probe `getRemoteFileContent` uses; exit 1 → paged
      read of the WORKING COPY; exit 0 or any other status → rethrow. On success → paged read of
      the working copy. Everything else rethrows.
    - The working-copy branch keeps the existing `realpath -e` root/target containment check and
      the `exit 77` → `PathOutsideRepoError` mapping, then pipes `cat -- "$target"` into the same
      `awk` pager.

    The pager, identical for both branches — one remote pass yields the page AND the total:

    ```
    awk -v s=<offset> -v e=<offset+limit-1> 'NR>=s&&NR<=e{print NR": "$0} END{print "###TOTAL "NR}'
    ```

    Parse: the last line starting with `###TOTAL ` is the total (strip the prefix, `parseInt`);
    every other line is a page line, kept verbatim (it already carries `<n>: `). `linesRead` is the
    count of page lines. `hasMore` is `offset + linesRead - 1 < totalLines`.

    Binary probe before the page, on the same blob:
    `git -C <repo> ... cat-file -p --end-of-options <spec> | head -c 1024 | od -An -tx1 | tr -s ' ' '\n' | grep -qx 00`
    Exit 0 means binary → return `isBinary: true`, `lines: []`, `linesRead: 0`, `totalLines: 0`,
    `hasMore: false`, without running the pager. Do the probe only when `offset === 1`; a later page
    of a file already known binary never reaches here.

    Clamp: `offset = Math.max(1, Math.floor(Number(offset)) || 1)`,
    `limit = Math.min(Math.max(1, Math.floor(Number(limit)) || 200), 2000)`.

    Leave `getRemoteFileContent` and `getRemoteWorkingFileContent` untouched — `RemoteFileViewer.tsx`
    needs whole-file reads for the editor, and they are not AI tool results.
