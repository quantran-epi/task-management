<objective>
Wire the six AI Office tables and the four chat-message attribution fields through the five-file backup contract, keeping the envelope at v11 and every new table optional-absent.

Purpose: D-34 (envelope stays v11; new tables optional-absent) and AIO-BACKUP-01. Backup is a five-file contract — `exportBackup.ts`, `types/backup.ts`, `validation/backupSchemas.ts`, `validateBackup.ts`, `restoreBackup.ts`. Missing any one is silent: data exports but vanishes on import, or a restore wipes rows it never received. `BackupChatMessageRecordSchema` is a plain `z.object`, so unknown keys are stripped by `safeParse` — attribution must be declared explicitly or it disappears on restore.
Output: updated backup types, schemas, export, validate and restore, plus `tests/services/backup/officeBackup.test.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-supplied backup file → canonical store | The highest-risk boundary in the app: an untrusted JSON file replaces local data |
| exported artifact → third-party storage | The backup may be uploaded to GitHub, so it must contain no secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-27 | Tampering | `restoreBackupPayload` | mitigate | Restore refuses any payload that fails `validateBackupPayload`; the existing pre-import snapshot is captured inside the transaction so a failed replace can be rolled back |
| T-34-28 | Information disclosure | exported AI Office rows | mitigate | No secret-bearing field exists on any new record; `persona` and `body` are the only free text, and `FORBIDDEN_BACKUP_KEYS` rejects `systemPrompt`/`prompt`/`token`/`secret` recursively |

| T-34-30 | Repudiation | restored message attribution | mitigate | `BackupChatMessageRecordSchema` declares `agentId`/`agentName`/`agentKind`/`messageKind` explicitly, so `safeParse` cannot strip them (Pitfall 6) |
| T-34-31 | Tampering | referential integrity of restored rows | mitigate | Validation rejects a member or link whose `teamId` names no team, a team whose `leadId` names no lead, and an employee whose `skillId` names no skill |
| T-34-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed; `git diff --stat package.json package-lock.json` must stay empty |
</threat_model>
