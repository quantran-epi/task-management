Create `src/services/ai/office/teamTools.ts`.

Define `TeamToolContext` as `{ db: TaskPlannerDatabase; teamId: string; threadId: string; agentId: string; skillId?: string }`. Every handler receives it as an argument. The team id and thread id come from the coordinator's request-bound state — no handler may read a team id, thread id or agent id out of the model-supplied `args`. Define `TeamToolRefusal` as `{ refused: true; code: TeamToolRefusalCode; message: string }` with `TeamToolRefusalCode` = `'TURN_NOT_IN_TEAM' | 'SKILL_NOT_ASSIGNED' | 'ITEM_NOT_LINKED' | 'AGENT_NOT_IN_ROSTER' | 'BATCH_TOO_LARGE'`. Mirror the artifact-tool refusal contract: a refusal is a returned value, never a thrown error.

`TEAM_TOOL_DEFINITIONS` is an `AiToolDefinition[]` with six entries. Vietnamese descriptions, matching the existing tool style:
- `search_team_history` — params `{ query: string, limit?: number }`. Description: tìm trong lịch sử nhóm bằng BM25 cục bộ.
- `read_team_turn` — params `{ turnId: string }`.
- `read_skill` — params `{}` (no arguments; the skill is the caller's assigned one).
- `list_linked_items` — params `{}`.
- `get_linked_context` — params `{ itemId: string }`.
- `delegate_batch` — params `{ assignments: Array<{ agentId: string, skillId?: string, task: string }> }`, with a description stating the cap of 3 and that the lead must wait for the whole batch.

`executeTeamTool(name, args, ctx)` dispatches on the normalized name and returns a JSON string.

`search_team_history`: read `buildTeamBm25Docs(ctx.threadId, ctx.db)`, call `rankBM25(query, docs, { limit: Math.min(Math.max(1, Number(limit) || 8), 20) })`, map each hit to `{ turnId: doc.id, agent: doc.title, timestamp: doc.updatedAt, kind: doc.tags[0], excerpt: extractRelevantSnippet(doc.body, query, 400) }`. Never return the full body — AIO-MEM-02 asserts the compact shape. Add a `ponytail:` comment noting `rankBM25` tokenizes the whole candidate set per call and that capping to the last 2 000 rows is the upgrade path if a transcript ever gets that large.

`read_skill`: when `ctx.skillId` is absent, return the `SKILL_NOT_ASSIGNED` refusal. Otherwise load the skill row and return `{ name, description, body }` with `body` verbatim. This is the only path by which a skill body ever reaches a model (D-24).

Then create `tests/services/ai/office/teamTools.test.ts` with a real `TaskPlannerDatabase`, a seeded team thread, and rows long enough that the excerpt is shorter than the body. Cover the eight behaviors.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model arguments → team data | A tool argument may name a turn, item or agent outside this team |
| linked note/document body → model context | User-authored content may contain instruction-like text |
| skill body → model context | Skill content is only ever released on demand |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-21 | Information disclosure | `read_team_turn`, `search_team_history` | mitigate | Team id and thread id come from `TeamToolContext` (request-bound), never from `args`; `getTeamTurn` additionally verifies `row.threadId === threadId`, so a model-supplied turn id cannot cross teams |
| T-34-22 | Information disclosure | `get_linked_context` | mitigate | `itemId` must be present in `listTeamLinks(ctx.teamId)` before any row is read; otherwise `ITEM_NOT_LINKED` |
| T-34-23 | Tampering | linked note/document body | mitigate | The handler returns raw data only; `teamPrompts.wrapUntrusted` is the single place that frames retrieved text as non-instructional, so the framing cannot be forgotten per tool |
| T-34-24 | Elevation of privilege | `delegate_batch` | mitigate | `agentId ∈ roster` and `length ≤ MAX_BATCH_SIZE` validated in the handler with structured refusals; the tool is lead-only and absent from `EMPLOYEE_READ_ONLY_ALLOWLIST`, so an employee cannot spawn a nested batch |
| T-34-25 | Denial of service (cost) | `search_team_history` | mitigate | `limit` clamped to 20 and the excerpt capped at 400 characters, so a search cannot dump the transcript into context |
| T-34-26 | Denial of service | `search_team_history` candidate set | accept | `rankBM25` tokenizes the whole thread per call; acceptable for a single-user personal transcript, documented with a `ponytail:` ceiling and a 2 000-row cap as the upgrade path |
| T-34-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed; `git diff --stat package.json package-lock.json` must stay empty |
</threat_model>
