<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → repository | Untrusted form input and model-derived ids enter the persistence layer |
| team A tool call → team B data | A tool argument could name a turn id from another team's thread |
| concurrent agent completions → member budget rows | Three agents finish at once and write usage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-06 | Tampering | `createTeam` / `addTeamMember` | mitigate | Zod `Schema.parse` at every entry; roster and activation caps enforced inside `db.transaction('rw', ...)` so a racing caller cannot exceed them |
| T-34-07 | Information disclosure | `getTeamTurn` | mitigate | Returns `undefined` unless `row.threadId === threadId`; the thread id is supplied by the caller's request-bound context, never by model arguments |
| T-34-08 | Tampering | `addUsedTokens` / `topUpMemberBudget` | mitigate | Single-row `update` on `aiTeamMembers`; no read-modify-write of a shared array, so concurrent completions cannot lose usage (D-32) |
| T-34-09 | Repudiation | `saveTeamMessage` | mitigate | Every row carries `agentId` + `messageKind`, so no message can be attributed to the wrong author after the fact |
| T-34-10 | Denial of service (cost) | `listAssignmentHistory` | mitigate | Hard cap `ASSIGNMENT_HISTORY_CAP` (50) prevents unbounded prompt growth across a long-lived team (D-29) |
| T-34-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed; `git diff --stat package.json package-lock.json` must stay empty |
</threat_model>
