# Phase 17 — UI Design Contract

> Visual and interaction contract for Phase 17 operational graph-projection surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope and Interaction Boundary

Phase 17 is server/projection-heavy. UI remains an operational inspection surface inside existing Docs publishing flow, not a graph product.

In scope:
- Extend existing `Bộ tài liệu xuất bản` detail drawer with compact graph projection status, validation summary, evidence-classification counts, quarantine/conflict counts, and rebuild action.
- Show graph build stage while candidate projection runs; preserve prior active graph until candidate succeeds.
- Let user inspect facts in a table/list with exact provenance and visible classification labels.
- Surface collision-safe URNs, extraction method, source document, heading path, and exact source range.
- Keep local Docs CRUD, autosave, folder navigation, and BM25 states unchanged when graph projection or Knowledge Server is unavailable.

Out of scope:
- Interactive graph canvas, node dragging, manual node/edge editing, free-form Cypher UI, graph search, hybrid retrieval, assistant citations, graph-path answer cards, corpus expansion, and approval authoring workflow.
- Direct Neo4j credentials or Neo4j connection controls in PlannerMate client.
- New top-level navigation route. Reuse existing Docs `Bộ tài liệu` drawer and publish-status flow.

Sources: Phase 17 CONTEXT D-01–D-22, Deferred Ideas; ROADMAP Phase 17 criteria; existing Phase 16 `DocumentSetDrawer`, `PublishPreviewModal`, and `PublishProgressPanel` patterns.

## Layout and Component Contract

### Placement

Visual hierarchy is fixed: graph status summary is primary visual focal point, followed by rebuild action, then evidence inspection. Status and safety must be understood before user acts or reviews individual facts.

1. Keep `Ghi chú & Tài liệu` page header and `Bộ tài liệu` button unchanged.
2. Add section `Đồ thị tri thức` in selected-set detail of existing 520px `DocumentSetDrawer`, after publish status/actions and before `Lịch sử xuất bản`.
3. Render graph status summary first as visually dominant card; place `Xây dựng lại đồ thị` directly after summary; place `Xem bằng chứng` and evidence details third.
4. Use Ant Design `Card` or bordered section, `Space direction="vertical"`, `Descriptions`, `Statistic`, `Tag`, `Alert`, `Button`, `Progress`, `Table`, and `Drawer`; no custom canvas library.
5. `Xem bằng chứng` opens nested/right inspection drawer, width 680px on desktop and 100% on viewport below 768px. It must not close parent set drawer or lose selected set.
6. Evidence fact list uses one row per semantic `factKey`, not one row per source occurrence. Expanding a row reveals every supporting/contradictory evidence occurrence.

### Graph status summary

Always show:
- Active graph snapshot identifier and activation timestamp, or explicit never-built state.
- Ontology version and extraction-rules version.
- Counts for nodes, semantic facts, evidence occurrences, conflicts, and quarantined identifiers.
- Current candidate stage when building: `Chuẩn bị`, `Trích xuất có cấu trúc`, `Trích xuất văn xuôi`, `Kiểm tra`, `Kích hoạt`.
- Prior active snapshot remains labeled `Đang hoạt động` throughout candidate build.

Primary states:

| State | Visual | Required text behavior |
|-------|--------|------------------------|
| Never built | neutral `CloudOutlined` tag | Explain published Markdown is source and graph has not been built |
| Building | processing tag + spinner/progress | State candidate is separate and prior active graph remains available |
| Active | success tag + `CheckCircleOutlined` | Show snapshot/version/time and counts |
| Active with warnings | warning tag + `WarningOutlined` | Keep active status visible; show conflict/quarantine counts and review action |
| Failed | error tag + `CloseCircleOutlined` | State candidate failed and previous active graph remains unchanged |
| Connectivity uncertain | warning `Alert` subordinate to primary state | Never relabel active graph as failed merely due to lost connection |

### Actions

- Primary CTA: `Xây dựng lại đồ thị`.
- CTA enabled only when selected set has an active published snapshot, Knowledge Server is configured/reachable enough to accept request, and no rebuild is active for that set.
- Before rebuild, use confirmation modal. Explain complete candidate rebuild from published Markdown, atomic promotion, and preservation of current active graph on failure.
- Starting rebuild must not republish local Markdown, run local DLP again, or imply unsaved/local changes are included. Rebuild consumes server-side active published snapshot only.
- While running, CTA becomes disabled loading button labeled `Đang xây dựng đồ thị`.
- `Kiểm tra trạng thái` retries reconciliation after connectivity loss; repeated clicks must not create duplicate builds.
- Secondary CTA: `Xem bằng chứng`; opens read-only inspection.
- Conflict and quarantine counters are links/buttons with text labels, not color-only affordances.

### Evidence inspection

Fact table columns, in order:
1. `Chủ thể` — canonical name, node-kind tag, full URN in tooltip/copy action.
2. `Quan hệ` — controlled relation label; operation/condition qualifier shown as compact neutral tag.
3. `Đối tượng` — canonical name, node-kind tag, full URN in tooltip/copy action.
4. `Phân loại` — explicit text tag.
5. `Bằng chứng` — occurrence count.
6. `Trạng thái` — clean, conflict, source missing, or quarantined candidate.

Expanded evidence occurrence displays:
- Document title/path.
- Exact heading path.
- `Dòng {start}–{end}` and source offsets when available.
- Extraction method: `Quy tắc có cấu trúc`, `Quy tắc định danh`, or `LLM văn xuôi`.
- Per-occurrence classification, environment metadata, confidence only for inferred candidates, and conflict branch label.
- Read-only source excerpt only when server contract safely returns it; otherwise location plus `Mở tài liệu nguồn`. Never fabricate excerpt from stale local content.

Classification presentation:

| Classification | Ant Design treatment | Icon/text contract |
|----------------|----------------------|--------------------|
| `OBSERVED` | blue/info tag | `Quan sát trực tiếp`; structured or explicit source statement |
| `INFERRED` | gold/warning tag | `Suy luận`; never hidden behind confidence score |
| `BUSINESS_APPROVED` | green/success tag | `Đã phê duyệt nghiệp vụ`; show approver and timestamp when available |

Conflict treatment:
- Red/error is reserved for contradiction/failure, not ordinary inferred evidence.
- Conflict row shows `Mâu thuẫn` text plus warning icon and both branches expanded together.
- Effective classification may be shown, but never replace per-evidence classifications or hide conflict.

Quarantine treatment:
- Quarantined identifiers appear only in warning inspection, never mixed into active fact rows or traversal counts.
- Show raw identifier, document, heading/range, method, and possible endpoint matches.
- Copy states `Chưa đủ thông tin để định danh duy nhất`; no merge/resolve control in Phase 17.

### Responsive behavior

- Desktop: 520px set drawer; 680px evidence drawer; fact table horizontal scroll at minimum 760px content width.
- Below 768px: both drawers use full viewport width; summary statistics become two columns; fact rows become stacked cards with same labels and expandable evidence.
- Do not squeeze URNs into unreadable columns. Truncate visually with ellipsis, preserve full value in accessible tooltip and copy button.
- Icon-only buttons have visible tooltip, accessible name, and minimum 44px touch target on mobile.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/tag gaps, evidence metadata separators |
| sm | 8px | Button groups, inline classification tags, compact row gaps |
| md | 16px | Card padding, section spacing, alert separation |
| lg | 24px | Drawer groups, modal body groups |
| xl | 32px | Major summary-to-evidence separation |
| 2xl | 48px | Empty-state canvas padding |
| 3xl | 64px | Page-level breathing room only; not inside 520px drawer |

Exceptions:
- Mobile icon-only touch targets: minimum 44px square.
- Standard Ant Design controls: 36px height from existing theme.
- Dense provenance rows: 20px minimum line box; content may wrap, never clip exact source location.
- Existing `PageHeader` 12px internal gap remains unchanged; do not create a new spacing token for it.

Source: existing app tokens/patterns plus default 8-point contract.

## Color

Use Ant Design semantic tokens so light/dark modes remain valid. Hex values define light-theme reference, not hardcoded component backgrounds.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8fafc` / `token.colorBgLayout` | App canvas and drawer surround |
| Secondary (30%) | `#ffffff` / `token.colorBgContainer` | Graph summary card, evidence list, expanded provenance surfaces |
| Accent (10%) | `#4f46e5` / existing `token.colorPrimary` | Rebuild CTA, selected evidence row, active inspection control, focus/selection highlight |
| Destructive / error | `#ff4d4f` / `token.colorError` | Failed candidate, contradictory evidence, destructive warning only |

Accent reserved for:
1. `Xây dựng lại đồ thị` primary button.
2. Selected fact/evidence row indicator.
3. Active segmented/tab control inside graph inspection.
4. Keyboard focus and selected technical identifier copy affordance.

Semantic colors:
- Success green `#52c41a`: active validated graph and `BUSINESS_APPROVED`.
- Info blue `#1677ff`: `OBSERVED`.
- Warning gold `#faad14`: `INFERRED`, quarantine, connectivity uncertainty.
- Error red `#ff4d4f`: candidate failure and conflict only.
- Neutral gray `#8c8c8c`: source missing, versions, timestamps, counts with zero value.

Never encode classification, conflict, graph state, or quarantine by color alone. Pair every color with label and icon where state-bearing.

## Accessibility and Interaction States

- Use semantic `section` headings and table headers; evidence expansion buttons expose `aria-expanded` and target relationship.
- Announce build accepted, stage changes, activation, failure, and connectivity uncertainty through existing `AriaLiveRegion`.
- Loading state does not block Docs editor or local search. Avoid full-page spinner.
- Modal focus starts on title/description, not destructive-looking confirm button. Escape/cancel before request closes modal with no rebuild; closing status UI after acceptance does not cancel server work.
- Preserve keyboard order: summary, rebuild/reconcile, evidence filters, table rows, row expansion, source actions.
- Copy buttons announce `Đã sao chép URN` or `Đã sao chép factKey`.
- Tooltips supplement visible labels; they never contain sole status/error explanation.
- Error, warning, success, classification, and conflict each use text plus icon/color.
