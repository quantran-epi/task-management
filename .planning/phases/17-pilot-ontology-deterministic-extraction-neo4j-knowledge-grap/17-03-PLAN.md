    1. Implement candidate merge engine in candidate.ts:
       - `mergeFactsDeterministicFirst({ deterministic, inferred, approvals })`:
         - Merges deterministic facts and validated inferred candidates.
         - Deduplicates facts using `factKey`: if the same semantic fact appears multiple times (e.g. from 01-wiring.md and 03-call-chain.md), create one `Fact` assertion and link all `EvidenceRecord` occurrences to it (D-04, D-14).
         - Conflict detection: checks functional relation slots (e.g. `USES_TYPE` for step+param, or single invoked target). If two facts assert conflicting objects in a functional slot, create a `ConflictRecord` linking both facts (D-12). For additive relations (`READS_FROM`, `WRITES_TO`, `CALLS`), multiple targets coexist without conflict.
         - Exact approval overlay: overlays approvals from durable ledger matching exact `factKey` (D-19).
         - Effective classification calculation: `BUSINESS_APPROVED > OBSERVED > INFERRED`, while preserving per-evidence classifications and conflict state (D-18).
         - Calculates `normalizedProjectionHash` over sorted canonical tuples of all entities and facts.
    2. Implement `GraphRepository` interface in graphRepository.ts:
       - `writeCandidate(candidate: GraphCandidate): Promise<void>`
       - `activateCandidate(setId: string, graphSnapshotId: string): Promise<void>`
       - `getActiveGraph(setId: string): Promise<ActiveGraphView | null>`
       - `getFacts(graphSnapshotId: string): Promise<FactDetail[]>`
       - `getQuarantines(graphSnapshotId: string): Promise<QuarantineRecord[]>`
       - Provide `InMemoryGraphRepository` for testing without live Neo4j.
    3. Implement `Neo4jRepository` in neo4jRepository.ts:
       - Uses `neo4j.driver` with connection pooling, authentication, and configured database name.
       - Parameterized static query maps (no string concatenation of Cypher clauses): uses `UNWIND $rows AS row` for batch insertion of entities, facts, evidence, conflicts, and controlled relationships.
       - Snapshot-scoped keys: `Entity.instanceKey = graphSnapshotId + ":" + urn`, `Fact.instanceKey = graphSnapshotId + ":" + factKey`. Direct relationship carries `factKey`, `graphSnapshotId`, and `defaultTraversable`.
       - Enforces uniqueness constraints on startup: `IF NOT EXISTS` constraints on `Entity(instanceKey)`, `Fact(instanceKey)`, `GraphSnapshot(graphSnapshotId)`.
       - Manages transactions cleanly: sessions closed in `finally` blocks; database operations isolated from model or filesystem side effects.
    4. In graphCandidate.test.ts and neo4jRepository.test.ts:
       - Test deduplication: repeated statements attach multiple evidence records to one factKey.
       - Test conflicts: conflicting cycle types (e.g. CYTP1002 vs CYTP1003 in same bind slot) produce a conflict record with both branches.
       - Test approvals: approval matching exact factKey upgrades effective classification to BUSINESS_APPROVED.
       - Test parameterized Cypher generation: verify parameters contain all values and Cypher strings are static constants.
  </action>
