    Implement durable snapshot storage, graph build orchestration, and rebuild tests (per D-19, D-20, D-21):
    1. Upgrade SnapshotStore in snapshotStore.ts:
       - Implement durable file-backed persistence for active snapshots using atomic write patterns (write to `.tmp`, then rename).
       - Ensure published snapshots survive daemon restarts without requiring client re-upload (Pitfall 1 in 17-RESEARCH).
       - Persist the durable human approval ledger separately so approvals survive graph wipe (D-19).
    2. Implement GraphBuildService in graphBuildService.ts:
       - Orchestrates the full graph projection pipeline:
         a. Retrieves the active published snapshot from SnapshotStore for the given setId.
         b. Initializes candidate build state with stage `Preparing`.
         c. Executes deterministic extraction (stage `Structured extraction`).
         d. Executes bounded prose fallback for uncovered segments (stage `Prose extraction`).
         e. Merges facts, deduplicates factKeys, links evidence, and detects conflicts (stage `Validation`). Apply D-20 lifecycle rule: if a factKey from the durable approval ledger no longer has matching source evidence in the current snapshot, retain the approved fact with `sourceMissing = true` and effective classification `BUSINESS_APPROVED`, while dropping any false `OBSERVED` claim and leaving supporting evidence list empty.
         f. Calculates normalizedProjectionHash.
         g. Writes candidate to Neo4j with state `READY` (inactive).
         h. Stale-source guard: verifies active sourceSnapshotId has not changed during candidate build.
         i. Executes atomic pointer swap in Neo4j in a single transaction (stage `Activation`):
            `MERGE (set:GraphSet {setId: $setId})`
            `MATCH (candidate:GraphSnapshot {graphSnapshotId: $graphSnapshotId, state: 'READY'})`
            `OPTIONAL MATCH (set)-[old:ACTIVE_GRAPH]->(previous)`
            `DELETE old`
            `SET previous.state = 'SUPERSEDED'`
            `MERGE (set)-[:ACTIVE_GRAPH]->(candidate)`
            `SET candidate.state = 'ACTIVE'`
         j. Updates build state to `Active` (or `Active with warnings` if conflicts or quarantines exist).
       - Failure handling: if any stage throws or fails validation, mark candidate as `Failed`. The prior active graph pointer remains completely unchanged (D-21).
    3. In graphRebuild.test.ts, test:
       - Atomic pointer swap: previous graph remains active until candidate activation completes.
       - Failure isolation: candidate with injected error fails while active graph remains identical to baseline.
       - Rebuild reproducibility: rebuilding twice from identical Markdown produces identical `normalizedProjectionHash`.
       - Stale guard: candidate build aborted if newer source snapshot activated while candidate was building.
       - Source disappearance retention (D-20): assert that when source evidence for an approved factKey is removed on rebuild, the approved fact persists with `sourceMissing = true` and `BUSINESS_APPROVED` retained, dropping its false `OBSERVED` status.
  </action>
