## 1. System Classification

**System Type:** Extraction

**Description:**
A deterministic-first TypeScript pipeline extracts closed-ontology facts from manually published Markdown and projects them into a rebuildable Neo4j knowledge graph. LLM use is limited to one bounded prose-only fallback call after structured tables, code, and explicit identifiers have been processed. Every inferred candidate must reference existing endpoints, pass strict runtime and semantic validation, and retain exact evidence provenance.

**Critical Failure Modes:**
1. LLM output overrides deterministic facts or is classified as `OBSERVED` without direct source evidence.
2. Composite identities collide across domain object types.
3. Graph relations lose source document, section, source range, extraction method, environment, or evidence classification.
4. Rebuilding from identical published Markdown produces a materially different graph.
5. Knowledge daemon absence or failure disrupts PlannerMate local behavior.

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds evaluation in process-analysis, data-lineage, and card-system evidence practice.

**Industry Vertical:** Financial-services card-processing operations and software/data lineage.

**User Population:** One developer/operator investigating process `60000006`, its container steps, software components, database objects, cycle types, statuses, and supporting Markdown documents.

**Stakes Level:** High. Graph output informs investigation and change reasoning, but remains advisory and rebuildable; it does not authorize production changes.

**Output Consequence:** Incorrect edges can misdirect impact analysis, hide contradictory evidence, or cause an operator to infer a false process or data dependency. Every result therefore needs inspectable provenance and evidence classification.

### What Domain Experts Evaluate Against

| Dimension | Good — expert accepts | Bad — expert flags | Stakes | Evidence basis |
|-----------|-----------------------|--------------------|--------|----------------|
| Identity separation | Source-native ID is namespaced by controlled object kind, such as `PRC_PROCESS:60000006` versus `PRC_CONTAINER:60000006` | Same numeric ID merges unrelated object types | Critical | Source table name/type plus exact identifier |
| Relation semantics | Relation type is in closed ontology and endpoint kinds satisfy relation domain/range | Free-text or impossible relation connects mismatched kinds | Critical | Ontology version and endpoint rules |
| Evidence fidelity | Exact immutable document occurrence, section, UTF-16 range, quote hash, extraction method, environment, and classification resolve to source | Missing, stale, mismatched, or reconstructed evidence | Critical | Published Markdown snapshot |
| Deterministic precedence | Structured tables, code, and explicit IDs are extracted before prose fallback and remain authoritative as `OBSERVED` | Model rewrites or downgrades deterministic facts | Critical | Extraction trace and consumed ranges |
| Conflict visibility | Contradictory assertions coexist with separate evidence and explicit conflict state | New assertion silently replaces old assertion | High | Fact/evidence comparison |
| Approval fidelity | `BUSINESS_APPROVED` applies only to exact unchanged `factKey` | Approval survives a changed endpoint, relation, or qualifier | Critical | Approval record keyed by exact fact identity |
| Rebuildability | Same Markdown, ontology, prompt version, and model/cache inputs produce same normalized projection | Graph becomes canonical or cannot be reconstructed | High | Golden rebuild comparison |

### Known Failure Modes in This Domain

- Numeric identifiers collide across `PRC_PROCESS`, `PRC_CONTAINER`, cycle, status, and other namespaces.
- SQL, package names, bind order, or table rows are paraphrased by an LLM and lose exact semantics.
- Environment-specific evidence from SIT, production, or manuals is merged without retaining environment context.
- Contradictory cycle-type or status claims overwrite each other instead of remaining inspectable.
- Model output invents an endpoint, unsupported relation, qualifier, or quote range.
- Removed source evidence leaves an unsupported edge active.
- A graph write partially succeeds and is promoted while SnapshotStore or source candidate remains unpromoted.
- Prompt injection inside Markdown is treated as an instruction instead of untrusted source data.

No direct automated decision or regulatory-reporting output is in scope. Apply least disclosure, data minimization, auditability, and secret-handling controls appropriate to financial-services internal documentation. Do not send unselected documents, credentials, runtime cardholder data, or operational secrets to model providers. Neo4j remains a derived projection, never canonical evidence.

## 2. Framework Decision

**Selected Framework:** Native TypeScript — no AI framework

**Version:** Node.js 24 native `fetch`; Zod 4.6.5; existing `unified`/`remark` Markdown pipeline

**Rationale:**
Phase 17 needs deterministic Markdown AST extraction, collision-safe identity generation, strict provenance, and one bounded prose fallback—not agent orchestration or RAG. Existing parsing libraries, Zod contracts, native `fetch`, and a thin graph repository keep control explicit. Framework abstraction would add unused machinery and weaken visibility into evidence handling.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LangChain.js 1.x | Adds abstractions and dependencies before provider switching, structured retries, tracing, or multi-step prose pipelines are proven needs. |
| LlamaIndex | Optimized for retrieval and document Q&A; Phase 17 builds a controlled extraction projection, not RAG. |
| Provider-specific SDK | User selected provider-neutral behavior; existing OpenAI-compatible 9router boundary already supplies the needed single-call interface. |

**Vendor Lock-In Accepted:** No. Preserve existing model-agnostic OpenAI-compatible 9router boundary.

### Selected Pattern

Native TypeScript pipeline. No AI framework, provider SDK, agent runtime, vector database, tracing SDK, or evaluation library. Use Node.js 24 native `fetch` for one non-streaming extraction request and Zod for runtime validation. Deterministic Markdown extraction always runs first.

### Entry Point Pattern

```typescript
export async function buildAndPromoteGraphCandidate(input: {
  snapshot: ProjectionSnapshot;
  graph: GraphRepository;
  proseClient: ProseExtractionClient | null;
  signal?: AbortSignal;
}): Promise<void> {
  const deterministic = extractDeterministicFacts(input.snapshot);
  const prose = collectUncoveredProse(
    input.snapshot,
    deterministic.consumedRanges,
  );
  const inferred = input.proseClient
    ? await extractProseCandidatesOnce({
        client: input.proseClient,
        segments: prose,
        resolvedEndpoints: deterministic.nodes,
        signal: input.signal,
      })
    : quarantineDisabledFallback(prose);

  const candidate = mergeFactsDeterministicFirst({ deterministic, inferred });
  validateGraphCandidate(candidate);
  await input.graph.writeCandidate(candidate);
  await input.graph.activateCandidate(candidate.snapshotId);
}
```

Model and Neo4j work must finish before existing candidate promotion. A failure leaves prior active projection unchanged.

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|------------|-----------------|
| `OntologyVersion` | Versioned closed node kinds, relation types, endpoint rules, and qualifier allow-lists | Extraction, validation, hashing, graph writes, tests |
| `ResolvedNode` | Collision-safe URN plus controlled kind and canonical metadata | Deterministic endpoint creation from exact source IDs |
| `FactAssertion` | Subject URN, controlled relation, object URN, semantic qualifiers, `factKey`, classification | Semantic fact independent of evidence occurrence |
| `EvidenceRecord` | Document, occurrence, exact UTF-16 range, quote hash, method, environment, classification | Every supporting or contradictory occurrence |
| `GraphCandidate` | Complete derived graph for immutable snapshot, including conflicts and quarantines | Validate before atomic active-pointer promotion |

### Fact Identity

```typescript
export function buildFactKey(input: {
  ontologyVersion: string;
  subjectUrn: string;
  relation: RelationType;
  objectUrn: string;
  qualifiers: Readonly<Record<string, string>>;
}): string {
  const qualifiers = Object.entries(input.qualifiers)
    .sort(([left], [right]) => left.localeCompare(right))
    .map(([key, value]) => `${key}=${value}`)
    .join('');

  return sha256Hex([
    input.ontologyVersion,
    input.subjectUrn,
    input.relation,
    input.objectUrn,
    qualifiers,
  ].join(''));
}
```

Source range, confidence, extraction method, classification, and environment belong to evidence records, not `factKey`.

### Common Pitfalls

1. Sending complete Markdown to model before tables, code, and explicit identifiers are extracted.
2. Treating `temperature: 0` or `seed` as deterministic across OpenAI-compatible providers.
3. Trusting model offsets or quotes without exact JavaScript `slice()` equality.
4. Allowing model output to create endpoints, choose `OBSERVED`, or choose `BUSINESS_APPROVED`.
5. Replacing deterministic facts instead of attaching evidence or recording conflict.
6. Streaming partial JSON for structured extraction.
7. Retrying malformed output and violating one-call budget.
8. Calling model or Neo4j externally inside a retryable Neo4j transaction callback.
9. Logging prompts, source prose, raw model output, credentials, or Neo4j parameters.

## 4. Implementation Guidance

### Model Configuration

```text
NINE_ROUTER_ENDPOINT=http://localhost:20128
NINE_ROUTER_API_KEY=<server-local secret; optional if router requires none>
NINE_ROUTER_MODEL=<operator-selected model ID returned by /v1/models>
```

Do not hard-code provider model names, provider hostnames, or provider SDKs.

| Setting | Value | Reason |
|---------|-------|--------|
| Endpoint | `${normalizedEndpoint}/v1/chat/completions` | Existing 9router contract |
| `model` | Required configured ID | Provider-neutral routing |
| `stream` | `false` | Validate complete JSON |
| `max_tokens` | `1200` | Bounded output |
| `temperature`, `seed` | Omit | Unsupported or non-deterministic across providers |
| Tools | Omit | No tool execution needed |
| Timeout | 30 seconds | Bounded publication latency |
| Calls | At most one per candidate snapshot | Cost and behavior ceiling |
| Input prose | At most 12,000 UTF-16 code units | Bounded context without tokenizer assumption |
| Candidates | At most 40 | Bounded graph mutation |
| Raw response | At most 100,000 characters | Memory/malformed-response guard |

### Strict Output Contract

```typescript
import { z } from 'zod';

export const RELATION_TYPES = [
  'CONTAINS_STEP', 'PRECEDES', 'CALLS', 'INVOKES', 'READS_FROM',
  'WRITES_TO', 'EMITS', 'CONSUMES', 'USES_TYPE', 'HAS_STATUS',
] as const;

export const ProseCandidateSchema = z.strictObject({
  subjectUrn: z.string().trim().min(1).max(500),
  relation: z.enum(RELATION_TYPES),
  objectUrn: z.string().trim().min(1).max(500),
  qualifiers: z.strictObject({
    operation: z.string().trim().min(1).max(120).optional(),
    condition: z.string().trim().min(1).max(240).optional(),
  }).default({}),
  evidence: z.strictObject({
    segmentId: z.string().min(1).max(128),
    startOffset: z.number().int().nonnegative(),
    endOffset: z.number().int().positive(),
    quote: z.string().min(1).max(2_000),
  }),
  confidence: z.number().min(0).max(1).optional(),
});

export const ProseExtractionOutputSchema = z.strictObject({
  candidates: z.array(ProseCandidateSchema).max(40),
});
```

Model cannot supply new nodes, `factKey`, classification, extraction method, absolute range, ontology version, approval state, or effective classification. Server derives them.

### Provider-Neutral Adapter

Use small server-local `ProseExtractionClient` backed by native `fetch`. Normalize endpoint exactly as existing 9router client does. Send system and user messages separately. Require one choice with string content, bound response size before `JSON.parse`, validate envelope with Zod, and map failures to stable content-free error codes. Do not import browser/Tauri code into `knowledge-server`.

### Core Pattern

Fixed order:

1. Parse immutable Markdown with existing MDAST pipeline.
2. Extract tables, code blocks, explicit identifiers, bind order, statuses, and controlled relations in source order.
3. Resolve namespaced URNs and emit `OBSERVED` evidence.
4. Record consumed source ranges.
5. Collect only uncovered prose paragraphs.
6. Select complete segments under fixed input ceiling.
7. Make zero or one LLM request.
8. Validate JSON schema, endpoint existence, ontology domain/range, qualifiers, and exact evidence slice.
9. Assign `LLM_PROSE` and `INFERRED` server-side.
10. Merge deterministic facts first; retain conflicts.
11. Sort normalized nodes, facts, and evidence.
12. Validate, write, and activate candidate graph.

Unsupported structured content is quarantined for deterministic-rule development, not reinterpreted as prose.

### Exact Evidence Validation

```typescript
const segment = segmentsById.get(candidate.evidence.segmentId);
if (!segment) throw new Error('LLM_UNKNOWN_SEGMENT');
if (!resolvedUrns.has(candidate.subjectUrn)) throw new Error('LLM_UNKNOWN_SUBJECT');
if (!resolvedUrns.has(candidate.objectUrn)) throw new Error('LLM_UNKNOWN_OBJECT');

const { startOffset, endOffset, quote } = candidate.evidence;
if (startOffset >= endOffset || endOffset > segment.text.length) {
  throw new Error('LLM_EVIDENCE_RANGE_INVALID');
}
if (segment.text.slice(startOffset, endOffset) !== quote) {
  throw new Error('LLM_EVIDENCE_QUOTE_MISMATCH');
}
```

JavaScript `slice()` and unist offsets use UTF-16 code units. Revalidate absolute immutable-document range before persistence.

### Deterministic-First Merge Precedence

1. Insert deterministic nodes and `OBSERVED` facts.
2. Validate every inferred candidate independently.
3. Recompute `factKey` server-side.
4. Exact matching fact adds separate `INFERRED` evidence; it does not alter observed assertion.
5. Contradictory object or qualifier retains both facts and creates conflict record.
6. Structured assertion remains `OBSERVED`; prose assertion remains `INFERRED`.
7. Quarantined candidates create no active nodes or edges.
8. Effective classification order is `BUSINESS_APPROVED > OBSERVED > INFERRED`.
9. Conflict state remains visible regardless of classification precedence.
10. Default traversal includes clean `OBSERVED` and `BUSINESS_APPROVED` facts only.

### Tool Use

No LLM tools or function calls. Fallback receives only ontology version, allowed relations and qualifiers, existing endpoint URNs/kinds, bounded prose segments, and required JSON shape. It receives no credentials, filesystem, shell, Neo4j access, full corpus, or mutation authority.

### State Management

Markdown remains canonical. Persist only rebuildable graph state: snapshot IDs, ontology/extraction versions, nodes, facts, evidence, conflicts, approvals keyed by exact `factKey`, quarantines, tombstones, and exact-input fallback cache.

Fallback cache key includes model, prompt version, ontology version, sorted segment IDs/content hashes, and sorted endpoint URNs. Cache only strictly validated normalized output. Cache is disposable.

Neo4j writes use parameterized Cypher, uniqueness constraints, bounded idempotent transactions, model calls outside transaction callbacks, candidate snapshot isolation, atomic active-pointer update, session cleanup in `finally`, and driver shutdown on server exit.

### Error Handling

| Failure | Result |
|---------|--------|
| Deterministic parser, identity, ontology, or provenance failure | Fail candidate; keep prior active snapshot |
| LLM timeout, HTTP error, malformed JSON, schema failure, invalid range, unknown endpoint | Zero retries; quarantine batch; emit content-free warning |
| Fallback disabled or model missing | Promote deterministic graph with warning when otherwise valid; quarantine eligible prose |
| Context exceeds ceiling | Include whole segments deterministically; quarantine overflow; no second call |
| Neo4j write/validation/activation failure | Fail candidate; keep prior active graph and SnapshotStore |
| Secret, prompt, raw model output, or source text in exception | Replace with stable error code before logging/storage |
| Caller abort | Stop HTTP work; do not activate candidate |

### Context Window Strategy

No tokenizer-specific assumptions. Exclude consumed structured content, select full prose paragraphs in stable source order, enforce 12,000 UTF-16 input characters and 1,200 output tokens, never truncate evidence segments, never summarize source before extraction, and quarantine overflow. Multi-call extraction requires a later explicit design decision.

### Testing Guidance

Use existing Vitest setup. Mock `ProseExtractionClient`, not provider behavior. Run smallest relevant tests only.

Required cases include namespaced identity collision, deterministic zero-call path, at-most-one fallback call, omitted sampling/provider fields, strict unknown-key rejection, exact UTF-16 evidence including surrogate pairs, unknown endpoint/relation quarantine, conflict retention, no retry, cache/rebuild stability, Neo4j rollback behavior, evidence removal, and exact approval retention.

## 4b. AI Systems Best Practices

### Structured Outputs with Zod

Pydantic is Python-specific. Zod 4.6.5 is the TypeScript boundary validator.

```typescript
export function parseProseExtractionOutput(rawContent: string) {
  let decoded: unknown;
  try {
    decoded = JSON.parse(rawContent);
  } catch {
    throw new Error('LLM_OUTPUT_NOT_JSON');
  }

  const parsed = ProseExtractionOutputSchema.safeParse(decoded);
  if (!parsed.success) {
    throw new Error('LLM_OUTPUT_SCHEMA_INVALID');
  }
  return parsed.data;
}
```

Use `z.strictObject()` at every model-controlled level. Do not strip Markdown fences or repair malformed JSON. After schema validation, validate ontology, endpoints, qualifiers, exact source slices, and immutable-document range. Perform zero model retries.

### Async-First Design

```typescript
const signal = callerSignal
  ? AbortSignal.any([callerSignal, AbortSignal.timeout(30_000)])
  : AbortSignal.timeout(30_000);

const result = await proseClient.completeJson({
  model,
  messages,
  maxTokens: 1_200,
  signal,
});
```

Await model and graph work before promotion. Keep current per-set serialization. Do not use unbounded `Promise.all()`. Use non-streaming requests for extraction. Never perform HTTP work inside retryable graph transaction callbacks.

### Prompt Engineering Discipline

System prompt holds immutable behavior and safety rules; user message contains ontology data, resolved endpoints, prose segments, and output shape. Treat Markdown as untrusted data. Require supplied URNs, closed relations, one exact contiguous quote, zero-based UTF-16 offsets with exclusive end, raw JSON only, and empty candidates when evidence is insufficient. Version prompt text. Do not add few-shot examples until evals prove a recurring failure.

### Context Window Management

Run deterministic extraction first. Exclude consumed tables/code/IDs. Preserve full paragraph boundaries and exact MDAST positions. Sort segments deterministically. Quarantine overflow rather than summarizing, random sampling, or splitting evidence. Do not include chat history, graph traversal output, unrelated documents, runtime sample rows, or hidden full-document context.

### Cost and Latency Budget

| Metric | Budget |
|--------|--------|
| Model calls per candidate | `0..1` |
| Timeout | 30 seconds |
| Retries | 0 |
| Supplied prose | 12,000 UTF-16 code units |
| Completion limit | 1,200 tokens |
| Candidate count | 40 |
| Raw response | 100,000 characters |
| Default-traversable LLM-only facts | 0 |

Record provider-reported usage, latency, cache hit, model ID, prompt version, candidate count, and stable error code. Never invent usage when 9router omits it. Use exact-match caching only; semantic caching is prohibited for evidence extraction.

## 6. Guardrails

### Online (Every Candidate / Request)

| Guardrail | Trigger | Blocking Intervention |
|-----------|---------|-----------------------|
| Deterministic-first boundary | Candidate contains tables, code, explicit identifiers, or structured ranges | Extract first; mark every range consumed or quarantined and exclude it from LLM input. Parser, identity, ontology, or provenance failure fails graph candidate. |
| Bounded fallback boundary | Eligible uncovered prose exists | Permit zero or one non-streaming request under ceilings. On overflow, timeout, provider error, malformed output, or abort, perform no retry; quarantine prose and allow only validated deterministic graph. |
| LLM candidate validation | Unknown field, endpoint, relation, qualifier, endpoint-kind pair, range, or quote | Quarantine candidate/batch before merge. Assign `LLM_PROSE` and `INFERRED` server-side. Invalid output creates no graph or traversal state. |
| Active graph integrity | Duplicate URN, uncontrolled kind, invalid `factKey`, unresolved endpoint, incomplete provenance, invalid classification, or quarantined edge | Reject complete candidate before write/activation; keep prior active projection. |
| Merge and conflict | Prose matches or contradicts deterministic/existing evidence | Matching semantics add evidence. Contradictions retain both facts and explicit conflict. Silent replacement/evidence loss rejects complete candidate. |
| Approval lifecycle | Approval carries into rebuild or evidence disappears | Carry only unchanged `factKey`; mark approved source loss `sourceMissing = true`, remove stale observed classification, remove unsupported unapproved facts. Violation rejects activation. |
| Rebuild drift | Same immutable inputs and versions already have result | Compare canonical `normalizedProjectionHash`; mismatch fails candidate and keeps prior active projection. |
| Atomic promotion | Validation, graph write/activation, or SnapshotStore promotion fails | Expose neither candidate pointer; keep both prior active pointers usable. Partial writes stay inactive. |
| Content-safe telemetry | Event contains selected Markdown/title/quote, prompt, raw output, credentials, response body, or Neo4j parameters | Drop/replace prohibited fields before any sink receives event. |
| Optional-daemon isolation | Daemon or Neo4j disabled, unreachable, or absent | Fail only knowledge publication/projection path; preserve PlannerMate local behavior. |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|--------|-------------------|----------------------|
| Inferred precision/recall | Full pilot dataset each change | Fix deterministic rule, ontology, prompt, or validator before release |
| Quarantine reason distribution | Every candidate snapshot, counts only | Investigate repeated reason; prefer deterministic rule addition |
| Conflict rate | Review all new conflicts in pilot | Confirm source contradiction; never auto-resolve |
| Rebuild drift | Every relevant test run | Block promotion/release |
| Fallback error/timeout rate | Every call, content-free metrics | Disable fallback if unstable; retain deterministic graph |
| Human rejection of inferred facts | Review all Phase 17 inferred candidates | Tighten prompt/schema/ontology; add fixture |

## 7. Production Monitoring

**Tracing Tool:** Existing structured logs and metrics only; no external tracing dependency in Phase 17. Telemetry allow-list: timestamps, durations, counts, booleans, ontology/extractor/prompt versions, HTTP status class, provider-reported usage, cache status, stable error/quarantine codes, and one-way identifiers. Never log or persist selected Markdown, document titles, source quotes, prompts, raw model output, credentials, HTTP response bodies, or Neo4j parameters.

**Key Metrics to Track:**
- Deterministic fact count, inferred candidate count, accepted/quarantined count by stable reason.
- Model call count, cache-hit count, latency, HTTP status class, and provider-reported token usage.
- Conflict count and approval count.
- Candidate build/write/activation duration and failure stage.
- Rebuild projection hash and active snapshot ID.

**Alert Thresholds:**
- Any active fact with invalid evidence, endpoint, relation, or classification: block promotion immediately.
- Rebuild hash mismatch on frozen inputs: block release.
- More than one model call per candidate: test failure/block release.
- Model timeout/error rate above 20% over last 10 calls: disable fallback and investigate.
- Neo4j activation failure: keep prior active projection and surface operator warning.
- Any PlannerMate local-function regression while daemon absent: block release.

**Smart Sampling Strategy:** Human-review every `INFERRED`, conflict, and newly `BUSINESS_APPROVED` fact during pilot. After pilot, sample all low-confidence/quarantined patterns plus any fact from new document shapes; do not sample away critical validation failures.
