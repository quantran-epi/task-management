  <behavior>
    - `buildResearchPrompt(questions: string[], systemCode: string): string` — instructs strict JSON output `{ summary, findings: [{ claim, scope, source, confidence }] }` per D-04, names the system code, and forbids editing files.
    - `buildResearchCommand(remoteRepoPath: string, prompt: string, includeWeb: boolean): string` — returns the exact remote command string, and is the only place that string is built (so it is unit-testable without a live SSH stream). Shape: `cd <escapeShellArg(remoteRepoPath || '.')> && exec claude -p <escapeShellArg(prompt)> --output-format json --allowedTools <tools>`.
      - `exec` goes on `claude`, not on `cd`: `cd` is a shell builtin, so `exec cd …` replaces the shell with the builtin and exits before the rest of the list runs. With `exec` on `claude`, the shell that `echo $$` reported becomes the claude process, so the PID stored in `SshStreamRegistry` is the one `ssh_kill_process` must signal — no forked child is orphaned.
      - No `sh -c` layer anywhere in the returned string: `channel.exec` already runs it through the remote login shell, and a nested `sh -c '…'` would be terminated early by the single quotes `escapeShellArg` emits.
      - `--allowedTools` is `WebSearch,WebFetch,Glob,Grep,Read`; when `includeWeb` is false it is `Glob,Grep,Read`.
    - `renderResearchMarkdown(payload: ResearchPayload): string` — a Markdown report with a summary section and one row per finding carrying `[EXTERNAL:WEB]` or `[EXTERNAL:REPO:{code}]`, its source, and its confidence.
    - `executeMultiSystemResearch(options): { promise: Promise<ResearchPayload>; cancel: () => Promise<void> }` — the cancel handle is part of the return value, never a side channel.
    - Options: `{ changeRequestId: string; threadId: string; sessionId: string; targetSystemIds: string[]; questions: string[]; includeWeb?: boolean; onLog: (line: string) => void; db?: TaskPlannerDatabase; timeoutMs?: number; now?: () => string }`. Key everything by `changeRequestId` — the same key `assertProjectThread` and `loadLatestResearchArtifact` use.
    - Availability pre-flight via `checkResearchAvailability`; unavailable entries go into `payload.skippedSystems` and each is `onLog`-ed as a Vietnamese line naming the system code and reason.
    - If every target is unavailable, reject with `ResearchRunError('RESEARCH_UNAVAILABLE', ...)`.
    - Per available system, sequentially: `getSystem`, `getSshConfigById(system.sshConfigId, db)`, then `buildResearchCommand(system.remoteRepoPath || '.', buildResearchPrompt(options.questions, system.code), options.includeWeb !== false)`.
    - `execRemoteCommandStream` is called with the resolved `SshConfig`; the cancel handle it returns is held in a **closure-local** variable inside `executeMultiSystemResearch` — never a module-level `activeCancel`. Two concurrent runs (two step panels, or a retry while the prior run is settling) would otherwise overwrite each other's handle and `cancel()` would stop the wrong run, producing exactly the orphaned process D-02 exists to prevent.
    - **SSH failure mapping:** if `execRemoteCommandStream` throws, or the exit event it delivers has a non-null `error`, reject with `ResearchRunError('RESEARCH_SSH_ERROR', ...)` after cancelling. A dropped connection must never resolve with partial data (D-03). This requires the `onExit: (event: SshStreamExitEvent) => void` signature from plan 01 — a zero-argument callback cannot see the error.
    - Timeout default 300_000 ms: on expiry call `cancel()` then reject with `ResearchRunError('RESEARCH_TIMEOUT', ...)`; clear the timer on settle.
    - `cancel()` is idempotent and settles the promise with `ResearchRunError('RESEARCH_CANCELLED', ...)`; no artifact is persisted on cancel or error.
    - On success, persist with `saveResearchArtifact({ changeRequestId, threadId, sessionId, inputRevision: 0, draftRevision: 0, inputHash: await defaultSha256(JSON.stringify(payload)), markdown: renderResearchMarkdown(payload), exportPayload: payload, approvedAt: options.now?.() ?? new Date().toISOString() }, db)`.
    - `sessionId` must be a real RFC 4122 v4 UUID — `SdlcArtifactMetadataSchema` validates it with `uuidSchema` (`wizardSchemas.ts:6`), so tests seed a UUID literal.
  </behavior>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-03 | Tampering / Code Execution | `researchService.ts::buildResearchCommand` | mitigate | `escapeShellArg` applied to both the prompt and `remoteRepoPath` before interpolation; the command is handed to the remote login shell unwrapped (no `sh -c`), so the escaping is consumed exactly once. |
| T-32-04 | Tampering | Remote git repository | mitigate | `--allowedTools` is pinned to `WebSearch,WebFetch,Glob,Grep,Read`; `Write`, `Edit`, and `Bash` are never granted. |
| T-32-02 | Denial of Service | Remote host process table | mitigate | The closure-local cancel handle from `execRemoteCommandStream` is invoked on timeout, user cancel, and SSH failure; `exec` on `claude` keeps the captured PID pointing at the real process, so no run is abandoned mid-flight. |
| T-32-SC | Tampering | npm packages | accept | No new npm dependencies. |
