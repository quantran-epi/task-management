  <behavior>
    - Define `SshStreamRegistry` with thread-safe `active_processes: Mutex<HashMap<String, u32>>` (mapping session_id to remote pid).
    - Implement `ssh_exec_stream(app, config, secret, session_id, command)` using non-PTY channel exec. It takes no `State` parameter: the managed registry is resolved inside the reader thread from the cloned `AppHandle`.
    - The reader thread must resolve the registry from the cloned `AppHandle` (`app_handle.state::<SshStreamRegistry>()`) — `State<'_, T>` is a borrowed guard and cannot be moved into a `'static` thread closure.
    - The `ssh2::Session` must be moved into the reader thread alongside the channel; dropping it at the end of the command closes the channel and truncates output.
    - Wrap remote execution with `sh -c 'echo "$$" && exec <command>'` to capture remote process PID on first stdout line.
    - Read subsequent stdout lines via `BufReader::new(channel).lines()` and emit Tauri events `ssh-stream:data:{session_id}`.
    - After stdout EOF, drain `channel.stderr()` and emit any non-empty lines with `stream: "stderr"`.
    - On stream EOF or channel close, remove PID from registry and emit `ssh-stream:exit:{session_id}` carrying `SshStreamExitEvent`.
    - Implement `ssh_kill_process(registry, config, secret, session_id)` looking up PID and executing `kill -TERM <pid>` over SSH.
    - Register `SshStreamRegistry::default()` state and commands in `src-tauri/src/lib.rs`.
  </behavior>
  <action>
    Per D-01 and D-02:
    1. In `src-tauri/src/ssh_service.rs`, declare `SshStreamRegistry` struct with `pub active_processes: std::sync::Mutex<std::collections::HashMap<String, u32>>`.
    2. Add `SshStreamEvent` struct with fields `session_id: String`, `stream: String` ("stdout" | "stderr"), `line: String`, and `#[serde(rename_all = "camelCase")]`.
    3. Add `SshStreamExitEvent` struct with fields `session_id: String`, `exit_status: i32`, `error: Option<String>`, same serde rename.
    4. Implement `ssh_exec_stream` command:
       - `connect_and_auth(&config, secret.as_deref())`, then `channel_session()`.
       - Wrap the command as `sh -c 'echo "$$" && exec <command>'` and `channel.exec(...)`.
       - Clone `AppHandle` and `session_id`; move **both** `session` and `channel` into the spawned thread so the SSH session outlives the read loop.
       - Inside the thread call `let registry = app_handle.state::<SshStreamRegistry>();` — import `tauri::Manager` for `.state()`. Do NOT take or capture a `State<'_, _>` argument; it is a borrowed guard and does not satisfy `'static`.
       - First stdout line parses as `u32` PID and is inserted into `registry.active_processes`.
       - Remaining lines emit `ssh-stream:data:{sid}` with `SshStreamEvent { stream: "stdout" }`.
       - After stdout EOF, read `channel.stderr()` to a `String`, emit each non-empty line with `stream: "stderr"`.
       - Remove the PID, then emit `ssh-stream:exit:{sid}` with `SshStreamExitEvent { exit_status: channel.exit_status().unwrap_or(-1), error: None }`.
    5. Implement `ssh_kill_process` command: remove pid from `registry.active_processes`, open a fresh channel, run `kill -TERM <pid>`, `wait_close()`.
    6. In `src-tauri/src/lib.rs`: add `.manage(ssh_service::SshStreamRegistry::default())` and add `ssh_service::ssh_exec_stream` and `ssh_service::ssh_kill_process` to `tauri::generate_handler!`.
