<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller args → folder writes | `teamName` and `agentName` originate from user- or model-authored rows and become note titles |
| stored `docsFolderId` → tree writes | A persisted id may name a deleted, trashed, or non-folder note |
| concurrent backfill runs | Two coordinator turns may reach `ensureTeamDocsReady` for the same team |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigate / rationale |
|-----------|----------|-----------|-------------|----------------------|
| T-41-05 | Tampering | `createMemberFolder` title | mitigate | The title is passed to `createNote`, which runs `NoteInputSchema.parse` — `title` is `.trim().max(120)`. A name that cannot fit is a validation error, not a silently truncated folder. The suffix loop is capped so a hostile roster cannot spin. |
| T-41-06 | Tampering | `ensureTeamDocsReady` idempotency | mitigate | The `docsFolderId` re-read and the `isLiveFolder` check both happen INSIDE the `rw` transaction over `[aiTeams, aiTeamMembers, notes, settings]`, so two concurrent runs serialise on the same rows and the second observes the first's write. A check outside the transaction would allow two trees. |
| T-41-07 | Tampering | `docsFolderId` naming a foreign live folder | mitigate | `isLiveFolder` requires `type === 'folder'` and no `deletedAt`. A hand-edited or restored id pointing at a live folder the team does not own is still treated as the team folder — accepted, because the id can only arrive through a backup restore or a direct Dexie edit, both of which already require local write access to the app's own database. The consequence is bounded: the next `deleteTeam` would delete that folder's children. Recorded as accepted risk, not mitigated further, because the alternative (a per-team ownership marker on every note) adds a table the phase forbids. |
| T-41-08 | Denial of service | `deleteTeamDocsTree` breadth | accept | The tree is at most three levels and one level of children is read, so the delete is bounded by the roster size. No recursion, no unbounded scan. |
| T-41-09 | Elevation of privilege | folder `type` | mitigate | Every folder this module creates passes a literal `type: 'folder'`; no caller-supplied type reaches `createNote`. Agents cannot reach this module at all (plan 41-04). |
| T-41-SC | Tampering | npm/pip/cargo installs | accept | No package install in this phase. |
</threat_model>
