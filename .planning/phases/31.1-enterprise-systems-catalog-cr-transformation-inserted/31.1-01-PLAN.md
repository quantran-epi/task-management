<objective>
Establish database schema migration SCHEMA_V15 for Enterprise Systems Catalog and Change Request (CR) transformation per ENT-SYS-01 and ENT-CR-01.

Purpose: Upgrade Dexie TaskPlannerDatabase to version 15, introducing the `systems` table for hierarchical enterprise systems/subsystems (with SSH/repo properties) and transitioning the `projects` domain entity to `changeRequests` (with 3 explicit types and multi-system targeting) while guaranteeing seamless data migration, task backward-compatibility, and encrypted backup safety.
Output: SCHEMA_V15 migration, System and ChangeRequest models, Zod validation schemas, systemRepo, changeRequestRepo, backup export/restore integration, and unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IndexedDB Schema Migration | Upgrade from V14 to V15 must not corrupt or drop existing project, milestone, or task data |
| Backup Restore | Restoring backup payloads containing systems and changeRequests must validate schemas before transaction commit |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31.1-01 | Tampering | Dexie version(15).upgrade hook | mitigate | Use safe transaction read from projects and copy to changeRequests with fallback defaults; do not drop projects table prematurely |
| T-31.1-02 | Denial of Service | Foreign key orphan cascade | mitigate | Retain projectId on Task entity matching ChangeRequest id so tasks never become unreachable |
| T-31.1-03 | Information Disclosure | Backup payload export | mitigate | SshConfig credentials remain excluded or secret-stripped; systems table only references sshConfigId |
</threat_model>
