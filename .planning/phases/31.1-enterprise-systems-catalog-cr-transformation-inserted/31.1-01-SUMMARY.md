# Phase 31.1 Plan 01: Enterprise Systems Catalog & CR Transformation Schema & Repositories Summary

**One-liner:** Upgraded Dexie TaskPlannerDatabase to SCHEMA_V15 with `systems` and `changeRequests` tables, automatic project migration, full CRUD repositories, and encrypted backup/restore safety.

## Key Changes

1. **Database Schema & Migration (SCHEMA_V15)**:
   - Extended Dexie schema in `src/db/schema.ts` with `systems: 'id, &code, parentId, type, sshConfigId, createdAt'` and `changeRequests: 'id, &code, status, type, createdAt, updatedAt'`.
   - Updated `TaskPlannerDatabase` in `src/db/index.ts` with version 15 upgrade hook that copies all existing `projects` records into `changeRequests` with default `type: 'ENHANCEMENT'`, `targetSystemIds: []`, and preserved timestamps.
2. **Domain Models & Zod Schemas**:
   - Added `SystemType = 'LOGICAL_GROUP' | 'SERVICE' | 'SCHEMA' | 'UI' | 'WORKER'` and `System` entity model to `src/types/models.ts`.
   - Added `CrType = 'NEW_FEATURE' | 'ENHANCEMENT' | 'BUGFIX'`, `CrStatus`, and `ChangeRequest` entity model to `src/types/models.ts`.
   - Added `SystemTypeSchema`, `SystemInputSchema`, `SystemUpdateSchema`, `CrTypeSchema`, `CrStatusSchema`, `ChangeRequestInputSchema`, and `ChangeRequestUpdateSchema` to `src/validation/schemas.ts`.
3. **Repositories**:
   - `src/db/repositories/systemRepo.ts`: Implemented `createSystem`, `updateSystem`, `getSystem`, `getAllSystems`, `getParentSystems`, `getSubsystems`, and `deleteSystem` (with child subsystem safeguards).
   - `src/db/repositories/changeRequestRepo.ts`: Implemented `createChangeRequest`, `updateChangeRequest`, `getChangeRequest`, `getAllChangeRequests`, `getChangeRequestsBySystem`, and `deleteChangeRequest` (with project cascade compatibility).
4. **Backup Integration**:
   - Added `systems` and `changeRequests` to `BackupTableData` and `BackupTableCounts` in `src/types/backup.ts`.
   - Added `BackupSystemRecordSchema` and `BackupChangeRequestRecordSchema` in `src/validation/backupSchemas.ts`.
   - Updated `exportBackupPayload`, `restoreBackupPayload`, and `validateBackupPayload` to serialize, validate, restore, and snapshot both tables.
