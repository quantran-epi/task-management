<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frozen outbound snapshot -> IndexedDB cache | User content must reduce to document IDs and submitted SHA-256 hashes only |
| Daemon POST response -> local attempt identity | Untrusted response IDs select durable reconciliation state |
| Backup JSON -> restored attempt cache | Untrusted import may inject malformed or content-bearing manifest fields |
| IndexedDB reopen -> resumed polling | Cached manifest must remain validated before it can drive active metadata replacement |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-23-01 | Tampering | accepted attempt/set identity | mitigate | Require response set ID match and strict UUID/hash parsing before cache write |
| T-16-23-02 | Tampering | `submittedDocuments` | mitigate | Reject duplicate document IDs, preserve order, and prevent status writes from erasing retained manifest |
| T-16-23-03 | Information Disclosure | frozen manifest cache/backup | mitigate | Persist IDs and SHA-256 hashes only; strict schemas reject body/title/tag/token/DLP fields |
| T-16-23-04 | Repudiation | close/reload recovery | mitigate | Key durable manifest by authoritative accepted attempt ID and retain attempt timestamps/metrics |
| T-16-23-05 | Denial of Service | backup restore | mitigate | Validate bounded manifest entries before existing atomic restore transaction |
| T-16-23-SC | Tampering | npm supply chain | mitigate | Use existing Dexie, Zod, Web Crypto-produced hashes, and Vitest; add no dependency |
</threat_model>
