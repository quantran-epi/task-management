<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser origin → independent daemon | CORS is browser boundary; bearer auth is authority boundary. |
| Untrusted JSON → attempt service | Payload must validate and remain bounded. |
| Daemon state → client manifest | Response must be sufficient for preview but content-free. |

| Threat ID | Category | Severity | Component | Disposition | Mitigation and verification |
|---|---|---:|---|---|---|

| T-16-29 | Tampering | High | Request/response DTO | mitigate | Strict Zod before processing and before response emission. |
| T-16-30 | Information Disclosure | Critical | Logs/errors | mitigate | Logger redaction and safe envelopes; seeded-secret negative assertions. |
| T-16-31 | Denial of Service | High | Request body/parser | mitigate | JSON body cap plus atomic 50,000 block guard downstream. |
| T-16-32 | Information Disclosure | High | Snapshot manifest | mitigate | IDs/hashes/ranges/policy only, no body/token/DLP details; schema test. |
| T-16-SC | Tampering | Medium | npm runtime | mitigate | Uses only `[OK]` audited packages from 16-04. |
