<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Canonical user text → DLP engine | Sensitive local text enters security-critical pure scanning logic. |
| Internal raw regex match → UI finding | Complete values must become non-reversible masked context before leaving scanner internals. |
| Findings → audit persistence | Only content-free aggregate metadata may cross persistence boundary. |

## STRIDE Threat Register

| Threat ID | Category | Severity | Component | Disposition | Mitigation and verification |
|---|---|---:|---|---|---|
| T-16-08 | Information Disclosure | Critical | Outbound DLP coverage | mitigate | Typed assembly scans set name, every title/body/tag; category and field-coverage tests prove no user text field is omitted. |
| T-16-09 | Elevation of Privilege | Critical | DLP override semantics | mitigate | Scanner/audit expose no trust, suppress, allow-list, or persistence API. Fresh UI confirmation is enforced in Plan 06 and tested there. |
| T-16-10 | Information Disclosure | High | Findings/audit/logs | mitigate | Raw matches remain internal; category masks plus negative serialized-secret tests. No console logging. |
| T-16-11 | Tampering | High | Finding locations/overlap | mitigate | Original-source offsets, Unicode/CRLF tests, fixed precedence, and stable ordering prevent misleading duplicate/shifted warnings. |
| T-16-SC | Tampering | Low | Package installs | accept | Native regex and existing test stack only. |
</threat_model>
