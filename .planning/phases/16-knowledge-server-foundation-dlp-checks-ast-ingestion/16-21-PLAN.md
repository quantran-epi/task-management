<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Daemon attempt resource -> local cache | Untrusted terminal status and activeSnapshotId drive local projection metadata |
| Durable submitted manifest -> active IndexedDB metadata | Content-free frozen IDs/hashes become active only after authoritative success |
| Mutable local Notes -> status derivation | Current Markdown may mark Local changes but must never rewrite submitted/published hash |
| Network observation -> server state | Observer loss must not fabricate terminal failure or cancel accepted work |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-21-01 | Tampering | `reconcileRemoteAttempt` | mitigate | Strict-parse set/attempt/snapshot relationships and exact manifest-to-replacement equality before one Dexie transaction |
| T-16-21-02 | Information Disclosure | `publishAttempts` / `publishedDocuments` | mitigate | Persist IDs, SHA-256 hashes, timestamps, and state only; no body/title/tag/token/excerpt |
| T-16-21-03 | Repudiation | resumed async attempt | mitigate | Resume by server attempt ID and retained submitted manifest; keep bounded timestamps/metrics |
| T-16-21-04 | Denial of Service | poll loop | mitigate | Existing bounded exponential delay and AbortSignal; network loss returns uncertainty instead of endless tight loop |
| T-16-21-05 | Tampering | failed candidate or later local edit | mitigate | Never replace active metadata unless explicit `In sync`; use retained submitted hashes, never live Notes, per D-10/D-14 |
| T-16-21-SC | Tampering | npm supply chain | mitigate | Use existing Dexie, Zod, fetch, AbortController, and Vitest; add no dependency |
</threat_model>
