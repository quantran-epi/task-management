## Information Architecture & Layout

### Document Set Management Drawer

1. **Drawer header:** title `Bộ tài liệu xuất bản`; subtitle `Quản lý nhóm tài liệu gửi thủ công đến Knowledge Server.`; primary button `Tạo bộ tài liệu`.
2. **Set list:** each item shows set name, member count, exact primary state badge, last successful publish time, and `Mở chi tiết`. One item per row; no card grid.
3. **Set detail:** back control, editable set name, ordered member list, `Thêm tài liệu`, drag/reorder controls with keyboard alternatives `Đưa lên` / `Đưa xuống`, remove control, current remote snapshot summary, and publish history.
4. **Footer actions:** secondary `Lưu thay đổi`; primary `Xem trước xuất bản`. Disable preview when set has zero members, server configuration is invalid, or same set has active attempt. Local member editing remains available while offline or during another set's publish.
5. **History:** latest 10 attempts, newest first. Each row exposes timestamp, duration, added/changed/removed/unchanged counts, DLP warning count, terminal status, and concise error summary. Never render body content, sensitive matches, or DLP excerpts in history.
6. **Primary focal point:** in both empty and populated list states, make `Tạo bộ tài liệu` the drawer's strongest visual action; set rows and `Mở chi tiết` remain secondary.

### Create/Edit Set

- Name is required, trimmed, and limited to 120 characters.
- Initialization choices use radio controls: `Bộ trống`, `Từ thư mục hiện tại`, `Chọn tài liệu`.
- Folder initialization captures one explicit snapshot. Supporting copy: `Tài liệu thêm hoặc di chuyển sau này không tự thay đổi bộ này.`
- Member selection uses searchable checkbox list grouped by folder. Every row shows document title and parent path; stable UUID remains available only in tooltip/details, not primary copy.
- Save is local and never starts publishing.

### Publish Flow

Use one modal sequence. Modal width 760px desktop, `calc(100vw - 32px)` mobile. Preserve frozen-at-confirmation semantics in copy.

1. **Preview:** title `Xem trước thay đổi`; summary counters in order `Thêm`, `Thay đổi`, `Gỡ khỏi máy chủ`, `Không đổi`. Below counters, use tabs and document rows. Removed rows get warning styling and copy `Tài liệu cục bộ vẫn được giữ nguyên.` No content-bearing request occurs here. The preview change summary is the primary focal point throughout the pre-publish flow; place it immediately below the title and above tabs, findings, and confirmation controls.
2. **Removal gate:** if removals exist, require checked checkbox `Tôi hiểu các tài liệu này sẽ bị gỡ khỏi ảnh chụp trên máy chủ, không bị xóa khỏi PlannerMate.` before continuing.
3. **DLP scan:** after user selects `Kiểm tra dữ liệu nhạy cảm`, show local progress with `Đang kiểm tra dữ liệu trên thiết bị…`. This step completes before publish is enabled.
4. **No findings:** show success result `Không phát hiện dữ liệu nhạy cảm theo bộ quy tắc hiện tại.` Primary action becomes `Xuất bản bộ tài liệu`.
5. **Findings:** show warning modal section with count, fixed ruleset version, and table/list containing category, document title, `Dòng {line}, cột {column}` when available, and masked context only. Never offer reveal/copy-full-value controls. Require fresh unchecked checkbox `Tôi đã xem cảnh báo và vẫn muốn xuất bản lần này.` Primary danger-emphasis action label `Vẫn xuất bản lần này`; `Hủy xuất bản` sends zero content.
6. **Accepted attempt:** freeze displayed member/content snapshot, POST once with idempotency key, close preview, and show publishing state in set detail. Do not block local editing.

### Publishing Progress & Recovery

- Set state stays `Publishing` until explicit terminal server result.
- Show stage text without fake precision: `Đã gửi ảnh chụp`, `Đang phân tích Markdown`, `Đang tạo ảnh chụp ứng viên`, `Đang kích hoạt` when server reports it; otherwise use `Đang xử lý trên máy chủ` with spinner.
- Provide `Đóng` only. Helper: `Đóng bảng không hủy tiến trình trên máy chủ.` No cancel button after POST acceptance.
- Connection loss renders warning `Mất kết nối — chưa xác định kết quả. PlannerMate sẽ đối chiếu lại khi có mạng.` beneath `Publishing`; never switch to `Failed` from timeout/offline alone.
- Reopen/reload resumes inspection from cached attempt and reconciles by `attemptId` when online.
- If server returns `SET_PUBLISH_IN_PROGRESS`, show `Bộ tài liệu này đang được xuất bản. Mở trạng thái hiện tại để theo dõi.` with action `Mở trạng thái`.
- Success toast: `Đã xuất bản bộ tài liệu.` If user edited a member after snapshot freeze, resulting state remains `Local changes`, with helper `Lần xuất bản vừa hoàn tất dùng ảnh chụp trước chỉnh sửa mới nhất.`
- Failed attempt shows `Ảnh chụp trước vẫn đang hoạt động.` followed by server error and actionable remedy. Oversized block error includes document, exact line/column, 50.000-character limit, and `Chia nhỏ bảng hoặc khối mã trong tài liệu nguồn rồi thử lại.`

### Status Badges

Use exact primary states; Vietnamese visible labels below. Color never stands alone: every badge includes icon plus text and accessible tooltip.

| Canonical state | Visible label | Ant Design semantic treatment | Icon | Behavior |
|-----------------|---------------|-------------------------------|------|----------|
| Never published | Chưa xuất bản | default / neutral | `CloudOutlined` | No active server snapshot |
| In sync | Đã đồng bộ | success | `CheckCircleOutlined` | Local hash equals active snapshot |
| Local changes | Có thay đổi cục bộ | processing / primary | `EditOutlined` | Manual publish available |
| Publishing | Đang xuất bản | processing with spinner | `LoadingOutlined` | Second attempt for same set disabled |
| Warning | Cảnh báo | warning | `WarningOutlined` | Inspect warning or partial operational issue |
| Failed | Thất bại | error | `CloseCircleOutlined` | Prior active snapshot remains intact when one exists |

- In `DocListPane`, place compact badge in metadata footer before updated date. Use text at widths >= 1100px; icon plus tooltip below that width.
- In `DocEditorPane`, place status beside save status in footer. Local auto-save remains visually separate: `Đã lưu` describes IndexedDB, publish badge describes server projection.
- One document in multiple sets: show aggregate status priority `Failed`, `Warning`, `Publishing`, `Local changes`, `In sync`, `Never published`; tooltip lists each set and state.
- `Warning` is not connectivity uncertainty. Connectivity warning remains subordinate message under `Publishing`.

### Responsive Contract

- >= 1200px: preserve existing folder/list/editor columns; drawer overlays from right.
- 768–1199px: keep current Docs layout; status badges may collapse to icon plus tooltip; publish preview remains single-column within modal.
- < 768px: set-management drawer fills viewport; modal fills available width; preview counters wrap 2×2; member and finding rows stack labels over values; primary actions stay visible in sticky footer.
- Controls use existing 36px height; icon-only controls expose `aria-label`, tooltip, and minimum 36×36px hit area. Destructive/sensitive confirmation actions use at least 44px height on mobile.

- DLP findings use `colorWarning` surfaces/borders and warning icon. Override button uses danger emphasis because it knowingly sends flagged content; warning never exposes unmasked values.
- `In sync` uses `colorSuccess`; `Failed` uses `colorError`; neutral state uses `colorTextSecondary`/default Tag.
- Every semantic color pairs with icon and text. Meet WCAG AA 4.5:1 body text and 3:1 large text/icons/boundaries.
- Dark mode derives from Ant Design tokens. Do not hard-code light surfaces in new components.

## Interaction & State Contract

### Configuration

- `Bật Knowledge Server` defaults off. Disabled state leaves local Docs CRUD, auto-save, folder navigation, and BM25 search untouched.
- Base URL label `URL Knowledge Server`; placeholder `https://knowledge.internal.example`; normalize trailing slash; derive `/api/v1` silently.
- Reject non-HTTPS remote URLs. Allow `http://localhost` and loopback addresses for local development only, with warning `HTTP chỉ được phép cho máy cục bộ.`
- Session token label `Token phiên`; password input with reveal control; helper `Chỉ giữ trong bộ nhớ và sẽ mất khi tải lại ứng dụng.` Never offer remember-token toggle.
- `Kiểm tra kết nối` is secondary and reports distinct success, authentication, CORS, invalid URL, and unreachable states. Connection test sends no document content.

### Loading, Empty, and Error States

- Initial drawer load: skeleton list, not blank surface.
- Empty set list: centered `Empty` with heading/body contract below and primary CTA.
- Empty member list: inline empty `Bộ tài liệu chưa có thành viên.` with `Thêm tài liệu`.
- Empty history: `Chưa có lần xuất bản nào.`
- Unconfigured server: non-blocking info `Chưa cấu hình Knowledge Server.` with `Mở cài đặt`; local Docs stays enabled.
- Offline/unreachable server: cached statuses remain visible with `Dữ liệu trạng thái gần nhất: {absolute timestamp}`. Do not clear badges or history.
- No changes preview: `Không có thay đổi để xuất bản.` Disable publish and offer `Đóng`.
- All async failures render next action. Never show raw stack traces, bearer token, document body, request payload, or raw DLP match.

### Keyboard & Accessibility

- Drawer and modal use Ant Design focus trap and restore focus to trigger on close.
- Member list supports keyboard selection and reorder buttons; drag is optional, never sole method.
- Escape closes pre-send preview/DLP modal and invokes `Hủy xuất bản` with zero content sent. After accepted POST, Escape only closes progress surface and does not cancel server attempt.
- DLP table has accessible caption `Phát hiện dữ liệu nhạy cảm đã che`; category and location are text, not icon-only.
- Publish status changes announce through existing `AriaLiveRegion`: scan complete, confirmation required, attempt accepted, connection uncertain, success, or failure.
- Polling does not steal focus or repeatedly announce unchanged status. Announce only transitions.

### Data Safety

- Removing member from local set editing is reversible until save. If member existed in active remote snapshot, preview calls it `Gỡ khỏi máy chủ`; local document remains untouched.
- No permanent document deletion belongs to this flow.
- DLP confirmation is per attempt and resets whenever preview closes, payload changes, scan reruns, or new attempt starts.
- History and audit display/persist categories and counts only; masked context exists only in current pre-send UI and must not enter history.
