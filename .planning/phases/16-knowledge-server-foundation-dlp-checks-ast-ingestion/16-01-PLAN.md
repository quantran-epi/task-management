## Trust Boundaries

| Boundary | Description |
|---|---|
| Existing V9 IndexedDB → V10 migration | Canonical local documents cross a schema upgrade that must not rewrite content. |
| Remote-status cache → local UI | Server-owned status is cached locally but must remain non-canonical and content-free. |

| Threat ID | Category | Severity | Component | Disposition | Mitigation and verification |
|---|---|---:|---|---|---|
| T-16-01 | Tampering | High | `SCHEMA_V10` migration | mitigate | Add stores only; migration test seeds Unicode/CRLF Markdown and asserts exact Note equality after upgrade. Verify with `npm test -- tests/knowledge/schemaV10.test.ts`. |
| T-16-02 | Information Disclosure | High | `PublishAttemptCache` / `dlpAudits` | mitigate | Schemas omit body, excerpt, matched value, token, and payload fields and use strict objects. Tests attempt forbidden fields and require rejection. |
| T-16-03 | Spoofing | Medium | Cached remote state | mitigate | Name/cache fields as last-known state and preserve server IDs/timestamps for later reconciliation; no cache field can activate server state. Repository behavior follows in Plan 02. |
| T-16-SC | Tampering | Low | Package installs | accept | No package install occurs in this plan. |
</threat_model>
