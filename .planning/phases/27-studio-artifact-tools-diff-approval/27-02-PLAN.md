## Host contract for wave 3

Add optional `artifactToolContext?: ArtifactToolContext` and `onApplyArtifactPatch?: (proposal: ArtifactPatchProposal, decision: ChatMessage) => Promise<void>` to StepChatPanelProps. The latter validates live identity/base, writes draft and approved decision atomically where persistence exists, then publishes host state. It rejects without changing editor on draft-write failure. Build the proposed approved decision row in StepChatPanel and pass it to this callback; do not independently save it afterward. Reject saves only a decision row using existing database transaction/repository capabilities. No callback means approval cannot proceed; render actionable unavailable message rather than acknowledging a write.

Decision rows use existing ChatMessage shape: stable runtime-generated UUID id retained across retries, current threadId, role `system`, content starting `ARTIFACT_PATCH_DECISION ` followed by proposalId, kind, sectionId, decision and newline plus exact UI-SPEC copy, normal createdAt. This is an internal transcript marker, not a new persisted schema. No diff, full document, raw tool arguments, or pending proposal is stored in the row. Render these rows through transcriptExtensions with human-readable copy only; filter them out of ordinary message bubbles and LLM history. Remaining runtime cards stay visible during the current scope; after remount persisted rows retain the decision even though pending payloads are gone.
