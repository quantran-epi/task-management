# Phase 27 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of this phase's UI:** one new surface — the artifact-diff approval card inside the shared `AiChatWidget` (new component extending the `MutationApprovalCard` pattern) — plus refusal/decision messaging in the SDLC `StepChatPanel` lane and transcript decision records. `get_artifact` itself has no dedicated UI: it appears only as an entry in the existing tool-activity list. No new screens, no new design system.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (approve patch, D-02) | Chấp thuận |
| Secondary CTA (reject patch, D-02/D-04) | Từ chối |
| Card title (pending, D-02) | Đề xuất chỉnh sửa: {tiêu đề mục} |
| Card meta line (D-02) | {kind} · phiên bản {version} · mục {sectionId} |
| Diff stat (D-02) | +{N} dòng thêm · −{N} dòng xóa |
| Stale warning (D-03) | Tài liệu đã thay đổi sau khi đề xuất này. Bản diff bên dưới chỉ để tham khảo — yêu cầu AI đề xuất lại trong khung chat. |
| Stale approve button | Chấp thuận (disabled, unchanged label — tooltip: Không thể áp dụng vì tài liệu đã thay đổi) |
| Resolved-approved record | Đã chấp thuận — bản nháp bước này đã được cập nhật. |
| Resolved-rejected record (D-04) | Đã từ chối đề xuất — tài liệu không thay đổi. |
| Refusal: preview/historical read-only (D-10) | Chỉ được phép chỉnh sửa ở phiên bản đang hoạt động. Đang xem phiên bản xem trước/lịch sử — hãy quay về phiên bản hiện tại để đề xuất chỉnh sửa. |
| Refusal: missing prerequisite (D-10, reuses 26 guard copy) | Chưa đủ điều kiện: Thiếu {Tên tài liệu} từ Bước {N}. Vui lòng hoàn thành bước trước để tiếp tục. — with action button `Chuyển đến Bước {N}: {Tên bước}` |
| Refusal: oversized patch (D-09) | Đề xuất quá lớn ({N} dòng thay đổi, giới hạn {cap}). Yêu cầu AI chia nhỏ thành nhiều chỉnh sửa theo từng mục. |
| Error state (patch write failure on approve) | Không thể cập nhật bản nháp: {mô tả lỗi}. Bản nháp hiện tại vẫn nguyên vẹn — thử chấp thuận lại hoặc gửi yêu cầu mới trong khung chat. |

Hard copy rules:
- **Approving never claims a version commit, approval state, or a save.** Approved wording is "bản nháp … đã được cập nhật" (draft updated) — never "đã lưu", "đã phê duyệt", "đã commit phiên bản".
- Reject copy states the editor is untouched; no reason dialog, no forced retry turn (D-04).
- Refusals name what was refused and why, with a next action — never a generic exception string (D-10).

No new destructive actions. Reject needs no confirmation (it writes nothing). Approve needs no confirmation modal (the diff on the card IS the confirmation). Clear-thread confirmation is unchanged from Phase 26.

## UI Component Contract Specifications

### 1. Artifact-diff approval card — new `ArtifactDiffApprovalCard` in `src/components/ai/widget/`

Purpose: satisfy D-01, D-02, D-03 (everything needed to decide without opening the editor).

- Extends the `MutationApprovalCard` visual DNA (icon header, right-aligned button row, radius 8) but uses a **neutral** container, because the diff itself carries semantic green/red and the warning treatment must stay available for stale state.
- Container: `padding: 16px`, `backgroundColor: token.colorBgContainer`, `border: 1px solid token.colorBorderSecondary`, `borderRadius: 8`, `margin: '8px 0 16px'`, column flex, `gap: 8`. When **stale**: border and background switch to `token.colorWarningBorder` / `token.colorWarningBg`.
- Header row (D-02): `ExclamationCircleOutlined`-class icon slot → use `DiffOutlined` (@ant-design/icons) in `token.colorPrimary`, title `Đề xuất chỉnh sửa: {section title}` at 14px/600, single-line ellipsis.
- Meta line (D-02): 12px, `token.colorTextSecondary`, `{kind} · phiên bản {version} · mục {sectionId}`.
- Diff stat (D-02): 12px chips — `+{N} dòng thêm` on added-line green background, `−{N} dòng xóa` on removed-line red background, `padding: '2px 8px'`, radius 8.
- Diff body (D-01): the unified diff rendered **verbatim** — parse with the existing `parseGitDiff` (`src/utils/gitDiffParser.ts`) or render raw lines; either way `+`/`-`/context prefix chars stay visible. Monospace 12px, line-height 20px, `maxHeight: 240`, `overflowY: auto`, `overflowX: auto`, `whiteSpace: 'pre'`. Line backgrounds per the diff palette in §Color. Diff gutter (line numbers, optional) uses gutter background — line numbers are optional, prefix markers are mandatory.
- Button row: right-aligned `Space size={8}`, `marginTop: 4` — `Từ chối` (default button, NOT `danger` when pending? No: match `MutationApprovalCard` — `danger` reject, primary approve). Stale state: approve `disabled`, reject remains enabled.
- Resolved state: buttons removed; card renders the decision record line (12px, icon + copy from Copywriting Contract) — approved uses `CheckCircleOutlined` + `token.colorSuccess`, rejected uses `CloseCircleOutlined` + `token.colorTextSecondary`. The record stays in the transcript; it survives re-render (runtime-owned pending-card state must persist across widget re-renders per CONTEXT discretion).

### 2. Turn flow and parking — `AiChatWidget` (D-07, D-08)

- One card per `patch_artifact_section` result; cards queue in tool-call order and resolve one at a time.
- While a card is pending, the turn sits in the existing `awaiting-approval` state — no spinner, staged loader shows `Chờ phê duyệt` only, composer disabled exactly as mutation approvals do today.
- Approving/rejecting resolves that card and surfaces the next queued one; the turn resumes only after the queue empties.
- Staleness check per card is against the draft as of that card's own tool call (D-08) via the existing `workflowCoordinator` draft state — no new staleness mechanism.

### 3. Refusal surfaces — `StepChatPanel` (D-10)

- Refusals render as inline `Alert type="warning" showIcon` in the chat lane at the tool's transcript position — never a fake assistant bubble, never raw JSON, never a thrown error toast.
- Missing-prerequisite alert includes the `Chuyển đến Bước {N}` action wired to the existing `onNavigateToStep` callback (same as Phase 26 §2).
- Oversized-patch alert states actual count vs cap and the split instruction; the model also receives the structured result so it can propose a split itself.
- Alerts are runtime-only: not persisted as assistant messages; dismissed on step change or thread clear.

### 4. Tool activity — carried, no layout change

- `get_artifact` and `patch_artifact_section` appear as `ToolEventBadge` entries in the existing activity list (`[Công cụ] get_artifact` etc., 12px, `colorFillAlter` background). `get_artifact` results must NOT dump full Markdown into the expanded detail — cap detail output the same way other tools do (the full artifact lives in the editor, not the transcript).

### 5. Unchanged surfaces (do not restyle)

- `MutationApprovalCard` (data-mutation card) keeps its warning treatment — the diff card is a separate component, no merge.
- `StagedLoadingIndicator`, `ArtifactEventCard`, quick-prompt chips, toolbox bar, `ResizeSplitter`, step views: Phase 25.3/26 layout unchanged.
- The SDLC editor itself is only ever changed by the approve handler through the existing `extractArtifactDraft`/`onArtifactDraft` path — the editor never receives patch text directly from the tool.

## Interaction Contract (acceptance-relevant)

| ID | Contract |
|----|----------|
| UI-27-01 | Every `patch_artifact_section` result renders an approval card; the editor draft changes only via Approve (SDLC-ART-02, ART-03). |

| UI-27-04 | Reject records only the decision; no reason dialog, no forced retry turn, editor untouched (D-04). |
| UI-27-05 | A stale card keeps its old diff, shows the warning strip, and has Approve disabled; re-proposal happens only through chat (D-03, D-08). |

| UI-27-07 | The diff renders verbatim, monospace, green/red backgrounds, inside a max-height scroll region that never stretches the chat lane (D-01). |
| UI-27-08 | All three refusals (read-only version, missing prerequisite, oversized patch) render as actionable Vietnamese alerts naming the refusal and the next action — never a generic exception (D-10). |
| UI-27-09 | Decisions survive widget re-render and remain visible in the transcript after resolution. |
| UI-27-10 | No text in any Phase 27 surface renders below 12px. |
