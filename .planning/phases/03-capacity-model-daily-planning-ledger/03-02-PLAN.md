      In a Dexie transaction on [db.plannedAllocations, db.tasks]:

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User UI → Allocation Repository | Task allocations with hours, minutes, and target dates enter data layer |
| Task Status → Load Calculations | Task completion state dictates inclusion or exclusion from capacity calculations |
| Allocation Mutation → Invariant Guard | Multi-table transactions maintain unique task/date constraints |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02 | Tampering / State Inconsistency | allocationRepo.upsertAllocation | mitigate | Enforce unique constraint per (taskId, date) using transactional check-and-update to prevent duplicate ledger entries (D-12) |
| T-03-03 | Elevation / Logic Error | allocationRepo.getAllocationsForDate | mitigate | Strictly check task.status; exclude 'Done' and 'Cancelled' tasks from active load sums to avoid false capacity overload alerts (PLAN-05, D-16) |
| T-03-04 | Denial of Service | TaskDrawerPlanning / AllocationModal | mitigate | Bound allocation minute values to 1-1440 (24h max per day); restrict multi-date allocation queries to target task UUID |
| T-03-SC | Tampering | npm dependencies | mitigate | Zero external package additions; native Web Crypto and existing libraries used exclusively |
</threat_model>
