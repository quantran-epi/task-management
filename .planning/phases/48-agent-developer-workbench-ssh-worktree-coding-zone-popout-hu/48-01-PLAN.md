<objective>
Build the backend and team-tool foundation for the Agent Developer Workbench: one Agent Developer roster member with a role-gated, worktree-confined code-edit capability, backed by SSH-native remote git commands with mandatory server-side path confinement. No UI in this plan.

Purpose: D-07/D-08/D-09/D-10 are the hard safety core of the phase. Research proves existing Ghost Dev accept/revert commands operate on local paths and the SSH session stores a synthetic `ssh://` path they cannot resolve, and `ssh_write_file` is unconfined. This plan creates the confined SSH worktree service first so later UI plans only issue safe verbs and never hand model-supplied paths to raw SSH primitives.

Output: `src/types/codingZone.ts`, `src/services/sshWorktreeService.ts`, new confined Rust commands, a `code_edit` team tool gated to the Agent Developer, the extended staff roster, and focused tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model → code_edit tool args | Model-supplied file path/hunk text is untrusted; worktree identity must come from request-bound TeamToolContext. |
| team tool handler → SSH worktree | Any path crossing to SSH must be confined server-side to the allocated worktree. |
| remote git output → tool result / chat | Remote file content and git output are untrusted data, never instructions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-01 | Elevation of privilege | code_edit tool dispatch | mitigate | Role gate `agentName === CODE_EDIT_AGENT_NAME` and `role !== 'lead'` in handler AND coordinator tool payload; test both refusal paths. |
| T-48-02 | Tampering / Info disclosure | sshWorktreeService + Rust confine_worktree_path | mitigate | `confineWorktreePath` lexical guard + Rust `canonicalize()`/`starts_with()` realpath boundary; reject `..`, absolute, `~`, symlink escape; never reuse unconfined `ssh_write_file` with model paths. |
| T-48-03 | Tampering | code_edit result / remote git output | mitigate | Wrap every tool result with existing untrusted delimiters (D-10); test the wrap assertion. |
| T-48-04 | Repudiation / data loss | apply/revert failure | mitigate | Typed failure returned on `git apply` error; never silently refresh away a failed decision (D-14). |
| T-48-05 | Elevation of privilege | worktree ownership | mitigate | Worktree descriptor derived from `ctx.remoteTarget` only; model args never select host/repo/path. |
| T-48-SC | Tampering | package installs | mitigate | No new packages; no install step; SUS packages already pinned (RESEARCH Package Legitimacy Audit). |
</threat_model>
