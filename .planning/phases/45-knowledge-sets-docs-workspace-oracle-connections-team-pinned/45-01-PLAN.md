<objective>
Harden the document-set lifecycle so local deletion can no longer leave silent orphan server snapshots, and give the user a Settings area to inspect and explicitly purge published sets.

Purpose: The orphan-set root cause (`.planning/debug/knowledge-server-orphan-sets.md`) is an AND-gate — a local-only delete path that skips purge, plus a server that persists and enumerates every snapshot forever. This plan closes both halves: default full-delete + type-to-confirm on the client (D-01, D-02), and a server-authoritative list + explicit admin purge surface (D-03, D-04). The live-server cleanup (D-05) is already applied and must not be re-run from this plan.

Output: `GET /api/v1/sets` server route, `listPublishedSets()` client method, a "Quản lý set" section in Settings > Knowledge Daemon, and a shared `DocumentSetDeleteDialog.tsx` carrying the full-delete-default / type-to-confirm gate (mounted by the legacy drawer now and by the new Docs `doc_set` detail in plan 02), each with focused Vitest coverage.
</objective>
