<objective>
Replace the single shared Oracle SQLcl connection string with a named, per-environment profile list (SIT/UAT/etc.), an active default, per-call selection, a discovery tool, a backward-safe migration, and a settings UI — without weakening read-only SQL guardrails or leaking connection passwords into backups or tool errors.

Purpose: D-09..D-15 lock the multi-connection contract. Research found the current single config is exported in plaintext backups (the key is missing from the backup denylist) and that migration must preserve the working connection. This plan defines the profile types first (interface-first), then the service/migration/resolution logic and tool contract, then the settings UI. Every Oracle path stays local and works when the knowledge daemon is absent.

Output: profile types, list config load/save + migration + `resolveOracleConnection`, selector args on query/describe, the `oracle_list_connections` tool, backup-denylist entry, settings modal/card profile management, and focused tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AI model → oracle tool args | Untrusted selector strings drive which stored connection is used |
| settings store → backup export | Persisted connection strings (with passwords) must not cross into plaintext backup JSON |
| coordinator → tool advertisement | Gating decides which Oracle tools are offered to a team |
| profile → shell command | Connection string is single-quoted into a remote shell command string |
