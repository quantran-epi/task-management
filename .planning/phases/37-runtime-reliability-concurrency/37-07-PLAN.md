<objective>
Add the user's retry path and make partial batches honest: a per-bubble retry that reruns exactly one assignment and re-synthesizes the batch, plus a lead that names what is missing.

Purpose: D-12/D-13/D-14 are what make stop and abort safe to use — without a retry, a stopped agent's work is simply gone, and without an honest synthesis the user cannot tell a partial result from a complete one.
Output: `retryAssignment`, `supersedeTeamMessage`, honest batch results, and the lead's incomplete-parts rule. The retry affordance and the observed Tauri walkthrough are 37-08.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user click → retry → provider request | a click causes a paid model call |
| ledger snapshot → retry prompt | stored free text is replayed into a model |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-37-22 | Denial of Service | double-click retry | medium | mitigate | An in-flight guard per agent rejects a second retry while the first is running, and the ledger's append-only attempt numbering would expose a duplicate as an anomaly in test. |
| T-37-23 | Tampering | retry re-running a completed agent | high | mitigate | `retryAssignment` refuses unless the source row is `stopped`/`error`; the test asserts siblings are invoked exactly once across the flow. |
| T-37-24 | Information Disclosure | retried task text | medium | accept | The retried task is text the same local user already authored and stored; it reaches the same provider the first attempt reached. No new disclosure boundary. |
| T-37-25 | Repudiation | stale synthesis | medium | mitigate | The previous synthesis is marked superseded with a message link, so the transcript always shows which synthesis is current (D-12). |
| T-37-SC | Tampering | npm/pip/cargo installs | high | mitigate | No dependency is added by this plan. |
</threat_model>
