<objective>
Build the two runtime primitives this phase is named for: a per-team FIFO scheduler with a live limit, and a module-level run manager that owns every coordinator instance so teardown is possible from anywhere.

Purpose: the coordinator currently starts every agent at once and its registry lives inside a React component, so a delete path that never mounts the workspace cannot tear a run down. Both defects are structural, and both primitives are pure enough to test without a database or a model.
Output: `src/services/ai/office/scheduler.ts`, `src/services/ai/office/teamRunManager.ts`, and `TeamRunCoordinator.dispose()`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| delete path → live run | a UI delete reaches a coordinator that may be mid-turn |
| scheduler → model provider | each admitted slot opens a real provider request |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-37-04 | Tampering | `teamRunManager.disposeRun` | high | mitigate | Dispose completes before the caller's `deleteTeam` transaction: the map entry is dropped even when `dispose` throws, so a half-torn-down coordinator can never be handed to a later turn and write to a deleted parent. The call-order requirement is enforced in 37-05 with an ordering test. |
| T-37-05 | Denial of Service | `scheduler.acquire` | medium | mitigate | Every parked acquire installs an abort listener with `{ once: true }` and removes it on release, so a long-lived turn signal cannot accumulate listeners across rounds (same rule as `budgetGate.ts:53-58`). |
| T-37-06 | Elevation of Privilege | `disposeRun` reachable from the explorer | low | accept | The explorer delete path runs as the same single local user with full IndexedDB access; there is no privilege boundary to cross. Accepted because the audience is one person with local-only data (CLAUDE.md constraints). |
| T-37-SC | Tampering | npm/pip/cargo installs | high | mitigate | No dependency is added. `p-limit`/`p-queue`/`async-mutex` are explicitly rejected (D-07); the acceptance criterion greps for them. |
</threat_model>
