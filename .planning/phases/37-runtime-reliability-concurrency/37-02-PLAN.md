    `acquire`'s signal is REQUIRED and is the cancellation channel for a queued assignment: a caller that may need to cancel while parked owns a per-assignment `AbortController` and hands `controller.signal` to `acquire`; aborting it rejects the parked acquire and removes the waiter. `cancel(handle)` cannot do that job — it only takes a handle that `acquire` has already returned — so document it as an idempotent release-equivalent, not as a queue-cancel. The doc comment must state both facts, because a caller that relies on `cancel` for a queued assignment would leave the acquire parked forever.
    `createTeamRunScheduler(initialLimit: number): TeamRunScheduler` holds `limit` (via `clampTeamConcurrency`), `running: Set<number>`, and `waiters: Array<{ resolve, reject, signal, onAbort }>` in issue order. `acquire` resolves with a fresh handle and inserts its slot into `running` when `running.size < limit`; otherwise it pushes a waiter and returns a promise parked exactly like `budgetGate.wait` (abort rejects with `new DOMException('Aborted','AbortError')` and removes the waiter). `drain()` shifts waiters in FIFO order while slots remain. `release(handle)` deletes the slot then `drain()`s; a handle not in `running` is a no-op. `cancel(handle)` is `release` semantics plus a guard so a later `release` for the same handle is also a no-op. `setLimit(n)` stores `clampTeamConcurrency(n)` and `drain()`s — raising admits queued waiters, lowering preempts nothing.
