<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user text → composer → outbox | free text is held in component state before it is persisted |
| explorer delete → live run | a destructive action reaches a running coordinator |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-37-18 | Tampering | outbox dispatch effect | medium | mitigate | The entry is removed through a functional state updater and dispatched from the removed value, so a double effect run cannot dispatch the same entry twice and a `send()` can never be re-entered. |
| T-37-19 | Data Loss | cancelled outbox entry | medium | mitigate | Cancel is the only path that drops text, it is an explicit user action on a visible chip, and no user message was persisted for it (nothing to reconcile). |
| T-37-20 | Tampering | delete ordering | high | mitigate | `disposeRun` runs strictly before `deleteTeam`; the ordering test records the call sequence, and a dispose failure aborts the delete so a live coordinator can never write to a deleted parent. |
| T-37-21 | Denial of Service | unbounded outbox growth | low | accept | One local user typing into their own composer; each entry is a short string and no network or timer is attached to it. Accepted. |
| T-37-SC | Tampering | npm/pip/cargo installs | high | mitigate | No dependency is added (`@testing-library/react` is already a dev dependency). |
</threat_model>
