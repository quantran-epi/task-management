  <behavior>
    - Test: `buildRetrievalGeneration` processes all chunks in batches of `RETRIEVAL_BATCH_SIZE` (default 32, range 25-50).
    - Test: Emits write transactions per batch; indexes are created only after all batches complete.
    - Test: All tests in `tests/retrievalBatching.test.ts` pass green.
  </behavior>
  <action>
    1. In `knowledge-server/src/graph/neo4jRepository.ts`:
       - Define `const DEFAULT_RETRIEVAL_BATCH_SIZE = 32;`.
       - Read batch size from environment: `const BATCH_SIZE = Math.max(10, Math.min(100, parseInt(process.env.RETRIEVAL_BATCH_SIZE || String(DEFAULT_RETRIEVAL_BATCH_SIZE), 10)));`.
       - In `buildRetrievalGeneration(candidate, sourceSnapshot, embeddingProvider)`:
         - Collect all chunk records into a lightweight array of chunk descriptors (without embedding vectors pre-allocated).
         - If chunks are empty, create indexes (if needed) and return early.
         - Loop over chunks in slices: `for (let i = 0; i < allChunks.length; i += BATCH_SIZE)`:
           - Slice current batch: `const batch = allChunks.slice(i, i + BATCH_SIZE);`
           - If `embeddingProvider`:
             - Compute vectors for batch: `const batchVectors = await embeddingProvider.embedDocuments(batch.map(c => c.text));`
             - Assign `batch[k].embedding = batchVectors[k];`
           - Open a write transaction on `this.getSession()`:
             - Run `CYPHER_QUERIES.UNWIND_INSERT_CHUNKS` with `batch`.
             - Run `SET c:\`${snapshotLabel}\`` for the inserted chunks in this batch.
             - Compute and write `CYPHER_QUERIES.LINK_FACT_CHUNK_SUPPORT` for the current batch chunks that overlap candidate evidence.
           - Crucial GC hygiene: dereference `batchVectors` and batch rows within the loop block.
           - Yield event loop: `await new Promise((r) => setImmediate(r));`
         - After all batches are written:
           - Execute Cypher to create fulltext index `IF NOT EXISTS` on `(c:\`${snapshotLabel}\`)`.
           - If vectors enabled: execute Cypher to create vector index `IF NOT EXISTS` on `(c:\`${snapshotLabel}\`)`.
           - Await indexes via `CYPHER_QUERIES.AWAIT_INDEX`.
           - Return `RetrievalGenerationMetadata`.
    2. In `knowledge-server/src/graph/graphRepository.ts`:
       - Update `InMemoryGraphRepository.buildRetrievalGeneration` to follow the same batching loop pattern with `setImmediate` yield to maintain parity with `Neo4jRepository`.
    3. Run `npm --prefix knowledge-server test -- tests/retrievalBatching.test.ts` and all knowledge-server unit tests.
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-03 | Denial of Service (OOM) | `Neo4jRepository.buildRetrievalGeneration` | mitigate | Stream chunks in bounded batches of 32; drop vector arrays immediately; call `setImmediate` between batches so V8 GC runs and liveness probes stay responsive. |
| T-23-04 | Injection | `CYPHER_QUERIES.UNWIND_INSERT_CHUNKS` | mitigate | Parameterized query (`$rows`, `$graphSnapshotId`) with escaped generation snapshot label `\`${snapshotLabel}\``. |
| T-23-SC | Tampering | npm dependencies | mitigate | Zero new runtime dependencies; uses native JavaScript arrays, `setImmediate`, and existing `neo4j-driver`. |
</threat_model>
