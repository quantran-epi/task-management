## Accomplishments

- `compactRemoteTree` merges `com/acme/orders` style single-child folder chains into dotted labels with key = first path (stable under reveal), path = last path (operation target), chain = all paths; stops at branch points, file children, JVM source roots, reveal targets and gitStatus-badged nodes. Pure, synchronous, dependency-free.
- `keyOfPathFor` maps every chain path back to the compact node's stable key, so a search-result reveal path selects the right node even after compaction; the raw tree stays the source of truth and only the final selection resolves through the map.
- Remote Git Explorer derives a compacted AntD tree with a remote-only `.remote-git-tree` CSS override (24px rows, 16px icons, 12px indent, 1px guides, nowrap + ellipsis, tokenized hover/selection), badges preserved on the row and full paths in Tooltip. Single-fetch guard and cross-target alignment of the reveal effect preserved.
- Folders-mode Enter in the Find dialog sets `setPendingRevealTarget({configId, repoPath, branch, filePath})` (explicit `onReveal` prop overrides), and the three obsolete inline search inputs plus their exclusive grep/name state and result blocks are removed while target selectors, global search, readonly tree, reveal and file viewer remain intact.

## Decisions Made

- Adapted the plan's assumed `RemoteGitTreeNode {path,name}` to the real type `{key,tree-title,title,isLeaf,size?,sha,children?,gitStatus?}`: `key` is the full repo-relative path and `title` is the segment label. Compaction derives names from `title`/last key segment and never mutates input.
- `PendingRevealTarget` uses `configId` (actual store field), not the plan text's `config`.
- Kept the global whole-ref search input ("Tìm toàn kho") — it is distinct from the three removed inline content/name inputs.
- The dialog is mounted without an `onReveal` prop in `WorkbenchLayout`; the default store-wiring in the dialog makes Folders-mode reveal work without editing a file outside this plan's file list.
