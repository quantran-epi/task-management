## Summary

Phase 46.1 is a UI-and-service integration phase on top of an already-rich SSH remote git inspection stack. Everything the dialog needs at the data layer exists: `grepRemoteRef` runs scoped, escaped `git grep` with NUL record parsing and truncation reporting; `searchRemoteTree` caches whole-ref `git ls-tree` and filters client-side with path confinement; `cancelToolCall` cancels a registered Tauri `callId`; `RemoteFileViewer` already accepts a one-shot `initialLine` param and scrolls/highlights it; `VirtualizedList` backs the existing Search Everywhere modal. The planner's job is composition, not new infrastructure — with two important gaps. First, `grepRemoteRef` currently clamps `limit` to 1..200, which must be raised to satisfy D-10's 2000-match bound. Second, there is no `find.inPath` action or `Ctrl/Cmd+Shift+F` keymap entry, and no Find session state module — those are genuinely new.

The visual half has a conflicting single-source-of-truth problem to resolve explicitly: the approved draft uses a blue accent (`--accent: #2f62d8;`) and a dark palette, while the current `workbench-tokens.css` and `AntdThemeAdapter` use a purple accent (`--accent: #5b4fe8;` / `colorPrimary: '#5b4fe8'`). D-02 requires that changing a shared token propagates, so the planner must decide which values win and migrate the touched surfaces' literals, not layer a second token set on top. Fonts are not installed; local bundling via Fontsource packages (legitimacy `OK`, no postinstall) or vendored woff2 files both work offline.

**Primary recommendation:** Build one new `src/workbench/search/find/` module (pure session/parser/compaction logic + thin React dialog/preview/rows), wire a `find.inPath` action through `actionRegistry` and `useGlobalKeymap`, mount the dialog in `WorkbenchLayout` alongside `SearchEverywhereModal`, extend `grepRemoteRef`'s limit ceiling, and extend `workbench-tokens.css` + `AntdThemeAdapter` as the single token source — then remove the three inline inputs last (D-11).

### Pattern 1: Supersede-and-guard session (D-08)

**What:** A session whose `search()` increments a sequence number, cancels any running request, marks results stale immediately, and drops every late event whose `seq !== current`. `cancel()` keeps partial results. Copy the OpenIdea `FindSession` shape (class with private `seq`, `request`, `state`; `deps.validate/start/cancel/nextRequestId`; `onChange` callback) but back `cancel` with `cancelToolCall(callId)`.
**When to use:** Any async command whose responses can arrive out of order relative to user input.
**Example (adapted, source: OpenIdea `find/session.ts:58-148`):**
```ts
// Source: /tmp/openidea-src.qOWKiJ/repo/src/features/search/find/session.ts
async search(query: RemoteQuery | null): Promise<void> {
  const seq = ++this.seq;
  this.cancelRunning();
  if (!query?.pattern) { this.update({ ...IDLE }, true); return; }
  this.update({ ...this.state, status: 'validating', stale: true }, true);
  const request = this.deps.nextRequestId();       // becomes the Tauri callId
  this.request = request;
  try {
    const result = await this.deps.start(request, query);
    if (seq !== this.seq) return;                   // stale guard
    this.update({ ...this.state, status: 'done', stale: false, files: result.files }, true);
  } catch (e) {
    if (seq !== this.seq) return;
    if (isCancelledError(e)) this.update({ ...this.state, status: 'done', stale: false }, true);
    else this.update({ ...this.state, status: 'error', error: errorMessage(e) }, true);
  }
}
```
`invalidate()` (`session.ts:74-79`) is the exact hook for "query change marks current results stale immediately"; D-08's 150 ms debounce wraps the call to `search()`.

### Pattern 2: Stable-key compact tree (D-12/D-13)

**What:** Turn a folder with exactly one visible child folder into one node whose `key` is the **first** folder path (stable under reveal), whose `path` is the **last** folder (target of operations), and whose `chain` lists all merged folder paths. Map every chain path back to the stable key so reveal from a search result still selects the compact node.
**When to use:** Remote tree rendering where dependency paths are deep (`src/main/java/com/acme/orders` → `com.acme.orders`).
**Example (adapted, source: OpenIdea `project-tree/model.ts:38-49,202-232,256-260`):**
```ts
// key = first folder path; path = last folder (operations target it); chain = all merged paths
const chain = [entry.path];
const names = [entry.name];
let end = entry;
for (;;) {
  const listing = listings.get(end.path);
  if (!listing) break;
  const visible = visibleEntries(listing, opts);
  if (visible.length !== 1 || !isDirEntry(visible[0]!)) break; // stop at branch points
  if (SOURCE_ROOT.test(relativeTo(root.path, end.path))) break; // stop at source roots
  end = visible[0]!;
  chain.push(end.path);
  names.push(end.name);
}
const label = names.length > 1 ? names.join(chainSeparator(root.path, entry.path)) : entry.name;
// reveal mapping: for (const p of kid.chain) keyOfPath.set(p, kid.key);
```
D-12 adds two TaskMate-specific stop conditions beyond OpenIdea: stop when the node is a reveal target, and stop when it carries a meaningful `gitStatus` badge (so status is never hidden — D-13).

### Anti-Patterns to Avoid
- **Second target store:** Do not create a new SSH-config/repo/branch picker for the dialog. Seed from `layoutStore` (`activeRemoteConfigId`, `activeRemoteRepoPath`, `activeRemoteBranch`) — CONTEXT `<code_context>` "reusable assets".
- **Hand-built shell strings in components:** Every user-derived value must reach the shell only via `escapeShellArg` / service functions (D-09 one-way). `grepRemoteRef` already does `-e <escaped>`, `--end-of-options`, and `-- <escaped path>`.
- **Raw pattern into git:** `-e` protects a leading `-`; never drop it. The Phase 42 state note records the whole-command `toBe` injection test as mandatory.
- **New schedule timer for debounce:** Use `setTimeout`/`clearTimeout` in an effect exactly as `RemoteGitExplorer.tsx:512-518` does; just change 300 → 150 (D-08).
- **Rendering a partial grep record:** The parser drops a trailing record not terminated by newline (`gitRemoteService.ts:460-468`); do not reintroduce it in a new parser.
- **Whole-app token rewrite:** D-03 limits migration to Remote Git Explorer shell/tree/rows, the new dialog, and adjacent global search rows.

## Common Pitfalls

### Pitfall 1: `grepRemoteRef` hard cap of 200 vs D-10's 2000
**What goes wrong:** D-10 requires 2000 bounded matches; the service silently clamps to 200.
**Why it happens:** `gitRemoteService.ts:398` — `const limit = Math.min(Math.max(1, Math.floor(Number(options.limit)) || 50), 200);` (verbatim). `GREP_BYTE_CAP = 262144` (line 382) is a *separate* byte cap; raising the count limit without considering the byte cap still truncates broad patterns.
**How to avoid:** Raise the numeric ceiling to 2000 and add an explicit `truncated` state to the UI. Decide deliberately whether to raise `GREP_BYTE_CAP` for content search or accept byte-based truncation with a truthful notice. Existing `RemoteGitExplorer` calls pass `CONTENT_HIT_LIMIT = 200` (`RemoteGitExplorer.tsx:473`) — keep that caller unchanged; the new dialog passes its own limit.
**Warning signs:** Dialog shows "truncated" on every moderately broad query; result count never exceeds 200.

### Pitfall 2: Accent/palette conflict between draft and current tokens
**What goes wrong:** Draft `--accent: #2f62d8;` (draft line 18) vs current `--accent: #5b4fe8;` (`workbench-tokens.css:38`) and `colorPrimary: '#5b4fe8'` (`AntdThemeAdapter.tsx:14`). Migrating only some surfaces yields two accents, violating D-02.
**Why it happens:** Draft and existing workbench were designed separately.
**How to avoid:** Decide one canonical accent before implementation. If draft wins, update BOTH `workbench-tokens.css` and `AntdThemeAdapter` token values and migrate touched-surface literals; if existing wins, accept deviation from the draft palette only with user confirmation (it is a visual source of truth — D-01). Dark theme has the same conflict: draft dark `--accent: #6a9bff;` vs current dark-mode handling via `useThemeMode` / `prefers-color-scheme`.
**Warning signs:** Find dialog blue while surrounding tree purple; a token change leaves a hardcoded hex behind.

### Pitfall 3: Dark-mode token source mismatch
**What goes wrong:** Draft uses `@media (prefers-color-scheme: dark)` plus `:root[data-theme="dark"]`; `AntdThemeAdapter` hardcodes `data-theme="light"` (`AntdThemeAdapter.tsx:52`) and `useThemeMode` reads `prefers-color-scheme`. `workbench-tokens.css` currently defines only light values (`:root, :root[data-theme="light"]`, line 5-6).
**How to avoid:** Extend `workbench-tokens.css` with a dark block keyed on the same attribute/media strategy the app actually uses, and make the Find dialog consume variables only. Flag the `data-theme="light"` hardcode as a decision point for the planner.
**Warning signs:** Dark OS setting leaves Find dialog in light colors or unreadable contrast.

### Pitfall 4: Font subset imported without `unicode-range`
**What goes wrong:** Importing only `vietnamese-400.css` makes the Vietnamese face claim all codepoints.
**Why it happens:** Per-subset CSS files have no `unicode-range` (verified in tarball).
**How to avoid:** Import default per-weight CSS (`@fontsource/inter/400.css`) so all subsets carry `unicode-range`, or hand-write complete `@font-face` blocks for both latin and vietnamese subsets.
**Warning signs:** ASCII text renders with missing glyphs, or Vietnamese diacritics fall back to system font.

### Pitfall 5: `Ctrl/Cmd+Shift+F` swallowed by input guard / OS
**What goes wrong:** `useGlobalKeymap` returns early for inputs (`useGlobalKeymap.ts:29-32`) but only for Alt/Insert shortcuts; the Ctrl+K handler is *before* that guard (lines 22-27). Place the new Ctrl/Cmd+Shift+F handler next to Ctrl+K (before the `isInput` return) so it works while typing. Also D-04 says "Ctrl/Cmd+Shift+F" — handle both `e.ctrlKey` and `e.metaKey`, and test `e.shiftKey` with `e.key === 'F'`/`'f'`.
**Warning signs:** Shortcut works in tree but not in the query input; macOS only responds to Ctrl not Cmd.

### Pitfall 6: Reveal breaks under compacted keys
**What goes wrong:** Tree keys change when chains merge, so `setSelectedKeys([result.path])` selects nothing.
**How to avoid:** Keep the compact node's `key` as the **first** path and build a `keyOfPath` map over every `chain` entry (OpenIdea model.ts:256-260). Resolve a search result path through that map before `setSelectedKeys`/`setExpandedKeys`. Preserve the existing reveal effect's cross-target alignment and single-fetch guard (`RemoteGitExplorer.tsx:646-728`).
**Warning signs:** "Reveal in Explorer" highlights nothing after compaction; duplicate `getRemoteTree` calls.

### Pitfall 7: Old search inputs removed before dialog verified
**What goes wrong:** D-11 is ordered deliberately. Removing inputs early loses the fallback if the new dialog fails verification.
**How to avoid:** Ship dialog + tests first; delete the three inputs only after focused tests and a Tauri walkthrough pass. Keep target selectors, tree, reveal, file viewer intact (selectors at `RemoteGitExplorer.tsx:785,800,828`; inputs at `:856,875`; segmented at `:862`).

### Pitfall 8: Cancellation without a real callId
**What goes wrong:** A new service path calls `execRemoteCommand` without passing `callId`, so `cancelToolCall` cannot find the process.
**How to avoid:** Generate/pass a stable `callId` per search request and pass it into `grepRemoteRef`/`searchRemoteTree`/`getRemoteFileContent` (all already accept `callId?`). `execRemoteCommand` auto-generates a `local-*` id only when absent (`sshService.ts:268`), which the session does not know — never rely on it for cancellable work. `cancelToolCall` is idempotent on Rust (`sshService.ts:273-279`).

### Pitfall 9: jsdom virtualization / scroll assumptions
**What goes wrong:** `useVirtualizer` returns zero items without layout; tests querying rows fail.
**How to avoid:** `VirtualizedList` already renders a 25-item fallback in jsdom (lines 46-61). Write component tests against row text/testids, not scroll geometry; `scrollIntoView` is shimmed in `tests/setup.ts`.
