## Warnings

### WR-07: File-mask toolbar button focus selector matches nothing

**File:** `src/workbench/search/find/FindInRemoteFiles.tsx:345`
**Issue:** The filter button's click handler is `document.querySelector<HTMLInputElement>('.find-mask input')?.focus()`. Ant Design renders `<Input className="find-mask" id="find-file-mask" …/>` with the `find-mask` class directly on the `<input>` element, not on a wrapper (confirmed against `antd/lib/input/Input.js` and `@rc-component/input/lib/BaseInput.js`, and reproduced in jsdom: the mask `<input>` carries `class="… find-mask …"`, parent is an unclassed `div`, and `document.querySelector('.find-mask input')` returns `null`). Clicking the button therefore focuses nothing (`document.activeElement === body`). The button advertises `aria-controls="find-file-mask"` (line 343), so the intended focus shortcut silently fails — an accessibility/UX defect. No existing test covers the focus action (the `icon-only buttons` test only checks the Close button).
**Fix:** target the actual input by id (or by its own class):

```tsx
onClick={() => document.getElementById('find-file-mask')?.focus()}
```

`document.querySelector<HTMLInputElement>('.find-mask')?.focus()` is equally correct. Add a test asserting `document.activeElement` equals the File mask textbox after clicking the filter button.

### WR-08: Clearing content pattern leaves stale results on screen

**File:** `src/workbench/search/find/FindInRemoteFiles.tsx:137-144`
**Issue:** The content-search effect early-returns when `remoteQuery.pattern` is empty:

```tsx
useEffect(() => {
  if (!open || mode !== 'content' || !remoteQuery.pattern) return;
  session.invalidate();
  const timer = setTimeout(() => { void session.search(remoteQuery); }, FIND_DEBOUNCE_MS);
  return () => clearTimeout(timer);
}, [open, mode, remoteQuery, session]);
```

When a search has completed and the user clears the Pattern field, this branch runs without calling `session.invalidate()` or clearing session state. `state.hits` stays at the previous result set, `contentRows` is still derived from it, and status stays `done`, so the dialog keeps showing results for a now-empty pattern with no stale indicator. Reproduced in jsdom: one result row after searching `needle`, still one row after clearing the pattern. This is the same class of defect WR-04 fixed for Files/Folders (empty needle must not show meaningless results); the content path is inconsistent with that contract.
**Fix:** clear results when the content pattern is empty, mirroring the Files/Folders guard:

```tsx
useEffect(() => {
  if (!open || mode !== 'content') return;
  if (!remoteQuery.pattern) {
    void session.cancel(); // invalidate in-flight work
    setState(EMPTY_STATE);
    return;
  }
  session.invalidate();
  const timer = setTimeout(() => { void session.search(remoteQuery); }, FIND_DEBOUNCE_MS);
  return () => clearTimeout(timer);
}, [open, mode, remoteQuery, session]);
```

Alternatively expose a `reset()` on `FindSession` that bumps `seq`, cancels any in-flight call, and emits `IDLE_STATE`. Add a regression test: search → assert rows → clear Pattern → assert zero rows / no stale results.
