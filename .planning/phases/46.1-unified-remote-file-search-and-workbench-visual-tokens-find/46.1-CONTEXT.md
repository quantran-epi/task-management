# Phase 46.1: Unified Remote Search and Visual Tokens - Context

**Gathered:** 2026-11-20
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase replaces the scattered SSH Remote Explorer search surfaces with one Find in Remote Files dialog modeled on OpenIdea and IntelliJ: result rows above, file preview below, selected row drives the preview, and Enter opens the exact remote file line. It also makes the remote folder tree compact for deep dependency paths and turns the approved draft's typography, palette, and control styling into shared workbench tokens used by the new UI and migrated surfaces.

In scope:
- Unified Content / Files / Folders search for the active SSH config, repo path, and branch, including scope controls and file mask.
- Two-pane result/preview dialog with virtualized result rows, highlight ranges, keyboard navigation, stale/cancel handling, and bounded results.
- Compact remote folder tree with stable-path reveal mapping.
- Locally bundled Inter and IBM Plex Mono with Vietnamese subsets, shared light/dark palette, typography roles, compact control sizes, hover/selection/match styling, and removal of hardcoded colors in touched surfaces.

Out of scope:
- Editing remote files, write commands, or replace-in-files.
- PWA, GitHub Pages, or browser-host validation; Tauri desktop is the only supported runtime for this work.
- New AI chat context types or other Phase 47 AI work.
- Searching the whole remote host outside the selected repo/ref as the default behavior.
- A new styling framework or new npm UI dependency.

</domain>

<decisions>
## Implementation Decisions

### Approved visual direction
- **D-01:** Use the approved HTML draft as the visual source of truth for the Find dialog and compact tree. Fonts: `Inter` for UI text and `IBM Plex Mono` for code/data; both must be bundled locally with Vietnamese subsets so Tauri remains offline-capable. — **Reversibility:** costly — font files, CSS font stacks, and component classes will be referenced across the workbench once adopted.
- **D-02:** Promote the draft's color, typography, row, icon, and control values into shared CSS custom properties. The new search UI and migrated workbench surfaces must consume those tokens instead of literal colors or one-off sizes. Changing a token in the shared token source must propagate without editing component literals. — **Reversibility:** costly — partial migrations leave literal values behind and break the single-source-of-truth guarantee.
- **D-03:** Apply the shared visual system to the workbench surfaces touched by this phase first: Remote Git Explorer shell/tree/result rows, Find in Remote Files dialog, and adjacent global search result rows where the same list/control patterns appear. Do not attempt a whole-app visual rewrite in this phase. — **Reversibility:** reversible — later phases can extend token coverage incrementally.

### Search surface
- **D-04:** Add one `Ctrl/Cmd+Shift+F` action named Find in Remote Files, seeded from the currently active SSH config, repo path, and branch. It opens a resizable modeless Ant Design dialog pinned near the top, matching the draft. The existing Search Everywhere modal remains local-first; it may hand off to this dialog but is not replaced. — **Reversibility:** costly — action registry, global keymap, layout mounting, and user muscle memory depend on this entry point.
- **D-05:** One input drives three modes: Content, Files, Folders. The dialog includes scope tabs for Whole ref and Directory, plus file mask and Match Case / Words / Regex toggles. Module/Scope tabs from OpenIdea are not required in this phase. — **Reversibility:** costly — changing modes or option contracts touches UI, query building, and tests.
- **D-06:** Top pane shows flat virtualized rows. Content rows show highlighted code text and right-aligned `relPath:line`. Files/Folders rows show icon, path, and count. Bottom pane shows a remote code preview for Content mode and a concise folder preview for Files/Folders modes. — **Reversibility:** costly — result row and preview contracts are shared across renderer, service, and tests.
- **D-07:** Arrow Up/Down and PageUp/PageDown move the active result; the preview follows the active result immediately. Enter opens the remote file at the exact match line in a readonly tab. Shift+Enter opens in a new tab or side target if the existing tab API supports it. Esc closes unless pinned. — **Reversibility:** costly — keyboard and tab-opening behavior becomes user-visible muscle memory.
- **D-08:** Use 150 ms debounce, sequence/stale guards, and real cancellation via the existing SSH cancel path. A query change marks current results stale immediately; late responses cannot overwrite newer results; Stop keeps partial results. — **Reversibility:** costly — cancellation and stale handling span session state, service calls, and Rust/Tauri command IDs.

### Remote search backend
- **D-09:** Content search uses scoped `git grep` against the selected ref and optional directory pathspec with `-I` to skip binary files. File/Folder modes use the existing `git ls-tree` cache, filtered client-side by query and mask. Query text must never be interpolated raw into a shell command. — **Reversibility:** one-way — loosening escaping or path confinement would weaken the read-only trust boundary.
- **D-10:** Results are bounded at 2000 matches with an explicit truncated state. Preview loads at most 256 KB; larger or binary files show a truthful truncation notice and an action to open the full file. — **Reversibility:** reversible — caps can be tuned later without changing the data model.
- **D-11:** Remove the three old search inputs from Remote Git Explorer only after the new dialog works. Keep target selectors, readonly tree, reveal, and file viewer behavior intact. — **Reversibility:** reversible — rollback can restore the old inline inputs if the new dialog fails verification.

### Compact tree
- **D-12:** Compact single-child folder chains into dotted labels like `com.acme.orders`, following OpenIdea's project tree model. Stop compaction at branch points, source roots, reveal targets, and nodes with meaningful status badges. — **Reversibility:** costly — tree keys, expanded state, and reveal mapping depend on chain semantics.
- **D-13:** Use 24 px rows, 16 px icons, 12 px indentation, 1 px guides, nowrap with ellipsis, and tokenized hover/selection styles. The compact row must not truncate important status information silently; status badges remain visible or available in tooltip. — **Reversibility:** reversible — CSS values are tokenized and tunable.

### Claude's Discretion
- Exact component/hook file names and whether FindSession is a class or reducer, provided boundaries stay testable and follow existing workbench patterns.
- Exact AntD props used to make a modeless resizable dialog, provided the final interaction matches the draft.
- Exact parser details for `git grep` records and preview snippets, provided `path:line`, match ranges, truncation, and errors are truthful.
- Whether Directory scope uses a text input plus browse button or only a text input, provided the chosen repo/ref path confinement is preserved.
- Exact test layout and mocking strategy, provided pure logic and component behavior are both covered.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `RemoteGitExplorer` already owns active SSH config, repo path, branch, lazy tree, reveal, and readonly file opening; the new dialog should seed from this source rather than invent a second target store.
- `VirtualizedList` is already used by Search Everywhere and can back the new result pane.
- `grepRemoteRef` already implements bounded `git grep` parsing with NUL records, exit-code handling, `-I`, and shell escaping; extend rather than duplicate where practical.
- `searchRemoteTree` already caches `git ls-tree` per config/repo/ref and filters client-side; reuse for Files/Folders modes.
- `cancelToolCall` and the Tauri `callId` registry already provide real SSH cancellation; add typed service access instead of inventing a new cancel transport.
- `RemoteFileViewer` and `layoutStore.openTab` already support readonly remote tabs and line/highlight params; reuse for Enter behavior.
- `workbench-tokens.css` already defines some shared tokens; extend and migrate touched components.

### Established Patterns
- Remote git inspection is strictly readonly against git branch state.
- SSH and git commands require explicit target identity, path confinement, and shell escaping.
- Search result caps and pagination must be explicit and truthful.
- Workbench UI uses Ant Design plus CSS tokens; tests are focused Vitest/RTL, not the full suite.
- Stable tree keys and one-shot reveal params are required for editor-to-tree navigation.

### Integration Points
- `Ctrl/Cmd+Shift+F` → action registry → global keymap → Find in Remote Files overlay mounted in WorkbenchLayout.
- Dialog query state → remote search service → `git grep` / `git ls-tree` over SSH → result rows.
- Result selection → preview fetch → highlighted code preview.
- Result activation → `layoutStore.openTab` remote file tab with line/highlight params.
- Compact tree model → AntD `Tree` nodes → reveal mapping from search result paths.

</code_context>
