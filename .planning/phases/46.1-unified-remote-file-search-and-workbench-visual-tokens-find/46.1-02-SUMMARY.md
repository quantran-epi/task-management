# Phase 46.1 Plan 02: Unified Remote Search and Visual Tokens Summary

**Ctrl/Cmd+Shift+F Find in Remote Files dialog with seeded remote target, 150 ms debounced grep, virtualized highlighted rows and a following bounded preview, plus client-side Files/Folders modes over the cached ls-tree**

## Accomplishments

- Registered `find.inPath` action dispatching `taskmate:open-find-in-remote-files` and added the Ctrl/Cmd+Shift+F handler before the input guard, so the shortcut works while typing and plain Ctrl+F is untouched; Search Everywhere remains local-first.
- Added an ephemeral zustand find store and mounted a seeded two-pane `FindInRemoteFiles` dialog in `WorkbenchLayout`; the dialog reads active SSH config/repo/branch from `layoutStore` with no second target picker.
- Wired a 150 ms debounce that passes an untransformed `RemoteQuery` to `FindSession.search`; `deps.start` alone calls `buildGrepOptions` and forwards `GrepRemoteRefOptions` (limit 2000) plus a stable callId with real cancel to `grepRemoteRef`.
- Derived display rows solely from the committed `RemoteGrepHit[]` via `hitsToMatchRows`, with UTF-16 ranges from `matchRanges(hit.text, …)` shared by rows and preview — no raw stdout re-parse.
- Added pure `HighlightedText`/`ResultRow`/`CodePreview`/`FolderPreview` render units using React text nodes and `<mark>` (never `dangerouslySetInnerHTML`), active-row keyboard nav with immediately following preview, and centered active-line scroll.
- Bounded preview fetch at 256 KB with a truthful single-source binary/oversize notice and open-full-file action; extended `FIND_STATUS_COPY` with empty/preview copy.
- Implemented Files/Folders modes as client-side filters over the cached `searchRemoteTree` with file-mask and confined directory scope; the query text never reaches git, and rows share virtualization/nav/Enter-to-open with Content mode.
- Focused proof: `tsc --noEmit` clean, 26/26 tests pass across 4 suites.

## Decisions Made

- Shortcut handler placed before the isInput guard to satisfy D-04 while typing.
- `deps.start` is the sole owner of `buildGrepOptions`; the component never sees service options.
- Ranges derive from already-parsed hit text; the plan 01 parser remains the only parser.
- Files/Folders modes never call grep; directory scope reuses `confineRepoPath` from plan 01.
- Shift+Enter uses a distinct tab id because `layoutStore.openTab` has no side target (D-07 fallback).
