<objective>
Plumb real provider usage through the runtime into split ledger columns, charge every terminal path including retries, aborts and leader-only turns, and reconcile live counters with persisted rows when a turn ends.

Purpose: `handleUsage` today collapses usage with `normalizeUsageTotal`, writes a single scalar through a get-then-update, and only enters its estimation branch when a callback fires with zero usage — so a request that never reports is free, and every report is a DB write that the terminal reconcile cannot defer. ROADMAP criteria 2 and 3 are unmet because the split is thrown away before it is stored and because a callback-less response costs nothing. This plan makes the funnel lossless, gives every request an explicit lifecycle with a chosen accounting source, defers the ledger to one terminal flush, and adds the estimation fallback (the tokenizer arrives in plan 10 — until then the fallback is chars÷4 and is still marked estimated).
Output: a typed `ChatTokenUsage` callback chain, cache-aware usage mapping, a per-request accounting record with explicit source selection, `tokenEstimate.ts`, one awaitable terminal seam shared by employee and lead turns, per-attempt usage rows, and reconcile inside `finalizeAttempt`.
</objective>
