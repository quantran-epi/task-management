# Phase 12.2: Multiple Reminders with Time, Notification Settings, Table Customization & Sidebar Persistence - Research

**Researched:** 2026-09-29  
**Domain:** Dexie schema migration, multi-reminder temporal evaluation, Web Notification API (`requireInteraction`), Ant Design Table customization & header sorting, localStorage UI persistence  
**Confidence:** HIGH  

## Summary

Phase 12.2 delivers 5 targeted enhancements across data modeling, notification ergonomics, table flexibility, and shell state persistence:
1. **Multiple Reminders with Optional Time (`NOTIF-06`):** Upgrade `Task`, `Milestone`, and `Project` entities to support `reminders: ReminderItem[]` (max 5 items per entity), with required `date: string` (YYYY-MM-DD), optional `time?: string` (HH:mm), and optional `note?: string`. Dexie schema bumps to Version 6 with backwards-compatible migration from legacy `reminderDate` and `reminderNote`.
2. **Persistent Desktop Notifications (`NOTIF-07`):** Dispatch browser Web Notifications with `requireInteraction: true` so alerts stay docked in the operating system's notification center until explicitly clicked or dismissed by the user.
3. **Dedicated Notification Settings (`NOTIF-08`):** Introduce Tab 4 ("Thông báo") in `SettingsView` housing controls for master browser notification toggle, `requireInteraction` toggle, deadline warning threshold days (1, 2, 3, 5), stale task threshold days (3, 5, 7, 14), capacity overload threshold (100%, 110%, 120%), and alert category toggles (`overdue`, `dueSoon`, `overload`, `stale`, `reminders`, `timer`).
4. **Table Column Customization & Header Sorting (`NOTIF-09`):** Provide a Column Visibility popover on `TaskTable` saving preferences to `localStorage` under `planner:task_table_columns`, along with 3-state Ant Design Table header sorting on task name, priority, status, deadline, and spent/estimate minutes.
5. **Sidebar Collapse Persistence (`NOTIF-10`):** Preserve desktop `<Sider>` collapse state across page reloads via `localStorage` key `planner:sidebar_collapsed`.

Zero new third-party dependencies are required. All capabilities build on native Web APIs, Ant Design 6.6.5, Dexie 4.4.6, and Zod 4.6.5.

**Primary recommendation:** Implement the Dexie Schema V6 upgrade and Zod schemas first, followed by the notification evaluation engine with time-awareness and user-configurable thresholds, then UI controls in Settings, TaskTable, and AppShell.

#### Multiple Reminders & Data Model (Nhiều nhắc nhở kèm giờ tùy chọn)
- **D-01:** Cấu trúc lưu trữ mảng reminders trong Entity: Bổ sung trường `reminders: ReminderItem[]` trực tiếp vào `Task`, `Milestone`, và `Project` trong `src/types/models.ts`. Mỗi `ReminderItem` có cấu trúc:
  ```ts
  export interface ReminderItem {
    id: string; // crypto.randomUUID()
    date: string; // YYYY-MM-DD
    time?: string; // HH:mm (optional)
    note?: string;
  }
  ```
- **D-02:** Nâng cấp Dexie schema lên Version 6: Giữ tương thích ngược bằng cách tự động migrate dữ liệu cũ từ `reminderDate` và `reminderNote` sang phần tử đầu tiên của mảng `reminders: [{ id: crypto.randomUUID(), date: reminderDate, note: reminderNote }]` nếu tồn tại. Cập nhật Zod validation schemas (`schemas.ts` và `backupSchemas.ts`).
- **D-03:** Phạm vi áp dụng: Hỗ trợ đầy đủ trên cả 3 cấp: `Task` (trong `TaskDrawer`), `Milestone` (trong `MilestoneModal`), và `Project` (trong `ProjectModal`).
- **D-04:** Giới hạn số lượng nhắc nhở: Tối đa 5 reminders cho mỗi item để đảm bảo giao diện form modal và drawer không bị vỡ layout hoặc quá tải.
- **D-05:** Giao diện nhập liệu: Hiển thị Dynamic Form List trong phần Reminders gồm các dòng: `DatePicker` (bắt buộc), `TimePicker` (`HH:mm`, tùy chọn/optional, mặc định để trống), `Input` (ghi chú ngắn), và nút icon xóa (thùng rác), kèm nút "Thêm nhắc nhở" (`+ Thêm nhắc nhở`).
- **D-06:** Cơ chế kích hoạt cảnh báo (Trigger evaluation):
  - Nếu không có `time`: Kích hoạt cảnh báo từ 00:00 ngày `reminderDate` khi `currentDate >= reminderDate`.
  - Nếu có `time` (`HH:mm`): Khi `currentDate === reminderDate`, chỉ kích hoạt khi thời gian hiện tại `currentTime >= reminderTime`. Khi `currentDate > reminderDate`, luôn kích hoạt.
  - Điều kiện kết thúc: Cảnh báo tự hết khi task chuyển sang `Done` / `Cancelled`, hoặc khi người dùng xóa reminder đó khỏi danh sách.

Thao tác Dismiss chỉ ẩn đúng reminder đó cho đến hết ngày hiện tại (`dismissAlertToday`), không làm tắt các reminder khác của cùng một item.
- **D-08:** Cảnh báo quá hạn (Past Trigger): Reminder đã qua mốc kích hoạt sẽ tiếp tục hiển thị trong NotificationDrawer cho tới khi người dùng xử lý (dismiss trong ngày, chỉnh sửa/xóa reminder, hoặc đánh dấu hoàn thành item).

### Pattern 1: Dexie Schema V6 Migration & Backward Compatibility
**What:** Introduce `SCHEMA_V6` in `src/db/schema.ts` and `.version(6).stores(SCHEMA_V6).upgrade(...)` in `src/db/index.ts`.
**When to use:** Migrating existing stores from single `reminderDate`/`reminderNote` properties to `reminders: ReminderItem[]`.
**Detail:**
- In `SCHEMA_V6`, replace index `reminderDate` with `*reminderDates` or keep existing indexes if direct querying is not required. Since reminders are evaluated by scanning active items in memory (small personal dataset) or indexing array of dates, Dexie supports multi-entry index syntax `*reminderDates`. If legacy fields `reminderDate` are retained for backwards compatibility or indexed via computed keys, ensure `toCollection().modify()` cleanly populates `reminders: []`.
- Upgrade handler:
```typescript
this.version(6)
  .stores(SCHEMA_V6)
  .upgrade(async (tx) => {
    const migrateReminders = (record: any) => {
      if (!Array.isArray(record.reminders)) {
        record.reminders = [];
        if (record.reminderDate) {
          record.reminders.push({
            id: crypto.randomUUID(),
            date: record.reminderDate,
            note: record.reminderNote || undefined,
          });
        }
      }
    };

    await tx.table('projects').toCollection().modify(migrateReminders);
    await tx.table('milestones').toCollection().modify(migrateReminders);
    await tx.table('tasks').toCollection().modify(migrateReminders);
  });
```

### Pattern 2: Multi-Reminder Evaluation with Optional Time
**What:** Pure function in `src/utils/notifications.ts` iterating through `item.reminders: ReminderItem[]`.
**When to use:** During `evaluateNotifications()` to generate `AlertNotificationItem` per triggered reminder.
**Evaluation Rules (D-06, D-07, D-08):**
- Let `currentDate = todayDate` (YYYY-MM-DD) and `currentTime = dayjs().format('HH:mm')`.
- For each `reminder` in `item.reminders`:
  - If `reminder.date > currentDate`: Future reminder -> Do not trigger.
  - If `reminder.date === currentDate`:
    - If `reminder.time`: Trigger only if `currentTime >= reminder.time`.
    - If no `reminder.time`: Trigger (since 00:00 of reminder date has arrived).
  - If `reminder.date < currentDate`: Past trigger -> Trigger (remains active until user handles it).
- Alert ID format: `reminder:${entityType}:${entityId}:${reminder.id}`.
- Can dismiss: `true` (calls `dismissAlertToday` for this specific `alertId`).

### Pattern 4: Ant Design Table Column Customization & Header Sorter
**What:** Column visibility toggles via Popover Checkbox and header click sorting with 3-state cycle (`ascend` -> `descend` -> `null`).
**Keys:**
- Fixed column: `name` (cannot be hidden).
- Optional columns: `status`, `priority`, `workType`, `opsOwners`, `businessAnalysts`, `estimateMinutes` (spent/estimate), `deadline`, `actions`.
- LocalStorage key: `planner:task_table_columns`.
- Sorters:
  - `name`: `(a, b) => a.name.localeCompare(b.name, 'vi', { sensitivity: 'base' })`
  - `priority`: Weight mapping `Urgent (4) > High (3) > Medium (2) > Low (1)`:
    ```typescript
    const PRIORITY_WEIGHTS: Record<TaskPriority, number> = { Urgent: 4, High: 3, Medium: 2, Low: 1 };
    sorter: (a, b) => PRIORITY_WEIGHTS[a.priority] - PRIORITY_WEIGHTS[b.priority]
    ```
  - `status`: Progress sequence `Open (1) -> In Progress (2) -> Resolved (3) -> In Review (4) -> Done (5) -> Cancelled (6)`.
  - `deadline`: String comparison `(a, b) => (a.deadline || '').localeCompare(b.deadline || '')`.
  - `estimateMinutes`: Numeric comparison using task estimate or spent minutes.

### Pattern 5: Synchronous Sidebar Collapse State in AppShell
**What:** Manage `<Sider>` state with initial value from `localStorage.getItem('planner:sidebar_collapsed') === 'true'`.
**When to use:** Rendering `AppShell.tsx` without screen flickering or delay.
```typescript
const [collapsed, setCollapsed] = useState<boolean>(() => {
  if (typeof window === 'undefined') return false;
  try {
    return localStorage.getItem('planner:sidebar_collapsed') === 'true';
  } catch {
    return false;
  }
});

const handleCollapse = (value: boolean) => {
  setCollapsed(value);
  try {
    localStorage.setItem('planner:sidebar_collapsed', String(value));
  } catch (err) {

## Common Pitfalls

### Pitfall 1: Breaking Schema Upgrades when Migrating Array Fields
**What goes wrong:** If `modify()` fails or does not check if `reminders` already exists, repeated migrations or partially upgraded databases could corrupt data or create duplicate reminders.
**Why it happens:** Modifying table collections in Dexie must be idempotent.
**How to avoid:** In `upgrade()`, check `if (!Array.isArray(record.reminders))` before creating the array, and only push legacy `reminderDate` if it exists and `reminders.length === 0`.
**Warning signs:** Vitest schema migration test fails or projects lose existing reminders upon upgrade.

### Pitfall 2: `TimePicker` Value Conversion with Ant Design Form
**What goes wrong:** Ant Design `TimePicker` requires a `dayjs` instance or undefined. Passing raw `"HH:mm"` string or trying to format null causes runtime exceptions.
**Why it happens:** Ant Design date components bind to dayjs objects internally.
**How to avoid:** When populating form initial values, convert `reminder.time` string (`"14:30"`) via `dayjs(reminder.time, 'HH:mm')`. When saving, format back to string via `val.format('HH:mm')`.
**Warning signs:** `val.format is not a function` error when submitting drawer/modal.

### Pitfall 3: Dismissed Alerts Key Mismatch
**What goes wrong:** If `alertId` changes from `reminder:${entityType}:${entityId}` to `reminder:${entityType}:${entityId}:${reminder.id}`, existing dismissal checks or `isAlertDismissible()` might fail if they expect a different pattern.
**Why it happens:** In `notificationRepo.ts`, `isAlertDismissible` uses `alertKey.startsWith('reminder:')`.
**How to avoid:** Ensure `alertKey.startsWith('reminder:')` matches any reminder alert key pattern. Ensure dismissal clears at midnight via `todayDate` check.

### Pitfall 4: `requireInteraction` Unsupported on Certain Platforms
**What goes wrong:** Some environments (e.g. mobile Safari, macOS WebKit notifications or test jsdom) may ignore or throw if `requireInteraction` is provided.
**Why it happens:** Web Notification API options vary slightly by engine.
**How to avoid:** Wrap `new window.Notification(title, options)` in a `try...catch` block (already implemented in `useDesktopNotification.ts`).

### Pitfall 5: FOUC (Flash of Unstyled Content) on Table Columns or Sidebar
**What goes wrong:** If table columns or sidebar collapse states are loaded asynchronously via Dexie `useLiveQuery`, the table/sidebar will render in default mode for 10-50ms before snapping to the stored user preference.
**Why it happens:** IndexedDB is asynchronous.
**How to avoid:** Store table column keys and sidebar collapsed state in `localStorage` under `planner:*` and read them synchronously during initial React `useState(() => localStorage.getItem(...))` initialization.

export const SCHEMA_V6 = {
  ...SCHEMA_V5,
  // Note: projects, milestones, tasks maintain existing indexes

// src/db/index.ts
this.version(6)
  .stores(SCHEMA_V6)
  .upgrade(async (tx) => {
    const migrate = (record: any) => {
      if (!Array.isArray(record.reminders)) {
        record.reminders = [];
        if (record.reminderDate) {
          record.reminders.push({
            id: crypto.randomUUID(),
            date: record.reminderDate,
            note: record.reminderNote || undefined,
          });
        }
      }
    };
    await tx.table('projects').toCollection().modify(migrate);
    await tx.table('milestones').toCollection().modify(migrate);
    await tx.table('tasks').toCollection().modify(migrate);
  });
```

### 2. Time-Aware Reminder Evaluation Engine
```typescript
// src/utils/notifications.ts
export function evaluateReminders(
  items: Array<{ id: string; name: string; status: string; reminders?: ReminderItem[]; projectId?: string }>,
  entityType: 'project' | 'milestone' | 'task',
  todayDate: string,
  currentTime: string, // 'HH:mm'
  dismissedMap: Record<string, string>,
  projectMap?: Map<string, string>
): AlertNotificationItem[] {
  const alerts: AlertNotificationItem[] = [];

  for (const item of items) {
    if (item.status === 'Done' || item.status === 'Cancelled') continue;
    if (!item.reminders || item.reminders.length === 0) continue;

    for (const reminder of item.reminders) {
      if (!reminder.date) continue;

      let isTriggered = false;
      if (reminder.date < todayDate) {
        // Overdue reminder: always active until resolved
        isTriggered = true;
      } else if (reminder.date === todayDate) {
        // Today's reminder: check time if specified
        if (!reminder.time || currentTime >= reminder.time) {
          isTriggered = true;
        }
      }

      if (isTriggered) {
        const alertKey = `reminder:${entityType}:${item.id}:${reminder.id}`;
        if (dismissedMap[alertKey] !== todayDate) {
          alerts.push({
            id: alertKey,
            category: 'reminder',
            title: item.name,
            subtitle: reminder.note || (entityType === 'task' && item.projectId && projectMap ? projectMap.get(item.projectId) : undefined),
            date: reminder.time ? `${reminder.time} ${reminder.date}` : reminder.date,
            tagColor: 'gold',
            tagLabel: reminder.time ? `Nhắc nhở (${reminder.time})` : 'Nhắc nhở',
            entityType,
            entityId: item.id,
            canDismiss: true,
            priorityOrder: 5,
          });
        }
      }
    }
  }

  return alerts;
}
```
