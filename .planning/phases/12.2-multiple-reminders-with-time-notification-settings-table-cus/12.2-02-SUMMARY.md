# Phase 12.2 Plan 02: Notification Settings Tab, Alert Thresholds & Desktop Notification Persistence Summary

Delivered dedicated Notification Settings management (Tab 4 in SettingsView), user-customizable alert thresholds and category toggles, and persistent desktop notifications (`requireInteraction: true`) with a minute-exact live reminder ticker.

## What Was Done

### Task 1: NotificationSettings types, default constants, and evaluation engine integration
- Defined `NotificationCategoryConfig`, `NotificationSettings`, `NOTIFICATION_SETTINGS_KEY`, and `DEFAULT_NOTIFICATION_SETTINGS` in `src/types/notifications.ts`.
- Updated `evaluateNotifications` in `src/utils/notifications.ts` to accept optional `settings?: NotificationSettings`:
  - Dynamically filtered alerts based on `enabledCategories` (overdue, dueSoon, overload, stale, reminders, timer).
  - Evaluated due soon tasks against user-defined `dueSoonDays` (1, 2, 3, 5).
  - Evaluated stale tasks against user-defined `staleTaskDays` (3, 5, 7, 14).
  - Compared capacity overload against user-defined `capacityOverloadThreshold` (100%, 110%, 120%).
- Updated `useNotifications` to reactively load notification settings from Dexie and pass them to `evaluateNotifications`.
- Added unit tests in `tests/utils/notifications.test.ts` verifying category muting and custom threshold evaluations.
- Commit: `b6de012`

### Task 2: Dedicated Notification Settings Tab in SettingsView and expanded NotificationSettingsCard
- Moved `NotificationSettingsCard` from the 'data' (Sao lưu & Dữ liệu) tab to a new 4th tab 'notifications' with a `BellOutlined` icon in `src/views/SettingsView.tsx`.
- Expanded `NotificationSettingsCard.tsx` with:
  - Section 1: Browser Desktop Notifications toggle and `requireInteractionEnabled` (Giữ thông báo trên màn hình) toggle.
  - Section 2: Alert Thresholds dropdowns for `dueSoonDays`, `staleTaskDays`, and `capacityOverloadThreshold`.
  - Section 3: Notification Categories checkboxes for overdue, dueSoon, overload, stale, reminders, and timer alerts.
  - Permission check with warning alert when browser notification permission is denied.
- Updated `tests/components/settings/NotificationSettingsCard.test.tsx` and `tests/views/SettingsView.test.tsx` verifying reactive persistence, threshold updates, and tab mounting.
- Commit: `ba7dd2e`

### Task 3: Desktop notification persistence and live reminder ticker
- Enhanced `useDesktopNotification.ts` to query `NotificationSettings` from Dexie.
- Passed `requireInteraction: resolvedSettings.requireInteractionEnabled` to `window.Notification` constructor.
- Implemented a 30-second interval ticker that scans active reminders for current minute clock matches (`${currentTime} ${currentDate}`), dispatching immediate discrete desktop notifications deduplicated per minute.
- Created `tests/hooks/useDesktopNotification.test.ts` testing `requireInteraction` (true/false), permission suppression, startup throttling, and live reminder dispatch.
- Commit: `1aee4a1`
