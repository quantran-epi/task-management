## Critical Issues

### CR-01: Skipping startup summary on reload leaves `notifiedAlertIdsRef` unseeded, triggering desktop notification storm

**File:** `src/hooks/useDesktopNotification.ts:100-140`  
**Issue:** `useDesktopNotification` maintains an in-memory `notifiedAlertIdsRef` to avoid spamming the user with individual desktop notifications for backlog items. In step 1 (startup summary), `alreadyShown` is read from `sessionStorage.getItem(SESSION_NOTIFICATION_SHOWN_KEY)`. When a user refreshes the page or navigates in an active session, `alreadyShown` is `true`. Because the seeding loop `notifiedAlertIdsRef.current.add(item.id)` is placed inside `if (!alreadyShown && notifications.activeCount > 0)`, it never executes on reload. Consequently, `notifiedAlertIdsRef` remains empty, and Step 2 ("Real-time alert dispatch across all enabled categories") loops over all existing `notifications.items` and dispatches individual OS desktop notifications for every active overdue task, overloaded day, due-soon task, and stale task at once.  
**Fix:**
Move the seeding of `notifiedAlertIdsRef.current` outside the `!alreadyShown` condition so existing backlog items are always suppressed on initial hook load:

```typescript
    // 1. Startup summary: check once on initial active load
    if (!initialLoadHandledRef.current) {
      initialLoadHandledRef.current = true;

      let alreadyShown = false;
      try {
        alreadyShown = sessionStorage.getItem(SESSION_NOTIFICATION_SHOWN_KEY) === 'true';
      } catch {
        // sessionStorage may be restricted in private/sandboxed contexts
      }

      if (!alreadyShown && notifications.activeCount > 0) {
        const overdue = notifications.categoryCounts.overdue;
        const overload = notifications.categoryCounts.overload;
        const stale = notifications.categoryCounts.stale;
        const reminders =
          notifications.categoryCounts.reminder + notifications.categoryCounts['due-soon'];
        const totalPending = reminders + stale;

        const summaryText = `Bạn có ${overdue} việc quá hạn, ${overload} ngày quá tải, và ${totalPending} việc cần xử lý.`;

        sendDesktopNotification({
          title: 'Task Planner',
          body: summaryText,
          requireInteraction: settingsData.settings.requireInteractionEnabled,
        });

        try {
          sessionStorage.setItem(SESSION_NOTIFICATION_SHOWN_KEY, 'true');
        } catch {
          // ignore
        }
      }

      // Always seed notifiedAlertIdsRef with existing non-reminder items on startup
      // to prevent spamming individual OS notifications on session reload
      for (const item of notifications.items) {
        if (item.category !== 'reminder') {
          notifiedAlertIdsRef.current.add(item.id);
        }
      }
    }
```

## Warnings

### WR-01: Missing icon `/task-management/favicon.ico` causes 404 network errors on notification dispatch

**File:** `src/utils/desktopNotification.ts:28`  
**Issue:** `options.icon` defaults to `payload.icon ?? '/task-management/favicon.ico'`. The file `favicon.ico` does not exist in `public/` (only `favicon.svg`, `pwa-192x192.png`, and `pwa-512x512.png` exist). When notifications fire, the browser attempts to fetch `/task-management/favicon.ico`, resulting in a 404 Not Found error and broken or missing notification badge icons.  
**Fix:**
Default to the valid existing PWA PNG icon (`pwa-192x192.png`):

```typescript
  const defaultIcon =
    typeof import.meta !== 'undefined' && import.meta.env?.BASE_URL
      ? `${import.meta.env.BASE_URL}pwa-192x192.png`
      : '/task-management/pwa-192x192.png';

  const options: NotificationOptions = {
    icon: payload.icon ?? defaultIcon,
  };
```

### WR-02: Missing Dayjs validity check in `formatRemindersForSave` can persist `'Invalid Date'` and throw Zod parse errors

**File:** `src/components/common/RemindersFormList.tsx:62-66`  
**Issue:** If a user enters invalid text into the date or time picker, `rawDate.format('YYYY-MM-DD')` produces the string `'Invalid Date'`. `formatRemindersForSave` checks `if (!rawDate) continue;` but does not check `rawDate.isValid?.()`. When `'Invalid Date'` is passed to `TaskUpdateSchema.parse` or `ProjectUpdateSchema.parse`, Zod fails date validation with a schema error, aborting the modal/drawer save operation.  
**Fix:**
Ensure Dayjs dates are valid before formatting and saving:

```typescript
    const rawDate = rec.date;
    if (!rawDate) continue;
    if (typeof (rawDate as { isValid?: () => boolean }).isValid === 'function') {
      if (!(rawDate as { isValid: () => boolean }).isValid()) continue;
    }

    const dateStr =
      typeof (rawDate as { format?: unknown }).format === 'function'
        ? (rawDate as { format: (fmt: string) => string }).format('YYYY-MM-DD')
        : String(rawDate).slice(0, 10);
```
