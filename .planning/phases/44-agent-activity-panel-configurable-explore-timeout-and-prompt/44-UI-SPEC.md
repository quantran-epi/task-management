# Phase 44 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: a right-side collapsible Agent Activity Panel inside `TeamWorkspace` (Timeline + Prompt log tabs), a configurable `explore_repo` timeout, and the migration of Debug Prompt from modal/menu into the panel. All upstream design decisions are locked in `44-CONTEXT.md` (D-01..D-18); this spec records the token mapping, states, responsive behaviour, accessibility and tab-migration contract before planning, as required by D-13. The HTML draft (`.planning/agent-activity-panel-draft.html`) is the approved **information architecture and visual direction**, not production code — its custom palette (`--accent: #b35e2a`) and font imports are illustrative and are deliberately remapped to the project's real tokens below (D-12).

## Interaction & Layout Contract

### Rail placement and open/close
- Add a **third `Splitter.Panel`** to the existing two-pane `Splitter` in `TeamWorkspace.tsx:794-830`, to the right of the 300px `TeamSidebar` and the center transcript. Do not use a Modal or Drawer (D-09).
- Default **open** on desktop; the only supported runtime is Tauri desktop (CLAUDE.md), so "desktop" is always true. Open state is runtime-only; reuse any existing local UI-state pattern only if already present — add no new persistence mechanism (D-07/D-10).
- Two reachable open/close controls: an explicit button in the rail header (close) and an "Activity" affordance in the workspace header (`TeamWorkspace.tsx:832-918`) that opens the rail. Both keep `aria-expanded`/`aria-controls` in sync with rail visibility (draft `#toggleRail`).

### Header and filter
- Rail header: title "Hoạt động agent" (16px/600) with "Live inspection" eyebrow, close button, then agent filter pills.
- Filter pills: `all` ("Tất cả") + current roster (lead + agents), each with a count. Selecting a pill filters Timeline rows by `agentId`; `all` is default active (D-11, draft `.pills`). Runtime-only state.

### Tabs
- Two tabs: `Timeline` (default) and `Prompt log`, using AntD `Tabs` or the draft's accessible tab strip (`role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`, `role="tabpanel"`). Claude's Discretion permits either; whichever is chosen must keep full keyboard parity.
- Filter pills are Timeline-scoped (they belong to the event list), not Prompt-log-scoped.

### Timeline event rows
- Reverse-chronological, one row per tool call keyed by tool-event **id** (D-05: upsert `call` + `result` into one row; replace label-based `pushStep` dedup). Max 200 rows (`MAX_LIVE_STEPS`, D-07).
- Row shows: status icon (running/done/error), tool name (mono, truncated with ellipsis + Tooltip), agent name, timestamp (`HH:mm:ss`), duration. Expanding reveals "Tham số" (serialized args) and, when present, "Kết quả" preview, each in a capped `<pre>` (D-11).
- Detail blocks are **collapsed by default** and never auto-expand (D-06). Expansion is a `<button aria-expanded aria-controls>` with Enter/Space parity, mirroring `AiChatWidget.ToolEventBadge`.
- Status is derived from the event payload, never a name: `call` without `result` = running; `result` with `{ refused:true, code }`, `error`, or thrown tool error = error; other result = done (D-08).

### explore_repo progress card
- Shown at the top of Timeline while an `explore_repo` call is in flight: tool name, agent, question snippet, "elapsed / deadline" (`HH:MM / MM:SS`), and a progress bar filled from elapsed ÷ `timeoutSeconds` in accent color (D-11, draft `.progress-card`).
- The deadline reflects the phase-44 configurable timeout (D-01: `timeoutSeconds`, 60..900, default 300). This card shows the app-level call and deadline only — never nested remote CLI steps (out of scope).

### Argument/result capping and safety
- Serialize args and result preview to strings and cap at **8 000 chars each** before storing in runtime state (D-06). The model still receives the full tool result; the cap is preview-only.
- Render previews as text / `renderSafeMarkdown` (`src/utils/markdown.ts`) never `dangerouslySetInnerHTML` on raw tool output. Treat all tool content as untrusted data, never instructions. Add a "… (đã rút gọn)" marker when a value was capped.

### Tab migration (exact decision, D-14/D-15/D-16)
- **Keep** `debugLogs` capture, type (`TeamDebugLog`, `TeamWorkspace.tsx:120`) and data shape unchanged. Move only its *presentation* into the rail's Prompt log tab, preserving each entry's `agentKind`, `agentName`, `timestamp`, `model`, `toolNames`, `text` and `systemMessages` (mirror the existing modal at `:1111-1124`).
- **Remove** the `Debug Prompt (${debugLogs.length})` dropdown item (`:894-899`) and the `<Modal title="Debug: Lịch sử Prompt gửi tới AI trong nhóm">` (`:1111-1124`), plus now-unused state/handlers/imports (`debugModalOpen`, `BugOutlined`, etc.).
- **Do not** touch `AIDebugModal.tsx` used by the ordinary chat drawer (`AIChatDrawer.tsx:2282`).
- With the rail closed, Prompt log is intentionally unreachable — the Activity affordance is the only path back (D-16). The "Xóa nhật ký debug" action moves into the tab with a Popconfirm (Copywriting row).

### Compact fallback
- The existing `TeamActivityIndicator` popover may remain for at-a-glance status, but if it does, it must read from the same `AgentRunState.steps` upsert path and must not become a second source of truth (Claude's Discretion). Prefer leaving it unchanged so its dedup path is not disturbed.

### Responsive / overflow
- Tauri desktop is the only supported runtime; windows may still be resized narrow. Every flex/grid child of the rail gets `min-width: 0`; long tool names/previews use `overflow-wrap: break-word` and scroll in their own `<pre>` (`max-height`, `overflow: auto`). The rail must never cause horizontal page/document overflow (D-12) — `workbench-tokens.css` already locks `html/body/#root` to `overflow: hidden`.
- At window widths below ~900px (draft breakpoint), prefer the rail closed by default and reopened via the Activity affordance; when open it stacks below the transcript with its own vertical scroll. Single-column stacking is a graceful degradation, not a PWA/mobile target.

### Accessibility
- Tabs: `role="tablist"` / `tab` / `tabpanel`, `aria-selected`, `aria-controls`; arrow-key navigation if using a custom strip.
- Expandable rows: `<button aria-expanded aria-controls>` with Enter/Space (D-11), matching `ToolEventBadge`.
- Filter pills: grouped (`role="group" aria-label="Lọc theo agent"`), single-select, active state exposed.
- Status conveyed by both icon and text label (never color alone). Focus rings use accent `#5b4fe8`, `outline-offset: 2px`.
- Reduced-motion: no new non-essential transitions/animations; honour `prefers-reduced-motion`.
- Rail and tab panels have accessible names (`aria-label="Agent activity detail"`).
