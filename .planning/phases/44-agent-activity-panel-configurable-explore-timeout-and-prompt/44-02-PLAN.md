<objective>
Turn the coordinator's `onToolEvent` stream into a single, capped, id-keyed timeline of tool calls
and results that the new panel will render. Extend `AgentLiveStep` additively (D-04), consume both
call and result events (D-05), cap previews and the row count (D-06/D-07), and derive status from the
payload (D-08) — all runtime-only, with no Dexie or backup changes.

Purpose: today result events are discarded and calls are deduplicated by label, so the app cannot
show durations, statuses or a reliable tool history. The panel (plan 03) depends on this single
data path being correct; the compact popover must keep working from the same rows (D-04/Pitfall 3).

Output: an additive type change, an id-based upsert in the coordinator, and focused coordinator
tests proving pairing, capping, status derivation and popover compatibility.
</objective>
