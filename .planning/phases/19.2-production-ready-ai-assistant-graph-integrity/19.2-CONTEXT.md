## Phase Boundary

Phase 19.2 delivers the complete, production-ready AI Assistant and Graph Integrity system for TaskMate. It transforms the AI Chat Drawer from an experimental prototype into a dependable vertical system for one non-technical user asking or commanding TaskMate naturally in any language.

Phase 19.2 owns:
1. **Mandatory LLM-first client state machine**: Strict 5-intent taxonomy (`operate_taskmate`, `query_taskmate`, `query_knowledge`, `mixed`, `clarify`) reasoned exclusively by LLM. No verb lists, keyword lists, regex classifiers, or route-picker bypasses for intent.
2. **Fail-closed LLM and graceful daemon fallback**: LLM unavailable/unconfigured/schema-invalid stops immediately and marks AI unavailable; knowledge-server/Neo4j down while LLM lives falls back to local IndexedDB BM25.
3. **Exact conversational clarification loop**: Model's exact `clarify_question` rendered as status; user follow-up appends to original request and re-enters LLM intent reasoning; repeated clarify turns capped to prevent loops.
4. **Answer truthfulness as a data contract**: Immutable citations for material claims; structured confidence (`high | medium | low | unknown`); separate `hypotheses` array restricted to explicit user speculation requests (`LOW` confidence only); explicit `NO_EVIDENCE` for missing facts; zero invented claims; citation repair without arbitrary fallback.
5. **Safe TaskMate operations**: Single read tool path for `query_taskmate`; mutation confirmation gate preserved; response buffer reset per tool turn; no redundant post-tool synthesis.
6. **Graph build runtime & safe activation**: Explicit dependency injection for embeddings and prose extraction; general document extraction without hardcoded procedure constants; two-phase candidate preparation, candidate-scoped validation, atomic activation, rollback within grace period, and leak-free snapshot cleanup.
7. **Plan-driven Neo4j retrieval integrity**: Idempotent indexes; fact-to-chunk `SUPPORTED_BY` evidence closure; ordered multi-hop traversal matching `LogicalQueryPlan.traversalSteps` without undirected catch-alls; LLM entity candidate disambiguation without keyword lists.
8. **First-class TaskMate ↔ knowledge links**: IndexedDB `KnowledgeLink` schema, Dexie migration, backup round-trip, cascade cleanup, AI linking tools with mutation confirmation, and retrieval hint propagation.
9. **Observability, Kubernetes hardening & test gates**: Structured logging chokepoints (`[ROUTE]`, `[RETRIEVE]`, `[TOOL]`, `[SYNTHESIS]`, `[PUBLISH]`) with correlation IDs and strict redaction; internal authenticated readiness probes; Node CLI smoke runner; Playwright browser E2E test suite; zero red release gates.
10. **Real Neo4j and 9router acceptance**: Read-only discovery baseline, isolated canary Document Set rebuild/activate/rollback, 11 live retrieval cases, and restart durability proof.

Phase 19.2 does **not** own:
- 30–50 question benchmark quality scoring and threshold calibration (strictly Phase 20).
- Anthropic SDK integration (strictly forbidden; preserve provider-neutral 9router/OpenAI-compatible clients).
- Replacing local IndexedDB as canonical TaskMate storage (Neo4j remains rebuildable projection).

<decisions>
## Implementation Decisions

### Intent routing and client state machine
- **D-01:** Every AI turn begins with `routeIntent()` LLM reasoning. No verb lists, keyword lists, regex classifiers, or deterministic bypasses for intent classification.
- **D-02:** Fixed 5-intent taxonomy: `operate_taskmate | query_taskmate | query_knowledge | mixed | clarify`.
- **D-03:** Technical identifiers (e.g. `MAIN1.FCL_CYCLE_COUNTER`, `PRC_PROCESS:60000006`) are taught through few-shot examples and system rules to classify as `query_knowledge`, not `clarify`. Deterministic fast path operates server-side **only after** LLM intent is known.
- **D-04:** LLM unreachable, unconfigured, or schema-invalid after one bounded repair: fail-closed immediately. Set state to `AI unavailable`, execute no tools, no local BM25 synthesis, and no mutations.
- **D-05:** Knowledge server / Neo4j unreachable while LLM is reachable: execute local IndexedDB BM25 fallback over resolved document set members with explicit local authority labeling.
- **D-06:** Clarification displays model's exact `clarify_question` with `role="status"`. User answer is appended to the original query (`{originalQuery}\n\nBổ sung: {answer}`) and re-enters `routeIntent`. Remove generic route override chips (`routeOverride`, operational/knowledge chips). Repeated clarify turns are capped at 2 before actionable failure.
- **D-07:** Tool loop hardening: Reset assistant response buffer on each tool iteration. Eliminate redundant post-tool synthesis when the tool loop already produced final user-facing text.

### Grounded truth, citations, and speculation contract
- **D-08:** Material factual claims require immutable citations to source chunks (`DIRECT` or `INFERRED`).
- **D-09:** Output schema enforces structured answer confidence: `high | medium | low | unknown`, derived from evidence coverage and conflict presence.
- **D-10:** Speculation is isolated in a dedicated `hypotheses` array, permitted **only** when `speculation_requested=true` (detected by LLM intent). Hypotheses must be labeled as speculation, carry `LOW` confidence, and never cite evidence or masquerade as verified facts.
- **D-11:** When evidence is absent and speculation was not requested: return `NO_EVIDENCE`, confidence `unknown`, explain missing information, and emit zero invented claims.
- **D-12:** Override / supersession validation requires structured document-set `scopeProof.overrideRelation === 'SUPERSEDES'` or cited policy/release/migration evidence, not a domain graph edge and not superficial Vietnamese wording such as `thay thế`.
- **D-13:** Citation repair normalizes valid chunk IDs but never attaches an arbitrary first citation to unsupported claims; ungrounded claims move to `unsupportedParts`.

### Graph build runtime and general extraction
- **D-14:** `GraphBuildService` requires explicit dependency injection at server startup: `GraphRepository`, `SnapshotStore`, `EmbeddingProvider` (identical to retrieval provider), and `ProseExtractionConfig`. Test-only fallback constructors must not run in production.
- **D-15:** Two-phase candidate/activation lifecycle:
  1. `prepareCandidate`: deterministic table extraction + prose extraction + vector generation + index validation -> candidate status `READY`.
  2. Candidate smoke validation runs against candidate snapshot without mutating active graph pointer.
  3. `activateCandidate`: atomic compare-and-swap of active snapshot pointer; stores previous snapshot ID and rollback grace expiry.
  4. `rollbackCandidate`: authenticated idempotent endpoint restoring prior active snapshot during grace period.
  5. Deferred cleanup: snapshot deletion occurs only after rollback grace expires and no read leases remain.
- **D-16:** General extraction: Remove hardcoded document-specific constants from `extraction.ts`. Derivations use header/table schema and structural context. Uncovered paragraphs and tables route through prose extraction with closed ontology and exact quoted evidence.

### Neo4j retrieval and query planning
- **D-17:** Neo4j schema includes idempotent indexes on `(graphSnapshotId, urn)`, `(graphSnapshotId, normalizedKey)`, canonical name, fact key, evidence fact, and chunk key/document range.
- **D-18:** Evidence-to-chunk closure: Evidence records link to overlapping immutable chunks (same document, line/offset range) via snapshot-scoped `SUPPORTED_BY` edges or chunk-key mappings, ensuring all traversable facts carry real chunk IDs.
- **D-19:** Traversal executes validated `LogicalQueryPlan.traversalSteps` in order: relation type, direction, target kind, step hops, overall depth (<= 3), snapshot pin, caps (`maxNodes=100`, `maxEdges=200`), and deterministic deduplication. Remove catch-all undirected one-hop queries.
- **D-20:** Delete keyword filters (`processKeywords`, `stepKeywords`, keyword->kind heuristics) from `queryPlanning.ts`. Ambiguous candidate URNs are sent to 9router planner in strict schema. If planner cannot disambiguate after one repair, return `NEEDS_CLARIFICATION`.

### First-class TaskMate ↔ knowledge links
- **D-21:** Add dedicated IndexedDB `KnowledgeLink` table in `SCHEMA_V11`, migrating from verified live `SCHEMA_V10`: stable link UUID, TaskMate entity type/ID (`task | project | milestone`), knowledge set ID, optional stable graph URN, optional document ID, display label, timestamps. If schema changes before Plan 19.2-07 executes, stop and rebase this migration rather than reusing an occupied version.
- **D-22:** TaskMate data remains canonical store; graph URNs survive graph snapshot rebuilds. Cascade deletion cleans links on task/project/milestone deletion. Backup export/import validates link schema.
- **D-23:** Linking AI tools (`link_entities_to_doc`, `unlink_document`, entity linking) require mutation confirmation.
- **D-24:** Scoped chat (Task/Project/Milestone) injects linked set IDs and URNs as retrieval hints. Server validates hinted URNs in active snapshot; stale links report degradation and fall back to standard entity resolution. Local fallback narrows BM25 to linked documents first.

### Observability, Kubernetes, and CI release gates
- **D-25:** Structured logging across client (`[ROUTE]`, `[RETRIEVE]`, `[TOOL]`, `[SYNTHESIS]`) and server (`[RETRIEVE]`, `[PUBLISH]`) with correlation ID, phase, outcome, latency, and counts. Zero sensitive text, tokens, prompts, or DLP content in logs.
- **D-26:** Update `k8s/knowledge-server.yaml` and runbooks: explicit embedding/prose configuration, authenticated internal readiness probe (Neo4j connection + index online + model ready) distinct from liveness probe.
- **D-27:** Standalone acceptance CLI (`knowledge-server/src/retrieval/acceptanceCli.ts`) built with Node `util.parseArgs`: supports federated requests, set tier assignments, metadata-only output, and nonzero exit code on assertion failure.
- **D-28:** Playwright browser test suite covering client LLM state machine, clarify loop, unavailable state, TaskMate read/mutation confirmation, citations, and local BM25 fallback.
- **D-29:** Zero red release gates: Both root and knowledge-server builds clean, all Vitest tests green, Playwright suite green, live acceptance CLI green against real Neo4j/9router, canary activation/rollback proven.

## Existing Code Insights

### Client Subsystem (`src/`)
- `src/services/ai/intentRouter.ts`: Implements LLM-first intent classification with `IntentResultSchema` and `INTENT_TAXONOMY`. Needs `speculation_requested: boolean`, multilingual few-shot examples, and strict error handling.
- `src/components/ai/AIChatDrawer.tsx`: Central chat controller. Needs complete removal of `routeOverride` chips, inline rendering of exact `clarify_question`, turn loop capping, and response buffer reset.
- `src/services/ai/groundedTurn.ts`: Orchestrates intent routing, scope resolution, federated retrieval, local fallback, and synthesis. Needs explicit `speculation_requested` propagation and fail-closed handling.
- `src/services/ai/groundedSynthesis.ts`: Synthesizes final grounded answer with few-shot prompt and output normalization. Needs structured confidence, isolated hypotheses, and relation-backed override validation.
- `src/db/schema.ts` & `src/db/index.ts`: Database definition. Live code is `SCHEMA_V10`; Phase 19.2 reserves `SCHEMA_V11` for `knowledgeLinks`. Re-verify immediately before execution and stop on version collision.

### Server Subsystem (`knowledge-server/`)
- `knowledge-server/src/main.ts`: Bootstrap and configuration parsing. Needs prose extraction configuration, strict dependency injection into `GraphBuildService`, and removal of test fallback constructors in production path.
- `knowledge-server/src/services/graphBuildService.ts`: Rebuild state machine. Needs two-phase candidate preparation and activation, rollback endpoint support, and prose extraction integration.
- `knowledge-server/src/graph/extraction.ts` & `src/ai/proseExtraction.ts`: Extraction engines. Needs removal of hardcoded procedure names and dynamic heading/table schema resolution.
- `knowledge-server/src/graph/neo4jRepository.ts`: Neo4j driver gateway. Needs multi-hop traversal with path records, chunk-key / `SUPPORTED_BY` links, and idempotent composite indexes.
- `knowledge-server/src/retrieval/queryPlanning.ts` & `nineRouterQueryPlanner.ts`: Query planner adapter. Needs removal of keyword lists (`processKeywords`, `stepKeywords`) and candidate resolution passed directly to LLM planner.
