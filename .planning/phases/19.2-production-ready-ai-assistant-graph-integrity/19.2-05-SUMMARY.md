# Phase 19.2 Plan 05: General Markdown & Table Extraction without Hardcoded Domain Shortcuts Summary

Generalized deterministic Markdown and table extraction engine in knowledge-server without domain shortcuts, backed by dynamic schema parsing and ontology-bounded prose extraction.

## Objective Achieved

Refactored knowledge extraction from domain-specific pilot logic into a general-purpose technical document extraction engine:
1. Eliminated all hardcoded container IDs (`60000006`), procedure literals (`PRC_FCL_CALCULATE_LIMIT`, `CRD_PRC_BILLING_PKG`, `FCL_PRC_CYCLE_COUNTER_PKG`), and Vietnamese domain tokens (`Hạch toán`, `Chu kỳ tính lãi`) from `knowledge-server/src/graph/extraction.ts`.
2. Implemented dynamic schema-based column detection (`detectTableSchema`) that classifies tables using header semantics across English and Vietnamese naming conventions.
3. Validated table-less Markdown ingestion and uncovered paragraph collection with exact quote evidence and entity quarantine safety.

## Key Changes

### 1. General Dynamic Table Schema Detection (`knowledge-server/src/graph/extraction.ts`)
- Replaced domain-specific table dispatch with role-based detection:
  - `idIdx`: matches `ID`, `CODE`, `STEP_ID`, `BIND_ID`, `MA_BUOC`, `MA_TIEN_TRINH`, etc.
  - `nameIdx`: matches `PROCEDURE_NAME`, `PROCEDURE`, `NAME`, `TEN_BUOC`, `DISPLAY_NAME`.
  - `targetIdx`: matches `TARGET`, `DOI_TUONG`, `DICH`, `RECEIVER`, `COMPONENT`, `PROCESS_ID`.
  - `orderIdx`: matches `EXEC_ORDER`, `ORDER`, `EXEC`, `THU_TU`, `SEQUENCE`.
  - `typeIdx`: matches `CYCLE_TYPE`, `TYPE`, `LOAI`.
  - `writesIdx`: matches `WRITES`, `GHI`, `WRITE_TO`, `TARGET_TABLE`.
- Disambiguated step bindings from invoked target processes by inspecting presence of bind columns (`BIND_ID`, `STEP_ID`, `MA_BUOC`).

### 2. Comprehensive Acceptance & Unit Test Suites
- Created `knowledge-server/tests/generalDocumentExtraction.test.ts`:
  - Regex AST scan verifying 0 hardcoded banking/domain strings in `extraction.ts`.
  - English workflow table extraction test (`Order Processing System`).
  - Vietnamese workflow table extraction test (`Quy trình thanh toán`).
  - Table-less document extraction verifying prose extraction with `INFERRED` classification and exact character range grounding.
  - End-to-end multi-lingual non-SHB microservice architecture fixture satisfying `GraphNodeSchema` and `GraphEvidenceRecordSchema`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Disambiguated Bind ID and Target Process ID in step table detection**
- **Found during:** Task 1 & Task 2 verification
- **Issue:** Tables containing both `Bind ID` and `PROCESS_ID` classified `PROCESS_ID` as the primary step ID rather than the invocation target, causing `INVOKES` relation omissions in pilot regression tests.
- **Fix:** Added disambiguation logic to `detectTableSchema` to assign `Bind ID` to `idIdx` and `PROCESS_ID` to `targetIdx` with index exclusion.
- **Files modified:** `knowledge-server/src/graph/extraction.ts`

**2. [Rule 1 - Bug] Added CODE column alias to idIdx for Status table detection**
- **Found during:** Task 3 verification
- **Issue:** Tables with columns `| Code | Name |` under `# Status Codes` were not matching `idIdx`, resulting in missing `Status` nodes in non-SHB fixture.
- **Fix:** Added `/^CODE$/` and `/MA/` patterns to `idIdx` regex in `detectTableSchema`.
- **Files modified:** `knowledge-server/src/graph/extraction.ts`

**3. [Rule 1 - Bug] Fixed exact optional property type and unused imports in knowledge-server build**
- **Found during:** Build verification
- **Issue:** TypeScript error on `ParsedStep.targetId` under `exactOptionalPropertyTypes: true` and unused imports in `neo4jRepository.ts`.
- **Fix:** Explicitly typed `targetId?: string | undefined` in `ParsedStep` and removed unused imports in `neo4jRepository.ts`.
- **Files modified:** `knowledge-server/src/graph/extraction.ts`, `knowledge-server/src/graph/neo4jRepository.ts`
