# Phase 19.2 Plan 07: Client Telemetry, Knowledge Links, AI Tools, and Scoped Grounding Integration Summary

First-class TaskMate ↔ Knowledge Links architecture implementing SCHEMA_V11, cascade lifecycle deletion, encrypted backup serialization, mutation-guarded AI linking tools, UI management, and scoped retrieval context hints.

## Overview of Tasks Completed

### Task 1: Dexie SCHEMA_V11 migration, KnowledgeLink model, repository, and cascade deletion
- Defined `KnowledgeLink` and `TaskMateEntityType` in `src/types/models.ts`.
- Added `SCHEMA_V11` to `src/db/schema.ts` and registered `this.version(11).stores(SCHEMA_V11)` in `src/db/index.ts`.
- Created repository `src/db/repositories/knowledgeLinkRepo.ts` with compound key builder `buildKnowledgeLinkKey`, validation requiring `urn` or `docId`, and entity/set query helpers.
- Updated `src/db/repositories/cascadeRepo.ts` so `deleteProjectWithCascade`, `deleteMilestoneWithCascade`, and `deleteTaskWithAllocations` atomically delete matching `knowledgeLinks` in the same Dexie transaction.
- Updated backup definitions and schemas in `src/types/backup.ts`, `src/validation/backupSchemas.ts`, `validateBackup.ts`, `exportBackup.ts`, and `restoreBackup.ts` with round-trip Zod validation.
- Verified with `tests/db/knowledgeLinkMigration.test.ts` and `tests/db/knowledgeLinkRepo.test.ts`.
- Commit: `2d4cf60`

### Task 2: AI linking tools with mutation confirmation and UI in LinkedKnowledgeSection
- Registered `link_taskmate_to_knowledge` and `unlink_taskmate_knowledge` in `AI_DATABASE_TOOLS` and `MUTATION_TOOLS` (`isMutationTool: true`).
- Implemented tool executions in `executeAiDatabaseTool` and provided descriptive Vietnamese mutation diffs in `describeToolMutation` and `describeToolMutationWithContext`.
- Upgraded `LinkedKnowledgeSection` to query live Dexie `knowledgeLinks` using `useLiveQuery`, rendering dual badges (documents in purple with quick preview; graph URNs in geekblue with monospace tooltip) and `Popconfirm` deletion.
- Added component test `tests/components/LinkedKnowledgeSection.test.tsx` and tool test `tests/ai/knowledgeLinkTools.test.ts`.
- Commit: `e67d38b`

### Task 3: Scoped retrieval context hints and mixed evidence grounding integration
- Extended `FederatedRetrievalRequestSchema` in both client `src/services/knowledge/retrievalProtocol.ts` and server `knowledge-server/src/types/retrievalProtocol.ts` with optional `contextHints`.
- Extended `GroundedTurnInput` with optional `scopedEntity: { type, id }` and added `loadKnowledgeLinks` hook to `GroundedTurnDeps`.
- Updated `executeGroundedTurn` to load active links, extract `setIds`, `urns`, and `docIds`, and forward them as `contextHints` into `retrieveFederated`.
- Updated `runLocalBm25` in `src/services/search/localGroundedRetrieval.ts` to accept `prioritizedDocIds` and prioritize linked documents in local fallback.
- Added graceful degradation so failing/stale links or missing URNs on the server never crash the turn.
- Verified with `tests/ai/groundedTurn.test.ts` and `tests/search/localGroundedRetrieval.test.ts`.
- Commit: `03ff01c`
