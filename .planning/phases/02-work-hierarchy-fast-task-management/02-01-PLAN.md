    - Test 6: Transaction failure rolls back completely without partial state deletion.
  </behavior>
  <action>
    Create src/db/repositories/cascadeRepo.ts:
    - deleteProjectWithCascade(projectId: string, mode: 'cascade' | 'orphan'): Promise<void>
      Wrap in db.transaction('rw', [db.projects, db.milestones, db.tasks, db.plannedAllocations], async () => { ... }).
      Find all milestones where projectId === projectId.
      Find all child tasks where task.projectId === projectId OR task.milestoneId in milestoneIds.
      If mode === 'cascade':
        Find all plannedAllocations where taskId in taskIds and delete them.
        Bulk delete tasks, bulk delete milestones, delete project.
      If mode === 'orphan':
        Update child tasks to projectId = undefined, milestoneId = undefined, updatedAt = now.
        Bulk delete milestones, delete project.
    - deleteMilestoneWithCascade(milestoneId: string, mode: 'cascade' | 'orphan'): Promise<void>
      Wrap in db.transaction('rw', [db.milestones, db.tasks, db.plannedAllocations], async () => { ... }).
      Find child tasks where task.milestoneId === milestoneId.
      If mode === 'cascade':
        Delete associated plannedAllocations.
        Bulk delete tasks, delete milestone.
      If mode === 'orphan':
        Update child tasks to milestoneId = undefined (retain task.projectId).
        Delete milestone.
    - deleteTaskWithAllocations(taskId: string): Promise<void>
      Wrap in db.transaction('rw', [db.tasks, db.plannedAllocations], async () => { ... }).
      Delete plannedAllocations where taskId === taskId.
      Delete task from db.tasks.
      
    Write comprehensive integration tests in tests/db/cascadeRepo.test.ts verifying both cascade and orphan modes, foreign key cleanup, and rollback on error.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User Input -> Repositories | Untrusted strings, URLs, dates, and numbers cross into persistence tier |
| Reparenting -> Storage | Hierarchy reassignment must not corrupt entity IDs or create invalid parent links |
| Cascade Deletion -> Multi-Table Stores | Deletion across projects, milestones, tasks, and allocations must not leave dangling records |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | src/validation/schemas.ts | mitigate | Validate all inputs with Zod schemas at repository boundary; reject invalid dates, negative minutes, and non-URL links |
| T-02-02 | Integrity / Tampering | src/db/repositories/taskRepo.ts | mitigate | Reparenting preserves original task.id; resets milestoneId to undefined if projectId changes (D-10) |
| T-02-03 | Denial of Service / Inconsistency | src/db/repositories/cascadeRepo.ts | mitigate | Execute cascade and orphan deletions within atomic Dexie db.transaction('rw', ...) ensuring plannedAllocations cleanup (D-16) |
| T-02-04 | Tampering | src/utils/time.ts | mitigate | Clamp estimate parsing to 0-6000 minutes; reject NaN, non-integers, and negative values (D-24) |
| T-02-SC | Tampering | Package dependencies | mitigate | Zero external package additions in Phase 2; use existing installed libraries (Dexie, Zod, Dayjs) |
</threat_model>
