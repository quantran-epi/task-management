## Phase Goal

**As a** personal task planner user, **I want to** push my encrypted backup to GitHub and have collisions safely detected, **so that** I never accidentally overwrite a newer remote backup made from another device.

## Artifacts this phase produces

### Types & Interfaces
- `GitHubConfig` in `src/services/github/types.ts`: Interface containing `owner`, `repo`, `branch`.
- `RemoteFileMetadata` in `src/services/github/types.ts`: Interface containing `exists`, `sha`, `size`, `contentBase64`, `lastModified`.
- `UploadBackupResult` in `src/services/github/types.ts`: Interface containing `sha`, `commitSha`, `exportedAt`.
- `SyncStatus` in `src/services/github/types.ts`: Union `'idle' | 'testing' | 'pushing' | 'pulling' | 'conflict' | 'error'`.

### Functions & Utilities
- `fetchRemoteBackupMetadata(config: GitHubConfig, token: string): Promise<RemoteFileMetadata>` in `src/services/github/githubApi.ts`: Queries `.task-management/backup.enc.json` via GET request. Returns `exists: false` on 404 per D-09.
- `uploadEncryptedBackup(config: GitHubConfig, token: string, contentBase64: string, remoteSha?: string, message?: string): Promise<{ sha: string; commitSha: string }>` in `src/services/github/githubApi.ts`: Sends PUT request to GitHub Contents API with Base64 payload and optional SHA for update. Throws `CONFLICT_409` on HTTP 409.
- `testGitHubConnection(config: GitHubConfig, token: string): Promise<{ ok: boolean; message: string; remoteSha?: string; fileExists: boolean }>` in `src/services/github/githubApi.ts`: Pre-flight check verifying token validity, branch existence, and remote backup status per D-05.
- `executeGitHubBackupPush(db: TaskPlannerDatabase, config: GitHubConfig, token: string, passphrase: string, expectedRemoteSha?: string, forceOverwrite?: boolean): Promise<UploadBackupResult>` in `src/services/github/githubSyncService.ts`: Exports local domain tables, encrypts payload, performs pre-flight SHA check, uploads to GitHub, updates `db.settings`, and logs audit trail to `db.backupMetadata` per D-06, D-09, D-13, D-17.

### Components
- `GitHubConflictModal` in `src/components/settings/GitHubConflictModal.tsx`: Ant Design modal presenting SHA conflict alert, offering Pull & Preview, Force Overwrite (gated by typing `OVERWRITE`), or Cancel per D-07, D-08.
- `GitHubSyncCard` in `src/components/settings/GitHubSyncCard.tsx`: Ant Design card displaying connection status badge, 7-character truncated SHA, last synced timestamp, and "Đẩy lên GitHub" trigger button per D-04, D-17.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → GitHub Contents API | Encrypted backup JSON envelope is transmitted over HTTPS to GitHub REST API |
| Memory → GitHub API | GitHub PAT is sent in HTTPS Authorization header directly to api.github.com |
| Remote SHA → Push Execution | Untrusted remote state is inspected via pre-flight GET before determining push safety |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-05 | Information Disclosure | `githubApi.ts` | mitigate | Strip GitHub token from error objects and reject responses; never log API request headers or bodies (SYNC-01) |
| T-08-06 | Tampering | `githubSyncService.ts` | mitigate | Pre-flight GET checks current blob SHA against `last_synced_sha` before pushing; halts on mismatch (SYNC-06, D-06) |
| T-08-07 | Repudiation | `githubSyncService.ts` | mitigate | Log all successful pushes into `db.backupMetadata` with timestamp, SHA, and record count for local auditability (D-17) |
| T-08-08 | Denial of Service | `GitHubConflictModal.tsx` | mitigate | Require explicit typing of `OVERWRITE` keyword before allowing destructive remote overwrite (D-08) |
| T-08-SC | Tampering | npm dependencies | accept | Native `fetch` used; no Octokit or third-party HTTP libraries added |
</threat_model>
