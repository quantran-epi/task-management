<objective>
Make the AI Chat Drawer genuinely per-tab: seed runtimes, route all transient request state through them, and replace the drawer-global send guard with a per-tab guard.

Purpose: SC-2 fails because `useTabRuntimes.initialize()` has zero callers and `patch()` no-ops on unseeded tabs, so `tabStatuses` is always `idle`; the single `if (isStreaming || Boolean(groundedLoadingStatus)) return;` guard makes D-06/D-10 concurrency impossible. This plan closes that gap without touching AI core routing.
Output: Seeded runtimes, per-tab streaming/loading/error/attachment/confirmation state, per-tab send guard, per-tab stop, and isolation regression tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Tab A request -> Tab B UI | Shared drawer state can leak streaming text, errors, or confirmation prompts across tabs. |
| Stop button -> other tab requests | Aborting by drawer-global ref would kill unrelated tab work. |
| Request registry -> tab status | Unseeded runtimes let status badges lie. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-25.1-39 | Information Disclosure | drawer transient state | mitigate | Every transient write keyed by captured `turnTabId`; render reads only `tabRuntimes.get(activeTabId)`. |
| T-25.1-40 | Denial of Service | global send guard | mitigate | Per-tab `hasActive(turnTabId)` guard; concurrency test submits in both tabs. |
| T-25.1-41 | Tampering | stop / close ownership | mitigate | `abortTab(activeTabId)` + runtime `requestController`; unmount iterates snapshot only. |
| T-25.1-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependency; no package install. |
</threat_model>
