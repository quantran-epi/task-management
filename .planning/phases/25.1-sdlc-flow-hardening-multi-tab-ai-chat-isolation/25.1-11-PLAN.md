<objective>
Make the AI Chat Drawer genuinely per-tab: seed runtimes, route all transient request state through them, and replace the drawer-global send guard with a per-tab guard.

Purpose: SC-2 fails because `useTabRuntimes.initialize()` has zero callers and `patch()` no-ops on unseeded tabs, so `tabStatuses` is always `idle`; the single `if (isStreaming || Boolean(groundedLoadingStatus)) return;` guard makes D-06/D-10 concurrency impossible; and `currentTurnAbortRef` (drawer-global, line ~318) makes every new send abort the previous turn in whichever tab started it. This plan closes that gap without touching AI core routing.
Output: Seeded runtimes, per-tab streaming/loading/error/attachment/draft/confirmation state, per-tab send guard, per-tab stop, `isCurrent` commit gate, and isolation regression tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Tab A request -> Tab B UI | Shared drawer state can leak streaming text, errors, drafts, or confirmation prompts across tabs. |
| Stop button -> other tab requests | Aborting by drawer-global ref (`currentTurnAbortRef`) would kill unrelated tab work. |
| Request registry -> tab status | Unseeded runtimes or unwritten `requestController` let status badges and stop buttons lie. |
| Superseded request -> history | A late-arriving stream can commit assistant output after the user stopped or the tab closed. |
