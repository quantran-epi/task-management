## What changed

### CR-09 — history reset keeps the tab/thread invariant

`clearAllChatHistory` (`src/db/repositories/chatRepo.ts`) now clears `chatTabs` and every
`sdlc_workflow:*` setting in the same transaction that clears `chatMessages`/`chatThreads`, so an
export taken after the reset passes `validateBackup` instead of being rejected with
`ChatTab references threadId ... not found`. The drawer's `handleClearAllHistory` discards the
per-tab runtimes, drops the cached SDLC coordinator, and rebuilds the scope's bootstrap tab (and
re-selects the SDLC tab for project scopes) because the `initTabs` effect will not re-run.

### CR-10 / WR-12 — tab lifecycle invariants

`deleteChatTab` replaces the final ordinary tab with `active: !stillActive`, so closing an inactive
ordinary tab under an active SDLC tab no longer leaves two `active: true` rows (which would fail
`Multiple active tabs for scope` in the app's own backup validator). `getOrCreateActiveChatTab` now
applies the same claimed-thread check the SDLC path uses and uses a `:chat:<id>` scopeKey whenever
the scope already has threads, so it can never collide with a claimed legacy `project:<id>` thread
(unique `chatTabs.threadId` / `chatThreads.scopeKey`).

### CR-11 — clarification and routed scope are per-tab

`transientClarifyMessage` became `clarifyByTab: Record<tabId, state>`. The send path reads only
`clarifyByTab[turnTabId]`, writes results back to that tab, and clears the tab's entry when the tab
closes, when the scope changes, or after a full history reset. `ChatMessageList` no longer matches
on `msg.content === originalQuery`; the card renders once from the active tab. The residual
drawer-global `latestRoutedScope` (REVIEW-4 CR-01 note) is now `routedScopeByTab`, so the scope chips
above the transcript follow the active tab.

### WR-08 — note-source picker reset

The reset effect fires only on the closed→open transition (`wasOpen` ref), so a drawer re-render no
longer discards checkboxes ticked before Apply.

### WR-09 — transient writes bind to the owner tab

Every `patchGroundedLoading` / `patchTurnError` call in a turn now passes the captured `turnTabId`
rather than defaulting to the late-bound `turnTabIdRef.current`.

### WR-11 — failed `begin` fails closed

The tab request is claimed before the user row is saved (moving the registry claim above the
`createOrGetThread` / retry-read / `saveMessage` awaits), and a `null` from `begin` now writes a
per-tab error and returns instead of running a detached, unpersisted turn.

### WR-10 — one store for restored workflow state

`replaceTables` mirrors each restored SDLC tab's `workflowState` into
`sdlc_workflow:<projectId>:<threadId>` — the key the drawer actually restores — letting the
validator's `interrupted` checkpoint win over a stale `running` one. `ImportPreviewModal` now warns
about missing sources and blocked tabs before the user confirms.

### WR-13 — Continue never strands a `running` checkpoint

`handleSdlcCheckpointContinue` refuses a missing-source resume *before* `resumeCheckpoint()` (so the
checkpoint stays `interrupted` and the banner stays operable) and releases a still-`running`
checkpoint after an early-returning send. `restoredMissingSources` moved above the callback so it
can be read there.

### WR-14 — snapshot captures the running timer

`captureSnapshot` now reads `activeTimers`, which `replaceTables` clears for both import and
rollback, so import → rollback restores the in-progress timer and its segments.

### WR-15 — one secret deny-list, row-safe hydration

`localSqlitePersistence` reuses the exported `UNSAFE_OR_EPHEMERAL_SETTING_KEYS`, so
`ninerouter_api_key`, `knowledge_server_token`, and `image_api_key` are no longer serialized into
`tauri_sqlite_queue` or the SQLite file. `hydrateDexieFromSqlite` wraps each row: a malformed row is
skipped and reported instead of aborting the batch after partial writes.

### WR-16 — tab strip ARIA

Removed the dangling `aria-controls` (no element carries a `chat-tabpanel-<id>`), documented the
existing Delete/Backspace close path via `aria-description`, and replaced the close `<span
role="button">` with a real `<button type="button" tabIndex={-1}>`.
