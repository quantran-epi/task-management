<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Provider/tool stream → transient tab buffer | Untrusted partial text, tool results, and generated files must not become canonical history before full validation. |
| Runtime request registry → Dexie commit | Late, aborted, or stale completions must not overwrite newer state or wrong-tab history. |
| Error/diagnostic object → UI/log | Raw errors may contain endpoint keys, prompts, source excerpts, tool arguments, or stack details. |
| Close-tab UI → active request/delete | Deletion can orphan network/tool work unless owning request abort completes first. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-25.1-04 | Information Disclosure | runtime error cards/log calls | mitigate | Map failures to enumerated codes/copy; never render or persist raw error, prompt, source, endpoint, token, tool arguments, or stack. |
| T-25.1-05 | Tampering | assistant commit boundary | mitigate | Validate complete payload and assert request ownership/currentness immediately before one Dexie write; abort/parse/tool-schema failure writes nothing. |
| T-25.1-06 | Denial of Service | close running tab | mitigate | Confirm, abort owning controller, discard state, then delete; tests assert ordering and no orphan request. |
| T-25.1-07 | Tampering | retry/double-submit | mitigate | New requestId, original user-message ID reuse, and one-active-request-per-tab registry guard. |
| T-25.1-SC | Tampering | npm/pip/cargo installs | mitigate | No package install; use existing React/Vitest/Dexie primitives. |
</threat_model>
