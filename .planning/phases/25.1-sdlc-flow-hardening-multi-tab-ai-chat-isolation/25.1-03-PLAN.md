<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| AI/OS lifecycle event → workflow checkpoint | Exit or late native callbacks can describe stale work and must not overwrite newer state. |
| Revision draft/source Notes → coordinator commit | User/model-proposed content crosses an approval boundary before becoming active artifact state. |
| Existing artifact Note → new baseline | Stale or wrong-project versions must not become active inputs for downstream steps. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-25.1-08 | Tampering | checkpoint save/load | mitigate | Bind checkpoint to tab/thread/request, validate currentness, convert running to interrupted on reopen, and require explicit continue/discard. |
| T-25.1-09 | Tampering | revision commit | mitigate | Preview source/hash/impact, require explicit confirm, verify active pointer, create immutable version, and never mutate old Note. |
| T-25.1-10 | Information Disclosure | restored source notice/diagnostics | mitigate | Render titles and stable missing-source metadata only; never raw prompt, source body, secret, or stack. |
| T-25.1-11 | Denial of Service | stale workflow baseline | mitigate | Reject stale artifact as downstream baseline and provide explicit read-only audit path. |
| T-25.1-SC | Tampering | npm/pip/cargo installs | mitigate | No package install; reuse Zod/Dexie/Ant Design and existing lifecycle hooks. |
</threat_model>
