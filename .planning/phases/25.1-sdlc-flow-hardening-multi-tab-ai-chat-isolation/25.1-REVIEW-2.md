## Critical Issues

### CR-01 [BLOCKER]: Request and confirmation state still belongs to drawer, not tab

**File:** `src/components/ai/AIChatDrawer.tsx:313-317, 640-661, 1202-1215, 1991-2023, 2584-2601`

**Issue:** `requestRegistry` owns request IDs by tab, but execution and UI still use drawer-global `isStreaming`, `streamingText`, `streamingStatus`, `groundedLoadingStatus`, `apiError`, `lastSubmittedText`, `sessionAttachedFiles`, `pendingConfirmation`, and both abort-controller refs. `handleStopGeneration` aborts `abortControllerRef.current` and `currentTurnAbortRef.current` without checking active tab ownership. A confirmation promise is also global; switching tabs while one tab waits for confirmation lets another tab's UI answer or cancel it. Grounded callbacks and status setters remain global. This still violates tab isolation and can stop or mutate wrong-tab work.

**Fix:** Put request controller, confirmation resolver, stream/status/error buffers, retry message ID, attachments, model, and wizard transient state in the owning tab runtime. Pass `{ tabId, threadId, requestId }` through callbacks. Stop and confirmation actions must resolve only the active tab's request.

### CR-02 [BLOCKER]: Retry is not bound to original user-message ID

**File:** `src/components/ai/AIChatDrawer.tsx:651-653, 1325-1337, 2290-2293`

**Issue:** `handleRetry` uses drawer-global `lastSubmittedText` and calls normal `handleSendMessage`, which saves another user message. It does not use `TabRuntime.retryUserMessageId`, despite that field existing, and it does not use `skipSavingUserMessage` with an immutable original ID. Duplicate identical prompts can therefore be retried against the wrong history entry and leave duplicate user messages. Request ownership guards stale assistant commits, but do not fix this retry-history corruption.

**Fix:** Store original user message ID per tab. Retry must capture that ID and thread ID, reuse the existing user message, and create a fresh request ID only for the assistant attempt.

### CR-03 [BLOCKER]: Revision confirmation still reruns AI instead of committing revision

**File:** `src/components/ai/AIChatDrawer.tsx:939-960, 2649-2669`; `src/components/ai/wizard/SdlcWorkflowHub.tsx:483-510`

**Issue:** `SdlcWorkflowHub` receives no `onRequestRequirementRevision` or `onRequestSolutionRevision`, so its fallback modal remains active. The modal compares each artifact content to itself (`before` and `after` both current content), then confirmation calls `onRerunStep`. Drawer rerun sends a fresh prompt or opens intake; it never calls `previewRevision` or `commitRevision`. No confirmed revision, version pointer update, or cycle transition occurs. `handleStartSdlcWorkflow` also still constructs a raw prompt and sends it directly; it does not call `buildMergedSdlcInput` or validate/persist the merged source payload.

**Fix:** Collect revision draft, call coordinator `previewRevision`, show its actual diff/source/impact, then call `commitRevision(preview, true)` only from explicit confirmation. Open/close revision cycle through coordinator. Build and parse `MergedSdlcInput` before starting the AI stage.

### CR-04 [BLOCKER]: Restore recovery remains disconnected from durable recovery state

**File:** `src/components/ai/AIChatDrawer.tsx:927-937, 2641-2648, 2697-2713`

**Issue:** `missingSources` is reset to `[]` after coordinator restore and is never populated from backup validation/recovery metadata. The notice therefore stays hidden even when validation returns missing sources. SDLC interrupted actions only call `setSdlcWorkflowState` with a local object; they do not call `clearCheckpoint`, persist the choice, or resume the checkpoint stage. General recovery still depends on `runtime.draft`, which is ephemeral and normally empty after restart. `handleSendMessage` rejects interrupted SDLC turns before recovery actions can resume them.

**Fix:** Persist and load `BackupRecoveryInfo` into tab workflow state. Render exact missing source metadata and keep affected stages blocked. Make Continue/Discard call coordinator persistence methods, clear or update the durable checkpoint, and resume with a new request ID. Never use runtime-only draft as restart input.

### CR-05 [BLOCKER]: Legacy restore still writes non-UUID SDLC tab IDs

**File:** `src/services/backup/restoreBackup.ts:75-80`

**Issue:** Legacy backfill still assigns `id: \`sdlc:${scopeKey}\`` for generated SDLC tabs. `ChatTab.id` is a UUID contract and `BackupChatTabRecordSchema` validates UUIDs. A legacy backup without `chatTabs` can therefore restore successfully only until the generated rows are exported or revalidated, where the non-UUID tab ID is rejected.

**Fix:** Use `generateId()` for every generated tab ID, including this SDLC branch. Keep `threadId` pointing to the UUID thread and add an export/re-import regression test for a legacy backup.

### CR-07 [BLOCKER]: Missing Notes validation still fails open

**File:** `src/services/backup/validateBackup.ts:401-417`

**Issue:** The source check remains `if (notes && !noteIds.has(artifact.noteId))`. When `tables.notes` is omitted, `notes` is `undefined`, so workflow artifacts referencing unavailable notes produce no `missingSources` or `blockedTabs` recovery metadata. Restore then imports a workflow that cannot resolve its source and is not blocked.

**Fix:** Treat omitted Notes as an empty source set whenever workflow/chat records exist: check `!noteIds.has(...)` without the `notes` guard. Normalize every unresolved source into bounded recovery metadata and persist blocked checkpoint state before allowing workflow execution.

## Warnings

### WR-01 [WARNING]: Runtime hook still publishes on every render and can loop

**File:** `src/components/ai/runtime/useTabRuntimes.ts:12-18, 36-45, 48-52`; `src/components/ai/AIChatDrawer.tsx:1142-1146`

**Issue:** `useTabRuntimes` returns a new registry object on every render. `AIChatDrawer` has an effect depending on that object; every effect run calls `initialize`, and `initialize` always calls `publish`, which sets a new snapshot object. This can cause repeated render/effect/publish cycles. `get` returns an unregistered runtime when absent, while `patch` calls `ensure(tabId)` without thread ID; an event before initialization can create runtime ownership with an empty thread ID.

**Fix:** Memoize the returned registry or depend on stable callbacks. Make initialization idempotent without publishing unchanged state. Have `get` be a pure snapshot lookup or initialize only in an event/effect that always supplies `{ tabId, threadId }`.

### WR-02 [WARNING]: Model, MCP, knowledge, attachments, and draft state remain partly global

**File:** `src/components/ai/AIChatDrawer.tsx:313-314, 402-404, 471-477, 1105-1106, 1728-1732, 2411-2432, 2741-2746`

**Issue:** Only model and attachments are partially persisted to `ChatTab.config`. MCP servers and knowledge config remain shared settings, `selectedModel` remains global and is used as fallback for active turns, `sessionAttachedFiles` remains global fallback and is merged into prompts, and draft state has no active-tab persistence. `TabRuntime` fields for `mcpEnabled`, `knowledgeEnabled`, `promptOptions`, and `draft` are not wired to UI/config. Switching tabs can therefore inherit configuration and attached files from another tab.

**Fix:** Load all per-tab chat options from active tab/runtime and write changes to that tab. Keep only endpoint, credentials, and other explicitly global settings global. Remove global attachment fallback and persist draft per tab.

### WR-03 [WARNING]: Note picker still lacks roving focus and keyboard row reachability

**File:** `src/components/ai/wizard/NoteSourcePickerModal.tsx:48-51, 225-241`

**Issue:** Rows use `role="option"`, but `focusedNoteId` starts as `null`, making every row `tabIndex={-1}`. No row receives initial focus, and no `ArrowUp`/`ArrowDown` handler moves focus or updates the focused item. Enter/Space handlers are useful only after a row is reached by another mechanism. This does not satisfy the required roving-focus contract.

**Fix:** Initialize focus to first filtered row, set exactly one row `tabIndex=0`, handle ArrowUp/ArrowDown/Home/End with `focus()`, update `focusedNoteId`, and use `aria-activedescendant` or a listbox roving-focus pattern. Keep checkbox selection separate from preview activation.

### WR-05 [WARNING]: E2E gate still overstates isolation, recovery, revision, and rollback proof

**File:** `e2e/sdlcFlowHardening.spec.ts:121-186, 213-273, 275-354`

**Issue:** E2E tests create/switch/close tabs and send one request, but do not hold concurrent requests, verify per-tab stream/error/history state, test abort-before-delete, exercise durable checkpoint decisions, verify revision commits/cycles, remove a source after import, or compare rollback state. The valid backup fixture contains only core project tables, so it cannot prove chat/workflow restore or missing-source recovery.

**Fix:** Add deferred per-tab transport fixtures, IndexedDB identity/count assertions, abort ordering checks, revision/cycle assertions, encrypted fixtures containing chat tabs/messages/checkpoints, missing-source restore checks, and rollback equality checks.

### WR-06 [WARNING]: Raw provider/validation errors still reach console diagnostics

**File:** `src/components/ai/AIChatDrawer.tsx:1629-1637, 1713-1720, 1796-1807`

**Issue:** The debug service no longer stores raw prompt/tool/error content, but the drawer still calls `console.error` with the caught grounded error and serialized `groundedErr.issues`, and logs caught errors from context/MCP paths. Provider errors or validation issue payloads can contain request details, source content, paths, or other sensitive diagnostic data. This leaves D-13 incomplete even though `AiDebugTurn` is sanitized.

**Fix:** Log only fixed error codes and bounded IDs/counts. Remove raw error objects and serialized validation issues from console output; map errors to safe UI messages before storing or logging.

### WR-07 [WARNING]: Restore does not clear backup metadata during full replacement

**File:** `src/services/backup/restoreBackup.ts:25-48, 213-243`

**Issue:** `RESTORE_TABLES` includes `backupMetadata`, but the clearing list omits `targetDb.backupMetadata.clear()`. Every full import leaves old metadata rows mixed with the imported dataset and appends another row. This makes restored counts and backup history reflect data from before the replacement.

**Fix:** Decide explicit metadata policy. For full replacement, clear and restore `backupMetadata` in the same transaction, or preserve it outside the replacement scope and document/test that exception. Do not include a table in `RESTORE_TABLES` while silently omitting its clear behavior.

## Confirmed Fixes

- **CR-06:** Snapshot now captures `settings`; replacement clears settings before restoring validated settings.
- **WR-04:** Replacement now clears document and dependent knowledge tables unconditionally, plus settings.
- **CR-08 debug storage:** `AiDebugService` stores lengths, counts, tool names, and error codes rather than prompt/tool payloads. Raw console logging remains covered by WR-06.
- **WR-01 render mutation sub-issue:** `get()` no longer calls `setSnapshot()` during render. The registry identity/publish cycle and missing thread initialization remain.
