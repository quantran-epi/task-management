# Phase 25.1: Code Review Report

**Reviewed:** 2026-10-31T00:00:00Z
**Depth:** standard
**Files Reviewed:** 48
**Status:** issues_found

## Summary

Phase changes do not meet locked isolation, checkpoint, revision, or restore contracts. Drawer-global request state still controls tab execution, stale responses can commit, SDLC revision controls do not commit revisions, restored-source recovery is disconnected from UI, and restore rollback omits settings. Backup and debug paths also expose raw request data.

## Critical Issues

### CR-01: Drawer-global runtime still aborts and leaks across tabs

**File:** `src/components/ai/AIChatDrawer.tsx:316-317, 628-642, 1152-1191, 1239, 1887-1893, 2581-2600`
**Issue:** Request ownership is not tab-local. `currentTurnAbortRef`, `abortControllerRef`, `isStreaming`, `streamingText`, `streamingStatus`, `groundedLoadingStatus`, `apiError`, `lastSubmittedText`, `sessionAttachedFiles`, `selectedModel`, `pendingConfirmation`, wizard state, and export state remain drawer-global. `!open` cleanup aborts both controllers, and scope changes abort `currentTurnAbortRef`. This violates drawer-close preservation and lets one tab's loading, draft, error, confirmation, stream, or stop action affect another tab. Grounded turns bypass `requestRegistry` entirely; operational turns call `begin` only after the long pre-request path. The UI renders global stream/error values instead of the active tab runtime.
**Fix:** Remove drawer-global request/transient fields. Store every request, controller, stream buffer, error, confirmation, draft, attachment, model, and wizard/export value under tab ID. Do not abort on drawer close or scope change. Start registry ownership before asynchronous request preparation and pass owning tab/thread IDs through every callback. Render only active-tab runtime values.

### CR-02: Stale and duplicate responses can write assistant history

**File:** `src/components/ai/AIChatDrawer.tsx:1313-1332, 1887-1890, 2029-2045`
**Issue:** Assistant commit performs no `requestRegistry.isCurrent(...)` check and no signal check immediately before `saveMessage`. `activeReq` can be `null` when same tab is already active, but code still creates fallback controller and continues. A second send can save another user message before that late guard. A response finishing after abort, tab switch, retry, or replacement can write into original thread, and retry does not reliably reuse a saved user-message ID: lookup is by matching text and can select wrong duplicate.
**Fix:** Acquire request ownership before saving or preparing turn; reject duplicate submission before any write. Capture immutable `{tabId, threadId, requestId, userMessageId}`. Immediately before sole assistant write require `isCurrent(requestId, tabId, controller)` and `!signal.aborted`; otherwise discard output. Retry must carry original message ID explicitly.

### CR-03: SDLC revision confirmation is not connected to revision commit

**File:** `src/components/ai/AIChatDrawer.tsx:925-946, 2634-2669` and `src/components/ai/wizard/SdlcWorkflowHub.tsx:197-223, 483-512`
**Issue:** Drawer passes no `onRequestRequirementRevision` or `onRequestSolutionRevision`, so hub fallback modal is used. Modal compares each artifact with itself (`before` and `after` both current content), and confirm calls `onRerunStep` rather than `previewRevision`/`commitRevision`. Drawer rerun sends a new AI prompt. No user-confirmed revision, immutable active pointer, or cycle update occurs. `handleStartSdlcWorkflow` builds raw prompt and invokes AI directly instead of building/validating `MergedSdlcInput` and passing it through coordinator.
**Fix:** Wire revision draft collection to `previewRevision`, display actual before/after/source/impact data, and make `onConfirm` call `commitRevision` only after explicit confirmation. Open a new cycle after completed CAB revision. Build `MergedSdlcInput` from source sets and free text, validate it, persist source refs, then invoke existing wizard/core path with validated payload.

### CR-04: Restored-source and interrupted recovery are disconnected from durable state

**File:** `src/components/ai/AIChatDrawer.tsx:914-923, 2634-2643, 2692-2707`
**Issue:** `RestoredSourceNotice` always receives `missingSources={[]}`, so missing-source recovery is never shown or enforced. SDLC interrupted banner actions only mutate React state; they do not call `clearCheckpoint`, do not persist decision, and `Tiếp tục` does not resume checkpoint stage. General interrupted banner sends `runtime.draft`, runtime-only and normally empty after restart. `handleSendMessage` blocks interrupted SDLC requests before any action. Restored workflow can remain durably blocked or appear cleared locally with no valid explicit continue/retry path.
**Fix:** Load recovery metadata into durable tab workflow state and render it. Block stage execution until sources are replaced. Make `Tiếp tục`/`Bỏ qua` call coordinator persistence APIs, clear/update exact checkpoint, and resume selected stage with new request ID. Never use runtime draft as restart input.

### CR-05: SDLC tab and legacy backfill IDs violate UUID contracts

**File:** `src/db/repositories/chatTabRepo.ts:73-76, 87-103` and `src/db/index.ts:230-244` and `src/services/backup/restoreBackup.ts:94-116`
**Issue:** SDLC IDs are `sdlc:project:<id>` and legacy restore creates `sdlc:<scopeKey>`, while models/backup schemas require UUIDs for `ChatTab.id`, `ChatTab.threadId`, and `ChatThread.id`. Next export/validation can reject these rows. `getOrCreateSdlcTab` also prefers legacy ordinary `project:<id>` thread before explicit `project:<id>:sdlc`, reclassifying ordinary history as SDLC.
**Fix:** Generate UUIDs with `crypto.randomUUID()` for tab and generated thread IDs. Match explicit `project:<id>:sdlc` first; promote `project:<id>` only as ordinary chat. Add export/re-import tests for generated rows and ordinary-history classification.

### CR-06: Rollback snapshot omits settings, including workflow checkpoints

**File:** `src/services/backup/restoreBackup.ts:173-189, 213-245, 260-266`
**Issue:** `captureSnapshot` never reads `settings`, while workflow checkpoints live in `db.settings`. Rollback cannot restore pre-import workflow state/settings byte-for-byte. `replaceTables` also does not clear settings before writing incoming settings, so full replacement leaves old settings mixed with imported settings. Rollback can leave stale checkpoint pointing at replaced thread.
**Fix:** Include settings in `SnapshotData`, clear and restore them in same replacement transaction, preserve only rollback marker outside replacement set, and test settings/checkpoint equality before import, after import, and after rollback.

### CR-07: Missing-source validation fails open when Notes table is absent

**File:** `src/services/backup/validateBackup.ts:261-263, 401-435`
**Issue:** Missing workflow artifact sources are checked only under `if (notes && !noteIds.has(...))`. Payload with workflow references but no `tables.notes` skips check, returns no recovery metadata, and imports workflow with unavailable sources. This defeats D-30.
**Fix:** Treat omitted Notes table as empty source set whenever chat/workflow records are present. Normalize every unresolved source to bounded recovery metadata and interrupted/blocked checkpoint. Reject malformed references that are not recoverable.

### CR-08: Raw prompts, tool data, and provider errors leak through diagnostics

**File:** `src/components/ai/AIChatDrawer.tsx:1860, 1968-1987, 2070-2079` and `src/services/ai/aiDebugService.ts:23-31, 63-66, 110-141`
**Issue:** Full system prompt/messages go to `aiDebugService`, full prompt is logged, tool arguments/results are logged/stored, and raw `err.message` enters runtime error state. Provider errors/tool payloads can contain API credentials, prompts, source content, file paths, or stack details. This contradicts D-13.
**Fix:** Replace debug payloads with bounded IDs, lengths, model, tool name, and enumerated error codes. Never log prompt/content/tool args/results. Map caught errors to fixed safe messages before runtime/UI storage; keep raw errors out of `AiDebugTurn`.

## Warnings

### WR-01: Runtime registry mutates React state during render and loses thread identity

**File:** `src/components/ai/runtime/useTabRuntimes.ts:19-31, 33-39` and `src/components/ai/AIChatDrawer.tsx:1126-1132`
**Issue:** `tabStatuses` calls `tabRuntimes.get(t.id)` during render. `get` creates runtime and calls `setSnapshot`, causing state updates during render. `patch` calls `get(tabId)` without `threadId`, so runtime first created this way keeps empty thread ID. This creates React warnings and inaccurate runtime ownership metadata.
**Fix:** Initialize runtimes in an effect or event path, never publish from `get` during render, and always initialize/update with durable `{tabId, threadId}`. Derive status from immutable snapshot.

### WR-02: Tab config requirements are not implemented per tab

**File:** `src/components/ai/AIChatDrawer.tsx:393-417, 463-466, 1060-1116, 2410-2416`
**Issue:** Selected model remains drawer-global and changes global 9router settings. MCP/knowledge toggles and attached files remain global. Only `analysisMode` writes to `ChatTab.config`. D-05/D-07 require remaining per-tab chat config to persist with thread; endpoint/API key stay global.
**Fix:** Read/write model, MCP, knowledge, prompt options, attachments/references, and draft from active tab runtime/config. Keep endpoint and credentials global.

### WR-03: Note picker violates keyboard/accessibility contract

**File:** `src/components/ai/wizard/NoteSourcePickerModal.tsx:217-241`
**Issue:** Note rows are clickable `div` elements without role, keyboard handlers, focus management, or accessible name. Plan requires keyboard row navigation and Space toggling.
**Fix:** Use semantic checkbox/list-item control or add `role="option"`, `tabIndex`, `aria-selected`, Enter/Space handlers, and roving focus. Keep preview activation separate from selection.

### WR-04: Full replacement leaves omitted optional tables stale

**File:** `src/services/backup/restoreBackup.ts:216-219`
**Issue:** documentSets and dependent knowledge tables clear only when `tables.documentSets` exists. Valid backup omitting optional table leaves old local records, mixing pre-import and imported state. Settings replacement has same flaw.
**Fix:** Clear every canonical table in restore scope on every full replacement, then bulk-add validated incoming rows. Use explicit legacy rules, not conditional clearing on one table.

### WR-05: E2E gate does not prove claimed restore and isolation behavior

**File:** `e2e/sdlcFlowHardening.spec.ts:121-186, 188-211, 213-273, 275-354`
**Issue:** Tests mostly check tab labels, one request, viewport width, and success UI. They do not send concurrent requests, inspect per-tab history/status/error buffers, exercise abort-before-delete, restore tabs/workflow/history, remove source after import, verify rollback identity, or prove no AI/Note side effects. Valid backup contains only core project tables, no chat tabs/workflow state. Passing output overstates D-01..D-35 coverage.
**Fix:** Add deferred per-tab transport fixtures, IndexedDB identity/count assertions, abort ordering checks, workflow/revision/cycle assertions, encrypted-envelope import fixtures with chatTabs/checkpoints, missing-source restore assertions, and rollback equality checks. Separate manual Tauri gates from browser proof.
