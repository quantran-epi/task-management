# Phase 25.1 Plan 11: Real Per-Tab AI Chat Runtime Summary

Every AI chat tab now owns its streaming text, loading/error state, draft, attachments, model, token usage, abort controller, and mutation confirmation; two tabs stream concurrently without touching each other, and a superseded request can no longer write history.

## Accomplishments

- `TabRuntimeRegistry.getSnapshot()` added: a live read of the runtime map, used by unmount and scope-change cleanup so those effects stay `[]`-dep and never re-run on publish.
- `createTabRuntime` no longer seeds `'gpt-4o'`; the empty mirror lets durable `ChatTab.config.model` win instead of shadowing it forever.
- The drawer seeds a runtime per active tab (initialize effect) and inside `handleSendMessage` before any patch, so `ChatTabBar` badges show real `processing`/`idle` status (SC-2) instead of always `idle`.
- Deleted drawer-global transient state: `currentTurnAbortRef`, `abortControllerRef`, `isStreaming`, `streamingText`, `streamingStatus`, `groundedLoadingStatus`, `apiError`, `lastSubmittedText`, `sessionAttachedFiles`, `selectedModel`, `pendingConfirmation`, `pendingConfirmationRef`.
- Per-tab send guard (`hasActive(turnTabId) || status === 'processing'`) replaces `if (isStreaming || groundedLoadingStatus) return`; a send in tab B never blocks or aborts tab A.
- `requestController` written exactly once at controller creation, which is what makes `handleStopGeneration`, tab close, and unmount functional.
- Stop aborts only its tab (`abortTab` + runtime controller + `confirmationResolver(false)`); unmount iterates `getSnapshot()` and aborts every tab; scope change aborts the outgoing scope's runtimes only. Drawer close still aborts nothing (D-09 preserved from plan 10).
- Per-tab model is durable in `ChatTab.config.model`: seeded once from the persisted nine-router default inside a conditional transaction, written on picker change and on model refresh, mirrored into `TabRuntime.model`, and resolved with precedence runtime → durable config → persisted default. `setNineRouterConfig({ defaultModel })` removed from the picker.
- Draft isolation: `ChatInputBar` accepts `value`/`onValueChange`, routes every internal writer through one `update()`, and is remounted per tab; a draft typed in tab A survives switching to B and back, and tab B starts empty.
- Attachments move onto `TabRuntime.references`, with one-shot append computed from the owning tab so a mid-send tab switch cannot merge another tab's files.
- Mutation confirmation lives on the owning runtime (`pendingConfirmation` + `confirmationResolver`); the chat yes/no path answers whichever tab is waiting, and the card renders only for the active tab.
- `requestRegistry.isCurrent(requestId, tabId, controller)` gates the assistant commit; abort or supersession writes no assistant row while the user message stays.
- One error-card owner: `InlineApiErrorCard` renders only from the active runtime status block; `error={apiError}` is no longer passed to `ChatMessageList` (exactly one `InlineApiErrorCard` element in the drawer).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Composer draft was dropped by the pre-hydration remount**
- **Found during:** Task 2
- **Issue:** With `key={activeTabId}` and a value controlled only once a runtime existed, a draft typed while `activeTabId` was still the provisional `'sdlc'` was lost when the durable tab id arrived and remounted the composer.
- **Fix:** Kept the per-tab remount key, made the value controlled whenever a runtime exists, and added a `draftCarryRef` that re-applies pre-hydration text onto the new tab's runtime.
- **Files modified:** `src/components/ai/AIChatDrawer.tsx`
- **Commit:** `e48019c`

**2. [Rule 1 - Bug] First send and drawer bootstrap could create two tabs for one scope**
- **Found during:** Task 2/3 integration
- **Issue:** Resolving the durable tab at send time and the non-project bootstrap effect both could insert a first `chatTabs` row, producing a duplicate tab and intermittent wrong-thread assertions.
- **Fix:** Added `getOrCreateActiveChatTab` (adopts a legacy scope thread, never orphans history) and single-flighted it per scope from the drawer.
- **Files modified:** `src/db/repositories/chatTabRepo.ts`, `src/components/ai/AIChatDrawer.tsx`
- **Commit:** `0f02a1c`, `e48019c`

**3. [Rule 1 - Bug] Empty model sentinel broke grounding validation**
- **Found during:** Task 2
- **Fix:** Added `persistedDefaultModelRef` (refreshed from config at send time) so `resolveActiveModel()` is never empty inside an async send that outruns the model effect.
- **Files modified:** `src/components/ai/AIChatDrawer.tsx`
- **Commit:** `e48019c`

**4. [Rule 1 - Bug] Scope picker rows had no keys**
- **Found during:** existing-suite verification
- **Issue:** Re-renders while runtimes hydrated could swap picker rows under a click, sending the test to the wrong scope.
- **Fix:** Stable `key={`${item.type}:${item.id ?? 'global'}`}` on picker rows.
- **Files modified:** `src/components/ai/ScopePickerModal.tsx`
- **Commit:** `a3a7686`

**5. [Rule 1 - Bug] Turns that ended before streaming left the tab stuck on `processing`**
- **Found during:** Task 2
- **Issue:** Clarify/grounded early returns reset only the loading string, so the per-tab guard would block the user's next message.
- **Fix:** `endTurnWithoutStream()` resets the owning runtime and finishes the registry request on every early return; the empty-response path no longer resets an error turn back to `idle`.
- **Files modified:** `src/components/ai/AIChatDrawer.tsx`
- **Commit:** `e48019c`
