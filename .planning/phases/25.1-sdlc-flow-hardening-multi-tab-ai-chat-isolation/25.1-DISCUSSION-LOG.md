## Vòng đời đa tab

| Decision | Alternatives considered | Selected |
|---|---|---|
| Initial tabs | Default chat; lazy creation; cross-scope restore | Default chat per scope; Project also gets one fixed SDLC tab |
| Close last chat | Create replacement; empty state; block close | Create replacement immediately |
| Tab title | Auto + editable; fixed number; AI-only | Auto-generated and user-editable |
| Active tab restore | Last per scope; first chat; always Project SDLC | Last active tab per scope |

**User's choice:** Recommended options throughout.
**Notes:** Every scope must support multiple tabs; Project is special only because it has at most one permanent SDLC tab.

## Cấu hình từng tab

| Decision | Alternatives considered | Selected |
|---|---|---|
| Isolation boundary | Full runtime/config; model+mode only; mode only | Full runtime/config per tab |
| Background requests | Continue; pause; abort on switch | Continue independently |
| Loading UI | Per-tab badge; badge-only; global toast | Per-tab badge plus local detail; other tabs remain usable |
| Persistence | DB with thread; session only; localStorage | DB with thread |
| Close running tab | Confirm+abort; block close; orphan background task | Confirm+abort before delete |
| App interruption | Checkpoint/resume; auto retry; error only | Interrupted state + explicit continue/retry |
| Concurrency | Provider-limited; one drawer request; fixed queue | No app-level global lock |

**User's choice:** Full isolation, including loading indicators that were previously shared.
**Notes:** Endpoint/API key stay global application credentials. Drawer close differs from process exit: drawer close does not abort; Tauri exit requires checkpoint/recovery.

## Response lỗi

| Decision | Alternatives considered | Selected |
|---|---|---|
| Assistant persistence | Commit complete; continuously persist; paragraph chunks | Commit only complete validated response |
| Error display | Runtime error card; toast; assistant error message | Runtime error card outside history |
| User message | Save immediately; save on AI success; save with error | Save immediately |
| Invalid structured payload | Reject all; keep text; auto-repair | Reject all and allow retry |
| Retry | Same user message/new request; auto retry; resend manually | Same user message/new request ID |

**User's choice:** Clean history over partial recovery.
**Notes:** Diagnostics sanitized. Partial buffers and error responses never enter chat history or backup.

## SDLC UX & sửa đổi

| Decision | Alternatives considered | Selected |
|---|---|---|
| Progress | Vertical timeline; horizontal chips; current-only | Compact vertical six-step timeline |
| View step | Selected view separate; jump workflow; read-only only | Selected view separate with valid actions |
| PL sources | Per-kind text/Note; one shared mode; unclassified notes | PL01/PL02 independently accept text or multiple Notes |
| Notes modal | Project-only; global search; plain IDs | Global search, default Project filter, multi-select and preview |
| Multiple Notes | Preserve+merge; concatenate; primary note | Preserve sources and create cited merge |
| Change trigger | Explicit actions; chat command only; direct modal edit | Explicit requirement/solution update actions |
| Impact | Preview+stale; stale only; overwrite automatically | Preview impact and require confirmation |
| Reinstall restore | Existing encrypted backup/import; new sync; Notes only | Existing encrypted GitHub backup or local import |
| Missing source | Keep checkpoint; drop workflow; empty placeholder | Keep checkpoint and request replacement source |

**User's choice:** Discoverable actions, source-preserving input, compact non-overflow UI.
**Notes:** Multiple PL01 and PL02 Notes may exist in one Project.

## SDLC state machine

| Decision | Alternatives considered | Selected |
|---|---|---|
| Requirement change | Dependency propagation; all steps; Solution only | Stale from Solution through CAB |
| Solution change | Downstream chain; Change Pack only; reset Intake | Stale Code Guide through CAB |
| Artifact history | Immutable+pointer; overwrite; keep one previous | Immutable versions + active pointer |
| Stale artifact | Read-only; temporary baseline; hidden | Read-only, never new baseline |
| CAB complete/change later | New cycle same tab; keep processing; reset | Completed cycle, then new revision cycle in same SDLC tab |
| Cycle history | Collapsed same tab; current only; one tab per cycle | Collapsed read-only cycles in same fixed SDLC tab |

**User's choice:** Completed does not permanently lock workflow; last-minute and post-go-live changes remain supported through revision cycles.
**Notes:** Project retains exactly one SDLC tab across all cycles.
