# Phase 25.1 Plan 12: SDLC Checkpoint, Revision, and Cycle Wiring Summary

SDLC turns now write a `running` checkpoint before dispatch and release it on every exit path, the interrupted banner genuinely resumes with a fresh request id or discards without persisting, revision commits run through the hub's own preview modal and open a new cycle after a completed one, and a stale artifact can never become the baseline of a new step.

## Accomplishments

- `handleSendMessage` calls `setCheckpoint(crypto.randomUUID(), currentStep)` after the user message is saved and before any transport call, then wraps the whole turn in one `try { … } finally { clearCheckpoint() }`. Every early return (clarification limit, aborted signal, all grounded-pipeline branches, silent-entity clarification, refine, error/fallback, rejected transport, abort catch) now passes through that single clear.
- The `interrupted` guard and the missing-source guard stay above `setCheckpoint`, so neither can leak a `running` checkpoint.
- Non-SDLC turns never write SDLC state: the whole checkpoint lifecycle is gated on `isSdlcActiveTurn` (project scope + SDLC tab).
- `Tiếp tục` calls `resumeCheckpoint()` (fresh request id), stores the resumed state, then dispatches exactly one turn with the fixed continuation prompt `Tiếp tục bước <step> sau khi bị gián đoạn.` and `{ resumeFromCheckpoint: true }`. The composer draft is deliberately not forwarded (resume means re-run the interrupted step).
- `Bỏ qua` calls `clearCheckpoint()`, stores the cleared state, and sends nothing; no history row is written.
- A plain send while the checkpoint is `interrupted` still returns before any transport call, and no request fires automatically on mount or on `restore()`.
- New `src/components/ai/wizard/revisionView.ts`: `toRevisionModalPreview` maps a coordinator `RevisionPreview` (using `preview.markdown` as the diff's `after`) to the hub modal shape, `previousArtifactContent` resolves the active artifact content per kind, and `stripStaleArtifacts` drops every artifact named by `staleSteps` (INTAKE → pl01+pl02, SOLUTION → solution, TECH_DOCS → pl03b+pl07, …) without mutating its input.
- The drawer passes `revisionDraft`, `revisionPreview`, `revisionLoading`, `onRevisionDraftChange`, `onPreviewRevision`, and `onCommitRevision` to `<SdlcWorkflowHub>` and never passes `onRequestRequirementRevision` / `onRequestSolutionRevision`, so the hub opens its own modal and previews on blur.
- `handleCommitRevision` opens a cycle when there is none or the last is completed, then commits `revisionPreview` with `confirmed: true`; the previous version is retained in `versions` and the coordinator's staleness pass marks the downstream steps stale.
- `stripStaleArtifacts` is applied exactly once, at the `buildSdlcWrapperPrompt` artifacts argument (D-25).
- `handleCabGenerate` calls `closeCycle()` after a successful `generateCab()`, with a `ponytail:` note naming the ceiling and the upgrade path to `commitCab`.
- `skipSavingUserMessage` is gone from the drawer; the send signature is now `(text, overrideScope?, options?)` on both the function and its ref.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Brace matcher in the new structural test could not handle template interpolation**
- **Found during:** Task 1
- **Issue:** The plan asked for a plan-10-style extractor to assert the checkpoint/try ordering. The plan-10 `matchBalanced` helper treats backticks as plain string literals, so a `` `${…}` `` inside the drawer body left the scanner inside a "string" and it never found the turn's closing brace.
- **Fix:** The new suite uses a mode-stack matcher (`code` / quote / `` ` ``) that pops back to code on `${`, and strips comments before matching.
- **Files modified:** `tests/ai/AIChatDrawerSdlcRecovery.test.tsx`
- **Commit:** `a6ed672`

**2. [Rule 3 - Blocking] `skipSavingUserMessage` had no surviving caller**
- **Found during:** Task 2
- **Issue:** Widening the signature to an options object would have left `skipSavingUserMessage` as an unreachable third parameter; the only historical caller was the routed continuation path that plan 11 removed.
- **Fix:** Deleted the flag (and its branch) rather than migrating it into the options object, so the user message is always persisted; plan 14 adds `retryUserMessageId` to the same options object.
- **Files modified:** `src/components/ai/AIChatDrawer.tsx`
- **Commit:** `b18d427`

### Scope Notes

- `tests/ai/AIChatDrawerSdlcRecovery.test.tsx`'s CAB test reproduces the wizard review state in a legacy `project:<id>` thread so the drawer's legacy-thread adoption path is exercised; the wizard coordinator is mocked, so `runCabStage` behaviour is unchanged.
- The revision-commit test seeds CODE_GUIDE and CHANGE_PACK artifacts whose `sourceHashes` reference the old SOLUTION, because the coordinator's staleness detector only marks downstream steps that already exist.
