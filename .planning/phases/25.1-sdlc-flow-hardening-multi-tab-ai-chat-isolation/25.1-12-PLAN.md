<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Process restart -> SDLC state | A `running` checkpoint must never be replayed as if the old request were still live. |
| Revision commit -> artifact history | Revision must not overwrite the active artifact without an explicit confirm. |
| Cycle transition -> audit history | Old cycles must remain readable and immutable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-25.1-42 | Repudiation | SDLC checkpoint lifecycle | mitigate | Checkpoint written before dispatch, cleared in `finally` on success/abort/error; resume generates a new request id. |
| T-25.1-43 | Tampering | revision commit path | mitigate | Commit only from `onCommitRevision` after `previewRevision`; `commitRevision` re-checks `baseVersion`/`baseHash`. |
| T-25.1-44 | Information Disclosure | interrupted banner | accept | Banner text contains only step id and timestamp; no prompt or provider payload. |
| T-25.1-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependency; no package install. |
</threat_model>
