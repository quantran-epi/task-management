# Phase 25.1 Plan 13: Merged SDLC Intake, Listbox Picker, and Editable Tab Titles Summary

SDLC intake now routes through `buildMergedSdlcInput` and sends every source's kind, title, id, version, and hash plus a conflict block when sources disagree; the Note picker is a real listbox with `aria-activedescendant`; ordinary tab titles rename inline through F2 or double-click and persist via `updateChatTab`.

## Accomplishments

- `handleStartSdlcWorkflow` calls `buildMergedSdlcInput({ pl01Text, pl02Text, pl01Sources: pl01Sources ?? [], pl02Sources: pl02Sources ?? [] })` once and builds the prompt from the result: header line `[Quy trình SDLC - Khởi tạo SOLUTION cho CR: …]`, `- Tính năng`, `- Đơn vị yêu cầu`, then `merged.mergedContent`, then `[NGUỒN PL01/PL02]`, then `[CẢNH BÁO MÂU THUẪN]` only when conflicts exist, then the existing instruction sentence. The e2e prefix assertion is untouched.
- The `[NGUỒN PL01/PL02]` section is built by mapping `merged.citations` through a `sourceById` map assembled from `merged.pl01Sources` (kind `PL01`) and `merged.pl02Sources` (kind `PL02`), emitting `- {kind} · {title} · id={sourceId} · v{version} · hash={hash8} · {section}` and de-duplicating by `sourceId`. No field is read off the citation except `sourceId` and `section`.
- New `sdlcSourceReferencesRef = useRef<{ scopeKey: string; pl01: string[]; pl02: string[] }>` is written inside `handleStartSdlcWorkflow` from the resolved merge, keyed by the current `scopeKey`.
- The `buildSdlcWrapperPrompt` call site applies `stripStaleArtifacts` as before, then adds `pl01.sourceReferences` / `pl02.sourceReferences` only when the ref's `scopeKey` matches the current scope and the corresponding id list is non-empty. A ref written under another project is ignored, not cleared, so no extra scope-change cleanup line is needed.
- `NoteSourcePickerModal`'s scrollable option container now carries `role="listbox"`, `aria-label={`Danh sách tài liệu nguồn ${kind}`}`, `aria-multiselectable="true"`, `tabIndex={0}`, and `aria-activedescendant={note-option-${focusedNoteId}}`. Each row keeps `role="option"`, gains `id={note-option-${note.id}}`, and loses its roving `tabIndex`; Arrow/Home/End/Enter/Space are handled once on the container against `focusedNoteId`, and `moveFocus` scrolls the active row with `scrollIntoView({ block: 'nearest' })`.
- `ChatTabBarProps.onRenameTab?: (tabId, title) => void`. F2 on a focused ordinary tab and double-click on an ordinary tab enter an Ant Design `Input` (`aria-label="Đổi tên tab"`, `autoFocus`); Enter and blur commit, Escape cancels, and empty or unchanged titles call nothing. The SDLC tab never enters edit mode.
- `AIChatDrawer.handleRenameTab` writes `updateChatTab(tabId, { title }, db)` (one transaction over `chatTabs` and `chatThreads`) and reports `Không thể đổi tên tab` on failure.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Note picker reset its selection on every parent render**
- **Found during:** Task 1 (intake test could not keep a picked source)
- **Issue:** `NoteSourcePickerModal`'s open effect depended on the `initialSelectedIds` array identity, and `StepInputDocsModal` builds that array inline (`pl01Sources.map(...)`) on every render. Any drawer re-render (tab hydration, live queries) therefore re-ran `setSelectedIds(new Set(initialSelectedIds))` and discarded the checkboxes the user had just ticked, so the Apply button stayed disabled or applied an empty set.
- **Fix:** Key the effect on `[...initialSelectedIds].sort().join(',')` instead of the array identity, so the reset runs only when the picked contents actually change. This keeps the intended "reopen seeds from props" behavior.
- **Files modified:** `src/components/ai/wizard/NoteSourcePickerModal.tsx`
- **Commit:** `7f084c9`

**2. [Rule 3 - Blocking] Escape would have committed the rename through blur**
- **Found during:** Task 3
- **Issue:** Escape calls `cancelEditing`, which unmounts the `Input`; unmount fires `onBlur`, and blur was wired to commit. The escape path would have written the typed title anyway.
- **Fix:** A `cancelRef` flag set by `cancelEditing` (and by a successful commit) short-circuits `commitEditing`, so only a genuine blur or Enter persists.
- **Files modified:** `src/components/ai/ChatTabBar.tsx`
- **Commit:** `ef76d65`

**3. [Rule 3 - Blocking] The intake test fixture did not satisfy the `Note` type**
- **Found during:** `npx tsc --noEmit`
- **Issue:** The seeded `sdlcArtifact` used `kind: 'PL01'`, which is not one of the `SdlcArtifactKind` values accepted by `Note.sdlcArtifact`; `entityType` also widened to `string`.
- **Fix:** Use `kind: 'PL02'` with `entityType: 'project' as const` and annotate the factory's return as `Note`.
- **Files modified:** `tests/ai/AIChatDrawerSdlcIntake.test.tsx`
- **Commit:** `c2aab2d`

### Scope Notes
