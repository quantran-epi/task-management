# Phase 25.1 Plan 14: Retry Identity, Restore Source Recovery, and Durable Analysis Mode Summary

Retry now reuses the original user message row and clears its anchor only on success, restored workflows surface their real missing source titles and refuse the next AI step before any checkpoint is written, and analysis mode reads durable per-tab config only after a one-shot migration of the legacy global key.

## Accomplishments

- `handleSendMessage` third parameter is now `options?: { resumeFromCheckpoint?: boolean; retryUserMessageId?: string | null }`. The `skipSavingUserMessage` flag and the reverse-find `m.content === trimmed` heuristic are gone.
- When `retryUserMessageId` is supplied the drawer loads `db.chatMessages.get(id)` and reuses it only if it exists, has `role === 'user'`, belongs to the resolved thread, and its content still matches the submitted text; otherwise it saves a fresh user message.
- Every turn writes `tabRuntimes.patch(turnTabId, { retryUserMessageId: savedUserMsg?.id ?? null, lastSubmittedText: trimmed })` on its own tab. The error paths keep the anchor; a successful assistant commit patches `{ retryUserMessageId: null }`.
- `handleRetry` reads the anchor from the active tab runtime and sends `{ retryUserMessageId }`. `onInvalidRetry`, `onFreshLookup`, and `onCandidateSelect` pass the same anchor so those retries also reuse identity.
- New `src/components/ai/wizard/restoreRecovery.ts` exports `deriveMissingSources(state, existingNoteIds)`, returning de-duplicated `{ id, title }` for every artifact whose `noteId` is absent, skipping `driftResult` through the shape check.
- `AIChatDrawer` derives `restoredMissingSources` with `useLiveQuery` over `db.notes.bulkGet`, and `<RestoredSourceNotice missingSources={restoredMissingSources} />` replaces the hard-coded `[]`. A missing-source set renders the real titles and, on submit, blocks the turn with a `request_failed` runtime error before `setCheckpoint` and before any transport call — no user row, no checkpoint, no auto-Note, no auto-AI.
- `currentTabAnalysisMode` is `isSdlcActiveTab ? true : Boolean(activeTab?.config?.analysisMode)`. The tab-init effect performs the one-shot migration (seed durable `analysisMode: true` for ordinary tabs with no explicit value when the legacy key is `'true'`, then `localStorage.removeItem(AI_ANALYSIS_MODE_KEY)` inside `try/catch`).
- The workspace analysis `Tag` gained `data-testid="analysis-mode-header-tag"` so the component tests can assert the header state; the tab-bar icon (`aria-label="Analysis Mode"`) is the per-tab indicator.
