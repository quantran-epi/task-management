    4. Returns parsed JSON when provider responds with valid JSON content.
    5. Throws `INVALID_RESPONSE` when content is not JSON.
    6. `probeStructuredOutputCapability` caches second call under same key (one `fetch` call total).

    - If both scores > threshold (0.3) → `'mixed'`.
    - If one score dominates by ratio >= 2 → that route, confidence proportional.
    - Else → `'clarify'` with confidence 0.

    Create `src/services/ai/semanticScopeRouter.ts` exporting `routeScope(input, deps): Promise<ResolvedScope>` where:
    - `input = {query, routedIntent}`
    - `deps = {catalog: SetCatalogEntry[]; completeJson?: typeof completeJson; completeJsonArgs?: {endpoint, apiKey, model}; signal: AbortSignal}`
    - `SetCatalogEntry = {setId: uuid; canonicalName: string; domain: string; environment: string|null; version: string|null; aliases: readonly string[]; relation: 'EXTENDS'|'SUPPLEMENTS'|'SUPERSEDES'|null; isBase: boolean}`
    - `ResolvedScope = {setTierAssignments: {setId, tier: 'REQUIRED'|'LIKELY'|'OPTIONAL', roleGroup: 'baseline'|'scope_diff'}[]; comparisonMode: 'single'|'baseline_vs_scope'|null; routerSource: 'llm'|'alias'|'base_default'}`.

    Logic (D-19/D-20/D-21):
    1. If `completeJson` provided AND capability probe says strict JSON Schema supported: call `completeJson` with system prompt "Return only canonical scope values from the supplied CATALOG. Never invent setId. Never include free-form text." and user content `{query, catalog: catalog.map(c => omit c.setId)}`. Response schema (strict): `{domain: string|null; environment: string|null; version: string|null; comparisonMode: enum; subqueries: string[] max 5}`. Validate via Zod.
    2. App code (NOT model) resolves canonical values back to `setIds` by matching catalog entries. Model's output never contains `setId` (D-19).
    3. Deterministic alias fallback (D-20): run always after LLM, OR exclusively when LLM unavailable. Match normalized query tokens against each catalog entry's `canonicalName + aliases`. Produce tier assignments: full canonical match → `REQUIRED`; partial alias match → `LIKELY`; related domain by `relation` edge (`EXTENDS`/`SUPPLEMENTS`) → `OPTIONAL`.
    4. General question with no explicit scope: resolve to `isBase === true` sets with `REQUIRED` tier (D-21).
    5. Named explicit scope (PROD): add matching scoped sets to `scope_diff` role group plus `isBase` baseline to `baseline` role group with `comparisonMode: 'baseline_vs_scope'` (D-21/D-22).
    6. Record `routerSource` for diagnostics.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-13 | Elevation | model-returned setId | mitigate | Model output schema has no `setId` field; app code resolves canonical values to setId after Zod parse (D-19). |
| T-19-14 | Information disclosure | apiKey in error paths | mitigate | `redactApiKey` applied in every thrown error from `completeJson` + `probeStructuredOutputCapability`. |
| T-19-15 | DoS | model timeout | mitigate | `AbortSignal.timeout(45_000)` with distinct TIMEOUT/ABORTED error codes. |
| T-19-16 | Tampering | prompt injection via query | mitigate | Query goes in `user` role content only; system prompt is static per prompt version. Scope schema has no free-text channel. |
