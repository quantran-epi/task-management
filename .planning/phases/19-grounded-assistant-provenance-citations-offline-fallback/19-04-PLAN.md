  <action>
    Create `knowledge-server/src/services/federatedRetrievalService.ts` exporting `runFederatedRetrieval(request, deps)` where request matches `FederatedRetrievalRequestSchema`: `query`, `setTierAssignments: { setId: string; tier: 'REQUIRED'|'LIKELY'|'OPTIONAL'; roleGroup: 'baseline'|'scope_diff' }[]`, `comparisonMode: 'single'|'baseline_vs_scope'|null`, `budgets: { concurrency, elapsedMs, maxSets, maxItems, maxEvidenceChars }`.

    Fan-out logic (per D-23):
    1. Phase 1 run REQUIRED sets concurrently (bounded by `budgets.concurrency`, each timed with `runWithTimeout` using `budgets.elapsedMs / tierCount`). Use existing per-set `retrievalService.retrieve(setId, request)` as inner primitive.
    2. If total citations+paths coverage below `budgets.maxItems * 0.6` OR comparisonMode === 'baseline_vs_scope' AND any required scope absent, expand to LIKELY.
    3. If still insufficient AND elapsed < budget, expand to OPTIONAL.
    4. Stop when any budget hits ceiling (sets, items, chars, elapsed). Record stop reason in `diagnostics.coverageWarnings` naming the budget hit (D-24, D-31).

    Combine results:
    - Preserve per-item `setId`, `snapshotId`, scope metadata (D-16).
    - Rank by role group (D-22): compute `fusionScore` only within one `(setId, snapshotId)` group; across groups preserve group order (baseline first, scope_diff next per comparisonMode). Never flatten scores across corpora.
    - Carry `paths[]` from each per-set response as-is; never merge or concatenate paths across snapshots (D-14).
    - Aggregate conflict groups per-set; cross-set differences remain presentation-level only (handled by UI as scope variation vs conflict per D-25).

    Partial failure (D-24):
    - If one set rejects (daemon-internal error) but others succeed, outcome = `DEGRADED`; add `coverageWarnings` entry naming the failed setId and reason enum (`TIMEOUT`/`STALE`/`ERROR`). Never silently drop and never mix successes with failed-set fallback.

    Return envelope strictly conforms to `FederatedRetrievalResponseSchema.parse(response)` server-out (fail-closed).

    Deps interface: `{ retrievePerSet(setId, request, signal): Promise<RetrievalResponse>; now(): number; }` for test injection.
  </action>

| T-19-11 | Elevation | setId arbitration | mitigate | Server resolves setIds against configured catalog; reject unknown setId with 404. Client-supplied setIds never bypass auth. |
