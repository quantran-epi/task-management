## Warnings

### WR-01: Circular draft update hazard between incomingDraft and onDraftChange

**File:** `src/components/sdlc/steps/Step2SolutionView.tsx:73-78`
**Issue:** `useEffect` listening to `incomingDraft` triggers `onDraftChange?.(incomingDraft)`. If parent (`ProjectSdlcView`) updates state and passes it down again, an unnecessary round-trip persistence occurs.
**Fix:**
```typescript
  useEffect(() => {
    if (incomingDraft !== undefined && incomingDraft !== content) {
      setContent(incomingDraft);
    }
  }, [incomingDraft]);
```

### WR-02: Missing cleanup of setTimeout on unmount in ProjectSdlcView

**File:** `src/views/ProjectSdlcView.tsx:153-156` and `269-272`
**Issue:** `setTimeout` calls dispatching message to `chatPanelRef.current?.sendMessage` do not store or clear the timer handle on component unmount or fast step switching.
**Fix:**
```typescript
  const analysisTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  useEffect(() => {
    return () => {
      if (analysisTimerRef.current) clearTimeout(analysisTimerRef.current);
    };
  }, []);
```

### WR-03: Hardcoded fallback mock values on active pack switch in Step4ChangePackView

**File:** `src/components/sdlc/steps/Step4ChangePackView.tsx:185`
**Issue:** When activating a previously loaded pack in `handleSelectActive`, `buildReconciliation` is called with dummy git commits `{ cr: crCode, base: 'base-commit', head: 'head-commit' }` and empty entries array `[]`. This can generate an inaccurate zero-entry drift result compared to the initial upload.
**Fix:** Store the parsed manifest entries inside `ChangePackHistoryItem` or re-parse the uploaded zip buffer when switching active pack so drift calculation remains consistent across selections.
