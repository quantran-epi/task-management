## Summary

Phase 25.2 giải quyết triệt để 3 vấn đề cốt lõi:
1. **Sửa lỗi TaskMate database mutation flow trong AI Chat thông thường (Analysis Mode OFF)**: Đảm bảo yêu cầu thay đổi dữ liệu (`create_task`, `update_task`, `delete_task`, `plan_allocation`...) được intent router phân loại chính xác là `operate_taskmate`, đi vào nhánh tool execution và thực thi trơn tru qua thẻ xác nhận (`pendingConfirmation`) hoặc chế độ tự duyệt (`autoApproveMutations`) mà không gặp lỗi phân quyền hoặc thiếu tool.
2. **Đồng bộ toàn diện bảng điều khiển AI Chat SDLC Studio (`StepChatPanel.tsx`) với Core AI Engine (`runAiOrchestratorLoop`)**: Tích hợp thanh công cụ `ChatTabToolbox` (lựa chọn Model, toggle Chế độ phân tích, toggle Tự duyệt, Popover quản lý máy chủ MCP, nút Xóa ngữ cảnh). Thực thi trực tiếp vòng lặp công cụ đa bước với ngữ cảnh cô lập theo từng bước CR (`sdlc:${projectId}:${crId}:${stepId}`).
3. **Chuẩn hóa quy trình phân tích Solution (Step 2) & Sửa lỗi Remount**:
   - Loại bỏ hoàn toàn `useEffect` auto-trigger gây lặp phân tích khi chuyển đổi qua lại giữa các bước.
   - Thao tác "Bắt đầu phân tích Solution" (Step 1) hoặc "Phân tích lại bằng AI" (Step 2) sẽ gửi thông điệp yêu cầu vào panel chat của Step 2.
   - Người dùng theo dõi trực tiếp luồng suy nghĩ, gọi công cụ (`query_notes`, `query_tasks`, Graphiti/MCP), và streaming Markdown trên chat panel.
   - Tự động trích xuất nội dung SOLUTION.md từ kết quả chat để điền vào editor Step 2 và lưu bền vững vào `sdlc_workflow:${projectId}:${crId}` trong IndexedDB.

**Primary recommendation:** Tận dụng trực tiếp `runAiOrchestratorLoop` và `ChatTabToolbox` cho `StepChatPanel`; quản lý state cấu hình tab (`analysisMode`, `autoApproveMutations`, `mcpEnabled`, `model`) độc lập cho từng step thread; chuyển toàn bộ logic AI của Step 2 thành pipeline trigger chat sang editor.

## User Constraints (from CONTEXT.md)

### Locked Decisions
- **D-01 (Strict Read-Only in Analysis Mode):** Analysis Mode is strictly read-only. Database mutations are permitted ONLY when Analysis Mode is OFF (normal chat mode). If user attempts mutation while Analysis Mode is ON, AI explains that Analysis Mode is read-only and instructs turning off Analysis Mode.
- **D-02 (Reliable Normal Mode Mutations):** In normal mode (Analysis Mode OFF), `operate_taskmate` intent must supply all database mutation tools (`create_task`, `update_task`, `delete_task`, `reparent_task`, `plan_allocation`, `create_project`, etc.) to the LLM without permission errors or accidental tool filtering.
- **D-03 (Confirmation & Auto-Approve Flow):** Preserve the existing two-tier approval mechanism:
  - Default: Show the confirmation card (`pendingConfirmation`) with detailed field diffs + support verbal confirmation ("ok", "đồng ý", "yes") via `confirmationResolver` or manual button clicks.
  - Auto-Approve: When the "Tự duyệt" toggle is ON on the active tab, bypass confirmation prompts and provide the full itemized change report in the response.
- **D-04 (Full Drawer Capabilities in SDLC):** The right panel in SDLC Studio (`StepChatPanel.tsx`) must feature full AI Chat Drawer parity:
  - Powered by `runAiOrchestratorLoop`.
  - Toolbox controls: Model selector, Analysis Mode toggle, Auto-Approve toggle, MCP servers management popover, and Clear Context.
  - Context grounding: Grounded strictly in the current Project and active SDLC Step (`sdlc:${projectId}:${crId}:${stepId}`).
  - Live tool execution feedback (`onStatusChange`), tool badges, and streaming Markdown formatting.
- **D-05 (No Auto-Trigger on Step Remount):** Remove component mount auto-trigger. Navigating between steps (e.g. Step 1 -> Step 2 -> Step 3 -> Step 2) must NEVER trigger an AI analysis call.
- **D-06 (Explicit Trigger via Chat Turn):** When user clicks "Bắt đầu phân tích Solution" (Step 1) or "Phân tích lại bằng AI" (Step 2):
  - System posts a prompt message into the SDLC chat thread.
  - Chat panel executes `runAiOrchestratorLoop` (with tools to inspect project notes/tasks/Graphiti).
  - User watches the live reasoning, tool calls, and streaming output in the right panel.
- **D-07 (Extraction & Editor Population):** Once the chat turn finishes, the generated Markdown solution is extracted from the assistant's message and populated into the Step 2 editor.
- **D-08 (Draft Preservation):** Editor drafts are persisted in workflow state (`sdlc_workflow:${projectId}:${crId}`) so user edits and AI drafts are never lost when switching steps.

### Claude's Discretion
- Markdown extraction logic: Support both fenced code blocks (`\`\`\`markdown ... \`\`\``) and plain structured markdown starting with `# SOLUTION`.
- Error boundary: If 9Router AI call fails or is aborted, preserve editor draft and display clear actionable notification.

- PWA/GitHub Pages compatibility tuning (desktop Tauri runtime is exclusive target).
- Multi-user collaboration, roles, or cloud synchronization.

## Architecture Patterns

### System Architecture Diagram: Step 2 Solution Generation & Mutation Flow

```
[User Action in SDLC Studio]
   │
   ├── "Bắt đầu phân tích Solution" (Step 1)
   └── "Phân tích lại bằng AI" (Step 2)
   │
   ▼
[Post Prompt to Step 2 Chat Thread (`sdlc:${projectId}:${crId}:SOLUTION`)]
   │
   ▼
[StepChatPanel: runAiOrchestratorLoop]
   ├── Grounding Context: PL01, PL02, Project Metadata
   ├── Tools: query_notes, query_tasks, search_memory_facts, dynamic MCPs
   │
   ├── [Loop 1..N: Reasoning & Tool Calls]
   │     ├─► Live streaming feedback on Right Panel
   │     └─► Mutation check gate (Analysis Mode ON: Read-only)
   │
   └── [Synthesis Pass: Complete Markdown SOLUTION.md]
         │
         ▼
[Auto-Extraction Callback]
   │
   ▼
[Populate Step 2 Editor (Step2SolutionView)]
   │
   ▼
[Persist Workflow State to Dexie: `sdlc_workflow:${projectId}:${crId}`]
```

### Pattern 1: Safe Mutation Gate in Ordinary Chat
Trong chat thông thường (Analysis Mode OFF):
1. LLM nhận đầy đủ bộ công cụ `AI_DATABASE_TOOLS` + dynamic MCPs.
2. Khi LLM gọi `isMutationTool(toolName)`:
   - Nếu `autoApproveMutations === true`: cho phép thực thi ngay (`proceed: true`), yêu cầu báo cáo chi tiết.
   - Nếu `autoApproveMutations === false`: tạo `pendingConfirmation`, hiển thị thẻ xác nhận hoặc lắng nghe lời thoại đồng ý của người dùng.
3. Trong Analysis Mode (Analysis Mode ON):
   - `getToolsForTurn` loại bỏ hoàn toàn các mutation tools.
   - `onMutationCheck` trả về `{ proceed: false, cancellationResult: 'Analysis Mode chỉ đọc...' }`.

### Pattern 2: Unified Chat-to-Editor Pipeline for SDLC Step 2
Thay vì `Step2SolutionView` tự gọi trực tiếp API `streamChatEvents`:
1. `Step2SolutionView` hoặc `Step1IntakeView` kích hoạt hàm `onTriggerSolutionAnalysis()`.
2. Hàm này gửi một tin nhắn có cấu trúc vào `StepChatPanel` của Step 2:
   ```markdown
   Hãy phân tích yêu cầu nghiệp vụ (PL01) và đặc tả chức năng (PL02) dưới đây để thiết kế tài liệu kiến trúc SOLUTION.md chi tiết:
   ...
   ```
3. `StepChatPanel` chạy `runAiOrchestratorLoop`.
4. Khi turn hoàn tất (`onComplete`), bắt sự kiện và gọi hàm callback `onSolutionExtracted(extractedMarkdown)`.
5. Editor nhận nội dung mới, đồng thời lưu vào `workflowState.artifacts.solution.content` để chống mất dữ liệu khi remount.

## Common Pitfalls

### Pitfall 1: Auto-trigger Loop on Component Remount
- **Nguyên nhân:** Đặt `useEffect(() => { if (!content && pl01) runAnalysis(); }, [content, pl01])` trong `Step2SolutionView`. Khi người dùng chuyển sang Step 1/Step 3 rồi quay lại Step 2, `hasTriggeredRef` bị reset và kích hoạt lại phân tích AI ngoài ý muốn, làm mất bản nháp người dùng vừa sửa.
- **Giải pháp:** Xóa hoàn toàn `useEffect` auto-trigger. Chỉ kích hoạt khi có sự kiện bấm nút tường minh từ người dùng.

### Pitfall 2: Assistant Response chứa Markdown Fenced Code Blocks
- **Nguyên nhân:** Mô hình AI thường bọc toàn bộ nội dung tài liệu trong thẻ code ```markdown ... ``` hoặc trả về lời dẫn chuyện kèm tài liệu.
- **Giải pháp:** Xây dựng hàm `extractSolutionMarkdown(text)` thông minh:
  1. Kiểm tra block ````markdown([\s\S]*?)````. Nếu có, trích xuất phần bên trong.
  2. Nếu không có block code nhưng bắt đầu bằng `# SOLUTION` hoặc chứa `# SOLUTION`, lấy từ vị trí `# SOLUTION` trở đi.
  3. Loại bỏ các khối thinking `<think>...</think>`.

### Pitfall 3: Lạc mất cấu hình Tab của Step Thread
- **Nguyên nhân:** Cấu hình `analysisMode` hoặc `model` của SDLC step chat lưu vào global key hoặc không được liên kết đúng với `ChatTab` tương ứng.
- **Giải pháp:** Đảm bảo `getStepThread` liên kết với một bản ghi `ChatTab` (`type: 'sdlc'`), lưu `config.analysisMode = true` mặc định, và cho phép chuyển đổi linh hoạt qua `ChatTabToolbox`.

## Code Examples

### Trích xuất Markdown Solution từ phản hồi AI
```typescript
export function extractSolutionMarkdown(rawResponse: string): string {
  if (!rawResponse) return '';
  const clean = rawResponse.replace(/<think>[\s\S]*?<\/think>/g, '').trim();

  // 1. Kiểm tra fenced markdown code block
  const fencedMatch = clean.match(/```(?:markdown|md)?\s*([\s\S]*?)```/i);
  if (fencedMatch && fencedMatch[1]?.includes('# SOLUTION')) {
    return fencedMatch[1].trim();
  }

  // 2. Tìm điểm bắt đầu # SOLUTION
  const solutionIdx = clean.indexOf('# SOLUTION');
  if (solutionIdx !== -1) {
    return clean.slice(solutionIdx).trim();
  }

  return clean;
}
```
