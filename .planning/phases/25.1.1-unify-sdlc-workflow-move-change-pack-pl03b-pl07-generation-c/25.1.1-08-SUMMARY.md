## Deviations from Plan

- **A pre-existing restore/turn race surfaced and was fixed.** With the wizard state gone, re-running `tests/ai/AIChatDrawerSdlcIntake.test.tsx` failed intermittently on `ignores citations resolved under a different scope`: the restore effect fired after a turn's `clearCheckpoint` and `coordinator.restore()` reloaded the persisted row, which still held `checkpoint.status === 'running'`; `restore()` promotes that to `interrupted`, and the next send returned at the interrupted-checkpoint guard, so `payloads` stayed empty. The effect now skips the reload when `coordinator.getState()` is already populated — the drawer's coordinator is the only writer of that settings row, so its in-memory state is authoritative. Verified with 5 consecutive passing runs of the suite. At HEAD the same test failed once in 8 runs, so this is a latent flake the removal made deterministic rather than a new defect.
- **`ReconciliationResult` and `ChangePackValidationCode` imports were dropped.** The plan listed them as "keep", but after the wizard handlers went, nothing in the drawer names them: plan 04's `handleHubPackSelect` captures the error code through `ChangePackValidationError` and `HubChangePackDraft` (declared in `HubStepPanels.tsx`, which owns those two imports). `tsc` flagged them as unused, so they were removed. `ChangePackManifest` and `cabActionRef` do remain (6 combined hits).
- **`handleSendMessage`'s wizard short-circuit was the only behavioural change to the send path.** No other send-path logic was touched.
- **A scripted edit briefly deleted the `ScopeChipsBar` opening tag instead of the `{wizardMetadataModal}` block**; caught by reading the region back and restored before any commit.

## Pre-existing failures (not regressions)

- `tests/ai/AIChatDrawerSdlcRecovery.test.tsx`: `opens a new cycle when the last cycle is completed` and `closes the active cycle when CAB generation succeeds` fail identically at HEAD (verified by stashing the working tree).
