# Phase 25.1.1 Plan 05: Hub Step 5 — PL03B/PL07 Generation and commitTechDoc

**Hub step 5 now generates PL03B and PL07 from the committed SOLUTION and confirmed change pack with no wizard session: the stage call is the exact shape the real `runWizardStage` accepts (pin carries `projectId`/`threadId`), evidence is scoped to the project's published SDLC sets, both payloads pass the real `buildWizardDocx` dispatcher, and `commitTechDoc` finally has production callers.**

## Accomplishments

- `src/services/wizard/hubTechDocs.ts`:
  - `toPl03bDocxPayload` narrows with `WizardPl03ProposalSchema`, builds the approved envelope, and copies the reconciliation verbatim as the approved drift record.
  - `toPl07DocxPayload` sanitizes marks through an **exact** section allowlist `/^(I|II|III|IV|V)\.\d+$/` (not `[IV]+`, which admits `VI.1`/`VII.1`/`IIII.1` and makes the dispatcher reject the whole payload), downgrades evidence-less positive marks to `unknown`, drops evidence-less `sectionVI` findings (renumbering the survivors), then re-validates through `WizardPl07ProposalSchema`.
  - `generateHubTechDocs` resolves `isCurrent` once, builds the identity-carrying pin, collects evidence once against `resolveSetIds(projectId)`, runs PL03 then PL07 **sequentially**, and persists both through `saveApprovedArtifact` with `sourceArtifacts: [{ solution }]`.
- `StepTechDocsPanel` is now the full state machine: `blocked` (persistent prerequisite hint + disabled button), `ready`, `generating` (`role="status"` + loading), `error` (enumerated copy + `Thử lại`), the `Tạo lại PL03B & PL07` label when stale or a doc exists, and a focus hand-off from the generation button to the PL03B row's export button.
- `AIChatDrawer`: `techDocsState` (derived from workflow artifacts, never persisted, reset per tab), `collectSdlcEvidence`, `resolveSdlcSetIds` (the `db.documentSets` lookup the wizard's `resolveEvidenceInput` performed), and `handleHubGenerateTechDocs`, which derives both revisions from the artifact chain and calls `commitTechDoc` twice.
- `handlePackConfirm` and the rest of the legacy wizard path are untouched.

## Deviations from Plan

- **`toPl07DocxPayload` validates twice.** The plan described a straight map; instead the sanitized marks are fed back through `WizardPl07ProposalSchema` and the payload is built from the parsed result. Same behaviour, one validator instead of two, and an out-of-enum `itemId` cannot reach the docx schema.
- **`inputRevision` is `pl03b.version + pl07.version + 1`** in the drawer, as the plan specified, while `draftRevision` is `max(...) + 1`. Both are derived; the shared draft revision keeps the two idempotency keys distinct by kind.
- **The plan's optional `errorMessage` prop is implemented** but the drawer leaves it unset, so the enumerated copy is the only error text that can render (no raw error objects).
