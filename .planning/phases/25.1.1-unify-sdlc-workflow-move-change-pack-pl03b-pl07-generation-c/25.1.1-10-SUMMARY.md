## Deviations from Plan

- **Task 2's drawer edit was a no-op.** Plan 08 already removed `createWizardCoordinatorFn` from `AIChatDrawerProps` and from the destructured defaults, so the plan's "if a leftover reference exists, it is a plan-08 bug" case had nothing to fix. `grep` confirms zero references.
- **A real collapse defect was found and fixed.** The acceptance spec asserted the six step rows disappear after `Thu gọn quy trình`. They did not: `SdlcWorkflowHub.tsx:381` set `hidden={!timelineExpanded}` but the same element carried an inline `display: 'flex'`, and inline `display` beats the `hidden` attribute's UA rule. The existing unit test (`collapses and expands the six-row timeline`) only asserted the `hidden` *attribute*, so it passed while the rows stayed visible. Fixed by making `display` follow `timelineExpanded`; both the unit suite (48 passed) and the acceptance test now pass. This is a genuine user-visible bug the plan's acceptance spec was written to catch.
- **`wizardState.test.ts` lost more imports than the plan listed.** Beyond `createWizardCoordinator`/`deriveActiveWizard`, `WizardCoordinatorDeps`, `ChangePackIdentity`, `ChangePackManifest`, `ReconciliationResult` and `vi` were used only inside the deleted describe or its fixtures, so `tsc` flagged them unused and they were removed.
- **`AIChatDrawerSdlcIntake.test.tsx` was not edited.** It never imported the coordinator (only the two other suites did); grep confirmed. Two of fourteen standalone runs hit the pre-existing `sends merged content with per-source id/version/hash citations` flake, which the phase context records as order-dependent and pre-existing.
