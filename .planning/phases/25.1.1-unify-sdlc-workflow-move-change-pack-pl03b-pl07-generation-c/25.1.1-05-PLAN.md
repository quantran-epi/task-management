Types:
- `export type HubExportKind = 'PL02' | 'PL03B' | 'PL07' | 'CAB'`.
- `export interface HubExportResult { status: 'saved' | 'saved_download_failed' | 'failed'; noteId?: string; filename?: string; sizeBytes?: number; errorCode?: string }`.
- `export interface HubExportInput { db: TaskPlannerDatabase; kind: HubExportKind; projectId: string; threadId: string; sessionId: string; inputRevision: number; draftRevision: number; metadata: SdlcWorkflowMetadata; state: SdlcWorkflowState; saveNote?: typeof saveApprovedArtifact; buildDocx?: typeof buildWizardDocx; downloadFile?: typeof downloadBlob }`.

`export function toPl02DocxPayload(metadata, markdown, inputRevision, draftRevision): Pl02DocxPayload` — approved envelope (`schemaVersion: 1, kind: 'PL02', status: 'approved', inputRevision, draftRevision, approvedRevision: draftRevision`), `metadata: { crCode, featureName, requestingUnit, author, createdDate: metadata.date }`, `introduction: { purpose: markdown, users: '(chưa cung cấp)', deploymentScope: '(chưa cung cấp)', risks: [], glossary: [] }`, one feature `{ name: metadata.featureName, description: markdown, fileLayout: [], inputRules: [], processingRules: [], flowSteps: [] }`, empty `permissions`/`notifications`/`apiContracts`/`staffing`. This mirrors the wizard's `normalizeApprovedExportPayload` so the produced document is byte-shape-identical after the move.

`export async function ensurePl02ArtifactNote(input): Promise<{ noteId: string; version: number; hash: string }>` — if `state.artifacts.pl02?.noteId` names a Note in this project whose `sdlcArtifact.kind === 'PL02'` and `inputHash === inputHash`, return it. Otherwise `saveApprovedArtifact({ kind: 'PL02', ..., exportPayload: toPl02DocxPayload(...) }, db)` and return `{ noteId, version, hash }`. Idempotency comes from `saveApprovedArtifact`'s key, so a second call returns the same Note with `created: false`.

`export async function exportHubArtifact(input): Promise<HubExportResult>`:
1. Resolve the kind's ref from `state.artifacts` (`pl02`/`pl03b`/`pl07`/`cab`). Missing → `{ status: 'failed', errorCode: 'ARTIFACT_NOT_READY' }`.
2. Resolve payload + markdown: `PL02` → `ensurePl02ArtifactNote` with `markdown = ref.content ?? ''`; `PL03B`/`PL07`/`CAB` → read the Note by `ref.noteId`, parse its body as `{ markdown, exportPayload }`; a parse failure → `{ status: 'failed', errorCode: 'ARTIFACT_PAYLOAD_INVALID' }`.
3. `blob = await (input.buildDocx ?? buildWizardDocx)(kind, payload)`. On throw, return `{ status: 'failed', errorCode: (err as { code?: string }).code ?? 'WIZARD_DOCX_BUILD_FAILED' }` **before** any Note write.
4. `PL03B`/`PL07`/`CAB` already have their Note; use `ref.noteId`. `PL02` uses the id from step 2.
5. `filename` = kind + CR + version, sanitized with the wizard's regex `replace(/[^\p{L}\p{N}._-]+/gu, '-')`, suffixed `.docx`.
6. `download = await (input.downloadFile ?? downloadBlob)(blob, filename)`; map `download_initiated`/`save_picker_saved` → `saved`; `cancelled` → `saved_download_failed` with `errorCode: 'WIZARD_EXPORT_DOWNLOAD_CANCELLED'`; `failed` → `saved_download_failed` with `download.errorCode`.
7. Never return `saved` before `noteId` is known.

Create `tests/ai/hubExport.test.ts` with a real `TaskPlannerDatabase`; seed a project, a project-scoped `chatThreads` row, and a PL03B artifact Note whose body is `JSON.stringify({ markdown, exportPayload })`. Copy the minimal PL03B payload literal shape used in `tests/export/wizardDocx.test.ts` (do not import from that test file). Cover all five behaviours; stub `downloadFile` per case.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored Note payload → docx builder | payload JSON came from a model response and round-tripped through Dexie |
| blob → filesystem | `downloadBlob` writes user-visible files |
| CAB sources → workflow state | three artifact pins decide what the approval document claims |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25.1.1-19 | Tampering | stored `exportPayload` | mitigate | `buildWizardDocx` re-validates every payload with its strict schema before packing, so a corrupted or hand-edited Note body fails loudly (`WIZARD_DOCX_PAYLOAD_INVALID`) instead of producing a misleading document. |
| T-25.1.1-20 | Repudiation | CAB source pins | mitigate | `validateCabSources` requires exactly PL02/PL03B/PL07 with matching ids, versions, hashes and `approved: true`; `saveApprovedArtifact` independently revalidates each source Note before writing. |
| T-25.1.1-21 | Information disclosure | exported filename | mitigate | Filenames are sanitized with the existing Unicode-safe regex; no token, path, or endpoint can enter a filename. |
| T-25.1.1-22 | Tampering | retry path | mitigate | Retry resolves the same stored Note by id and never re-saves, so a double click cannot create duplicate artifact Notes or duplicated backup payloads. |
| T-25.1.1-23 | Denial of service | CAB stage | accept | One extra 8k-token stage, guarded by the caller's in-flight ref; a failure writes nothing. |
</threat_model>
