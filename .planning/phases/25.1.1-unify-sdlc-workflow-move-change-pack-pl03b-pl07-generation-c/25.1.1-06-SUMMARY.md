# Phase 25.1.1 Plan 06: Export and CAB services

**Export and CAB now exist without the wizard: every artifact resolves to a real `buildWizardDocx` payload and a Note, CAB resolves its own PL02 pin from the content hash (so the typed-text path works), and CAB generation is proven against the real `runWizardStage` rather than a stub.**

## Performance

- **Duration:** ~14 min
- **Tasks:** 2 (both verified)
- **Files modified:** 4 (4 created)

## Accomplishments

- `src/services/wizard/hubExport.ts`:
  - `ensurePl02ArtifactNote` is the PL02 Note producer. It hashes `markdown.trim()` with `defaultSha256` — the exact value `startOrUpdateIntake` recorded and `validatedSources` compares — and derives `inputRevision = draftRevision = (state.artifacts.pl02.version ?? 0) + 1`. It returns the pinned Note on a hash match and otherwise writes a new one, so identical content replays to the same Note via `${sessionId}:PL02:${hash}`.
  - `exportHubArtifact` resolves the stored payload for PL03B/PL07/CAB, builds the blob **before** any Note write, then downloads and maps `download_initiated`/`save_picker_saved` → `saved`, `cancelled`/`failed` → `saved_download_failed`. It never returns `saved` without a `noteId`.
  - `toPl02DocxPayload` mirrors the wizard's `normalizeApprovedExportPayload` shape, so the produced document is unchanged by the move.
- `src/services/wizard/hubCab.ts`:
  - `toCabDocxPayload` narrows with `WizardCabProposalSchema`, maps sections 2..n into `technicalChanges` bounded to 600 chars / 12 items, keeps section 1 as `contextObjective`, folds `missingTests` into `caveats`, and leaves `sit`/`uat` null rather than inventing results.
  - `generateHubCab` builds one `CabSourcePin[]` and reuses it for the stage payload and the docx payload, calls the stage with `model` + `isCurrent`, collects evidence against `resolveSetIds(projectId)` (never `[]`), and persists the CAB with `sourceArtifacts` keyed by `artifactId`.
  - PL02 comes from `ensurePl02ArtifactNote`, not from `state.artifacts.pl02.noteId` — the defect that made CAB unreachable is closed.

## Deviations from Plan

- **`ensurePl02ArtifactNote` takes an optional `saveNote` seam.** The plan's `HubExportInput` already had it; the standalone function needed it too so the "retry never duplicates" test can assert the save call count alongside the Note count. Production callers omit it.
- **`exportHubArtifact` builds the PL02 payload locally but writes through `ensurePl02ArtifactNote`.** The plan described step 2 as "PL02 → the Note from `ensurePl02ArtifactNote`"; implemented as build-first-then-resolve, which is the stronger ordering (a failed build writes nothing) and keeps one PL02 writer.
- **Extra guard `if (!noteId) return failed('ARTIFACT_PAYLOAD_INVALID')` before download.** Without it `HubExportResult.noteId` would be `string | undefined` under `exactOptionalPropertyTypes`, and the plan's "never return `saved` before `noteId` is known" would be unenforced by types.

## Issues Encountered

- A test seeded `pl07.noteId` as `undefined` to model the missing-PL07 case; `SdlcWorkflowStateSchema` is a strictObject, so the key had to be omitted entirely (`withPl07: false`) rather than set to `undefined`. The first run failed with `ARTIFACT_SOURCE_MISMATCH` (the stage ran before the persisted CAB write), which is exactly why the guard belongs before the stage call — fixed at the test-fixture level.
- `tsc` under `exactOptionalPropertyTypes` rejected the optional `noteId` in the `saved_download_failed` branches; resolved by the explicit `noteId` guard above rather than widening the type.
