# Phase 25.1.1 Plan 01: Wizard-Free, Content-Addressed Artifact Persistence Summary

**Artifact and change-pack Notes now persist with zero wizard rows in the thread, and the idempotency key is addressed by content hash so regeneration lands at version 2 instead of throwing `ARTIFACT_IDEMPOTENCY_CONFLICT`.**

## Accomplishments
- Deleted `currentWizardSnapshot` and the completed-snapshot event write; persistence is now gated on `assertProjectThread` (thread exists, `scopeType === 'project'`, owned by the project) plus `assertCommitIdentity` (session, revisions, hash shape, approval timestamp).
- `buildWizardIdempotencyKey` takes optional `inputHash`; when present the key is `${sessionId}:${kind}:${inputHash}` so a changed body is a new version and an identical body replays regardless of `draftRevision`. Legacy format preserved when no hash is supplied.
- New `tests/ai/artifactPersistence.test.ts` proves all seven required behaviours with no wizard fixtures, plus canonical chain ordering across a regeneration.

## Decisions Made
- Content-addressed key excludes `draftRevision`: callers derive it from the version the first save advanced, so including it would make every second click a new key.
- Kept the legacy revision-addressed format when `inputHash` is absent, preserving `tests/ai/wizardState.test.ts` legacy expectations and existing `persistConfirmedPack` entry prefixes.
- Reused `WIZARD_THREAD_MISMATCH` / `WIZARD_PROJECT_MISMATCH` codes rather than inventing new ones, so existing callers and messages stay valid until the wizard is deleted in plans 09/10.
