## Deviations from Plan

- **`HubExportKind` is imported, not redeclared.** The plan's action asked for `renderExportRow` to be normalized to `(kind: 'PL02' | 'PL03B' | 'PL07' | 'CAB') => React.ReactNode`; `hubExport.ts` already exports that exact union, so `HubStepPanels.tsx` imports it and exports only the `RenderExportRow` alias. One owner for the union, and a future kind cannot drift between the service and the panels.
- **The per-kind in-flight guard is a `useRef<Set<HubExportKind>>`, not `exportStates[kind].phase`.** Reading the phase inside `setExportStates` would need a mutable escape hatch; the ref is the same pattern `techDocsBusyRef`/`hubPackBusyRef` already use in this file.
- **`handleHubExport` and `handleCabGenerate` were moved below `handleHubGenerateTechDocs`.** Both close over `getSdlcCoordinator`, `collectSdlcEvidence` and `resolveSdlcSetIds`, which are declared further down the component; the original wizard-era position only worked because those helpers were not referenced. `tsc` rejected the forward use.
- **`StepCabPanel`'s export slot only renders once `cab` exists**, so a missing CAB cannot surface an export button that would immediately fail with `ARTIFACT_NOT_READY`.

## Issues Encountered

- The first `handleCabGenerate` rewrite referenced `cabBusyRef` (never declared) and the helpers declared below it; `tsc` reported 7 errors. Fixed by using the surviving `cabActionRef` as the guard and relocating the two handlers after `handleHubGenerateTechDocs`.
- A scripted move of those handlers left a dangling `]);` and split the dependency array; caught by `tsc` (`TS1137`/`TS1128`) and repaired before the Task 2 commit.
