# Phase 25.1.1 — Context

**Source:** user directive in session 2026-10-31, after reviewing Phase 25.1 code review round 4.
**Mode:** decisions locked up front; no discuss-phase needed.

## Problem statement (evidence, not opinion)

The SDLC flow currently has two parallel state machines:

- **`SdlcWorkflowHub` / `createSdlcWorkflowCoordinator`** (`workflowCoordinator.ts`, `workflowSchemas.ts`) — the visible 6-step timeline.
- **`WizardSkillBar` / `createWizardCoordinator`** (`wizardCoordinator.ts`, `wizardSchemas.ts`) — a separate chat-driven document wizard.

Grep of production callers shows the hub cannot finish its own flow:

| Hub API | Production caller |
|---|---|
| `startOrUpdateIntake` | `AIChatDrawer.tsx:1158` |
| `commitSolution` | `AIChatDrawer.tsx:1258` |
| `commitChangePackAndDrift` | **none** |
| `commitTechDoc` | **none** |
| `commitCab` | **none** |

Steps 4–6 run through the wizard instead:

- `handlePackSelect` / `handlePackConfirm` → `wizardCoordinator.selectChangePack` / `confirmChangePack` / `generateTechnicalDocs` (`AIChatDrawer.tsx:919-955`).
- `handleCabGenerate` → `wizardCoordinator.generateCab`, then only `getSdlcCoordinator()?.closeCycle()` (`AIChatDrawer.tsx:956-977`); the code comment at `:963-965` states `commitCab` is unreachable.
- DOCX export (`buildWizardDocx`, bank templates) exists only in the wizard path (`wizardCoordinator.ts:609`). `SdlcWorkflowHub.tsx` has zero docx references.

User-visible symptoms:

1. Hub step 4 says "kéo thả file change-pack.zip" but renders no drop target; the dropzone only appears after activating the wizard toolbar.
2. Activating the wizard toolbar opens `WizardMetadataModal`, asking for CR / feature name a second time (hub already collected them in `StepInputDocsModal`).
3. `packVisible = wizardSnapshot?.skill === 'PL03' || 'PL07'` (`AIChatDrawer.tsx:1269`) gates the dropzone on wizard session state, not on the hub step.
4. `WizardSkillBar` renders unconditionally for every scope and tab (`AIChatDrawer.tsx:3178`), so PL02/PL03/PL07/CAB buttons appear in ordinary chat tabs where they cannot work.
5. Two metadata sources can disagree: PL03B/PL07 may be generated under a different CR than the PL01/PL02 committed to the hub.

## Locked decisions

- **D-U1.** The SDLC Hub is the single executable path from INTAKE to CAB. Wizard entry points do not survive as a parallel path.
- **D-U2.** Steps 4–6 run from the hub's own step panel. No step may instruct the user to use a separate toolbar.
- **D-U3.** `commitChangePackAndDrift`, `commitTechDoc`, and `commitCab` become the production writers for their steps. They already exist and are tested at the service layer; they are missing callers, not missing behaviour.
- **D-U4.** DOCX export (bank templates: PL02, PL03B, PL07, CAB) must be reachable from the hub, and each export persists as a Project-linked Note, preserving Phase 25 success criterion 3. The pure builders in `src/services/export/` stay; only the coordination moves.
- **D-U5.** `WizardMetadataModal` metadata is replaced by hub metadata (`SdlcWorkflowState.metadata`: `cr`, `featureName`). One source of truth. The wizard may prefill from hub state only during a transition period; it must never write divergent metadata.
- **D-U6.** `WizardSkillBar` is removed from production render. `WizardMetadataModal` is removed from the flow. Drawer-global wizard session state (`wizardSkill`, `wizardMetadataOpen`, `wizardSnapshot`, `wizardCoordinatorRef`) is retired.
- **D-U7.** No regression to Phase 25.1 guarantees: per-tab runtime isolation, per-tab abort/stop ownership, retry identity, checkpoint set/clear/resume/discard, revision preview + immutable cycle commit, missing-source recovery, 320px accessible vertical timeline, and the `isCurrent` commit gate.
- **D-U8.** Data safety: existing persisted user data (Notes, artifacts, `sdlc_workflow:*` settings, chat history with `wizard` snapshots) must remain readable. Removing the wizard UI must not orphan or delete previously exported artifacts.

## Scope fences

**In scope**
- Hub step 4: change-pack dropzone + confirm strip + drift matrix inside the step panel.
- Hub step 5: regenerate/generate PL03B & PL07 action.
- Hub step 6: CAB generation wired through `commitCab`.
- Hub-level DOCX export actions for PL02, PL03B, PL07, CAB.
- Retire `WizardSkillBar` + `WizardMetadataModal` from production render.
- Tests: hub/coordinator integration, change-pack, DOCX export, Playwright acceptance.

**Out of scope**
- Rewriting the docx template builders.
- Changing the six-step order or adding steps.
- Multi-user / collaboration.
- PWA behaviour.
- Cyber/security hardening beyond existing threat model.
- The order-dependent test flakes already recorded in `25.1/deferred-items.md` (pre-existing, tracked separately).

## Success criteria (mirrors ROADMAP Phase 25.1.1)

1. `commitChangePackAndDrift`, `commitTechDoc`, `commitCab` each have a production caller in the hub path; the SDLC artifact chain reaches `pl03b`, `pl07`, `cab` without the wizard coordinator.
2. Hub steps 4/5/6 expose their actions in their own step panel; no step points at a separate toolbar.
3. Every generated document exports as bank-template `.docx` from the hub and persists as a Project-linked Note.
4. `WizardSkillBar`, `WizardMetadataModal`, and drawer-global wizard session state are removed from production render; `StepInputDocsModal` metadata is the only metadata input.
5. All Phase 25.1 guarantees still hold (per-tab isolation, checkpoint/resume, revision preview + stale propagation, immutable cycles, missing-source recovery, 320px a11y timeline).
6. Focused suites (hub, coordinator, change-pack, docx, Playwright SDLC spec) pass; no skipped Phase 25.1.1 tests.
