# Phase 25.1.1 Plan 03: Hub Step 2 SOLUTION Writer

**Hub step 2 now saves SOLUTION.md without a wizard session: the Note is written first through `saveSolutionVersion`, `artifacts.solution` gains the `noteId`/`version`/`hash` triple steps 4 and 6 pin against, and a repeated save no longer pushes the workflow version past the Note version.**

## Performance

- **Duration:** ~6 min
- **Tasks:** 2
- **Files modified:** 4 (2 created)

## Accomplishments

- `src/services/wizard/hubSolution.ts` — `saveHubSolution` trims, hashes with `defaultSha256`, writes via `saveSolutionVersion` (project/thread identity asserted inside the repo), and returns `{ noteId, version, hash, created }`. It writes no workflow state by design, documented in the module.
- `AIChatDrawer` hub step 2:
  - `solutionDraftMarkdown` = newest assistant message in the SDLC thread that has no `wizard` payload and does not start with `Saved ` or `Confirmed change pack `.
  - `handleHubSaveSolution` bails on re-entry (`solutionSaveBusyRef`), warns on an empty draft, saves the Note, then commits **only** when `saved.created` or the `noteId` changed.
  - Errors surface as the fixed copy `Không thể lưu SOLUTION.md: kiểm tra PL01/PL02 đã nạp rồi thử lại.` with no raw error text; workflow state untouched on failure.
  - Save state resets on `[activeTabId]` so a save cannot leak across tabs.
  - `stepPanels.solution` passes `StepSolutionPanel` with `artifact`/`stale`/`canSave`/`onSave`/`saving`/`savedNoteId`. No `onRequestRevision` — the hub card keeps its single revision entry point.
- Version-parity regression test: save A (Note v1) → save A with `draftRevision: 2` (still v1, `created: false`) → save B (Note v2), then `persistConfirmedPack` accepts the v2 triple and writes the pack entry.
