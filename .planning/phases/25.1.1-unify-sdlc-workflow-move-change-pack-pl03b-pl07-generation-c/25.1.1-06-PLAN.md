<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| export control → filesystem | a click writes a file and a Note |
| CAB stage → workflow state | one commit changes `currentStep` and closes a revision cycle |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25.1.1-36 | Tampering | export state record | mitigate | State is keyed by `SdlcArtifactKind` only, so a stale chat id cannot target another artifact's Note; the handler re-reads `sdlcWorkflowState` at call time rather than closing over a snapshot. |
| T-25.1.1-37 | Repudiation | CAB success claim | mitigate | `message.success` fires only after `commitCab` resolves with a persisted `noteId`; `closeCycle` runs after the commit, so the cycle band cannot claim completion for an uncommitted CAB. |
| T-25.1.1-38 | Denial of service | repeated export clicks | mitigate | The per-kind `building` guard blocks re-entry, so repeated clicks cannot fan out concurrent packer runs. |
| T-25.1.1-39 | Information disclosure | model config | mitigate | Endpoint/key are read at call time and passed to the stage only; they are never placed in `exportStates`, the Note, or the filename. |
</threat_model>
