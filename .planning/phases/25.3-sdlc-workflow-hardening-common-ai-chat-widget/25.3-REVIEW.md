Phase 25.3 unified the presentational chat widget (`AiChatWidget`), decoupled headless turn orchestration (`chatTurnRuntime`), hardened SDLC workflow guards, and introduced pure prompt composition (`sdlcPromptComposer`).

- Turn isolation per tab and step is preserved without cross-talk or cancellation interference.

## Warnings

### WR-01: `isApproved` state de-synchronization on prop change in Step2SolutionView

**File:** `D:\personal\task-management\src\components\sdlc\steps\Step2SolutionView.tsx:39`
**Issue:** `isApproved` initializes via `useState(Boolean(solutionArtifact?.approvedAt))` on mount. When `solutionArtifact` changes (such as version switching or external approval/invalidation), `isApproved` is not updated because it lacks synchronization inside `useEffect`.
**Fix:**
```typescript
useEffect(() => {
  setIsApproved(Boolean(solutionArtifact?.approvedAt));
}, [solutionArtifact?.approvedAt]);
```

### WR-02: Missing `approvedAt` timestamp assignment in commitRevision

**File:** `D:\personal\task-management\src\services\wizard\workflowCoordinator.ts:184-192`
**Issue:** `commitRevision` creates the next artifact without assigning `approvedAt: now()`, unlike `commitSolution`, `commitTechDoc`, and `commitCab`. Consequently, subsequent workflow guards requiring an approved artifact (e.g. `SOLUTION_REQUIRED_FOR_CHANGE_PACK`) will block downstream progress until re-approved.
**Fix:**
```typescript
const next: SdlcArtifactRef = {
  kind: preview.kind,
  version: preview.baseVersion + 1,
  hash: preview.hash,
  title: previous?.title ?? preview.kind,
  content: preview.markdown,
  sourceHashes: previous?.sourceHashes ?? [],
  updatedAt: now(),
  approvedAt: now(),
};
```

### WR-03: Uncleaned setTimeout timer on unmount in ProjectSdlcView

**File:** `D:\personal\task-management\src\views\ProjectSdlcView.tsx:337`
**Issue:** `handleTriggerSolutionAnalysis` invokes `setTimeout` to dispatch `sendMessage` to `chatPanelRef.current` after 300ms. The timeout handle is not saved or cleared on unmount, risking execution against an unmounted or re-keyed panel ref.
**Fix:**
```typescript
const analysisTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

useEffect(() => {
  return () => {
    if (analysisTimerRef.current) clearTimeout(analysisTimerRef.current);
  };
}, []);

// In handleTriggerSolutionAnalysis:
if (analysisTimerRef.current) clearTimeout(analysisTimerRef.current);
analysisTimerRef.current = setTimeout(() => {
  chatPanelRef.current?.sendMessage(prompt, 'ANALYSIS');
}, 300);
```

### IN-01: Inconsistent message ID vs event ID tracking in appendArtifactEventMessage

**File:** `D:\personal\task-management\src\services\ai\chatRepo.ts:40-48`
**Issue:** `appendArtifactEventMessage` assigns `id: crypto.randomUUID()` while accepting `event.eventId`. Queries searching by `eventId` will not match `message.id`.
**Fix:**
```typescript
id: event.eventId ?? crypto.randomUUID(),
```
