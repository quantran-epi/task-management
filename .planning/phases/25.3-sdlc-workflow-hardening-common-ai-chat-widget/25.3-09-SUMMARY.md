# Plan 25.3-09 Summary — StepChatPanel as thin host adapter

## Objective

Turn `StepChatPanel` into a thin host adapter over the shared `AiChatWidget`, drive
`workflowState` from the coordinator's restore path, and persist one durable artifact card
per artifact version.

## What changed

### Task 1 — StepChatPanel becomes a host adapter (278 → 273 lines)

- One `useChatTurn` per step scope; the inline message loop, streamed-status state, mutation
  approval UI and composer are gone.
- Every turn is composed through `composeSdlcTurn` (plan 25.3-03), so the shared policy,
  step contract, grounding and optional artifact-output contract arrive as layers.
- Toolbox state (models, Analysis Mode, Auto-approve, MCP, clear) moved to the new
  `useStepChatToolbox` hook. Step chat defaults Analysis Mode on for inspection.
- New `createDefaultChatTurnDeps(db)` in `chatTurnRuntime.ts` keeps `runAiOrchestratorLoop`,
  `saveMessage` and `describeToolMutationWithContext` out of every host component, so exactly
  one wiring point exists. This also satisfies the plan's acceptance that `StepChatPanel`
  contains zero direct references to those three symbols.
- `onRequestAiAnalysis` prop removed (was never read — TS6133). The solution-analysis trigger
  is now `StepChatPanelHandle.requestArtifactAnalysis`, a post-turn action.

### Task 2 — Coordinator restore before action

- `ProjectSdlcView` no longer reads `sdlc_workflow:` itself. `workflowStorageKey(projectId, crId)`
  is exported from `workflowCoordinator.ts` and `saveState` / `loadState` / `deleteState` all
  go through it. The view contains **zero** `sdlc_workflow:` literals.
- A race-guarded effect calls `coordinator.restore()` on mount and on CR change. A rejected
  restore leaves `workflowState` undefined so step views render their prerequisite guards
  instead of throwing.
- `handleCommitSolution` and `handleResetWorkflow` no longer touch the workflow row directly;
  reset goes through `coordinator.reset()`.
- `createSdlcWizardRuntime` is built once per DB. A construction failure (e.g. no configured
  model) leaves `wizardRuntime` undefined so Step 5/6 render their configuration guard.
- Guard failures surface via `formatGuardMessage` in `message.error`; raw codes never reach
  the user.
- `hasIntakeBaseline` and `onNavigateToStep` are wired into Step 2 and the workspace.

### Task 3 — Durable artifact event cards

- `appendArtifactEvent(stepId, kind, ref, status)` writes exactly one `ChatMessage` carrying
  `artifactEvent` into the thread of the step that produced it (`getStepThread`).
  `content` is a one-line label — the artifact body stays in the editor (D-06).
- Called on SOLUTION draft extraction (`draft`, CTA `Mở trình soạn thảo`) and after each
  successful commit (`approved` for SOLUTION, PL03B/PL07 into `TECH_DOCS`, CAB into `CAB`).
- `onArtifactOpen(eventId, readOnly)` selects the owning step and flips the SOLUTION editor
  into preview mode when read-only.
- `readOnly = version !== activeVersions[kind] || cr.status !== 'active'`. `SdlcCr.status` is
  `'active' | 'completed' | 'archived'`; there is no `'closed'`.
