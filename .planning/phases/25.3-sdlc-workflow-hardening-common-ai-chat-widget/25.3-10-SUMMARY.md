# Phase 25.3 Plan 10: AIChatDrawer as a host over the shared widget Summary

The Drawer lost its 900-line inline turn loop and now hosts `AiChatWidget` with one shared turn runtime per tab, so a background request keeps streaming when the user switches tabs.

## What Was Built

**`src/components/ai/runtime/tabRuntimes.ts` (new)** — `createTabTurnRegistry(createDeps)` returning `{ get, peek, discard, abortTab, abortAll, getSnapshot }`. `get(tabId, threadId)` returns the same `createChatTurnRuntime` instance until the thread changes, `discard` aborts and drops it, `abortAll` covers unmount and scope change. All state is in a `Map` behind a ref; nothing here is React state.

**`src/components/ai/AIChatDrawer.tsx` (2481 → ~2180 lines)** — turn loop deleted. What remains:

- `handleSendTurn` composes the prompt (scope grounding, mentions, attached files, MCP instructions, anti-hallucination system prompt), persists the user row, routes the grounded pipeline, then hands a `ChatTurnRequest` to `registry.get(tabId, threadId).start(...)`.
- Per-tab host abort controllers (`hostAbortRef`) carried through `hostSignal(tabId)`; the runtime keeps its own controller for the tool loop, so stop/close/unmount abort both halves of exactly the owning tab.
- Runtime publishes map onto the existing `useTabRuntimes` snapshot (status badge, streaming text, tool name, pending approval, error) plus a `turnRevision` counter so the widget re-reads the registry.
- Retry delegates to `runtime.retry()`, which anchors on the persisted user id — no second user row.
- Kept: header, tab bar, scope picker, debug/instructions/MCP modals, `ScopeChipsBar`, `QuickPreviewDrawer`, grounding callbacks, clarify state, evidence synthesis, `/plan|/status|/overdue|/help|/clear`, desktop notification, aiDebugService turn tracking, `getToolsForTurn` re-export.
- Exactly one literal `runAiOrchestratorLoop({ ... })` inside `runDrawerTurnLoop`, and exactly one `runGroundedTurn(` call — both pinned by `tests/phase25_1SafetyGates.test.ts:273`.

**`src/components/ai/AiChatWidget.tsx`** — added host slots instead of letting the Drawer render its own transcript: `headerSlot`, `statusExtensions`, `transcriptExtensions`, `messageListExtensions` (typed passthrough for `ChatMessageList`'s host callbacks), `onClearAllHistory`, `onOpenSettings`, `attachedFiles`, `onAttachFile`, `onRemoveFile`, `autoFocus`, `disabled`. Composition order in the transcript area is unchanged (list → extensions → tool events → staged indicator → approval → artifacts → quick prompts → composer).

**`src/components/ai/runtime/chatTurnRuntime.ts`** — `ChatTurnRequest.contextWindowTokens`, `ChatTurnRuntimeDeps.onFileGenerated`, visible-delta derivation (thinking blocks stripped before `onDelta`, so the host does not re-derive), and `durationMs` + `generatedFiles` on the persisted assistant row.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] User row was not persisted before grounded routing**
- **Found during:** Task 1 (clarify test)
- **Issue:** The old loop saved the user row after `saveMessage`; with routing first, a `clarify_intent` turn left no question in the transcript.
- **Fix:** persist the user row before routing and pass its id as `retryUserMessageId`, which the runtime then reuses verbatim.
- **Commit:** `489b2a2d`

**2. [Rule 2 - Missing critical functionality] Host prelude had no abort path**
- **Found during:** Task 1 (D-09 / scope-change tests)
- **Issue:** Stop, close and scope change only aborted the tool loop's controller; grounded routing and prompt assembly kept running.
- **Fix:** per-tab `hostAbortRef` controllers, aborted alongside `turnRegistry.abortTab`/`abortAll`.
- **Commit:** `489b2a2d`

**3. [Rule 2 - Missing critical functionality] Restored-source and checkpoint recovery had no host**
- **Found during:** Task 2 (`AIChatDrawerRestoreRecovery`, `AIChatDrawerSdlcRecovery`)
- **Issue:** `RestoredSourceNotice`, `deriveMissingSources` and `InterruptedBanner` were never mounted after the SDLC surface moved to `ProjectSdlcView`; the Drawer also never blocked a send on missing restored sources.
- **Fix:** resolve each SDLC tab's `sdlc_workflow:` row, derive missing sources, render the notice, block the send with the exact refusal string, and render the Continue/Discard banner that persists its decision before any transport call.
- **Commit:** `489b2a2d`

**4. [Rule 1 - Bug] Send could land on the previous tab**
- **Found during:** Task 2 (isolation `stop aborts only the active tab`, flaky)
- **Issue:** `ensureTurnTab()` reads the durable active pointer, which lags the click; a send right after switching tabs could own the old tab.
- **Fix:** resolve the visible tab from `durableTabs` first and fall back to `ensureTurnTab()` only while the tab list is hydrating.
- **Commit:** `489b2a2d`

No architectural (Rule 4) changes. No authentication gates.
