# Phase 25.3 Plan 02: Step 3 Handoff Contract and Step 4 Prerequisite Gate Summary

Deleted Step 3's fake implementation-status checklist in favour of a coding handoff contract with the external change-pack command, and moved Step 4's prerequisite check ahead of intake while replacing fabricated reconciliation pins with the real pinned SOLUTION Note.

## What Was Built

**Step 3 (`Step3CodeGuideView.tsx`)** — D-12:
- Removed the `Checklist kiểm tra trước khi nạp pack` card, `checkedItems` state, `handleCheckChange`, and the `Checkbox` import. No status tracker remains.
- Added `Hợp đồng bàn giao Coding & Change Pack` card with four labelled paragraphs: scope/acceptance (from new optional `approvedSolutionMarkdown`, falling back to `(chưa cung cấp)`), required tests, migration & rollback, and Change Pack requirements naming `diff.patch` / `meta.json` / CR identity.

**Step 4 (`Step4ChangePackView.tsx`)** — D-20 / D-13:
- `ChangePackDropzone` gained `disabled?: boolean`: `openPicker` early-returns, root gets `aria-disabled="true"` and `tabIndex={-1}`, all six handlers `preventDefault()` and skip `onSelect`, cursor `not-allowed`, background `colorBgContainerDisabled`. `role="button"` and `aria-label` unchanged.

- `ChangePackHistoryItem` gained `manifest?: ChangePackManifest`; the validated manifest is persisted (entry `content` replaced with `''`) at upload. `handleSelectActive` with a manifest-less legacy row renders `Tải lại tệp pack để đối soát` and leaves `driftResult` untouched.
- `ProjectSdlcView` wires `onNavigateToStep` and `approvedSolutionMarkdown`.

**Drift matrix (`DriftMatrixView.tsx`)** — D-13:

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `buildHubReconciliation` pinned on the wrong thread**
- **Found during:** Task 2
- **Issue:** The plan implies passing "the validated manifest identity and entries", but `buildHubReconciliation` also requires `threadId`, and it compares that value against `note.sdlcArtifact.threadId`. `Step2SolutionView` writes the SOLUTION Note under scope key `sdlc:${projectId}:${crId}:SOLUTION`, while the old local builder used `:CHANGE_PACK`. Passing the CHANGE_PACK thread would fail every reconciliation with `PACK_SOLUTION_MISMATCH`.
- **Fix:** Added `solutionThreadId(projectId, crId)` returning the SOLUTION scope key and pass it to `buildHubReconciliation`.
- **Files modified:** `src/components/sdlc/steps/Step4ChangePackView.tsx`
- **Commit:** eef0ce9f

**2. [Rule 2 - Missing critical] Persisted manifest carried raw entry bytes**
- **Found during:** Task 2
- **Issue:** `ChangePackEntry.content` holds file text/Uint8Array. Persisting the manifest verbatim would duplicate up to the 26 MB expanded pack into the settings row.
- **Fix:** `persistableManifest()` replaces every entry's `content` with `''` before persisting; reconciliation only needs `path`/`status`/`coverage`.
- **Files modified:** `src/components/sdlc/steps/Step4ChangePackView.tsx`
- **Commit:** eef0ce9f

### Non-deviations worth noting

- The plan's `grep -c "base-commit\|head-commit"` acceptance check is satisfied by construction: the literals are gone. Verified `grep -c "repeat(64)"` returns 0.
- `grep -c "manifest?"` on `sdlcCrManager.ts` returns 1 (single declaration).
