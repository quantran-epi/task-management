# Phase 25.3 Plan 04: Step 2 Intake-Baseline Guard Summary

Step 2 can no longer approve a SOLUTION without PL01 and PL02: the approve control is disabled up front, the warning Alert names both missing artifacts and the supplying step, and a primary CTA jumps straight to Bước 1.

## What Was Built

**`src/components/sdlc/steps/Step2SolutionView.tsx`**
- New props `hasIntakeBaseline?: boolean` and `onNavigateToStep?: (step: SdlcStepId) => void`.
- `baselineReady = hasIntakeBaseline ?? Boolean(pl01Content.trim() && pl02Content.trim())` — authoritative host answer first, text fallback second (T-25.3-45).
- Approve button: `disabled={!content.trim() || !baselineReady}`, label unchanged (`Duyệt & Lưu SOLUTION.md`).
- Warning `Alert` above the editor when `!baselineReady`: `message={formatGuardMessage('INTAKE_BASELINE_MISSING')}`, description naming `PL01 — Yêu cầu nghiệp vụ` and `PL02 — Đặc tả chức năng` from Bước 1, `action` holding `Chuyển đến Bước 1: Hồ sơ đầu vào` → `onNavigateToStep?.('INTAKE')` (disabled when the callback is absent).
- `metadata` now renders as a CR `Tag` in the header — the three TS6133 errors (`pl01Content`, `pl02Content`, `metadata`) are gone.
- `Phân tích lại bằng AI` untouched: read-only analysis of a missing baseline stays available (D-23, no AI call on mount).

**`tests/unit/sdlc/Step2SolutionView.test.tsx`** (new) — 4 cases: disabled + both artifacts named + nav CTA fires `INTAKE`; AI analysis reachable without baseline; enabled once both contents supplied; `hasIntakeBaseline` overrides the text fallback.

**`tests/unit/sdlc/StepViews.test.tsx`** — Step2 block now supplies `pl01Content`/`pl02Content`/`hasIntakeBaseline` and keeps the two-way editing + sanitized preview assertions; adds one assertion that dropping the baseline leaves the button disabled, renders the guard copy and never commits.
