# Phase 25.3 Plan 06: Step 6 Evidence-Honest CAB Summary

Step 6 now generates a CAB draft from real evidence only, discloses gaps instead of asserting control, keeps a separate TaskMate-internal CR summary, and commits nothing until the user clicks `Lưu & Phê duyệt`.

## What was built

**Task 1 — TaskMate-only structured CR summary (D-15).**

- `src/services/wizard/hubCrSummary.ts`: `HubCrSummarySchema` (`z.strictObject`) with `scope`, `actualChanges`, `keyDecisions`, `risksRollback`, `openGaps`, `evidenceLinks`; `buildHubCrSummary`, `renderHubCrSummaryMarkdown`.
- `actualChanges` reads only `PL03B` implementation bullets (heading matched by `/thực tế triển khai|implementation|thay đổi/i`); SOLUTION prose is never used as proof of shipped work.
- `rollbackVerified` is `true` only for `status === 'verified'` **and** `evidenceIds.length > 0`. Status `verified` with no evidence ids stays unverified and adds `Thiếu bằng chứng: rollback chưa được kiểm chứng` to `openGaps`.
- `openGaps` never returns empty: each absent source (CAB, Change Pack, driftResult, PL03B) contributes a `Thiếu bằng chứng: ...` entry, and unresolved drift tuples are appended.
- `evidenceLinks` maps only artifact refs actually present in state.
- Rendered markdown carries no `GoLive`, addressee, or approval-request wording — asserted by test.
- `SdlcWorkflowStateSchema.artifacts` gained an optional `crSummary: { markdown, updatedAt }` strict slot. No Dexie version bump (`version(` count unchanged at 14), no new `SdlcArtifactKind` member, no `saveHubCrSummary`.

**Task 2 — Evidence-constrained CAB draft with explicit approval (D-13, D-17, D-20).**

- `hubCab.ts` split into a shared body and two entry points:
  - `generateCabBody` — evidence collection, `runStage({ kind: 'CAB' })`, `toCabDocxPayload`, markdown. Writes nothing.
  - `generateHubCabDraft` — resolves PL02 **read-only** from `state.artifacts.pl02` (note id + content required) and throws `CAB_SOURCE_CHAIN_REQUIRED` otherwise. Imports/calls neither `ensurePl02ArtifactNote` nor `saveApprovedArtifact`.
  - `generateHubCab` — calls `ensurePl02ArtifactNote` then the shared body, then `saveApprovedArtifact`. Both write symbols appear exactly once (1 import + 1 call for `saveApprovedArtifact`; `ensurePl02ArtifactNote` at line 261 inside `generateHubCab` only).
- CAB markdown gained `## Khoảng trống bằng chứng` listing drift status, uncovered coverage entries, unresolved drift tuples, and proposal `unresolvedDrift`/`caveats`. Empty only when the reconciliation itself reports nothing.
- `rollbackLine` renders `chưa có bằng chứng kiểm chứng` when `payload.rollback.verified` is true but `driftResult.dbChangesRollback.rollback.evidenceIds` is empty — no bare `đã kiểm chứng`.
- `Step6CabView` rewritten: deleted the hand-built `sources` array with `?? 'pl02-note-id'` / `'02'.repeat(32)` fallbacks, the synthetic `risks`, `unresolvedDrift: []`, `rollback: { verified: true }`, and the `Verified: ...` line.
- New optional props: `onNavigateToStep`, `onDraftChange`, `generateCabDraft`, `wizardRuntime`.
- Generation stores the returned markdown as local draft state, tagged `Bản nháp` until `artifacts.cab` exists. `Lưu & Phê duyệt` is the only `onCommitCab` caller; `handleCompleteCr` stays a separate later action.
- Precondition failure renders `formatGuardMessage('ALL_DOCS_REQUIRED_FOR_CAB')` with a `Chuyển đến Bước 5: Tài liệu kỹ thuật` action calling `onNavigateToStep('TECH_DOCS')`.
- Missing `wizardRuntime` and no injectable generator → disabled button plus `Chưa cấu hình mô hình AI...` Alert.
- New `Tóm tắt CR nội bộ (chỉ trong TaskMate)` Card renders the summary fields with a `Chưa kiểm chứng` tag when rollback is unproven; no `buildWizardDocx` call is reachable from it.
- `handleExportAllZip` simplified: the fabricated PL02 payload literal was removed; all four kinds now read their `exportPayload` from the artifact Note, so PL02 must be approved (it already was, via `pl02.noteId` gating) rather than fabricated in the view.
