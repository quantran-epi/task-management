Output: Finish-reason events, explicit `truncated` turn failure, conditional `max_tokens` forwarding on all provider payload paths, and focused regression tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Provider stream -> local persistence | Partial response must not be committed as complete assistant output |
| Caller request -> provider payload | Completion limit is caller-supplied; provider/router settings remain authoritative |
| Retry -> message history | Retry must reuse existing user row and avoid duplication |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25.3-15-01 | Tampering | `chatTurnRuntime` persistence | mitigate | Reject `truncated` before `saveMessage`; test asserts no assistant row |
| T-25.3-15-02 | Denial of Service | `aiOrchestratorLoop` payloads | accept | Host adds no output cap or default; router/model configuration controls limits and runtime rejects explicit `length` results |
| T-25.3-15-03 | Spoofing | Provider finish metadata | mitigate | Typed finish event is emitted only from provider `finish_reason` and covered by SSE/fallback tests |
| T-25.3-15-04 | Repudiation | Retry identity | mitigate | Retain original user message ID and verify no duplicate row on retry |
