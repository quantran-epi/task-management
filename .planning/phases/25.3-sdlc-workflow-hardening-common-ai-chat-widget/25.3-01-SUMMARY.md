# Phase 25.3 Plan 01: Coordinator Self-Healing and Guard Registry Summary

Coordinator now restores persisted workflow state before any action inspects artifacts, and every prerequisite failure returns a stable guard code plus Vietnamized actionable copy.

## What Was Built

**`src/services/wizard/workflowGuards.ts`** — single source of truth for control-flow guard failures:
- `WorkflowGuardCode` union of the eleven codes used by the coordinator.
- `WORKFLOW_GUARD_STEP_NUMBER` mapping each `SdlcStepId` to its displayed step number (INTAKE=1 … CAB=6).
- `WORKFLOW_GUARD_MESSAGES` mapping each code to `{ missingArtifact, supplyingStep }` using the documented Vietnamese artifact labels.
- `formatGuardMessage(code)` producing the UI-SPEC Copywriting Contract sentence: `Chưa đủ điều kiện: Thiếu {doc} từ Bước {N}. Vui lòng hoàn thành bước trước để tiếp tục.`
- `guardError(code)` returning `Error & { code }` whose `message` is the raw code.

**`src/services/wizard/workflowCoordinator.ts`** — restore-before-action:
- New `ensureState()` sits right after `restore()`: returns `currentState` when present, otherwise awaits a single shared `restoreInFlight` promise, then falls back to `guardError('WORKFLOW_NOT_INITIALIZED')`.
- All twelve asynchronous actions (`setCheckpoint`, `clearCheckpoint`, `resumeCheckpoint`, `previewRevision`, `commitRevision`, `openCycle`, `closeCycle`, `commitSolution`, `commitChangePackAndDrift`, `commitTechDoc`, `commitCab`, `navigateToStep`) resolve state through `ensureState()` and throw `guardError(...)` codes.
- `startOrUpdateIntake` does `const existing = currentState ?? await restore();` so a reloaded page continues the same session and bumps artifact versions instead of resetting to v1.
- `getState()` and `selectStep()` remain synchronous (render-path contract).
- `currentStateOrThrow` deleted; `restore()` race guard and interrupted-checkpoint normalization untouched.
