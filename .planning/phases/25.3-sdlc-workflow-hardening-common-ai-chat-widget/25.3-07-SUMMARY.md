# Phase 25.3 Plan 07: Framework-free Chat Turn Runtime Summary

One React-free turn state machine plus a thin hook now owns a chat turn end to end, replacing the two diverged copies in `AIChatDrawer` and `StepChatPanel`.

## What Was Built

**`src/services/ai/chatTurnTools.ts`** — `getToolsForTurn(analysisMode, dynamicMcpTools)` moved verbatim out of the Drawer component module. Analysis Mode still returns non-mutation DB tools plus read-only MCP tools. `AIChatDrawer.tsx` now re-exports it (`export { getToolsForTurn } from '../../services/ai/chatTurnTools';`) so existing importers keep working until plan 25.3-11 drops the shim; the now-unused `AI_DATABASE_TOOLS` and `isReadOnlyMcpTool` imports were removed from the Drawer.

**`src/components/ai/runtime/chatTurnRuntime.ts`** (351 lines, zero React imports) — `createChatTurnRuntime(deps)` returning `{ start, retry, abort, resolveApproval, getStatus, isRunning }`.

- `start` rejects with `Error('TURN_IN_PROGRESS')` when a turn is live, then publishes `preparing` **before the first await**, so the host can paint loading feedback immediately.
- User-row identity: a `retryUserMessageId` is reused only when it matches thread, role `user`, and identical content; otherwise a fresh row is saved. `retry()` re-sends the last request with that id anchored, so no duplicate user message (T-25.3-24).
- Loop invocation mirrors the Drawer option set: `keepRecentToolOutputs: 20` / `maxOldToolChars: 100_000` in Analysis Mode, `compactAtRatio` 0.9 vs 0.75, `executeToolFn` delegating with `{ allowMutation: autoApprove }`, `maxLoops: 30`.
- Callback mapping: `onTextChunk` → `streaming` + `onDelta`; `onStatusChange` containing `tổng hợp` → `synthesizing`; `onToolCall`/`onToolResult` → `tool` + `onToolEvent`; `onUsage` accumulates token usage.
- `onMutationCheck` guard order is fixed (T-25.3-21): Analysis Mode read-only cancel → Auto-approve proceed → publish `awaiting-approval`, emit `onAwaitingApproval` with the `describeToolMutationWithContext` summary, and await `resolveApproval`.
- Persistence gate (T-25.3-22): assistant row written only when the turn completed, the request is still current, and stripped content is non-empty. Abort, error, rejection and empty output write nothing.
- Errors become `{ code, message }` where `message` is the fixed UI-SPEC AI-turn-failure sentence — no provider text, no key, no `Authorization`, no stack (T-25.3-23).
- `abort()` aborts the controller **and** releases a turn parked on approval, so an approval wait can never hang after a stop.

**`src/components/ai/runtime/useChatTurn.ts`** (119 lines) — `useChatTurn({ scopeKey, deps })` holding one runtime in a `useMemo` keyed on `scopeKey`, mirroring `onStatus`/`onDelta`/`onAwaitingApproval` into React state and returning `{ status, streamingText, streamingStatusLabel, pendingApproval, start, retry, abort, resolveApproval, runtime }`. `stageLabelFor` maps statuses to the four UI-SPEC staged labels; `onReasoningChunk` is never read (D-04). Effect cleanup aborts on scope change and unmount.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Duplicate status publishes collapsed**
- **Found during:** Task 2 GREEN
- **Issue:** Each text chunk re-published `streaming`, and each tool result re-published `tool`, so hosts would receive repeated labels that restart CSS animations and re-render needlessly.
- **Fix:** `publish` now no-ops when the status is unchanged; the test asserts the exact sequence `preparing → streaming → tool → synthesizing → complete`.
- **Files modified:** `src/components/ai/runtime/chatTurnRuntime.ts`
- **Commit:** `9cf21764`

**2. [Rule 1 - Bug] Abort while parked on approval would hang the turn**
- **Found during:** Task 2 GREEN
- **Issue:** A turn awaiting mutation approval had no resolver after abort, so the promise never settled and `running` stayed true.
- **Fix:** `abort()` resolves the pending approval as `false` and publishes `aborted`.
- **Files modified:** `src/components/ai/runtime/chatTurnRuntime.ts`
- **Commit:** `9cf21764`

No architectural (Rule 4) changes. No authentication gates.
