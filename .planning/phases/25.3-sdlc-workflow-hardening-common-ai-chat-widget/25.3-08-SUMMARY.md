# Phase 25.3 Plan 08: Common AI Chat Widget Summary

One presentational `AiChatWidget` now renders the whole chat surface for any host — header, toolbox, transcript, staged loading, tool badges, approval wait, artifact cards, composer — and hosts only supply a turn snapshot plus typed callbacks.

## What Was Built

**`src/components/ai/widget/StagedLoadingIndicator.tsx`** — renders the four UI-SPEC stage labels (`Chuẩn bị ngữ cảnh`, `Truy xuất công cụ`, `Đang phản hồi`, `Chờ phê duyệt`) in a `role="status"` / `aria-live="polite"` container, emphasizing the active one. `synthesizing` folds into `Đang phản hồi`. When `stage === 'tool'`, a `Tag` reads `[Công cụ] {toolName}` with `SyncOutlined spin` during `call` and `CheckCircleOutlined` on `result`.

**`src/components/ai/widget/MutationApprovalCard.tsx`** — the D-22 wait state. Exact header `Yêu cầu xác nhận thay đổi dữ liệu` with an `#faad14` `ExclamationCircleOutlined`, body through `renderSafeMarkdown`, primary `Chấp thuận` / danger `Từ chối`. No spinner, no auto-dismiss: the card itself is the wait.

**`src/components/ai/artifacts/ArtifactEventCard.tsx`** — metadata-only `Card size="small"`: title, `Bản nháp` vs `Đã duyệt (v{n})`, version, kind, a `Xem chi tiết` open action and a host CTA (default `Mở tài liệu`). `readOnly` disables the CTA behind the tooltip `Phiên bản đã đóng hoặc không còn hiệu lực`. No artifact body, no `dangerouslySetInnerHTML` (T-25.3-30).

**`src/components/ai/AiChatWidget.tsx`** (377 lines) — purely presentational. Exports `AiChatWidget`, `AiChatWidgetProps`, `AiChatScope`, `AiChatQuickPrompt`, `AiChatArtifactEvent`, `AiChatToolboxProps`, `AiChatTurnSnapshot`.

- No import of `runAiOrchestratorLoop`, `getToolsForTurn`, `useChatTurn`, or the DB module.
- Header: scope label plus status chips for `Chờ phê duyệt` / the staged label / `Phân tích`.
- `ChatTabToolbox` gets `activeTabId={scope.scopeKey}`, `compact`, and `onClearContext={onClearThread}` — one clear callback, forwarded, never duplicated.
- `ChatMessageList` gets `messages`, `streamingText`, `isStreaming` over the four active statuses, `streamingStatus`, `onRetry`, sanitized `error`, and the host `emptyState`. It is called **without** `pendingConfirmation`/`onConfirmAction`, so `MutationApprovalCard` is the only approve control (T-25.3-27).
- Collapsed-by-default `ToolEventBadge` per host `toolEvents` entry; the payload renders only after an explicit click and goes through `renderSafeMarkdown`. No reasoning prop exists at all (T-25.3-29).
- Artifact cards render one per event; `onOpen(id, readOnly)` and `onCta(id)` are host-owned.
- Quick prompts render only while the transcript is empty, there is no error and no active turn; clicking one calls `onSubmit(prompt.prompt)`.
- `ChatInputBar` is fully controlled through `draft`/`onDraftChange`, with `externalValue` passthrough and `onStop`.

**`src/types/models.ts`** — new `ChatArtifactEvent { kind, title, version, hash, status, ctaLabel? }` and optional `ChatMessage.artifactEvent`. **`src/db/repositories/chatRepo.ts`** — `SaveMessageInput.artifactEvent`, pre-write validation (`SdlcArtifactKindSchema`, non-empty title, `^[a-f0-9]{64}$` hash, integer `version >= 1`, `draft|approved` status) throwing `INVALID_ARTIFACT_EVENT`, and a conditional spread into the row. No Dexie version bump: `chatMessages` stores whole objects and needs no new index.

**`src/components/ai/ChatMessageList.tsx`** — added optional `emptyState?: { heading; body }`, falling back to the existing default copy. No behaviour change for current callers.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `exactOptionalPropertyTypes` broke every optional passthrough**
- **Found during:** Task 2 GREEN (`tsc --noEmit`)
- **Issue:** Passing `compact={compact}` or `toolName={maybeUndefined}` into props typed without `| undefined` produced six new TS2375/TS6133 errors under the project's `exactOptionalPropertyTypes: true`.
- **Fix:** optional toolbox/indicator/card props are now conditionally spread (`{...(cond ? { prop } : {})}`), unused icon/`Typography` imports removed, and `pendingConfirmation={undefined}` was replaced by omitting the props entirely so `ChatMessageList`'s public types stayed untouched.
- **Files modified:** `src/components/ai/AiChatWidget.tsx`, `src/components/ai/widget/StagedLoadingIndicator.tsx`, `src/components/ai/widget/MutationApprovalCard.tsx`
- **Commit:** `f09ec45e`

**2. [Rule 1 - Bug] Artifact ordering test tied on millisecond timestamps**
- **Found during:** Task 3 GREEN
- **Issue:** Two immediate writes shared a `createdAt` millisecond, so `sortBy('createdAt')` ordering was non-deterministic.
- **Fix:** the test separates the two writes by 2ms so it asserts the sort rather than a tie; no production change.
- **Files modified:** `tests/ai/AiChatWidget.test.tsx`
- **Commit:** `18418b39`

**3. [Rule 2 - Missing critical functionality] Host empty state had no renderer**
- **Found during:** Task 2
- **Issue:** `AiChatWidgetProps.emptyState` was required by the plan, but `ChatMessageList` hard-coded the Drawer's empty copy — an SDLC step host could not show `Trợ lý SDLC — {Tên bước}` per the UI-SPEC copywriting contract.
- **Fix:** optional `emptyState` prop on `ChatMessageList` with the current strings as defaults.
- **Files modified:** `src/components/ai/ChatMessageList.tsx`
- **Commit:** `f09ec45e`

No architectural (Rule 4) changes. No authentication gates.

## Notes for Downstream Plans

- `AiChatWidgetProps.toolEvents` was added (optional) beyond the plan's prop list: the plan's must-have "tool details are collapsed by default and expandable" needs the host's `ChatTurnToolEvent[]`, and plan 25.3-07 already emits them through `onToolEvent`.
- `AiChatWidgetProps.turn` is typed via the exported `AiChatTurnSnapshot`, not an inline literal — hosts can build it straight from `useChatTurn`'s `{ status, streamingText, streamingStatusLabel, pendingApproval }`.
- Hosts must pass `onArtifactOpen(eventId, readOnly)`; the widget derives `readOnly` from the event and hands it back so history views and live views can differ.
- `StagedLoadingIndicator`'s `toolName` currently comes from `turn.pendingApproval` only; plan 25.3-09/10 should surface the in-flight tool name in the snapshot if they want the badge during retrieval.
