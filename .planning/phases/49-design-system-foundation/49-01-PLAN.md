<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| boot entry → shell | `main.tsx` selects the single shell; no user-controlled input may reintroduce a branch |
| hash route → popout view | `useHashRoute()` route value decides which popout view mounts |
| localStorage → shell flag | legacy `taskmate_ui_shell` key must be ignored, not read |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-01 | Tampering | `src/main.tsx` boot branch | mitigate | Hard-code `<AppIntelliJ />`; shellRemoval.test.ts asserts no `?ui=`/`taskmate_ui_shell` token returns |
| T-49-02 | Tampering | `useHashRoute` `coding-zone-popout` route | accept | Route value only selects a local view; no data crosses a trust boundary; existing route guard in `useHashRoute` unchanged |
| T-49-03 | Tampering | legacy shell flag in localStorage | mitigate | No reader remains after deleting `shouldBootIntelliJ` and TitleBar switch; stale key is inert test data (C-16) |
| T-49-04 | Information disclosure | PWA manifest / service worker precache | mitigate | Delete all PWA code/config/tests; no install prompt or offline shell can leak legacy app assets |
| T-49-SC | Tampering | npm installs / lockfile sync | mitigate | No new packages in this plan; if `npm install --package-lock-only` runs, use `--ignore-scripts` and review the lockfile diff |
