## Accomplishments

- `tokens.contract.ts` exposes `ControlSize`, `WrapperPolicy`, `getSharedControlTokens()`, `getStatusTokens()` and `withoutUndefined()`; every metric and status color traces back to `src/styles/tokens.ts` with zero hex literals.
- `Button` maps a documented `variant` policy prop to AntD `type`/`danger`, applies `--ui-control-*` custom properties, and forwards loading/disabled faithfully. `IconButton` requires `aria-label` at the type level and defaults to the middle size without emitting a fractional inline font-size.
- `icon.tsx` contains one `wrapIcon` factory with token-derived whole-pixel icon size and shared status tone, plus 141 exact-name wrapped icon exports generated from the live working-tree scan; the barrel re-exports the icon family.
- `tests/helpers/antdInventory.ts` derives consumed components/icons/utilities from real source imports (excluding type-only names), derives wrapped names from ui/ exports, computes missing wrappers, and flags pass-through re-exports.
- Verification: 2 scoped Vitest files / 11 tests pass; `npx tsc --noEmit` clean; wrapped-icon count gate reports 141; no full suite run.

## Decisions Made

- 49-UI-SPEC bans odd/fractional inline `font-size`, so Button applies all four control metrics as custom properties rather than writing `font-size: 13.5px` on the DOM node.
- The researched 144-icon figure includes other branches' worktrees; scanning the actual working tree yields 141 icons, all wrapped. The generator excludes `.claude/worktrees`.
- `type` modifiers and `as` aliases are handled by the scanner; type-only imports never become required wrappers.
- The scanner intentionally does not assert full-tree coverage — plan 08 owns the failing gate once all wrapper families exist.
