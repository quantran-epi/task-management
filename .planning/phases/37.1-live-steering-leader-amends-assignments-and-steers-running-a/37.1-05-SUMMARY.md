# Phase 37.1 Plan 05: Leader amends queued assignments Summary

The leader can now cancel or rewrite a `queued` assignment mid-batch, both writes go through `finalizeAttempt`, and anything that is not queued — or belongs to another batch — is refused with a structured code and no ledger write.

## What Was Built

**Task 1 — `amend_assignments` definition, validator, lead-only exclusion (commit `af1edb43`)**

- `TeamToolRefusalCode` gained `'NOT_QUEUED'` and `'ASSIGNMENT_NOT_IN_BATCH'`.
- `TEAM_TOOL_DEFINITIONS` gained `amend_assignments` after `deliver_steer`: one required `operations` array of `{ op: 'cancel' | 'rewrite_task', assignmentId, task?, reason? }`.
- `amendAssignments(args)` in `teamTools.ts` is a validator only, mirroring `delegateBatch`: `EMPTY_BATCH` on an empty/non-array list; `NOT_QUEUED` for an unknown `op`, a missing `assignmentId`, or a `rewrite_task` with no `task`; otherwise `{ operations: normalized }` with `task` only on a rewrite and `reason` only when supplied. A comment records that ledger membership is deliberately not checked here (no `batchId` available).
- `executeTeamTool` gained `case 'amend_assignments':`.
- `LEAD_ONLY_TEAM_TOOLS` was extended in place to `delegate_batch`, `deliver_steer`, `amend_assignments` — one declaration, and `EMPLOYEE_TEAM_TOOLS` derives from it, so no coordinator edit was needed for the payload exclusion.
- Tests: the definitions count moved 7 → 8, the lead-only test now asserts all three names are absent from `EMPLOYEE_READ_ONLY_ALLOWLIST` and `AI_DATABASE_TOOLS`, and a new `amend_assignments` describe covers the empty list, an unknown op, a rewrite with no task, a missing id, and a valid two-op normalization.

**Task 2 — coordinator executor, widened terminal writer, tier-1 refusal (commit `16172ef5`)**

- `finalizeAttempt`'s `to` union widened to `'done' | 'stopped' | 'error' | 'skipped'` in both the interface and the implementation. Nothing else changed: the report-insert branch keys off `contentWhenMissing` and `incomplete: to !== 'done'` already yields `true` for `'skipped'`.
- `AMENDED_REPORT_COPY` sits beside `STOPPED_REPORT_COPY`; `EMPLOYEE_AMEND_REFUSAL` sits beside `EMPLOYEE_DELIVER_STEER_REFUSAL` (exported so the test can assert it).
- `amendAssignments(rawArgs)`: refuses on `disposed`, refuses with `ASSIGNMENT_NOT_IN_BATCH` when no batch is open, validates through `executeTeamTool('amend_assignments', …)` and returns the raw refusal string unchanged, then checks every `assignmentId` against `listBatchAssignments(openBatchId)` (T-37.1-20) and every row's `runStatus === 'queued'` (T-37.1-24) before applying anything.
  - `cancel`: sets `userStopped` to `'leader-amend'` **before** aborting the assignment controller, then `finalizeAttempt(row.id, 'queued', 'stopped', 'leader-amend', AMENDED_REPORT_COPY)`, `settleAgent(..., 'stopped')`, and drops the `assignmentIdsByAgent` entry when it still points at this row. The marker is cleared in `finally`. Why the order matters is documented inline: the parked `dispatchAssignment` catch races this finalize with `userStopped.get(...) ?? disposeCause ?? 'user-abort'`, and whichever transaction commits first wins the `from: 'queued'` guard.
  - `rewrite_task`: resolves the employee (refusing `AGENT_NOT_IN_ROSTER` when absent), `createAssignment({ …, task: op.task, retryOfAssignmentId: row.id })` so `attemptNo` is allocated inside the insert transaction, `finalizeAttempt(row.id, 'queued', 'skipped', 'leader-amend', AMENDED_REPORT_COPY)`, re-points `assignmentIdsByAgent`, sets the agent back to `queued`, and re-dispatches into the same batch controller with the source row's `instructionMessageId` when present.
  - Returns `{ applied: [{ op, assignmentId, replacementId? }] }`.
- `makeExecuteToolFn` gained a tier-1 `amend_assignments` branch before the `TEAM_TOOL_NAMES` branch: an employee (or a coordinator with no lead) gets `EMPLOYEE_AMEND_REFUSAL` and writes nothing (T-37.1-19).
- `resolveTeamToolName` returns `'coordinator'` for `amend_assignments`, so the "every advertised tool resolves" guard keeps proving it.
- `leadSteerTools()` now filters `TEAM_TOOL_DEFINITIONS` for `deliver_steer` **and** `amend_assignments`; `leadTools()` was verified unchanged (it already spreads every team tool).
- `onBatchSettled` now resolves each agent's **latest** attempt from `listBatchAssignments(batchId)` instead of the dispatch-time `attemptIdsByAgent` id, falling back to the old lookup. Without this a rewritten agent's synthesis entry would read the retired `skipped` row and report "chưa hoàn tất" for work that actually completed.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `onBatchSettled` read the dispatch-time attempt id, so a rewrite's result was invisible**
- **Found during:** Task 2, while writing the rewrite test
- **Issue:** `onBatchSettled` looked up `attemptIdsByAgent.get(agentId)` — the attempt created during dispatch. After a `rewrite_task` that row is `skipped`, so the synthesis would have carried `skipped/leader-amend` and `incomplete: true` for an agent whose replacement attempt actually finished `done`. The plan's threat register (T-37.1-23) requires the batch to wait for the replacement; it says nothing about reading it, and the existing code would have reported the wrong row.
- **Fix:** resolve `latestByAgent` from `listBatchAssignments(batchId)` (highest `attemptNo` per agent) and prefer it, keeping the old `attemptIdsByAgent` lookup as the fallback. The rewrite test asserts the synthesis prompt contains the replacement's report.
- **Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
- **Commit:** `16172ef5`
