## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model → `amend_assignments` args | A model-supplied `assignmentId` and `task` cross into ledger writes |
| employee runtime → coordinator | A non-lead agent could call the tool by name |
| coordinator → ledger | The single `runStatus` write path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37.1-19 | Elevation of privilege | `amend_assignments` callable by an employee | mitigate | Excluded from `EMPLOYEE_TEAM_TOOLS` via `LEAD_ONLY_TEAM_TOOLS` AND refused at tier-1 dispatch with `EMPLOYEE_AMEND_REFUSAL` |
| T-37.1-20 | Elevation of privilege | model-supplied `assignmentId` addressing another batch's row | mitigate | Validated against `listBatchAssignments(openBatchId)`; `getAssignment` alone is never the authorization |
| T-37.1-21 | Tampering | `runStatus` written outside the single writer | mitigate | Both operations route through `finalizeAttempt`; the acceptance check forbids a direct status `update()` |
| T-37.1-22 | Repudiation | a retired row leaving an interrupted-turn banner forever | mitigate | `finalizeAttempt` inserts the report row, so `listInterruptedAssignments` stays quiet; a test asserts it |
| T-37.1-23 | Denial of service | a rewritten assignment the batch never waits for | mitigate | The replacement is dispatched into the same batch and `onBatchSettled`'s ledger poll waits for `queued`/`running` to drain |
| T-37.1-24 | Tampering | partial application of a multi-op list | mitigate | The whole list is refused when any row is not `queued`, so the leader's report matches the ledger |
| T-37.1-SC | Tampering | npm/pip/cargo installs | mitigate | No package is installed; any install task would require a blocking human checkpoint |
</threat_model>
