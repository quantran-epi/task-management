Answers to the three scrutiny questions:

- **Can `registry.abort(row.agentId)` abort a runtime a replacement dispatch has claimed?** It can
  kill the replacement's turn, but that is not a defect. A replacement row created by
  `amend_assignments` is itself in the sweep's `live` list (the retired source row is `skipped`, so
  it is filtered out at `:2534-2536`), and it is finalized by the same sweep pass or by its own turn
  after the abort. When the sweep's `row` is a stale source row (amend retired it mid-pass), the
  finalize loses the `from` guard and `settleAgent`'s identity guard (`:659-661`) drops the settle
  because `assignmentIdsByAgent` already points at the replacement. No orphan row is left with no
  writer: a killed running turn finalizes itself; a queued replacement is caught by the next pass.
  The pre-commit behaviour was worse — the replacement kept running and `stillLive` left
  `openBatchId` set with no synthesis. No blocker.
- **Is `stopped`/`tool-limit` reachable for a row that did NOT commit?** Yes, via the
  `dispatchAssignment` catch reading the sweep's `userStopped` marker (`:2208`), and via this sweep's
  own earlier commit. In both cases the row was `queued` when the terminal write landed, so its turn
  never started and no drain can follow — stripping is still correct. The only writer of
  `tool-limit` is this sweep (grep: `:2548`, `:2554`), and it aborts the runtime before writing, so
  "terminal + tool-limit" implies "runtime aborted". No finding.
- **Can aborting the runtime double-settle?** No. `start()` returns `aborted` instead of rejecting
  (`chatTurnRuntime.ts:506-510`), and every settle side effect is idempotent: `settleAgent` skips the
  status write and `finishTurn` when the state is already terminal (`:665-677`), `releaseLiveUse` is
  guarded by the `liveAgents` set (`:692-695`), and the deferred resolve/delete is a no-op the second
  time (`:679-680`).

Residual, deliberate trade-off (not a finding): the gate is narrower than "row terminal and runtime
aborted". If the sweep loses the guard to a writer that recorded a different stop reason (e.g. the
turn's own `user-abort`), the markers survive even though the turn is dead — a false "chưa giao",
which is the safe direction (resend is idempotent at `:1794`).

No blocker. No new warning.
