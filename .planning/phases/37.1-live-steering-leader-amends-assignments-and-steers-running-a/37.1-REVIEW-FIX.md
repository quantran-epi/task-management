## Fixed Issues

### CR-01: A steer sent while the leader is parked is marked read and then silently dropped

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
**Commit:** 87c6c8cc
**Applied fix:** `runLeadSteerTurn` no longer clears `pendingSteerMessageIds` before
`start()`. The pending ids are removed only after a turn actually ran to a read outcome
(`complete`/`cancelled`/`tool-limit`); on `TURN_IN_PROGRESS` they stay pending, so the
running lead turn's `drainLeaderSteerQueue` injects them at its next round boundary
(D-16). The claim is also rolled back when `start()` refuses, so the live turn keeps its
accounting key, live-use claim and status.

### CR-02: `amend_assignments` applies part of the list, then reports a total refusal

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
**Commit:** 87c6c8cc
**Applied fix:** the roster check for `rewrite_task` moved out of the apply loop and into
the pre-validation loop, so the whole list is refused before any mutation. The apply loop
can no longer return early.

### CR-03: Rewriting a queued assignment silently discards steers already delivered to it

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
**Commit:** 87c6c8cc
**Applied fix:** a `rewrite_task` on a row whose `steerMessageIds` is non-empty is refused
in pre-validation (`NOT_QUEUED` + "Việc này đang có chỉ đạo chưa đọc…"), so the user's
instruction can never vanish after `deliver_steer` reported success. `dependsOn` is now
carried onto the replacement row.

### CR-04: The "delivered" state is erased by the drain, so every consumed steer renders "chưa giao"

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,
`src/components/ai/office/TeamWorkspace.tsx`
**Commits:** 87c6c8cc, 89ab3a6f
**Applied fix:** took the no-schema-change route. `steerMessageIds` on the assignment row
is now the durable delivered marker (D-14/D-25) and is never cleared; re-injection inside
one session is prevented by a new in-memory `injectedSteerIdsByAttempt` set. On the
render side, an unaddressed steer (`targetAgentId === undefined`) has no delivery concept
(D-28) and a steer whose target attempt is terminal has been consumed — neither renders a
badge. No Dexie version bump, no backup-schema change.

### CR-05: `deliverSteer` and `drainSteerInbox` are non-transactional read-modify-write on `steerMessageIds`

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
**Commit:** 87c6c8cc
**Applied fix:** `deliverSteer` performs its read-modify-write inside one `rw` transaction
over `aiTeamAssignments`, re-reading the array under the lock and returning `duplicate:
true` when the id is already present. The drain no longer writes the array at all (see
CR-04), which removes the lost-update window entirely.

### CR-06: The steer caption always shows the raw target UUID in production

**Files modified:** `src/components/ai/ChatMessageList.tsx`,
`src/components/ai/ChatMessageBubble.tsx`
**Commit:** 81a0eac6
**Applied fix:** `ChatMessageList` resolves the directory entry from `targetAgentId` when
the row has no `agentId`. The bubble suppresses the agent attribution header for steer
rows so D-15's "renders as a user row" still holds, and falls back to the neutral label
`Nhân viên` rather than an id (IN-08d). Added a `ChatMessageList`-level test asserting the
name, not the id.

### WR-01: `retryAssignment` bypasses the lead-turn chain and can lose its synthesis

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
**Commit:** 87c6c8cc
**Applied fix:** the retry synthesis now runs through `runLeadTurnSerialized`, with the
batch reports collected before entering the chain.

### WR-02: The steer lead turn is invisible and its tokens are never accounted

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
**Commit:** 87c6c8cc
**Applied fix:** the steer turn gets its own `leadTurnSeq` accounting key (so `handleUsage`
sees a positive delta and D-13's "billed to the leader" holds), a `claimLiveUse`, a
`running` agent state and a registered agent turn — then settles through `settleAgent` so
the indicator shows the leader reading.

### WR-03: `steer()` returns `'blocked'` after the row is already persisted

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
**Commit:** 87c6c8cc
**Applied fix:** the post-persist dispose check now returns `'steered'`, so the composer
does not restore text that is already a transcript row.

### WR-04: A rewritten assignment's old parked task can stomp the replacement's live state

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
**Commit:** 87c6c8cc
**Applied fix:** `settleAgent` takes an optional `attemptId` and drops a settle whose
attempt is no longer the agent's current one; every call site that owns a specific attempt
passes it. The rewrite path also moves `assignmentIdsByAgent` to the replacement and sets
the `leader-amend` marker before aborting the retired controller, so the old parked
dispatch cannot settle the replacement or release its deferred.

## Notes for the developer

- **Logic-level fixes needing a human read:** CR-01 (the "clear only after a read
  outcome" rule), CR-04 (the "terminal attempt means consumed" derivation), and WR-02
  (the claim/rollback around `start()`) are behavioural changes verified by new tests but
  worth a manual pass against D-03/D-14/D-16.
- **Known residual:** CR-04's "terminal attempt means consumed" derivation assumes one
  attempt per agent per batch for the badge. After a rewrite (attempt 2), a steer delivered
  to attempt 1 reads its latest attempt — correct for the badge, but a steer delivered to a
  superseded attempt is now indistinguishable from a consumed one. This matches the
  reviewer's "minimum viable fix without a schema change"; a per-id `deliveredAt` would be
  the durable upgrade if per-steer audit is ever needed (D-25 already defers that to a
  later phase).
- **No schema change:** `steerMessageIds` semantics changed (never cleared) but the field
  itself is unchanged, so no Dexie version bump and no backup-schema edit was required.
