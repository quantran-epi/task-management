## Fixed Issues

### CR-01: A steer sent before the batch opens is delivered but its badge stays "chưa giao" forever

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,
`src/components/ai/office/TeamWorkspace.tsx`,
`tests/services/ai/office/teamRunCoordinator.test.ts`,
`tests/components/ai/office/TeamWorkspaceSteer.test.tsx`
**Commit:** f21aadb0
**Applied fix:** `deliverSteer` now stamps `assignment.batchId` onto the steer
row inside the same `rw` transaction as the `steerMessageIds` append (both
tables in one scope, so the marker and the delivery fact cannot disagree). The
workspace derivation additionally treats "no assignment in any queried batch
for this target" as nothing-to-deliver rather than held. Two regression tests:
a coordinator-level one proving the stamp lands on a row persisted before the
batch existed, and a `TeamWorkspace`-level one proving no
`steer-badge-<id>` renders after the delivery write.

### WR-01: The steer turn injects every pending steer twice

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,
`tests/services/ai/office/teamRunCoordinator.test.ts`
**Commit:** 7e54ad38
**Applied fix:** the steer turn records the ids it rendered in
`[CHỈ ĐẠO CHỜ XỬ LÝ]` and passes them to `drainLeaderSteerQueue` as a skip set,
so the round-1 `beforeToolRound` drain cannot append the same text as a user
message. The ids stay pending until a read outcome, preserving CR-01's
"never lose a steer" guarantee. Test asserts the steer turn's round-1 drain
returns nothing.

### WR-02: The steer-turn rollback clobbers the running lead turn's turn registration

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,
`tests/services/ai/office/teamRunCoordinator.test.ts`
**Commit:** cc853482
**Applied fix:** the rollback now captures and restores the full prior agent
state (`agents`), the prior `ChatTurnRequest`, and the prior `aiTurnManager`
entry, and never calls `finishTurn` on a turn it did not register. When there is
no prior entry it purges its own with `'aborted'` instead of the default
`'complete'`. The parked-steer test now asserts the running turn's `status`,
`startedAt` and turn registration all survive a steer.

### WR-03: `amend_assignments` refuses a `cancel` for undrained steers, with a rewrite-only message and the wrong code

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,
`src/services/ai/office/teamTools.ts`,
`tests/services/ai/office/teamRunCoordinator.test.ts`
**Commit:** 1dc8a052
**Applied fix:** the guard is scoped to `operation.op === 'rewrite_task'` and
returns the new `STEER_PENDING` refusal code. Added a test proving a `cancel`
on a queued row holding a delivered steer is applied (`stopped` /
`leader-amend`).

### WR-04: A rewrite can lose the `queued → skipped` race and start two turns for one agent

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,
`src/db/repositories/teamTranscriptRepo.ts`,
`tests/services/ai/office/teamRunCoordinator.test.ts`
**Commit:** 6366293a
**Applied fix:** the retired controller is now aborted BEFORE
`createAssignment`, and a `retiredAssignmentIds` set makes the retired row's own
`dispatchAssignment` neither start nor settle. The whole list is re-read before
the apply loop so the all-or-nothing contract holds; a row that still leaves
`queued` is reported in a partial-refusal result rather than silently dropped.
Test forces the race and asserts the whole list is refused with the cancel in
the same list left `queued`.

**Also fixed (surfaced by this work):** `listInterruptedAssignments` paired
instruction/report rows by index, so a report written in the same millisecond as
its instruction could sort before it (the tie-break is by id) and look
unanswered — a pre-existing latent flake that the new test made reproducible.
Both rows carry `assignmentId` (D-22), so pairing on it is now exact.

### WR-05: The bounded settle poll closes the batch while rows are still live

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,
`tests/services/ai/office/teamRunCoordinator.test.ts`
**Commit:** 4f0b6401
**Applied fix:** deadline expiry now aborts each stuck row's controller,
finalizes it `stopped`/`tool-limit` through the one terminal writer, and settles
the agent, over a few bounded passes. If a row survives the abort, `openBatchId`
stays set so no second batch can open over this one. Added a
`settlePollDeadlineMs` test seam and a test proving a stuck row gets a terminal
triple, no phantom `running` agent survives, and the batch really closed.

## Notes for the developer

- **Logic-level fixes needing a human read:** CR-01 (the batch stamp as the
  delivery-side write), WR-01 (skip-set scoping so a steer is injected exactly
  once per turn), and WR-04 (the `retiredAssignmentIds` guard plus the
  whole-list re-read) are behavioural changes verified by new tests but worth a
  manual pass against D-14/D-16/D-28.
- **WR-02 is defence in depth.** Every lead turn goes through
  `runLeadTurnSerialized`, so the `TURN_IN_PROGRESS` rollback is currently
  unreachable. The fix is still correct and the test asserts the invariant
  (running turn's live state survives a steer) rather than the dead branch.
- **WR-05 ceiling.** If a row somehow survives the abort, the batch stays open
  and the phase stays `batch-running`, so later submits route as steers until it
  settles. That is deliberately the safe side of the reviewer's "at minimum keep
  `openBatchId` set" instruction.
- **No schema change.** `steerMessageIds` semantics are unchanged from
  iteration 1; `batchId` on a chat message already existed and is already in the
  export/restore/validate/SQLite lists. No Dexie version bump, no backup-schema
  edit, no Rust change.
- **`STEER_PENDING`** is a new member of `TeamToolRefusalCode` (a returned-value
  union, not a persisted column), so it needs no migration.
