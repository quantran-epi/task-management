## Fixed Issues

### CR-01: A held pre-batch steer loses its badge entirely (claims delivered)

**Files modified:** `src/components/ai/office/TeamWorkspace.tsx`,
`tests/components/ai/office/TeamWorkspaceSteer.test.tsx`
**Commit:** fa6604d9
**Applied fix:** the "no assignment" rule now gates on the steer row's own
`batchId` instead of `!pending.has(row.id)`:

```ts
// A steer with no batch link has never been delivered; keep its honest 'held' badge.
if (assignment === undefined && row.batchId !== undefined) continue;
```

`deliverSteer` is the only writer of that stamp, so "no `batchId`" is exactly
"never delivered". The reviewer's alternative (stamping `openBatchId` onto
pending steer rows in `dispatchBatch`) was NOT taken — one badge contract, not
two. A row that carries a `batchId` but has no live assignment still clears, so
the iteration-2 over-suppression case stays fixed. New workspace test renders a
held pre-batch steer with no pending id and asserts the `chưa giao` badge.

### WR-01: `deliverSteer` reports success for an attempt that settled during the read→write window

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,
`tests/services/ai/office/teamRunCoordinator.test.ts`
**Commit:** 7d3bd036
**Applied fix:** the `rw` transaction now re-validates the row it is about to
stamp and returns a `null` sentinel when the attempt is gone, in a foreign
batch, or no longer `queued`/`running`. The caller maps `null` to the existing
`NOT_QUEUED` refusal, so nothing is appended, `pendingSteerMessageIds` keeps the
id, and no badge is suppressed. Test fakes the in-transaction read (via
`Dexie.currentTransaction`) so the outer guard still sees `queued` while the
transaction sees `stopped`.

### WR-02: The duplicate branch of `deliverSteer` moves the delivery stamp to the wrong batch

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,

**Commit:** 77a2719b
**Applied fix:** the duplicate branch writes nothing. The append path keeps the
stamp (now sourced from the re-read `live.batchId`, which WR-01 proved is still
the open batch). Test seeds a steer row stamped with an earlier batch and a

still points at `earlier-batch`.

### WR-03: A dispatch already past the retired check can still start a turn for a skipped row

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,
`tests/services/ai/office/teamRunCoordinator.test.ts`
**Commit:** 9f97e2a0
**Applied fix:** both write results are honoured.

- `startEmployeeTurn` captures `transitionAssignment(queued→running)` and throws
  `DOMException('Aborted', 'AbortError')` when it returns `null`. Its catch now
  returns early for a retired attempt, so the amend path keeps sole ownership of
  that row's terminal write and of the replacement's live state.
- The amend rewrite branch finalizes BEFORE `createAssignment` and pushes
  `{code: 'NOT_QUEUED'}` (and drops the retired marker) when the finalize
  returns `null`. Finalizing first means a refusal leaves no orphan replacement
  row for the settle poll to wait on.

### IN-01: A `cancel` on a row holding a delivered steer drops the instruction with no signal

**Files modified:** `src/services/ai/office/teamRunCoordinator.ts`,
`tests/services/ai/office/teamRunCoordinator.test.ts`
**Commit:** 79ca9ad1
**Applied fix:** the `STEER_PENDING` guard is no longer scoped to
`rewrite_task` — both amend ops refuse while the row holds an undrained steer,
with copy naming the op. The iteration-2 test that asserted a cancel was allowed
was inverted: it now asserts the refusal and that the row is still `queued` when
the refusal returns.

## Notes for the developer

- **Logic-level fixes needing a human read:** CR-01 (badge contract keyed on the
  delivery stamp), WR-03 (the two write-result checks change when a turn starts
  and when a replacement is dispatched), and IN-01 (a cancel can now be refused)
  are behavioural changes covered by new tests but worth a manual pass against
  D-06/D-09/D-14/D-24/D-28.
- **WR-03 ordering change.** The rewrite branch used to `createAssignment` then
  finalize; it now finalizes then creates. The old order left an orphan
  replacement row when the finalize lost the race, which the settle poll would
  then wait on. The new order makes the refusal atomic.
- **IN-01 ceiling.** A queued row that holds a delivered steer can no longer be
  cancelled by the leader; it is ended by the settle-poll deadline
  (`stopped`/`tool-limit`) if its agent never starts. That is the deliberate
  trade: a lost instruction is worse than a delayed cancel.
- **No schema change.** No new persisted field, no Dexie version bump, no
  backup-schema edit, no Rust change. `STEER_PENDING` remains a returned-value
  union member, not a column.
