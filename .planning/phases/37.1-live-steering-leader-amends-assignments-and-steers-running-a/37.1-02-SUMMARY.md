# Phase 37.1 Plan 02: Return-value round-boundary hook Summary

`beforeToolRound` is now a delivery channel: it fires on every round including round 1, runs after in-loop compaction, and whatever messages it returns are appended to the conversation the next model call sees.

## What Was Built

**Task 1 — loop contract (`src/services/ai/aiOrchestratorLoop.ts`)**

- `AiOrchestratorLoopOptions.beforeToolRound` widened from `((round, signal?) => Promise<void>) | undefined` to `((round, signal?) => Promise<ChatCompletionMessage[] | void>) | undefined`; doc comment now states every-round, after-compaction, appended-return semantics.
- The old `if (loopCount > 1 && beforeToolRound) { … }` block was deleted from the loop head. The call now sits immediately after the `compactMessagesInLoop` block and before `const messagesToSend = prune(currentMessages);`:

  ```ts
  if (beforeToolRound) {
    const injected = await beforeToolRound(loopCount, signal);
    signal?.throwIfAborted();
    if (injected && injected.length > 0) currentMessages.push(...injected);
  }
  ```

- `signal?.throwIfAborted()` still runs immediately after the hook resolves, so a hook that resolves normally after a Stop still rejects (T-37.1-07). Synthesis pass, pruning, and tool dispatch untouched.

**Task 2 — runtime forwarding (`src/components/ai/runtime/chatTurnRuntime.ts`)**

- `ChatTurnRequest.beforeToolRound` widened to the same return-value type; doc comment updated.
- The existing arrow was already expression-bodied, so it already returned the promise value — verified and left textually unchanged: `beforeToolRound: (r: number) => request.beforeToolRound!(r, turnController.signal)`. The conditional spread still omits the option when the request has no hook.
- Added `import type { ChatCompletionMessage } from '../../../services/ai/types';` — no other dependency.
- The single-save-at-complete block (D-19) was not touched.

**Task 3 — test contract**

- `tests/services/ai/aiOrchestratorLoop.test.ts`: the round-1 test is inverted to `'fires on round 1 and every later round with the 1-based round number'` — expects 2 calls with `[1, 2]`. Two new tests: `'appends the messages the hook returns so the next model call sees them'` (round-1 steer with the `[Chỉ đạo từ người dùng]` prefix appears in the second `mockStreamChatEvents` payload) and `'does not append anything when the hook returns void or an empty array'` (message count matches the no-hook baseline, no steer marker in any payload). The four surviving tests (`receives the loop signal`, `suspends after the completed round tool results are appended`, `rejects with AbortError when the signal aborts while parked`, `leaves behavior unchanged when the hook is omitted`) stay green.
- `tests/ai/chatTurnRuntime.test.ts`: `'forwards beforeToolRound into the loop bound to the turn signal'` now has the request hook return an array and asserts `returned` (the loop option's resolved value) `toBe(steer)` — the same array instance. Round/signal assertions kept; the omit-option test unchanged.
- Suite totals: `aiOrchestratorLoop.test.ts` 40 passed, `chatTurnRuntime.test.ts` 46 passed, `teamRunCoordinator.test.ts` 92 passed.
