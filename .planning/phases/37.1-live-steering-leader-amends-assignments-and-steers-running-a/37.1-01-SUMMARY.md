# Phase 37.1 Plan 01: Event-driven `delegate_batch` Summary

`delegate_batch` now dispatches and returns an acknowledgement while the leader's turn ends; a batch-scoped `AbortController` owns agent cancellation and `onBatchSettled` opens the synthesis turn.

## What Was Built

**Task 1 — `dispatchBatch` + `onBatchSettled` + batch controller**

- `runBatch` was renamed to `dispatchBatch(rawAssignments, signal)` and keeps everything up to and including the create/dispatch loop: validation, plan snapshot, `awaiting-plan` park (D-24 keeps approval inside dispatch), `openBatch`, `batch-running`, per-assignment `createAssignment` + instruction row, and the `BATCH_DISPATCH_FAILED` catch. It stops there and returns `{ dispatched, batchId, status: 'dispatched', agents: [{ agentId, agentName, assignmentId }] }`.
- `ALREADY_RUNNING_REFUSAL` is the first statement of `dispatchBatch`, before the `disposed` check (T-37.1-02).
- `batchControllers: Map<string, AbortController>` — one controller per open batch. `dispatchAssignment` now takes `batchController: AbortController` and bridges it with `addEventListener('abort', …, { once: true })`; the leader's tool-call signal is gone from the agent path entirely (T-37.1-01).
- Post-`acquire` ledger re-read (T-37.1-04): a row whose `runStatus !== 'queued'` throws `AbortError` instead of starting.
- `onBatchSettled(batchId, assignments, attemptIdsByAgent)` awaits the deferreds, polls `listBatchAssignments` until nothing is `queued`/`running`, builds the results, moves `priorBatchResults`, clears `agentDeferreds`, sets `lead-synthesizing`, closes the batch row, and runs the synthesis turn. Whole body is `try/catch/finally`; `finally` deletes the controller and finishes the team turn.
- `abortAll` and `dispose` abort every batch controller.

**Task 2 — team turn lifetime and per-turn usage baseline**

- `batchOwnsTeamTurn` is set after the ack is built; `send()`'s `finally` only finishes the team turn when it is false; `onBatchSettled`/`abortAll`/`dispose` finish it unconditionally (T-37.1-03).
- `usageBaselineKey: Map<string, string>` + `leadTurnSeq` / `employeeTurnSeq` give every turn its own `usageTotals` key, so the synthesis turn no longer wipes the dispatch turn's baseline. `handleUsage(agentId, usage, accountingKey)` keeps member totals/buckets keyed by the real agent id.
- `runLeadTurnSerialized(task)` chains lead turns so two can never overlap on one runtime; the synthesis call routes through it (plan 04 reuses it for steer turns).

**Task 3 — test contract**

- All `delegate_batch` result assertions rewritten against the ack; outcomes are now read from the ledger or the snapshot. No test deleted: 87 → 92 `it(` blocks, 53 `delegate_batch` references (was 48).
- New `describe('D-24 event-driven batch')` with five tests: leader turn ends while agents run, aborting the leader tool-call signal does not abort the batch, second dispatch refused (one `aiTeamBatches` row), team turn registered through `batch-running` and finished once, and tokens from both lead turns counted (300 + 400 = 700).
- Harness gained `synthesisScript` and a `waitForReady` helper, so a delegating lead script cannot open a second batch on the synthesis turn.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Two "current" synthesis rows per batch**
- **Found during:** Task 3 (remount test)
- **Issue:** With D-24 the dispatch turn's answer and the real synthesis are both `messageKind: 'synthesis'` rows. Nothing superseded the dispatch one, so `findCurrentSynthesisMessageId` could return either — a pre-existing D-12 violation that D-24 made reachable on every batch.
- **Fix:** `onBatchSettled` resolves the previous synthesis (`lastSynthesisMessageId ?? findCurrentSynthesisMessageId`) before the synthesis turn and supersedes it afterwards, mirroring `retryAssignment`'s existing block.
- **Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
- **Commit:** a08b16eb

**2. [Rule 3 - Blocking] `started` promise array became dead code**
- **Found during:** Task 1
- **Issue:** `dispatchAssignment` is fire-and-forget under D-24, so the `started: Promise<void>[]` + `Promise.allSettled(started)` pair had no consumer.
- **Fix:** dispatches use `void … .catch(() => {})`; the array was removed.
- **Files modified:** `src/services/ai/office/teamRunCoordinator.ts`
- **Commit:** a08b16eb
