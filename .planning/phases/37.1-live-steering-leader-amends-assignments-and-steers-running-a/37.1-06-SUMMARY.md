# Phase 37.1 Plan 06: Team chat UI — inline activity, hover-gated actions, steer badge Summary

**One-liner:** The team transcript now reads like a group chat — no outbox, no streaming bubble, one inline "An đang làm việc · Bình đang tổng hợp" line with a click-through per-agent step popover, hover-gated Stop, and steer rows that walk "chờ leader đọc" → "chưa giao" → nothing.

## What Was Built

### Task 1 — Outbox gone, composer unconditional (D-01/D-02/D-12)

Plan 04 had already removed `OutboxPanel`, the `outbox`/`dispatchInFlight`/`releasingRef` state, the release effect and the `statusExtensions` prop from `TeamWorkspace.tsx`, and had already widened `sendTurn`'s return type and made `handleSubmit` unconditional. Verified by grep (all zero) and left untouched. This task therefore did the remaining test work:

- `git mv tests/components/ai/office/TeamWorkspaceOutbox.test.tsx → TeamWorkspaceSteer.test.tsx`, header comment rewritten to describe steering rather than queueing.
- Added a `it.each` sweep over all eight `TeamRunPhase` values asserting neither `team-outbox` nor `team-outbox-item` ever renders.
- `TeamWorkspaceWhitespaceSubmit.test.tsx` header comment now names the renamed file; its `team-outbox` assertion already asserted absence.

### Task 2 — Inline activity line + per-agent popover (D-19/D-20/D-21/D-22)

- `src/types/aiOffice.ts`: new exported `AgentLiveStep { id, label, at }` and `AgentRunState.steps?: AgentLiveStep[] | undefined`. Runtime-only — no Dexie version bump, no backup schema change.
- `teamRunCoordinator.ts`: module counter `stepSeq` and `pushStep(agentId, label)`. Returns early when the agent has no state row or when the last step already carries the same label; appends and caps at `slice(-6)`.
- `buildRuntimeDeps`: `onStatus` maps `streaming` → "đang viết", `synthesizing` → "đang tổng hợp", `preparing` → "đang chuẩn bị" and ignores the rest; `onToolEvent` appends only on `phase === 'call'` (`read_skill` → "đã đọc skill", otherwise "đang gọi tool <name>"). `steps: []` cleared at both `status: 'running'` turn starts and at the queued reset.
- New `TeamActivityIndicator.tsx`: `PHASE_ACTIVITY_VERB` with exactly the five D-21 strings; one `Typography.Text type="secondary"` at 12px joined by `' · '`, wrapped in a `Button type="text"` trigger inside an Ant Design `Popover` (`trigger="click"`, `placement="topLeft"`, `getPopupContainer` copied from `ChatTabToolbox.tsx`). No `Spin`, no icon, no second line. Popover content lists each non-terminal agent's step labels (plain text, `'Chưa có bước nào'` when empty) and an `AgentStatusRow` with `idPrefix="indicator"`.
- `AgentAttributionRow.tsx`: `AgentStatusRowProps.idPrefix?: string` defaulting to `'agent'`, applied to both stop and retry test ids.
- `TeamWorkspace.tsx`: `liveBubbles` deleted, `ChatMessageBubble` import removed, `<TeamActivityIndicator …>` mounted as the first `transcriptExtensions` child with `onStopAgent` supplied only when a coordinator exists.

### Task 3 — Hover-gated actions (D-23) + steer caption and badge (D-15/D-03)

- `AgentStatusRow`: `hovered`/`focused` state declared before the `done` early return (stable hook order), `alwaysVisible = stopped || error`, `actionsVisible = alwaysVisible || hovered || focused`. Buttons wrapped in `agent-actions-<agentId>` with `data-visible` and `opacity` — mounted at all times so arrow-key focus still reaches them.
- `ChatMessageBubble`: new `steerState?: 'pending' | 'held'`. A `messageKind === 'steer'` row renders `steer-label-<id>` with `'Chỉ đạo'` (no target) or `'Chỉ đạo → <name>'` (name from the `agent` prop, falling back to the raw id), plus `steer-badge-<id>` reading exactly `'chờ leader đọc'` or `'chưa giao'` when `steerState` is defined.
- `ChatMessageList`: `steerStates?: Map<string, 'pending' | 'held'>` forwarded per row.
- `TeamWorkspace`: distinct steer `batchId`s → one `useLiveQuery` over `aiTeamAssignments.where('batchId').anyOf(...)` → `deliveredSteerIds` set → `steerStates` memo keyed off `messages`, `snapshot.pendingSteerMessageIds` and that set, passed inside the existing `messageListExtensions` object.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Queued-only pending set rendered no trigger at all**
- **Found during:** Task 2 (`TeamChatIndicator.test.tsx` failed: `Unable to find an element by [data-testid="team-activity-indicator"]`)
- **Issue:** The plan's rule "render `null` when the running/paused list is empty" meant a batch whose agents are all still `queued` produced no trigger, so the popover — the only Stop affordance for a queued agent after `liveBubbles` was deleted — was unreachable. That contradicts the plan's own must-have "Stop remains reachable for a queued or running agent".
- **Fix:** The component now returns `null` only when there is no non-terminal agent at all. When every pending agent is queued, the line reads `'<name> đang xếp hàng'` instead of claiming work.
- **Files modified:** `src/components/ai/office/TeamActivityIndicator.tsx`
- **Commit:** 908a79d8

**2. [Rule 3 - Blocking] `useLiveQuery` inferred `never[]` for the batch-scoped read**
- **Found during:** Task 3 typecheck (`TS2322` / `TS2339` on `steerMessageIds`)
- **Issue:** The ternary `Promise.resolve([]) : db…toArray()` widened to `never[]`, so `row.steerMessageIds` did not exist.
- **Fix:** Explicit `useLiveQuery<AiTeamAssignment[]>` type argument and an `AiTeamAssignment` type import.
- **Files modified:** `src/components/ai/office/TeamWorkspace.tsx`
- **Commit:** 29b17422

**3. [Rule 1 - Bug] Hook order violated the rules of hooks**
- **Found during:** Task 3 implementation
- **Issue:** The new `useState` pair was first placed after `if (status === 'done') return null`, which would break when `status` changes across renders.
- **Fix:** Moved both hooks above the early return, with a comment explaining why.
- **Files modified:** `src/components/ai/office/AgentAttributionRow.tsx`
- **Commit:** 29b17422

**4. [Rule 1 - Bug] Duplicate-text assertion in the steer test**
- **Found during:** Task 3 test run
- **Issue:** `getByText('An')` matched both the attribution row and the mention pill.
- **Fix:** Asserted `getAllByText('An').length > 1` with a comment naming both carriers.
- **Files modified:** `tests/ai/ChatMessageListAttribution.test.tsx`
- **Commit:** 29b17422

No architectural (Rule 4) decisions were needed. No auth gates. No package installs.
