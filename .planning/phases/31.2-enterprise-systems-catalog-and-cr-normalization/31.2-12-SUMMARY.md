# Phase 31.2 Plan 12: Parent Classification Fix and System Catalog Action Sets Summary

One `isLogicalParent` predicate replaces the live `parentId === null || type === 'LOGICAL_GROUP'` bug at every call site, so an unparented subsystem is finally selectable as a CR target; Systems Explorer action sets diverge per D-30, SystemModal reports invariant violations inline, and ChangeRequestModal accepts pre-filled soft-locked targets.

## What Was Built

**Task 1 — one predicate everywhere (commit `900acff0`)**

`SystemTable` had three inline copies of the buggy predicate (tree grouping at 85, row rendering at 119, action set at 279). All three now call `isLogicalParent` from `systemRepo`. `TargetSystemsSelector` was the live defect: its `parentNodes` filter treated any `parentId === null` system as a group header, so an unparented `SERVICE` rendered as a purple folder and could never be selected as a CR target. It now classifies with `isLogicalParent` / `isSubsystem`, and the synthetic `Chưa phân nhóm hệ thống` node collects every subsystem whose parent is absent or missing — as a selectable leaf. `SystemDetailView` line 59 (reversed operand order) is converted too, so the repo-wide grep gate is exit-0 at wave 5 rather than waiting for plan 14.

`systemRepo.getParentSystems` already filtered with `isLogicalParent` (landed in plan 03); confirmed, no change.

**Task 2 — divergent action sets and inline invariant errors (commit `f3bebd0b`)**

`SystemsExplorer.getNodeMenu` now branches on `isLogicalParent`. Parent menu: `Xem chi tiết`, `Thêm subsystem`, `Sửa`, divider, `Xóa` — no `Tạo CR`, ever. Subsystem menu: `Xem chi tiết`, `Tạo CR` (accent `RocketOutlined`), `Mở Git`, `Mở Terminal`, `Sửa`, divider, `Xóa`. Git/Terminal route through `useSystemActions()`; when `disabledReason(system)` is defined the item is `disabled` and carries `title` equal to `Chưa cấu hình SSH/Repo — mở System Catalog`. `Tạo CR` opens `ChangeRequestModal` with `initialTargets=[{ systemId }]`.

The tree also gained a root-level branch for unparented subsystems — previously they were invisible in the explorer entirely (only children of a `LOGICAL_GROUP` rendered), which would have made their new `Tạo CR` action unreachable.

`SystemModal.handleSubmit` no longer fires `message.error` on a repo invariant violation. It maps the message to the responsible field via `invariantFieldFor` and calls `form.setFields`, keeping the modal open. The existing `err?.errorFields` early return is preserved, as is the type-conditional SSH/repo block visibility.

**Task 3 — pre-filled targets and targets-based CR table (commit `db38f1ae`)**

`ChangeRequestModal` gained `initialTargets?: CrTarget[]`. The form field renamed `targetSystemIds` → `targets`, seeded from the prop on create and from `changeRequest.targets` on edit. `handleOk` emits `targets: values.targets.map((systemId) => ({ systemId }))` — the `feature/{code}` default stays in `changeRequestRepo` per D-25. `TargetSystemsSelector` gained `preselectedIds` (renders an `Đã chọn sẵn` tag; still removable, so the lock is soft) and an optional `systems` prop so a preselected code renders on first paint instead of as a raw UUID.

`ChangeRequestTable` renders pills from `cr.targets` and counts tasks by `t.crId`; `t.projectId` is gone.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `QuickReminderModal` imported a deleted repository**

- **Found during:** Task 3 (first run of the CR modal/table suites)
- **Issue:** `src/components/common/QuickReminderModal.tsx` imported `updateProject` from `../../db/repositories/projectRepo`, which Dexie v16 removed. The import failed to resolve, so `ChangeRequestTable.test.tsx` could not even load — the whole suite errored at transform time, not at assertion time.
- **Fix:** Retargeted the modal to `updateChangeRequest` and changed the `target` union member `{ type: 'project'; entity: Project }` → `{ type: 'cr'; entity: ChangeRequest }`, matching plan 31.2-22's stated intent for this file. `ChangeRequestTable` now passes `{ type: 'cr', entity: reminderTargetCR }`.
- **Files modified:** `src/components/common/QuickReminderModal.tsx`, `src/components/changeRequests/ChangeRequestTable.tsx`
- **Commit:** `db38f1ae`

**2. [Rule 1 - Bug] `ChangeRequestTable` chat scope still used the retired `'project'` scope**

- **Found during:** post-implementation `tsc --noEmit` sweep
- **Issue:** `openChat({ type: 'project', ... })` — `ChatScopeType` is `'global' | 'task' | 'cr' | 'system' | 'document'` after D-48, so this was a type error and would have opened a dead scope at runtime.
- **Fix:** `type: 'cr'`.
- **Files modified:** `src/components/changeRequests/ChangeRequestTable.tsx`
- **Commit:** `0f8f9cc2`

**3. [Rule 1 - Bug] `SystemDetailView` still read the retired `cr.targetSystemIds`**

- **Found during:** post-implementation grep for `targetSystemIds`
- **Issue:** `relatedCrs` filtered on `cr.targetSystemIds?.includes(...)`, a field that no longer exists on `ChangeRequest` — the Impacted CRs list would always have been empty.
- **Fix:** `cr.targets?.some((t) => t.systemId === system.id)`.
- **Files modified:** `src/views/SystemDetailView.tsx`
- **Commit:** `0f8f9cc2`

**4. [Rule 2 - Correctness] Unparented subsystems were invisible in Systems Explorer**

- **Found during:** Task 2, while wiring the subsystem action set
- **Issue:** The tree only rendered children of `LOGICAL_GROUP` rows. A subsystem with `parentId === null` — legal per D-24 — appeared nowhere, so its new `Tạo CR` / `Mở Git` / `Mở Terminal` actions were unreachable. Same class of defect as the TargetSystemsSelector bug this plan exists to fix.
- **Fix:** Unparented subsystems (and those whose parent row is missing) render at tree root with the subsystem action set.
- **Files modified:** `src/workbench/toolwindows/SystemsExplorer.tsx`
- **Commit:** `f3bebd0b`
