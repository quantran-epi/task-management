## Fixed Issues

### CR-01: Replacing CR targets leaves tasks pointing at a dropped subsystem

**Files modified:** `src/db/repositories/changeRequestRepo.ts`
**Commit:** f309cd61
**Applied fix:** `updateChangeRequest` computes the removed systemIds and clears
`Task.systemId` for them inside the same `rw` transaction as the CR put, mirroring
`removeSubsystemFromChangeRequest` (D-26).

### CR-02: Any CR edit resets every per-target feature branch

**Files modified:** `src/db/repositories/changeRequestRepo.ts`
**Commit:** f309cd61
**Applied fix:** Target replacement now preserves the prior target's `featureBranch`
(`target.featureBranch ?? prior.featureBranch ?? feature/{code}`), so a name/status/description
edit no longer wipes the branch Step 3 chose.

### CR-03: Dexie v16 migration silently deletes tasks with no resolvable CR

**Files modified:** `src/db/index.ts`
**Commit:** cae746fa
**Applied fix:** Unresolvable tasks are parked under a `CR-LEGACY-UNASSIGNED` recovery CR
(stable UUID `00000000-0000-4000-8000-000000000001`) instead of deleted. The recovery code
is suffixed if a legacy CR already owns it (unique `&code` index).

### CR-04: v16 leaves legacy `entityType` / `taskMateEntityType` values

**Files modified:** `src/db/index.ts`
**Commit:** cae746fa
**Applied fix:** New migration step 3b detaches `notes` whose `entityType` is
`project`/`milestone` and re-points `knowledgeLinks.taskMateEntityType` to `cr`, so the
exported payload passes the v11 backup schema.

### CR-05: `BackupNoteRecordSchema` omits the `'diagram'` note type

**Files modified:** `src/validation/backupSchemas.ts`
**Commit:** cae746fa
**Applied fix:** Note type enum is now `['quick_note', 'document', 'folder', 'diagram']`.

### CR-06: Backup import never validates D-24/D-25/D-26

**Files modified:** `src/services/backup/validateBackup.ts`
**Commit:** 03b49861
**Applied fix:** Added a Stage 4 before `valid: true` that rejects unknown/non-subsystem CR
targets, tasks whose `crId` is unknown or whose `systemId` is not a target, a `LOGICAL_GROUP`
with a parent or SSH/repo fields, and a subsystem whose `parentId` is not a logical group.

### CR-07: `deleteTaskWithAllocations` deletes chat threads but not their tabs

**Files modified:** `src/db/repositories/cascadeRepo.ts`
**Commit:** 66491e73
**Applied fix:** `db.chatTabs` added to the transaction table list and the task's tabs are
deleted alongside its messages and threads.

### CR-08: Pre-import snapshot download writes tokens and passphrases as plaintext

**Files modified:** `src/services/backup/restoreBackup.ts`
**Commit:** 2b1055ca
**Applied fix:** `captureSnapshot` filters settings through `isSafeBackupSetting`, and
`downloadSnapshotFile` re-applies the filter as a second line of defence.

### CR-09: SDLC workflow persistence key no longer matches the restore path or drawer

**Files modified:** `src/services/wizard/workflowCoordinator.ts`, `src/views/ChangeRequestSdlcView.tsx`,
`src/views/SystemDetailView.tsx`, `src/db/repositories/chatTabRepo.ts`, `src/services/ai/sdlcArtifactTools.ts`
**Commit:** 0210317c
**Applied fix:** `workflowStorageKey(changeRequestId, threadId)` — the second segment is the
CR's durable SDLC tab thread, resolved via the new `getOrCreateSdlcTab` / `getSdlcTabThreadId`
helpers. `SystemDetailView` parses the CR id from the second segment. The pre-fix
`<crId>:<crId>` row is still read as a fallback so an upgraded workspace keeps its version chain.

### CR-10: "Mở SDLC Studio" from a system opens the wrong CR

**Files modified:** `src/views/SystemDetailView.tsx`
**Commit:** 0210317c
**Applied fix:** `params: { changeRequestId: crId }`.

### CR-11: Step 3 overwrites the selected subsystem's SSH/repo

**Files modified:** `src/components/sdlc/steps/Step3CodeGuideView.tsx`
**Commit:** 2b96c1ae
**Applied fix:** The subsystem effect now resets every field on switch (empty when the
subsystem has no binding), and `loadInitial` seeds the first SSH profile only when no
subsystem is selected. The effect depends on `selectedSystemId`.

### CR-12: `generate_file` executes model-supplied JavaScript without confirmation

**Files modified:** `src/services/ai/aiTools.ts`
**Commit:** 5a878be1
**Applied fix:** `generate_file` added to `MUTATION_TOOLS`, so the orchestrator asks for

### CR-13: `createTask` / `reparentTask` / `updateTask` never verify the CR exists

**Files modified:** `src/db/repositories/taskRepo.ts`
**Commit:** 66491e73, f9925a23
**Applied fix:** `assertSystemInCrTargets` resolves the CR unconditionally and throws when it
is missing. `updateTask` runs the check only when the patch touches `crId`/`systemId`, so an
unrelated edit of a row whose CR is already gone stays editable.

### CR-14: v16 deletes tasks but leaves their dependants orphaned

**Files modified:** `src/db/index.ts`

**Applied fix:** Tasks are no longer deleted at all (see CR-03), so allocations, sessions,
timers and notes cannot be orphaned by the upgrade. `deleteTaskWithAllocations` remains the
cascade path for real deletions.
