<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| subsystem config → pack shell commands | Each pack call interpolates `remoteRepoPath` and branch refs into git/ssh commands |
| pack loop → UI state | A thrown error must not abort the loop or blank the view |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31.2-44 | Tampering / Elevation | per-subsystem pack commands | mitigate | Each call goes through `createChangePackFromSnapshot`, which already rejects control characters in `baseRef` and paths and routes arguments through `escapeShellArg`; the new loop must not build its own command strings |
| T-31.2-45 | Denial of service | Pack All loop | mitigate | Per-iteration `try/catch` plus a between-iteration stop check, so one failure or a stop cannot abort the run mid-write or blank the step |
| T-31.2-46 | Repudiation | pack history | mitigate | Every pack is persisted with its `systemId`, so the summary can always name which subsystem produced which artifact |
| T-31.2-64 | Repudiation | `Step6CabView` completion | mitigate | Completion writes `status: 'Done'` through `updateChangeRequest` in the same plan that deletes `completeCr`, so no call site can silently keep writing the legacy settings CR store |
| T-31.2-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase |
</threat_model>
