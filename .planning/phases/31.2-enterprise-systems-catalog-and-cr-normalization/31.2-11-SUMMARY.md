# Phase 31.2 Plan 11: Daily-Flow Surfaces Re-Axed onto CR/System Summary

**Eighteen daily-flow files now speak Change Request and Subsystem, with zero dropped-store reads and a `changeRequestId` docx export contract**

## What Was Built

Task 1 — dashboard, timer, planner, palette:

- `AttentionTodayList`: `projectMap` prop became `crMap`, loaded from `db.changeRequests.toArray()`, and the row subtitle renders the CR code (name fallback).
- `ActiveTimerWidget` / `TimerPopoutView`: hierarchy subtitle reads `task.crId` / `task.systemId`, bulk-loads `database.changeRequests` / `database.systems`, and `formatHierarchySubtitle` now composes `CR code › subsystem name`.
- `FeasibilityModal`: `db.changeRequests.get(task.crId)`, banner retitled `Task & CR Context Banner`, CR code tag in the context header.
- `AllocationModal` / `ActualWorklogPlanner` / `PlannerView`: project filter and project subtitles replaced with CR filter and CR subtitles; worklog row subtitle is `CR code › subsystem`.
- `CommandPaletteModal`: `Project`/`Milestone` types became `ChangeRequest`/`System`; `onOpenProject`/`onOpenMilestone` became `onOpenCr`/`onOpenSystem`; category union is `'cr' | 'system'`; palette items open `cr_detail` / `system_detail` tabs; the milestone parent lookup and item are gone; the `#` cheatsheet entry now describes CR & systems.

Task 2 — notes, Jira, search, diagram explorer, docx:

- `DocEditorPane`: parent entity loads from `db.changeRequests` for `cr` notes, wiki-link candidates come from `db.changeRequests`, entity detection passes `(tasks, changeRequests, systems)`, and `BacklinksSection` receives `changeRequests` + `onOpenCr`.
- `NoteDetailModal` / `NoteEditor`: entity handling and select options are `cr` / `system`.
- `BacklinksSection`: prop `projects` became `changeRequests`, label `Change Request`, icon `ProjectOutlined`.
- `QuickPreviewDrawer`: `linkedParentProject` became `linkedParentCr`; backlink list and counts use `backlinks.changeRequests`.
- `CreateJiraIssueModal`: default Epic Key resolves from the task's parent CR (`db.changeRequests.get(task.crId)`).
- `SearchEverywhereModal`: `projects` tab replaced by `cr`; CR results open `cr_detail`; Systems results open `system_detail` with `params.systemId`; tab cycle order is `all → tasks → cr → docs → systems → actions`.
- `DiagramExplorer`: entity link options are `cr` / `system`, backed by `db.changeRequests` / `db.systems`.
- `cabDocx` / `wizardDocx`: `projectId` renamed to `changeRequestId` in both payload types, both Zod schemas, and the CAB source identity check.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Palette needed a navigation path that exists today**
- **Found during:** Task 1
- **Issue:** The plan says `onNavigate('cr_detail')`, but `AppRoute` (plan 05) has no `cr_detail` member — CR detail is a workbench `EditorViewType`, not a hash route. Calling `onNavigate('cr_detail')` would not type-check or route.
- **Fix:** `CommandPaletteModal` opens the `cr_detail` / `system_detail` tab through `useLayoutStore.openTab` (the pattern `CRExplorer` and `SystemsExplorer` already use), and still accepts `onOpenCr` / `onOpenSystem` props so plan 22 can inject AppShell handlers.
- **Files modified:** `src/components/palette/CommandPaletteModal.tsx`
- **Commit:** db0044f5

**2. [Rule 3 - Blocking] `tests/notes.test.ts` imported cascade functions deleted in wave 4**
- **Found during:** Task 2
- **Issue:** The suite imported `deleteMilestoneWithCascade` / `deleteProjectWithCascade`, which no longer exist, so the whole file failed at import.
- **Fix:** Replaced the milestone/project detach cases with one CR detach case against `deleteChangeRequestWithCascade`, and cleared `changeRequests` / `systems` in `beforeEach`. Also added the now-required `crId` to the task fixture.
- **Files modified:** `tests/notes.test.ts`
- **Commit:** 0fbae72c

**3. [Rule 3 - Blocking] Test fixtures referenced dropped stores**
- **Found during:** Tasks 1–2
- **Issue:** `AttentionTodayList`, `ActiveTimerWidget`, `FeasibilityModal`, `CommandPaletteModal`, `SearchEverywhereModal` and `wizardDocx` suites seeded `projects`/`milestones` or passed `projectId`.
- **Fix:** Rebuilt fixtures on `changeRequests`/`systems` with `crId`/`systemId`, renamed assertions to CR codes, and swapped the palette tab/cheatsheet expectations.
- **Files modified:** `tests/components/AttentionTodayList.test.tsx`, `tests/components/ActiveTimerWidget.test.tsx`, `tests/components/FeasibilityModal.test.tsx`, `tests/components/palette/CommandPaletteModal.test.tsx`, `src/workbench/search/__tests__/SearchEverywhereModal.test.tsx`, `tests/export/wizardDocx.test.ts`
- **Commit:** db0044f5, 0fbae72c
