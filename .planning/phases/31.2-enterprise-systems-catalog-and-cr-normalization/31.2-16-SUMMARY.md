# Phase 31.2 Plan 16: Per-subsystem Step 2 contract and Step 3 branch resolution Summary

Step 2 now asks the model for one `### [CODE] name` section per CR target and renders each one with a cyan mono code tag, and Step 3 reads its branch off the CR target instead of guessing it from a branch name.

## What Was Built

### Task 1 — per-subsystem Step 2 contract and renderer (commits `bb442e3d`, `f8b01be4`)

`src/services/ai/sdlcPromptComposer.ts`:

- `buildSubsystemSectionContract(targets)` emits `[HỢP ĐỒNG MỤC THEO SUBSYSTEM — BƯỚC 2]`, one literal `### [CODE] name` line per target in `cr.targets` order, the bullet-list expectation, and the rule that an untouched subsystem gets the exact line `Không có thay đổi ở subsystem này` instead of an empty section. Returns `''` for zero targets.
- `composeSdlcTurn` gained an optional `targets` input and a `segments.subsystemSections` field, populated only when `step === 'SOLUTION'`. It is spliced into the system message after `stepContract` and before `toolPolicy`, so `policy` still leads and the existing layer-order assertions are untouched.
- `buildToolPolicy` and `SDLC_STEP_ALLOWED_TOOLS` were not modified.

`src/components/sdlc/steps/Step2SolutionView.tsx`:

- `parseSolutionSubsystemSections(markdown)` splits on `^###\s+\[([^\]]+)\]\s*(.*)$` into `{ preamble, sections }`.
- `SolutionPreview` renders the preamble, then per section a cyan mono `Tag` with the code and the name at 16/600, then the body. A body equal to the unaffected marker renders as muted `Typography.Text`; anything else goes through `SafeMarkdown`.
- With no subsystem headings the whole document renders through `SafeMarkdown` — legacy drafts keep working.
- `ConventionsSummaryCard` stays the first child, unchanged in position.

`src/components/sdlc/common/SafeMarkdown.tsx` is the new single wrapper around `renderSafeMarkdown`, so `Step2SolutionView.tsx` no longer contains `dangerouslySetInnerHTML` (T-31.2-41).

### Task 2 — Step 3 branch resolution (commits `2ab960b2`, `388c32d0`)

`src/components/sdlc/steps/Step3CodeGuideView.tsx`:

- `targetBranch = crTargets.find(t => t.systemId === selectedSystemId)?.featureBranch ?? ''` — derived, not mirrored into state. No `branchList.find`, no `branchList[0]`.
- `baseBranch` comes from `selectedSystem.defaultBaseBranch ?? 'origin/main'` via an effect keyed on the selected system.
- Empty `targetBranch` renders a `Select` (`data-testid="step3-branch-picker"`) with `value={pendingBranch || undefined}` — no preselection — plus a `Xác nhận nhánh` button disabled until a branch is chosen. Confirming calls `onFeatureBranchChange(selectedSystemId, branch)`; `ChangeRequestSdlcView` already maps that to `updateChangeRequest(cr.id, { targets })`, so the CR repo re-validates (T-31.2-43).
- A non-empty `targetBranch` renders as a read-only cyan mono tag; the picker is not mounted.
- The local `selectedSystemId` state and the duplicated `Segmented` switcher were deleted; the component consumes the view-level prop from the Context Bar (plan 15).
- The remote branch list load is unchanged — picker options only.
