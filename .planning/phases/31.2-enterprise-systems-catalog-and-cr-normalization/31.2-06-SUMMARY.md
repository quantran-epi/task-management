## Accomplishments

- `CRExplorer.tsx` is a real 484-line tree: CR node (type icon, blue code tag, 600-weight name, status tag, task count) -> one cyan pill per `cr.targets[]` -> task leaves, with tasks lacking `systemId` under the synthetic `Chung (không gắn)` node. No Milestone tier anywhere.
- Selection routing: CR -> `cr_detail` tab with `params.changeRequestId`; pill -> `sdlc` tab with `params.changeRequestId` + `params.systemId`; task -> insight tab.
- Both context menus match UI-SPEC §1 exactly, including `Gỡ khỏi CR` going through `removeSubsystemFromChangeRequest` behind a `Modal.confirm`.
- Three empty states (`Chưa có Change Request nào` + CTA, `Chưa gắn subsystem`, `Chưa có tác vụ`) and a search filter across CR name/code, subsystem code and task name.
- `useSystemActions` exposes `openGit` / `openTerminal` / `disabledReason`; the terminal receives a validated absolute path and issues a quoted `cd` once the PTY connects.
- `layoutStore` no longer has a dead id: `cr_detail` added, `projects` removed from `EditorViewType`, default `leftActiveId` is `cr_explorer`, persist key is `taskmate_workbench_layout_v2`, and `partialize` coerces a stale `projects` id / drops stale `projects` tabs.
- Alt+1 still works: the action id renamed to `view.toggle-cr-explorer` and `useGlobalKeymap` dispatches it.
- `ProjectExplorer.tsx` (901 lines) deleted; zero non-test references remain in `src/`.

## Decisions Made

- `openGit` activates the existing LEFT `remote_explorer` tool window rather than creating a bottom `remote_git` id (locked reinterpretation of D-35).
- `pendingTerminalTarget` is deliberately non-persisted; `partialize` omits it.
- Repo path written to the PTY is POSIX single-quoted (`shellQuote`) so a path cannot break out of `cd`.
- `RemoteGitExplorer` sync effect is keyed on the last applied store value, so a second 1-click switches target while local typing is not clobbered mid-edit.
