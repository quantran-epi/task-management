# Phase 31.2 Plan 13: CR Detail View Summary

One-liner: Single-screen CR detail tab with a 6-step SDLC progress strip, an editable Subsystem cell constrained to `cr.targets`, and collapsed secondary blocks — rendered from a new `cr_detail` branch in `EditorArea`.

## What Was Built

**`src/views/ChangeRequestDetailView.tsx`** (527 lines) — takes `{ changeRequestId, db? }`:

- **Header (UI-SPEC §3a)** — CR code as a blue mono `Tag`, name at Display 20/600, type tag with the type color + icon + Vietnamese label (`Tạo mới` / `Nâng cấp` / `Sửa lỗi`), status tag. Below it the target subsystem pills (cyan `Tag` + `BranchesOutlined`, 12px mono code, `Tooltip` = `{name} ({type})`), or the muted `Chưa gắn subsystem` + `Chọn subsystem` link. Right side: primary `Mở SDLC Studio`, default `Sửa`, danger `Xóa`.
- **Progress strip (§3b)** — six steps (`Nạp yêu cầu`, `Giải pháp`, `Coding`, `Change Pack`, `Tài liệu`, `CAB`) in a 24px row joined by 1px `--border` lines; each wrapped in a `Tooltip` carrying the full step title from `SDLC_STEPS_CONFIG`. Clicking opens `openTab({ id: 'sdlc-<crId>', viewType: 'sdlc', params: { changeRequestId, stepId } })`.
- **Task table (§3c)** — antd `Table size="small" pagination={false}` with exactly five columns in order: `Task`, `Subsystem`, `Status`, `Ước lượng`, `Hạn`. The Subsystem cell is an antd `Select` (small, borderless) whose options are `cr.targets` mapped to system codes plus `{ value: '__none__', label: 'Chung (không gắn)' }`; `onChange` calls `updateTask(task.id, { systemId: value === '__none__' ? undefined : value }, db)` so `assertSystemInCrTargets` re-checks membership. Overdue deadlines render in `--danger`.
- **Secondary blocks (§3d)** — `Collapse size="small" ghost`, all collapsed, headers `Jira Epic` / `Tài liệu liên kết` / `Nhắc nhở` with a count badge when non-empty and muted `Chưa có` in the body when empty.
- **Empty state** — `CR này chưa có tác vụ nào` with a `Thêm tác vụ` CTA.
- **Delete** — `Modal.confirm` with the exact UI-SPEC §Destructive confirmations copy for `Xóa Change Request`, calling the cascading `deleteChangeRequest`.

**`src/workbench/EditorArea.tsx`** — added `case 'cr_detail'` rendering the view with `params.changeRequestId`; deleted the dead `case 'projects'` branch and its `ProjectsView` import (the file no longer exists on disk); re-pointed the `sdlc` case at `ChangeRequestSdlcView`; `default:` still returns `TasksView` so a stale persisted tab degrades safely.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `ProjectSdlcView` import no longer resolves**
- **Found during:** Task 2 baseline run
- **Issue:** `src/workbench/EditorArea.tsx` imported `../views/ProjectSdlcView`, which was renamed to `ChangeRequestSdlcView.tsx` in commit `4483d8dc` (plan 31.2-05). The stale import made `EditorArea` fail to transform at all, so `src/workbench/__tests__/EditorArea.test.tsx` could not run — blocking Task 2's verification.
- **Fix:** Re-pointed the import and the `case 'sdlc'` branch at `ChangeRequestSdlcView`, passing `changeRequestId` (falling back to the legacy `params.projectId` for old persisted tabs).
- **Files modified:** `src/workbench/EditorArea.tsx`
- **Commit:** `bc7de0f3`

**2. [Rule 3 - Blocking] `EditorArea.test.tsx` mocked the deleted `ProjectsView`**
- **Found during:** Task 2
- **Issue:** The test file had `vi.mock('../../views/ProjectsView', ...)`, which vitest cannot resolve now that the module is gone.
- **Fix:** Replaced that mock with `ChangeRequestDetailView` + `ChangeRequestSdlcView` mocks and added a test asserting a `cr_detail` tab renders the view with its `changeRequestId`.
- **Files modified:** `src/workbench/__tests__/EditorArea.test.tsx`
- **Commit:** `bc7de0f3`

**3. [Rule 1 - Bug] antd v6 renamed the Select selector class**
- **Found during:** Task 1 GREEN
- **Issue:** The test opened the Subsystem dropdown via `.ant-select-selector`, which does not exist in Ant Design 6 (it is `.ant-select-content` now). Three tests failed with "Unable to fire a mousedown event".
- **Fix:** Target the `.ant-select` root instead — stable across antd versions and sufficient for the mousedown trigger.
- **Files modified:** `tests/views/ChangeRequestDetailView.test.tsx`
- **Commit:** `ac83f0ac`

**4. [Rule 2 - Missing critical functionality] "Thêm tác vụ" could not pre-fill the CR**
- **Found during:** Task 1
- **Issue:** The plan says to open `TaskDrawer` with `crId` pre-filled, but `TaskDrawerProps` has no such prop — `taskId: string | null` is required and the form only populates from a loaded task.
- **Fix:** Create the task row first via `createTask({ crId, name: 'Tác vụ mới', ... })`, then open the drawer on the new id — the same pattern `ItemInsightView.handleCreateTaskInCr` already uses. `crId` is then populated from the record.
- **Files modified:** `src/views/ChangeRequestDetailView.tsx`
- **Commit:** `ac83f0ac`

## Known Stubs

None. The progress strip renders a static "step 1 complete / rest future" visual because the CR detail view does not load the SDLC workflow state (that lives in `db.settings` keyed by `sdlc_workflow:{crId}:{crId}` and is owned by `ChangeRequestSdlcView`). The strip's job per UI-SPEC §3b is navigation, and every step deep-links correctly; the completed/current/future styling would need a settings read to be live. This is a deliberate scope call, not a broken data path — flagging it for the verifier.
