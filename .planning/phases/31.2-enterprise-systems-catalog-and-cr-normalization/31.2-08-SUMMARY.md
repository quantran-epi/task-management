## Accomplishments

- `TasksView` reads `getAllChangeRequests`/`getAllSystems`, builds `crMap`/`systemMap`, aggregates owner/BA autocomplete from CRs + tasks, groups the feasibility modal by CR, and exposes `initialCrId` + `handleSelectCr` (`hierarchyScope: 'cr'`).
- `TaskTable` leading columns are exactly `Task | CR | Subsystem | Status | Ước lượng | Hạn`. CR cell is a code tag in the CR type colour with the CR name as tooltip; Subsystem cell is a cyan mono tag or `Chung` when `systemId` is undefined. Ops Owner / BA inherit from the CR via `resolveInheritedTags(..., { cr })`.
- `TaskFilterBar` offers `Lọc theo CR` and `Lọc theo Subsystem` (options limited to the selected CR's targets, disabled until a CR is chosen); scope segmented control is `Tất cả / CR / Độc lập`; `eligibleMilestones` and the milestone field are gone.
- `QuickAddBar` renders CR select → Subsystem select → work type → input; with no CR the input is disabled with placeholder `Chọn CR trước khi thêm tác vụ`.
- `TaskDrawer` form fields are `crId` (required, label `Change Request (CR)`) and `systemId` (optional, label `Subsystem`, options = CR targets + `Chung (không gắn)`, tooltip `Chọn CR trước` while no CR). Changing CR clears a subsystem outside the new targets. Save routes through `reparentTask` + `updateTask`, so `assertSystemInCrTargets` re-validates (T-31.2-21).
- `BatchActionBar` reparent target is a CR + optional Subsystem and goes through `reparentTask`, so a batch cannot move tasks to a subsystem outside their CR (T-31.2-22).
- `HierarchyBreadcrumb` rewritten to `CR > Subsystem` (`crCode`, `crName`, `systemCode?`, `systemName?`, `onSelectCr`).
- `ItemInsightView` supports `itemType: 'task' | 'cr' | 'system'`: task shows parent CR + subsystem breadcrumb, CR lists that CR's tasks with a `Mở CR detail` action, system lists tasks across CRs targeting it. Project/milestone analysis paths, `ProjectModal`, `MilestoneModal` and the project/milestone repos are no longer imported.

## Decisions Made

- CR and Subsystem are dedicated columns rather than a breadcrumb prefix inside the name cell — matches UI-SPEC §7 ordering literally and keeps the columns sortable/visible independently.
- `HierarchyBreadcrumb` remains a standalone component with the new `CR > Subsystem` contract (the plan requires the rewrite) but the TaskTable no longer embeds it, since CR/Subsystem are now first-class columns.
- Batch reparent requires a CR selection; `Áp dụng` stays disabled until one is picked, because `Task.crId` is non-optional.
- `openCrDetail` calls `onNavigate('cr_detail' as AppRoute, { changeRequestId })`. `AppRoute` has no `cr_detail` member yet (plan 31.2-13 owns `EditorArea`); in the workbench the call reaches `openTab`, in hash-routing mode it degrades to the default route. Plan 13 wires the real tab.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Tooltip inside Form.Item broke the Subsystem form binding**
- **Found during:** Task 2 (TaskDrawer)
- **Issue:** `Form.Item` wrapped a `Tooltip` wrapping the `Select`. Ant Design Form only injects `value`/`onChange` into its direct child, so the selected subsystem never reached form state and `systemId` was never saved.
- **Fix:** Moved `Tooltip` outside `Form.Item` and wrapped the item in a block-level `<span>` so the tooltip still has a hover target.
- **Files modified:** `src/components/tasks/TaskDrawer.tsx`
- **Commit:** `d693e312`
