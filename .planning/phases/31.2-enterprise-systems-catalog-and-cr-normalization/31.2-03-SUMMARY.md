# Phase 31.2 Plan 03: Repository Invariants & CR Cascade Summary

**D-24/D-25/D-26 invariants now throw from the repository layer with the UI-SPEC's exact Vietnamese messages, and CR deletion cascades through `deleteChangeRequestWithCascade` with zero `db.projects` dependency.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3
- **Files modified:** 5 (4 repositories + 1 test file)

## Accomplishments

### Task 1 — System repo predicates and invariants (`c5350952`)

- `isLogicalParent(system)` / `isSubsystem(system)` exported; `getParentSystems` now `all.filter(isLogicalParent)`, deleting the `parentId === null || type === 'LOGICAL_GROUP'` misclassification (H1).
- Three module-private assertions: `assertParentIsLogicalGroup` (`Hệ thống cha không tồn tại.` / `Subsystem phải trỏ tới một Logical Parent`), `assertNoCycle` (`Không thể tạo vòng lặp phân cấp`), `assertParentHasNoRepoFields` (`Hệ thống cha không được có SSH/Repo`).
- `updateSystem` promoting a subsystem to `LOGICAL_GROUP` clears `parentId` plus the three repo fields.
- `deleteSystem` runs one `db.transaction('rw', [db.systems, db.changeRequests, db.tasks])`: children guard, filter the id out of every CR's `targets`, `delete task.systemId` on affected tasks, then delete the system.

### Task 2 — CR repo targets, branch defaulting, subsystem removal (`e9b543cf`)

- `assertTargetsAreSubsystems` throws `Subsystem không tồn tại.` / `Chỉ được gắn subsystem vào CR`.
- `applyFeatureBranchDefaults` maps each target to `feature/{code}` when no branch is given; only applied when the patch carries `targets`, so a code rename leaves stored branches untouched.
- `removeSubsystemFromChangeRequest(crId, systemId, db)` filters the target and clears `systemId` on that subsystem's tasks in one transaction; tasks survive.
- `getChangeRequestsBySystem` matches on `cr.targets.some`; `deleteChangeRequest` delegates to `deleteChangeRequestWithCascade`.

### Task 3 — Task repo re-axis and CR cascade (`647bc180`)

- `assertSystemInCrTargets` validates `Change Request không tồn tại.` and `Subsystem của tác vụ phải thuộc CR đã chọn.`; called from `createTask`, `updateTask` and `reparentTask`.
- `getTasksByProject`/`getTasksByMilestone` replaced by `getTasksByCr`/`getTasksBySystem`; `projectId`/`milestoneId` fully gone from `taskRepo.ts`.
- `reparentTask(taskId, crId, systemId?)` validates target membership before writing.
- `deleteChangeRequestWithCascade` deletes the CR, its tasks, allocations/sessions/timers, detaches note entity links, purges `cr:<id>` and `task:<id>` chat threads + tabs + messages, and removes knowledge links — all in one transaction.
- `deleteProjectWithCascade` and `deleteMilestoneWithCascade` deleted outright (D-27 forbids aliases); no `db.projects` / `db.milestones` reference remains in `cascadeRepo.ts`.

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `cascadeRepo.test.ts` asserted on deleted functions**
- **Found during:** Task 3
- **Issue:** The suite imported `deleteProjectWithCascade`/`deleteMilestoneWithCascade` and `createProject`/`createMilestone`, all of which are gone after this plan. The file could not even import, so the plan's own verify command could never pass.
- **Fix:** Rewrote the file onto the CR model, keeping `deleteTaskWithAllocations` and the transaction-rollback case (both still valid). Project/milestone cascade cases were dropped — plan 31.2-19 (wave 10) owns the full CR rewrite of this file per its `files_modified`.
- **Files modified:** `tests/db/cascadeRepo.test.ts`
- **Commit:** `647bc180`

**2. [Rule 1 - Bug] `ChangeRequest.code` is required but was assigned conditionally**
- **Found during:** Task 2 typecheck
- **Issue:** The old `createChangeRequest` set `code` only when defined (it was optional pre-31.2-01). `ChangeRequest.code` is now required, so the object literal failed `tsc`.
- **Fix:** Assign `code: validated.code` in the literal (the Zod schema already requires it). Same in `updateChangeRequest` — dropped the `delete updated.code` branch.
- **Files modified:** `src/db/repositories/changeRequestRepo.ts`
- **Commit:** `e9b543cf`

**3. [Rule 1 - Bug] `CrTargetInput` vs `CrTarget` mismatch on `featureBranch`**
- **Found during:** Task 2 typecheck
- **Issue:** `exactOptionalPropertyTypes` makes the Zod-inferred `{ featureBranch?: string | undefined }` unassignable to `CrTarget`'s `featureBranch?: string`.
- **Fix:** `applyFeatureBranchDefaults` / `assertTargetsAreSubsystems` take `readonly CrTargetInput[]` and the mapper always produces a concrete string branch.
- **Files modified:** `src/db/repositories/changeRequestRepo.ts`
- **Commit:** `e9b543cf`

**4. [Rule 3 - Blocking] `deleteMilestoneWithCascade` had no remaining caller path**
- **Found during:** Task 3
- **Issue:** The plan only names `deleteProjectWithCascade` for deletion, but `deleteMilestoneWithCascade` reads `db.milestones`, which V16 dropped — it would throw at runtime and violates the plan's own `does NOT contain db.projects` intent for the file.
- **Fix:** Removed it alongside the project cascade. Its two remaining callers (`aiTools.ts`, `ProjectExplorer.tsx`) are owned by plans 10 and 06 respectively.
- **Files modified:** `src/db/repositories/cascadeRepo.ts`
- **Commit:** `647bc180`
