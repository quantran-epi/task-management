# Phase 31.2 Plan 18: Subsystem Proposal Tool and Confirm-Only Approval Card Summary

`propose_subsystems` AI tool that returns catalog-validated candidate subsystems and writes nothing, plus a `SubsystemProposalCard` whose `Thêm vào CR` click is the only path that ever writes `cr.targets`.

## What Was Built

### Task 1 — tool registered at all six points

- `src/services/ai/aiTools.ts`: `propose_subsystems` definition with an optional `items`/`evidence` schema and no required arguments (the CR comes from the trusted `ArtifactToolContext`, never from model args). Not added to `MUTATION_TOOLS`. Dispatch case added alongside `get_artifact`/`patch_artifact_section`.
- `src/services/ai/sdlcArtifactTools.ts`: `SubsystemProposalItem` (`systemId`, `code`, `name`, `confidence`, `reason`) and `SubsystemProposalResult` (`items`, `evidence`). New `proposeSubsystems` branch runs **before** the `prepareArtifactPatch` fallthrough, re-resolves every id against `db.systems`, drops unknown ids and `LOGICAL_GROUP` parents, dedupes, and takes `code`/`name` from the catalog.
- `src/services/ai/sdlcPromptComposer.ts`: `propose_subsystems` added to `SDLC_STEP_ALLOWED_TOOLS.SOLUTION` and `.INTAKE`; deliberately kept out of `ARTIFACT_STEP_TOOL_NAMES` (that constant drives `ownsDocuments`). `buildToolPolicy` gained a `hasProposal` guidance line; the two machine-parsed name lines are unchanged, so the parser equality still holds.
- `src/services/ai/chatTurnTools.ts`: added to the hardcoded no-allowlist exclusion array (T-31.2-49).
- `src/components/sdlc/chat/StepChatPanel.tsx`: host gate now drops `propose_subsystems` when no live CR scope exists, matching the artifact-tool gate.

### Task 2 — confirm-only card

- `src/components/sdlc/common/SubsystemProposalCard.tsx`: checkbox rows with cyan mono code tag, name, confidence `Tag` (`Cao`/`Trung bình`/`Thấp`) and a 2-line reason with tooltip; evidence in a collapsed `Collapse` labelled `Bằng chứng ({n})`; footer `Thêm vào CR` (disabled + tooltip `Chọn ít nhất một subsystem`) and `Bỏ qua`. Title switches to `Đề xuất bổ sung subsystem` with the existing-count subtitle when the CR already has targets, and only missing subsystems are listed. Mounting performs no write.
- `src/components/sdlc/chat/StepChatPanel.tsx`: parses `propose_subsystems` result events into a `ProposalRecord`, renders the card in-thread via `transcriptExtensions`, and owns the only write — `handleApproveProposal` guards on stale scope, reads the live CR, appends only missing targets through `updateChangeRequest` (the repo re-validates and applies `feature/{code}` defaults). `handleSkipProposal` plus the card both call `dismissProposal`, writing `sdlc_proposal_dismissed:<crId>`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Host gate would advertise the proposal tool without a CR scope**
- **Found during:** Task 1 verification (`StepChatPanelToolPolicy.test.tsx`)
- **Issue:** The allowlist alone made `propose_subsystems` appear in the payload even when no trusted artifact context existed, so the model could call a tool that always refuses.
- **Fix:** Added `if (name === 'propose_subsystems') return artifactsAllowed;` to the existing host gate filter in `StepChatPanel.tsx`.
- **Commit:** 24498859

**2. [Rule 3 - Blocking] Existing tests asserted the pre-change tool count and allowlist**
- **Found during:** Task 1 verification
- **Issue:** `tests/ai/aiTools.test.ts` asserted `AI_DATABASE_TOOLS.length === 73`; `tests/ai/sdlcPromptComposer.test.ts` asserted the exact per-step allowlist; `tests/ai/sdlcPromptIsolation.test.ts` filtered only the two artifact tools out of "ordinary tools".
- **Fix:** Updated those three assertions to the new 74-tool array and the `INTAKE`/`SOLUTION` proposal allowlist. These files are also in plan 19's scope; the edits here are the minimal correct state for this plan's contract.
- **Commit:** 24498859

**3. [Rule 1 - Bug] Dismissal write initially lived only in the panel handler**
- **Found during:** Task 2 verification
- **Issue:** The card hid itself on `Bỏ qua` before the host persisted the key, so a remount could re-show the proposal.
- **Fix:** Extracted `dismissProposal(crId, db)`; both the card and `handleSkipProposal` call it (idempotent put).
- **Commit:** 14c02b52
