## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `query_notifications` crashed on the missing `changeRequests` read**
- **Found during:** Task 4 (AI tool suites)
- **Issue:** `evaluateNotifications` destructures `changeRequests` unconditionally to build its `crMap`; the `query_notifications` handler passed neither the read nor the argument, so the tool threw `actual value must be number or bigint, received "undefined"`.
- **Fix:** Read `db.changeRequests` alongside `db.tasks` and pass it into `evaluateNotifications`.
- **Files modified:** `src/services/ai/aiTools.ts`
- **Commit:** `a4a43c15`

**2. [Rule 1 - Bug] Composer disabled while awaiting approval made the documented typed yes/no path unreachable**
- **Found during:** Task 4 (AI drawer suites)
- **Issue:** `AiChatWidget` passed `disabled || awaitingApproval` to `ChatInputBar`, but the placeholder and `handleSendTurn` both advertise typing yes/no as an approval path.
- **Fix:** `disabled={disabled}`; updated the two assertions that expected a disabled composer.
- **Files modified:** `src/components/ai/AiChatWidget.tsx`, `tests/ai/AiChatWidget.test.tsx`, `tests/ai/ArtifactDiffApprovalCard.test.tsx`
- **Commit:** `90ecfc03`

**3. [Rule 3 - Blocker] Acceptance grep blocked by production `projectId` props**
- **Found during:** Task 3
- **Issue:** `grep "projectId"` over the Task-3 file set could not reach zero while `SdlcSidebar`, `Step4ChangePackView` and `ChangeRequestSdlcView` still used the old prop name.
- **Fix:** Renamed the prop to `changeRequestId` in all three (and dropped the unused `Step3CodeGuideView` prop). This also cleared a pre-existing type error: `Step4ChangePackView` was feeding `projectId` into `buildHubReconciliation`, which requires `changeRequestId`.
- **Files modified:** `src/components/sdlc/SdlcSidebar.tsx`, `src/components/sdlc/steps/Step4ChangePackView.tsx`, `src/components/sdlc/steps/Step3CodeGuideView.tsx`, `src/views/ChangeRequestSdlcView.tsx`
- **Commit:** `2a5310bd`

**4. [Rule 3 - Blocker] Repo gate blocked by `EditorArea` and `layoutStore` legacy reads**
- **Found during:** Task 4 (repo gate)
- **Issue:** `EditorArea.tsx` still read `db.projects`/`db.milestones` and `tab.params?.projectId`; `layoutStore.ts` still carried the `'projects'` -> `'cr_explorer'` migration and the `'projects'` tab filter.

- **Files modified:** `src/workbench/EditorArea.tsx`, `src/workbench/store/layoutStore.ts`, `tests/workbench/CRExplorer.test.tsx`, `tests/db/documentLinkRepo.test.ts`
- **Commit:** `83e1986d`

**5. [Rule 1 - Bug] `Explorers.test.tsx` hung indefinitely**
- **Found during:** Task 3
- **Issue:** The `vi.mock('dexie-react-hooks')` returned `defaultVal ?? []`, a fresh array per render; `DocsExplorer`'s publish-status effect depends on `allNotes`, producing an infinite re-render loop (repeated 120s/180s timeouts, orphaned workers).
- **Fix:** Module-scoped stable `EMPTY` array returned from `useLiveQuery`.
- **Files modified:** `src/workbench/__tests__/Explorers.test.tsx`, `src/workbench/__tests__/StripeRemoteExplorer.test.tsx`
- **Commit:** `2a5310bd`

**6. [Rule 1 - Bug] `AIChatDrawerRetry` turn-count assertion was wrong about the orchestrator**

- **Files modified:** `tests/ai/AIChatDrawerRetry.test.tsx`
