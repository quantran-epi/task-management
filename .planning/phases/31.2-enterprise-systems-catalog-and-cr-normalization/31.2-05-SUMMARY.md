# Phase 31.2 Plan 05: Legacy Project/Milestone Deletion and CR-Renamed SDLC Studio Summary

Deleted the entire legacy Project/Milestone UI and repository surface plus the SDLC repo-config view, renamed the SDLC Studio to CR terminology, and removed the second SSH/repo config path from the service layer so System Catalog is the only config source.

## What Was Built

**Task 1 — Legacy surface deleted.** `src/components/projects/` (5 files: CascadeDeleteModal, MilestoneModal, ProjectDetailModal, ProjectModal, ProjectTable), `src/views/ProjectsView.tsx`, `src/db/repositories/projectRepo.ts`, `src/db/repositories/milestoneRepo.ts`, `src/components/sdlc/config/RepoConfigView.tsx` and its test are gone — 3013 lines removed with no re-export shims. `AppRoute` lost `'projects'`, `App.tsx` lost the `case 'projects'` branch and the `ProjectsView` import, `Navigation.tsx` lost the `Dự án` item and the `ProjectOutlined` import, and the `insight` `validTypes` narrowed to `['task', 'cr', 'system']`.

**Task 2 — SDLC view renamed, config branch removed, binding deleted.** `ProjectSdlcView.tsx` → `ChangeRequestSdlcView.tsx` (`git mv`, 93% similarity), component `ChangeRequestSdlcView`, prop `projectId` → `changeRequestId`. The view now reads `db.changeRequests` only (no `db.projects`), loads conventions via `loadMultiRepoConventions(cr.targets.map(t => t.systemId), db)`, and has no `isConfigActive` state or `RepoConfigView` branch. `SdlcSidebar` dropped the `sidebar-btn-repo-config` chip, the `getProjectRepoSshBinding` live query, and the `legacyCrs`/`sdlcCrManager.listCrs` fallback (CR picker reads `db.changeRequests` only). `ChangeRequestsView` opens a `sdlc` workbench tab (`params: { changeRequestId }`) instead of inline-swapping the SDLC view, filters subsystems via `isSubsystem`, and counts child tasks by `t.crId`. `gitRemoteService` lost `PROJECT_SSH_REPO_SETTING_PREFIX`, `getProjectSshRepoKey`, `getProjectRepoSshBinding`, `saveProjectRepoSshBinding` (kept `escapeShellArg`, `getRemoteBranches`, `getDiffSummary`, `getFileDiff`, `checkHeadDrift`); `conventionService` lost the legacy `loadRepoConventions(projectId)` (kept `loadRepoConventionsForSystem` and `loadMultiRepoConventions`); `ProjectRepoSshBinding` deleted from `types/gitRemote.ts`. The two test blocks exercising the deleted functions were removed. `MermaidAssistantView` and `NotesPopoutView` entity pickers now read `changeRequests`/`systems`; `useHashRoute` lost the `milestoneId` sanitizer and the `'projects'` whitelist; `useGlobalShortcuts` lost the `nav-projects` entry and the Alt+4 route.

**Task 3 — Step 3/Step 4 repointed onto CR targets.** Step 3 deleted the binding import, the read, the write helper and all five call sites; SSH/repo/base come from `targetSystems.find(s => s.id === selectedSystemId)`; the `branchList.find(b => b.name.includes(crCode))` heuristic and the `branchList[0]` auto-select are gone — `targetBranch` comes from the new `crTargets` prop (`crTargets.find(t => t.systemId === selectedSystemId)?.featureBranch`), and a user-confirmed picker choice calls the new `onFeatureBranchChange(systemId, branch)` prop, wired in the view to `updateChangeRequest({ targets })`. Step 4 resolves SSH/repo from a new `targetSystems` prop with `branchSnapshot.*` as fallback.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `MultiRepoConventionResult.repoPath` broke `exactOptionalPropertyTypes`**
- **Found during:** Task 2
- **Issue:** `loadMultiRepoConventions` assigned `repoPath: system.remoteRepoPath` where the value is `string | undefined`, which `exactOptionalPropertyTypes: true` rejects.
- **Fix:** Spread the field conditionally (`...(system.remoteRepoPath ? { repoPath: system.remoteRepoPath } : {})`).
- **Files modified:** `src/services/conventionService.ts`
- **Commit:** 4483d8dc

**2. [Rule 1 - Bug] `SdlcSidebar` read `crCode`/`featureName` off `ChangeRequest`**
- **Found during:** Task 2
- **Issue:** The sidebar's CR picker used `(c as any).crCode` / `(c as any).featureName` and the progress header printed `currentCr.crCode` — those fields belong to the legacy `SdlcCrRecord`, not `ChangeRequest`.
- **Fix:** Read `c.code` / `c.name` directly (the model's real fields) and print `currentCr.code`.
- **Files modified:** `src/components/sdlc/SdlcSidebar.tsx`
- **Commit:** 4483d8dc

**3. [Rule 2 - Missing critical functionality] `SdlcWorkspace` had no config branch to remove**
- **Found during:** Task 2
- **Issue:** The plan lists `SdlcWorkspace.tsx` as carrying an `isConfigActive ? <RepoConfigView/>` branch; the branch actually lived in `ProjectSdlcView.tsx` (`renderStepNode`). `SdlcWorkspace` had no such code.
- **Fix:** No edit needed. The branch was removed from the renamed view instead. File left untouched.
- **Files modified:** none
