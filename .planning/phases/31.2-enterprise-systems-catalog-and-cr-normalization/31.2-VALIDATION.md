# Phase 31.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest ^5.0.2 + jsdom + @testing-library/react ^16.3.3 |
| **Config file** | `vite.config.ts` (`test:` block, lines ~66-84) |
| **Setup file** | `tests/setup.ts` (`fake-indexeddb/auto`, jest-dom, Blob/matchMedia shims) |
| **Quick run command** | `npx vitest run <explicit paths>` |
| **Full suite command** | `npx vitest run` — **do not run** (repo rule: >1 hour) |
| **Estimated runtime** | ~5–20s per scoped file; serial (`fileParallelism: false`) |

---

## Sampling Rate

- **After every task commit:** Run the single scoped test file for that task (e.g. `npx vitest run tests/db/systemRepo.test.ts`)
- **After every plan wave:** Run the union of that wave's scoped files, passed explicitly
- **Wave 0 (plans 20/21):** the suites exist and are discoverable (`npx vitest list <paths>` exits 0). They are RED until their owning plan lands; a `No test files found` error is the failure signal this gate exists to prevent
- **Before `/gsd-verify-work`:** Every file listed below, in small batches, plus a manual Tauri smoke test on a real SSH host
- **Never:** `npx vitest run` bare (full suite >1 hour)
- **Max feedback latency:** 30 seconds
