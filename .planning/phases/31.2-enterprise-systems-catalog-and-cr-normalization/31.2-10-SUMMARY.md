# Phase 31.2 Plan 10: AI Surface Re-Axis Summary

The AI surface now speaks CR/System: five CR/system tools replace the eight project/milestone tools, mutation classification covers the three CR write tools, grounding resolves CR/subsystem hierarchy, and chat scope offers `Tác vụ` / `CR` / `Subsystem` / `Tài liệu` tabs with `cr:` / `system:` mention keys.

## What Changed

**Task 1 — tool definitions and dispatch (`src/services/ai/aiTools.ts`)**
- Deleted `query_projects`, `query_milestones`, `create_project`, `update_project`, `delete_project`, `create_milestone`, `update_milestone`, `delete_milestone`.
- Added `query_change_requests` (status/type/systemId/search filters; returns code, name, type, status, targets, task counts), `query_systems` (type/search; returns code, name, type, parentId, remoteRepoPath), `create_change_request` (required code/name/type; optional status/description/targets), `update_change_request` (id plus patch), `delete_change_request` (id). Descriptions state targets accept subsystems only and a logical parent is rejected.
- `MUTATION_TOOLS` now lists `create_change_request` / `update_change_request` / `delete_change_request` and no project/milestone name (T-31.2-26).
- Dispatch calls `getAllChangeRequests`, `getAllSystems`, `createChangeRequest`, `updateChangeRequest`, `deleteChangeRequest`; the repo re-validates targets regardless of model input.
- Re-axed `query_tasks`, `get_item_details`, `query_worklogs`, `get_analytics_summary`, `query_notes`, `get_document_backlinks`, `generate_standup_report`, `query_attention_items`, `query_recurring_tasks`, `query_notifications`, `auto_link_document`, `manage_reminders`, `link_document`, `unlink_document`, and both mutation-description helpers onto `crId`/`systemId`.
- Insight tool: `type === 'cr'` calls `analyzeChangeRequestInsight`; `type === 'system'` returns a plain CR/task summary reading `db.changeRequests`/`db.systems`. Dropped the `analyzeProjectInsight` / `analyzeMilestoneInsight` import specifiers.
- `pruneToolsForContext` needed no name-list edit — it filters through `isMutationTool`, which now reflects the CR tools.
- `aiOrchestratorLoop.ts` label is `query_change_requests` → `Tra cứu Change Request` (plus `query_systems`); the telegram prompt names `query_change_requests`.

**Task 2 — grounding, scope UI, mentions**
- `contextGrounding.ts`: `serializeChangeRequestContext` / `serializeSystemContext` replace the project/milestone serializers; a CR grounds on its target subsystems and tasks, a system on its parent and tasks, a task on its parent CR (`code`, `name`, `type`, `status`) and subsystem (`code`, `name`, `type`, `remoteRepoPath`). `ExtractedMentions` carries `crIds`/`systemIds`. Bounded-evidence and truncation behaviour untouched.
- `ScopePickerModal.tsx`: unions are `global | task | cr | system` and tab set is `Tất cả` / `Tác vụ` / `CR` / `Subsystem`; reads `db.changeRequests` / `db.systems`; scope keys are `cr:<id>` / `system:<id>`.
- `AIChatDrawer.tsx`: `isProjectScope` → `isCrScope`; `'project'`/`'milestone'` scope branches → `'cr'`/`'system'`; `entityType` ternary narrowed to `task | cr | system`.
- `ChatMessageBubble.tsx` mention regex now matches `(?:cr|system):<id>` and renders a CR pill (BranchesOutlined) or System pill (ApartmentOutlined).
- `ChatInputBar.tsx` emits `[code](cr:<id>)` and `[code](system:<id>)` options.
- `AITaskPlannerInstructionsModal.tsx` tag is `# CR`.
- `NoteSourcePickerModal.tsx` scope is `cr | all` filtered by `crId`; `StepInputDocsModal.tsx` takes a `changeRequest` prop and forwards `crId`/`crName`.

## Cross-Plan Gap Closed (plan 31.2-05 report)

`AIChatDrawer.tsx` called `loadRepoConventions(activeProjectId, db)`, which plan 05 deleted. Resolution: the drawer now tracks `activeTargetSystemIds` (the in-scope CR's target subsystems, or the parent CR's targets when the scope is a task) and calls `loadMultiRepoConventions(activeTargetSystemIds, db)`, feeding `buildConventionsSegment({ global, repos })`. The dead `loadRepoConventions` import is gone. This unblocks plan 31.2-24's exit-0 `tsc` gate for this file.
