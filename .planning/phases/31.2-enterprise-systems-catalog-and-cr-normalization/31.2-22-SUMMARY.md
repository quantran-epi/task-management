# Phase 31.2 Plan 22: Shell, notification type surface and shared components Summary

Shell, notification union and nine shared components moved off Project/Milestone, with `analyzeChangeRequestInsight`/`analyzeSystemInsight` replacing the Project/Milestone analyses and every remaining `'project'` literal that named a domain entity reworded.

## What Was Built

### Task 1 — Narrowed notification union and converted shell

`src/types/notifications.ts` now declares `NotificationEntityType = 'task' | 'cr' | 'system' | 'capacity'` (ENT-NORM-01). `NotificationItemRow` renders a CR folder icon and a System flag icon; `NotificationPanel` replaces the nested ternary with a `switch` over the narrowed union mapping CR/System rows to the insight tab and everything else to the task panel type.

`src/components/shell/AppShell.tsx` lost all Project/Milestone wiring: the `projectRepo`/`milestoneRepo` imports, the `Project`/`Milestone` type imports, the three modal renders and the three inspection state hooks. Notification clicks now resolve the CR or System in the DB and route to `insight`; quick-create (global shortcut and command palette) attaches to the most recent CR and warns when the DB has none.

### Task 2 — Shared components, insight analysis and copy debt

- `TaskAllocationCard`: `project`/`projectName` props replaced by `changeRequest`, subtitle renders the CR code.
- `TagListDisplay`: `isInherited` is `source === 'cr'`, origin label `CR` — matches the narrowed `TagSource`.
- `InlineAISelectionBar`: scope union is `'task' | 'cr' | 'system' | 'global'`, mapped from `targetType`/`parentTask`/`parentCr`/`system`.
- `itemInsight`: `analyzeChangeRequestInsight` (CR + its tasks + target systems) and `analyzeSystemInsight` (system + its tasks + CRs targeting it) replace `analyzeProjectInsight`/`analyzeMilestoneInsight`; the task analysis is untouched.
- `agentSkillService`: `source` member `'project'` renamed `'workspace'`; `AgentTerminalLog` branches and renders `Workspace`.
- Copy: Jira default-key label, ghost-dev prompt (`Repository root directory:`), JetBrains icon comment (`CR Explorer`), Telegram scope copy (`Tasks & CRs`).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `TaskAllocationCard` prop rename ripple**
- **Found during:** Task 2
- **Issue:** Plan said replace `project?: Project` with `changeRequest?: ChangeRequest`; the sibling `projectName?: string` prop would have been left naming a removed entity.
- **Fix:** Removed `projectName` too — the CR object carries `code` and `name`, so one prop covers the subtitle.
- **Files modified:** `src/components/planner/TaskAllocationCard.tsx`
- **Commit:** `c16a389e`

**2. [Rule 2 - Missing critical functionality] Quick-create had no CR to attach to**
- **Found during:** Task 1
- **Issue:** `Task.crId` is required after plan 01, so the two `createTask` calls in `AppShell` (global shortcut, command palette) failed to type-check and would have thrown at runtime.
- **Fix:** Both paths load `db.changeRequests`, attach to the most recent CR, and warn `Vui lòng tạo Change Request trước khi thêm tác vụ` when the table is empty.
- **Files modified:** `src/components/shell/AppShell.tsx`
- **Commit:** `faa41ff7`

**3. [Rule 2 - Missing critical functionality] Notification navigation could open a dead view**
- **Found during:** Task 1 (threat register T-31.2-56)

- **Fix:** `handleNotificationClick` resolves the row through `db.changeRequests.get` / `db.systems.get` before navigating.
- **Files modified:** `src/components/shell/AppShell.tsx`
- **Commit:** `15a39907`

**4. [Rule 3 - Blocking] `NotificationPanel` lost its Zustand selector type**

- **Fix:** Annotated the selector parameter as `LayoutActions`.
- **Files modified:** `src/workbench/toolwindows/NotificationPanel.tsx`
- **Commit:** `faa41ff7`

**5. [Rule 1 - Bug] `promptBuilder` test asserted the old prompt copy**
