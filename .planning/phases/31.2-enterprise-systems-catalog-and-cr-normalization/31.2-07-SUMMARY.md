# Phase 31.2 Plan 07: Utility and Hook Re-Axis Summary

Pure utility and hook layer now speaks CR/Subsystem: filters narrow on `crId`/`systemId`, every label resolves through `crMap`, and the milestone tier is gone from inheritance, reminders, standup and smart ingestion.

## What Changed

**Task 1 — filter, selection context, recurrence, inheritance**

- `src/utils/filter.ts`: `TaskFilterState.crId`/`systemId` replace `projectId`/`milestoneId`; `hierarchyScope` is `'all' | 'cr' | 'standalone'`; `FilterContext.crMap`/`systemMap` replace `projectMap`/`milestoneMap`. The `'standalone'` scope now means "no `systemId`", since every task has a CR. Ancestor resolution collapsed to the CR tier.
- `src/utils/selectionContext.ts`: `parentCr` and `system` replace `parentProject`; all reads go through `db.changeRequests`/`db.systems`; note `entityType` handles `'cr'` and `'system'`. CR/system grounding blocks are built locally — `contextGrounding`'s project serializer is deleted by plan 10, so importing it would have created a cross-wave dependency on a symbol that does not exist yet.
- `src/utils/recurrence.ts`: the spawned task carries `crId` (required, copied from the source) and `systemId` (when present).
- `src/domain/inheritance.ts`: `TagSource` is `'direct' | 'cr' | 'none'`; `EntityTagAncestors` has only `cr`.

**Task 2 — label surfaces**

- `src/utils/notifications.ts`: input takes `changeRequests` instead of `projects`/`milestones`; `crMap` maps id to CR code; the milestone reminder branch is deleted and the CR reminder branch is keyed `reminder:cr:<id>`.
- `src/utils/standup.ts`: `crMap`/`systemMap` context; task lines read `(CR: <name>[/<systemCode>] | ...)`.
- `src/utils/dayInsight.ts`: `crNameById` input, `DayInsightRow.crName` output.
- `src/utils/smartIngestion.ts`: `detectReferencedEntities(markdown, tasks, changeRequests, systems)`; matches CR and subsystem names and codes; `DetectedEntity.type` is `'task' | 'cr' | 'system'`.
- `src/hooks/useWeeklyPlanner.ts`: entries carry `cr`/`crName`; reads `targetDb.changeRequests`.
- `src/hooks/useTaskFilters.ts`: options take `changeRequests`/`systems`; context returns `crMap`/`systemMap`.
- `src/hooks/useDayInsight.ts`: reads `targetDb.changeRequests`, forwards `crNameById`.
- `src/hooks/useNotifications.ts`: reads `targetDb.changeRequests`, drops the `projects`/`milestones` params.
- `src/components/planner/DayColumn.tsx` / `DayInsightPanel.tsx`: two files in no plan's `files_modified` that consumed the renamed `projectName` field. Leaving them would have been a runtime blank label and a compile error at plan 24.
