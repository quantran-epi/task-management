# Phase 31.2 Plan 17: Per-subsystem pack cards and Pack All Summary

Rebuilt Step 4 as one pack card per target subsystem with a sequential, stoppable Pack All that survives a single subsystem failing, and moved Step 6 CAB completion onto the CR repository.

## What Was Built

### Task 1 — Subsystem-aware pack state (commit `1f409e6a`)

`src/services/wizard/sdlcCrManager.ts`

- `ChangePackHistoryItem` now requires `systemId: string`; `groupPacksBySystem(state)` buckets history per subsystem for the per-card result and the Pack All summary.
- `getMultiPackState` maps any row written before the subsystem dimension existed to `LEGACY_SYSTEM_ID` (`'__legacy__'`) instead of dropping it. The `sdlc_packs:` key format is byte-identical.
- Deleted `listCrs`, `getActiveCr`, `createNewCr` and `completeCr` — the CR list is `db.changeRequests` now. `getStepThread` and the pack helpers stay.

`src/services/wizard/workflowSchemas.ts`

- `artifacts.branchSnapshots: z.record(z.string(), BranchSnapshotSchema).default({})` keyed by `System.id`.
- The single `artifacts.branchSnapshot` stays as an optional deprecated field so an in-flight workflow still parses. The `BranchSnapshot` refinements (branch-or-targetBranch, headSha-or-headCommit) are untouched.

### Task 2 — Per-subsystem cards and Pack All (commit `e025af42`)

`src/components/sdlc/steps/Step4ChangePackView.tsx`

- The single `errorMsg`/`packagingStepStatus` pair is replaced by `packState: Record<string, PackCardState>` keyed by `systemId`, plus a `manualError` slot scoped to the manual zip upload only. No global error state can blank the step.
- One `Card size="small"` per target in a `repeat(auto-fit, minmax(420px, 1fr))` grid. Header: cyan mono code tag, name at 16/600, status tag (`Chưa đóng gói` / `Đang đóng gói` + `SyncOutlined spin` / `Thành công` / `Thất bại` / `Bỏ qua`). Body: base/head/file-count from `branchSnapshots[systemId]`, a primary `Đóng gói` button, and either an inline success `Alert` (filename, size, drift count) or an inline error `Alert`.
- `Đóng gói tất cả ({n})` iterates `cards` in order with a per-iteration `try/catch`; a throw records `status: 'error'` for that system and the loop continues. Stop is checked between iterations only, so no card is killed mid-write. While running the button becomes `Dừng đóng gói` (`danger`, `StopOutlined`) with `Đang dừng...` copy until the in-flight card settles, and a `Progress` shows `{settled}/{total}`.
- Summary `Alert`: `type="warning"` with `Đóng gói hoàn tất một phần: {ok}/{n} subsystem thành công. Lỗi: {CODE}.` naming every failed subsystem code, `type="success"` when all pass, `type="info"` when stopped (remaining cards become `Bỏ qua`).
- Manual dropzone kept as an explicit labelled fallback, now auto-opened only when there is no snapshot at all.
- `snapshotFor(systemId)` reads `branchSnapshots[systemId]` first, then falls back to the legacy single `branchSnapshot` only when it is unambiguous (single card, or matching `sshConfigId`).

`src/components/sdlc/pack/MultiPackTable.tsx`

- New leading `Subsystem` column resolving `systemId` to a cyan mono code tag, with `Chung` for `LEGACY_SYSTEM_ID`. The drift matrix stays one shared table.

### Task 3 — Step 6 CAB completion (commit `2efd4f73`)

`src/components/sdlc/steps/Step6CabView.tsx`

- `completeCr` import and call deleted; completion is `await updateChangeRequest(crId, { status: 'Done' }, db)` from `changeRequestRepo` (T-31.2-64).
- `projectId` prop renamed `changeRequestId`. The thread-key template literal `` `sdlc:${changeRequestId}:${crId}:CAB` `` keeps the same produced value (Pitfall 1).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Deleting the legacy CR-list functions broke `ChangeRequestSdlcView.tsx`**
- **Found during:** Task 1
- **Issue:** The view imported `listCrs`, `getActiveCr` and `createNewCr`. Deleting them in `sdlcCrManager.ts` left the view non-compiling, and no later plan in this wave owns that conversion.
- **Fix:** The view reads `allChangeRequests` (`db.changeRequests`) for its CR list, initialises the active CR from that list, and creates a missing CR through `createChangeRequest`. `crStatus` now maps `CrStatus` (`'Done'`/`'Cancelled'`) onto the `'active' | 'completed' | 'archived'` shape the grounding builder expects, and the header reads `code`/`name` instead of the removed `crCode`/`featureName`.
- **Files modified:** `src/views/ChangeRequestSdlcView.tsx`
- **Commit:** `1f409e6a`

**2. [Rule 3 - Blocking] `stepGroundingContext` did not type-check with the new `branchSnapshots` field**
- **Found during:** Task 2
- **Issue:** `artifacts: workflowState?.artifacts ?? {}` produced `{}`, which no longer satisfies the schema type now that `branchSnapshots` is required (it has a Zod default, so the inferred type marks it present).
- **Fix:** Fall back to `{ branchSnapshots: {} }`.
- **Files modified:** `src/views/ChangeRequestSdlcView.tsx`
- **Commit:** `e025af42`

**3. [Rule 3 - Blocking] `tests/unit/sdlc/sdlcCrManager.test.ts` tested only the deleted functions**
- **Found during:** Task 1
- **Issue:** Two of the four cases exercised `createNewCr`/`getActiveCr`/`listCrs`/`completeCr`, which this plan removes, so the plan's own `<verify>` command could not pass.
- **Fix:** Rewrote the suite onto the surviving surface: `getStepThread` isolation, `saveMultiPackState`/`getMultiPackState` round-tripping two packs with different `systemId`s under one CR, `groupPacksBySystem`, and the legacy-row fallback.
- **Files modified:** `tests/unit/sdlc/sdlcCrManager.test.ts`
- **Commit:** `1f409e6a`

**4. [Rule 3 - Blocking] `tests/unit/sdlc/Step6CabView.test.tsx` and `StepViews.test.tsx` passed the removed `projectId` prop**
- **Found during:** Task 3
- **Issue:** Renaming the prop made both suites a type error at every `Step6CabView` call site.
- **Fix:** Renamed the prop at the seven `Step6CabView` call sites in `Step6CabView.test.tsx` and the one in `StepViews.test.tsx`, and added a case asserting the CR row reaches `status: 'Done'` through the repo. The deeper CR-model rewrite of both suites stays with plan 31.2-19.
- **Files modified:** `tests/unit/sdlc/Step6CabView.test.tsx`, `tests/unit/sdlc/StepViews.test.tsx`
- **Commit:** `2efd4f73`
