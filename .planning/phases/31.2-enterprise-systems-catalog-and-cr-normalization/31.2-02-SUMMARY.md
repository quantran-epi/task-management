# Phase 31.2 Plan 02: Dexie Schema V16 Migration Summary

**Dexie v16 drops the projects/milestones stores, re-axes tasks onto crId/systemId, converts CR targetSystemIds to CrTarget[], backfills CR-LEGACY-<n> codes, and purges legacy chat scopes plus SSH/repo settings in one upgrade transaction**

## Decisions Made

- **Dexie store removal requires an explicit `null`.** `Version.prototype.stores()` merges `storesSource` cumulatively across every declared version, so `{ ...SCHEMA_V15, tasks: ... }` retains `projects` and `milestones`. The plan's "absent from the resulting object" instruction does not hold; `projects: null, milestones: null` is the mechanism that makes `deleteRemovedTables` fire.
- **Orphan tasks deleted, not nulled.** Matches D-27 and T-31.2-06: no row may violate the required-`crId` invariant.
- **Legacy code backfill is id-ordered.** `CR-LEGACY-1/2/3` map to `cr-a`, `cr-b`, `proj-1`, which is what the Wave 0 suite asserts.
- **Historical hooks untouched.** V2/V6/V15 keep `tx.table('projects')` / `tx.table('milestones')`; Dexie materialises removed stores for the duration of a hook, so those calls resolve against the pre-V16 schema of that step.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `SCHEMA_V16` must null out the dropped stores**
- **Found during:** Task 1 (V16 schema + upgrade hook)
- **Issue:** `SCHEMA_V16 = { ...SCHEMA_V15, tasks: ... }` leaves `projects` and `milestones` in the store spec. Dexie merges store specs cumulatively, so `db.tables` still contained both and `deleteRemovedTables` never fired — the "drops the projects and milestones object stores" test failed with `expected [ 'projects', 'milestones', … ] to not include 'projects'`.
- **Fix:** Added `projects: null, milestones: null` to `SCHEMA_V16` (Dexie's documented removal marker, typed `string | null` in `dexie.d.ts`).
- **Files modified:** `src/db/schema.ts`
- **Verification:** `npx vitest run tests/db/schemaV16Migration.test.ts` → 7/7 pass
- **Committed in:** `f91508ea` (Task 1 commit)

- **Fix:** Removed `projects`/`milestones` from the expected table list; moved the two fixture tests onto `changeRequests` with `type: 'ENHANCEMENT'` and `targetSystemIds: []`; swapped the `Project` type import for `ChangeRequest`.
