# Phase 31.2 Plan 09: Backup Envelope v11 and Legacy Rejection Summary

**Backup envelope bumped to version 11 with project/milestone tables removed and an envelope-stage guard that rejects pre-31.2 payloads with the UI-SPEC message before any local write**

## Accomplishments
- `CURRENT_SCHEMA_VERSION` is 11; `exportBackupPayload` reads and exports `systems`/`changeRequests` and no longer touches `projects`/`milestones`
- `assertNoLegacyTables` rejects any payload carrying a `projects` or `milestones` table before per-table validation, with the exact UI-SPEC copy
- `restoreBackup` never reads, clears or writes project/milestone tables; a rejected payload performs zero writes (asserted by a pre-seeded CR surviving the attempt)
- Backup task records require `crId`; note `entityType`, chat `scopeType` and knowledge-link entity types narrowed to `task`/`cr`/`system`
- The two deferred failures from plan 03 (`tests/db/systemRepo.test.ts`, `tests/db/changeRequestRepo.test.ts`) are green

## Decisions Made
- Envelope-stage rejection (D-49) rather than row mapping: a legacy payload cannot be partially interpreted.
- Version < 11 rejected outright; the old schemaVersion-1 normalization path now only backfills task fields (unreachable for real payloads, kept for the schema contract).
- `restoreBackupPayload` now includes the validator's first error message in its thrown error so the legacy copy reaches the UI instead of a generic string.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] BackupChangeRequestRecordSchema still used the pre-plan-01 shape**
- **Found during:** Task 1 verification (`tests/db/changeRequestRepo.test.ts` still failing)
- **Issue:** The schema required nothing for `code` and expected `targetSystemIds: string[]`, but plan 01 made `code` required and replaced `targetSystemIds` with `targets: CrTarget[]`. Exported CRs therefore failed validation on restore.
- **Fix:** `code` required (min 1, max 64); `targets: z.array(z.object({ systemId: uuidSchema, featureBranch: z.string().optional() }))`
- **Files modified:** `src/validation/backupSchemas.ts`
- **Verification:** `tests/db/changeRequestRepo.test.ts` and `tests/db/systemRepo.test.ts` pass
- **Committed in:** `fb8cdf03`

**2. [Rule 1 - Bug] Chat tab and SDLC document-set validation still keyed on project scope**
- **Found during:** Task 2 (validateBackup rewrite)
- **Issue:** `expectedScope` and the duplicate-SDLC-tab check compared against `thread.scopeType === 'project'` and `project:<id>` keys, which the V16 migration purges; SDLC document sets read `set.sdlc.projectId`, which no longer exists on the schema (`changeRequestId`).
- **Fix:** Both checks re-axed onto `cr` scope and `sdlc.changeRequestId`; `restoreBackup`'s workflow-state mirror keys off `cr:` scope.
- **Files modified:** `src/services/backup/validateBackup.ts`, `src/services/backup/restoreBackup.ts`
- **Verification:** `tests/services/backup/restoreBackup.test.ts` SDLC mirror test passes
- **Committed in:** `7c724067`

**3. [Rule 2 - Missing Critical] Restore error hid the D-49 message**
- **Found during:** Task 2 (zero-write test)
- **Issue:** `restoreBackupPayload` threw a generic `Backup payload must pass validation before restore`, so the UI-SPEC legacy copy never reached the caller.
- **Fix:** Append the validator's first error message to the thrown error.
- **Files modified:** `src/services/backup/restoreBackup.ts`
- **Verification:** zero-write test asserts the thrown message contains `Backup phiên bản cũ không còn được hỗ trợ`
- **Committed in:** `7c724067`
