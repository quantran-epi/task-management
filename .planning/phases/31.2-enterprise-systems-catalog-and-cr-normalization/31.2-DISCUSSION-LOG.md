**Date:** 2026-11-07

## Mental model (user's own words, condensed)

TaskMate xoay quanh CR. CR có 3 type: New Feature, Enhancement, Bugfix. Dưới CR là Task. CR gắn với các subsystem nó tác động; Task cũng gắn với subsystem nó tác động.
System có 2 loại: Logical Parent (chỉ phân nhóm deployment unit) và Subsystem (deployment unit thật, mỗi subsystem gắn duy nhất 1 repo remote SSH).
SDLC Studio = vòng đời của 1 CR. 1 CR = 1 SDLC lifecycle. Trong SDLC, user pick CR; mọi cấu hình repo/SSH đi theo subsystem mà CR ảnh hưởng; cần view riêng để user dễ quan sát.
Trong SDLC flow, khi phân tích solution, hệ thống có thể đề xuất gắn subsystem ảnh hưởng vào CR nếu user chưa gán hoặc chưa biết CR ảnh hưởng subsystem nào.

Yêu cầu thiết kế: toàn diện, giao diện focus, đơn giản nhưng đủ thông tin, dễ theo dõi, không gây confuse.

## Decisions

1. **Zero-Legacy**: xoá `projects`, `milestones` khỏi Dexie/types/code/tests. Task → `crId` (bắt buộc) + `systemId?`. Reset data test được phép.
2. **Bất biến dữ liệu** enforce ở repo + Zod: parent không repo/SSH/CR; subsystem đúng 1 repo; `task.systemId ∈ cr.targetSystemIds`.
3. **SystemDetailView**: 4 tab (Overview / Subsystems / Impacted CRs / Git & Branches). Tab Git & Branches chỉ có ở subsystem.
4. **Tạo CR từ Subsystem**: chỉ subsystem có nút; mở modal với `targetSystemIds = [subsystem.id]` điền sẵn.
5. **1-click Git/Terminal**: set `activeRemoteTarget` rồi mở bottom tool window; thiếu cấu hình thì disable + tooltip dẫn về Catalog.
6. **CR Explorer** (Alt+1) viết lại thật: CR → Subsystem → Task; bỏ tầng Milestone.
7. **Click CR** mở tab `ChangeRequestDetailView`, không popup/swap inline. Task table phẳng có cột Subsystem.
8. **SDLC Studio**: bỏ hẳn `RepoConfigView` khỏi luồng; thay bằng panel read-only "Subsystems & Repos".
9. **Subsystem Context Bar** dùng chung Step 3/4, state ở cấp SDLC view; ẩn khi CR chỉ có 1 subsystem.
10. **Step 2**: solution phân mục `### [SYSTEM_CODE]` cho từng subsystem; conventions nạp theo repo kèm header.
11. **Step 4**: mỗi subsystem một card + Pack riêng; `Pack All` chạy tuần tự, báo lỗi từng phần; drift matrix một bảng chung có cột Subsystem.
12. **AI đề xuất subsystem**: artifact có cấu trúc (systemId, confidence, reason), chỉ chọn từ Catalog, không tự gắn — user tick + xác nhận mới ghi. Đề xuất bổ sung được khi CR đã có subsystem nhưng thiếu.
