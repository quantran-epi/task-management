# Phase 31.2 Plan 20: Wave 0 Data-Layer Suites Summary

Six data-layer suites exist at wave 1, each encoding the exact behaviours its owning implementation plan enumerates. All six are discoverable via `npx vitest list`, so plans 02/03/04 gates resolve to real files instead of `No test files found`.

## What Was Built

**Task 1 — `tests/db/schemaV16Migration.test.ts` (7 tests, 339 lines)**

Seeds a real V15 database (`new Dexie(name).version(15).stores(SCHEMA_V15)`) with one project, one milestone, four CRs (one sharing the project id, two without `code`, one with `CR-KEEP`), three tasks (project-linked, project+milestone-linked, standalone), three chat threads (`project:`, `milestone:`, `task:` scopes) with messages and tabs, and three settings rows. Then reopens through `TaskPlannerDatabase` at the current version and asserts:

- project-linked tasks carry `crId === oldProjectId`; the standalone task is gone
- no task retains `projectId`/`milestoneId`
- `targetSystemIds: ['a','b']` became `targets: [{systemId:'a'},{systemId:'b'}]`, with no `targetSystemIds`
- missing codes become `CR-LEGACY-<n>` deterministically by ascending id (`cr-a` → 1, `cr-b` → 2); an existing code is untouched
- `db.tables` has no `projects`/`milestones`
- `project:`/`milestone:` threads, tabs and messages are gone; the `task:` thread survives
- `project_ssh_repo:x` / `project_repo_ssh_binding:x` settings are gone; an unrelated setting survives

**Task 2 — five repo suites (35 tests total across the five paths)**

- `tests/db/systemRepo.test.ts` (extended, 11 tests): adds `isLogicalParent`/`isSubsystem` predicate coverage, `getParentSystems` returning LOGICAL_GROUP only, parent-must-be-LOGICAL_GROUP, LOGICAL_GROUP-cannot-carry-SSH/Repo, cycle rejection, type-change clearing of `parentId`/`sshConfigId`/`remoteRepoPath`/`defaultBaseBranch`, and `deleteSystem` cascading into CR `targets` and task `systemId`. The pre-existing children guard assertion was retargeted at the UI-SPEC message `Hệ thống còn 1 subsystem con`.
- `tests/db/changeRequestRepo.test.ts` (extended, 11 tests): rewrites the legacy `targetSystemIds` fixtures to `targets`, and adds LOGICAL_GROUP-as-target rejection, missing-target rejection, `feature/CR-7` defaulting, explicit `featureBranch` retention, no rewrite on code-only change, and `removeSubsystemFromChangeRequest` clearing task `systemId` while keeping the task.
- `tests/db/taskRepo.test.ts` (new, 6 tests): `crId` required, out-of-CR `systemId` rejection with `Subsystem của tác vụ phải thuộc CR đã chọn.`, in-CR acceptance, `updateTask` rejection, `getTasksByCr`/`getTasksBySystem` scoping, and `deleteChangeRequestWithCascade` deleting the CR + tasks + note links + `cr:` chat thread while leaving a second CR intact.
- `tests/db/tagRepo.test.ts` (new, 3 tests, 74 lines): unions ops owners / BAs over `changeRequests` + `tasks` only, and drops a tag once its only CR is deleted. No `db.projects` reference.
- `tests/db/documentLinkRepo.test.ts` (new, 4 tests): links a CR to a doc through a `changeRequests` transaction, accumulates CR `documentLinks`, unlinks from `changeRequests.documentLinks`, and reads backlinks without a dropped store.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Pre-existing `getParentSystems` assertion encoded the legacy classification**
- **Found during:** Task 2
- **Issue:** `tests/db/systemRepo.test.ts` asserted an unparented `SERVICE` appears in `getParentSystems` — the exact `parentId === null || type === 'LOGICAL_GROUP'` rule plan 03 deletes. Left as-is, plan 03's green gate would have been unsatisfiable.
- **Fix:** Assertion inverted to the D-24 semantics (the unparented SERVICE is a subsystem, not a parent).
- **Files modified:** `tests/db/systemRepo.test.ts`
- **Commit:** aa3820b5

**2. [Rule 1 - Bug] Pre-existing children-guard assertion targeted the English message**
- **Found during:** Task 2
- **Issue:** `/child subsystems/i` matched the current English string, which plan 03 replaces with the UI-SPEC Vietnamese message.
- **Fix:** Retargeted at `/Hệ thống còn 1 subsystem con/`.
- **Files modified:** `tests/db/systemRepo.test.ts`
- **Commit:** aa3820b5

**3. [Rule 3 - Blocking] `BacklinksResult` shape is owned by plan 11, not plan 04**
- **Found during:** Task 2
- **Issue:** The plan's behaviour text implied asserting CR backlinks, but `BacklinksResult` exposes `projects` today and its CR rename lands with the notes components in plan 11. Asserting a `changeRequests` field would have made plan 04's gate unsatisfiable.
- **Fix:** The suite asserts backlinks resolve without touching a dropped store (`tasks`/`referencingNotes` defined) and leaves the shape rename to plan 11.
- **Files modified:** `tests/db/documentLinkRepo.test.ts`
- **Commit:** aa3820b5

**4. [Rule 1 - Bug] WebKit-cursor fallback test could not isolate the CR store**
- **Found during:** Task 2
- **Issue:** Spying `orderBy` on `db.changeRequests` to simulate WebKit #319640 was fragile and asserted an implementation detail rather than behaviour.
- **Fix:** Replaced with a behavioural test: a tag disappears from aggregation once its only CR is deleted.
- **Files modified:** `tests/db/tagRepo.test.ts`
- **Commit:** aa3820b5
