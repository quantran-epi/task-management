## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model output → `cr.targets` | The model proposes subsystem ids; only a user click may write them |
| settings → dismissal state | A stale dismissal key must not permanently hide legitimate proposals for a different CR |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31.2-47 | Spoofing / Tampering | `propose_subsystems` result | mitigate | Every `systemId` is validated against `db.systems` and `isSubsystem` in the tool, and `updateChangeRequest` re-validates on confirm, so a hallucinated or parent id can never enter `cr.targets` |
| T-31.2-48 | Elevation of privilege | proposal write path | mitigate | The tool returns data only and is absent from `MUTATION_TOOLS`; the only write is the card's confirm handler, asserted by a test that mounting the card performs no write |
| T-31.2-49 | Tampering | `chatTurnTools` exclusion | mitigate | `propose_subsystems` is added to the hardcoded exclusion array so it cannot be offered in ordinary chat where there is no CR context |
| T-31.2-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase |
</threat_model>
