<objective>
Preserve resolved seed entities end-to-end and surface them as a distinct `SEED_ONLY` outcome with separate entity, edge, and path counts, plus explicit failed-seed reporting and content-free stage diagnostics.

Purpose: Today a resolved seed disappears whenever no path completes (`neo4jRepository.ts` drops zero-edge paths), the response collapses counts into one `itemCount`, the outcome selector reports `NO_EVIDENCE`, which the client treats as failure and routes to BM25 fallback (D-01, D-02, D-03, Pitfalls 3 and 4). The planner now produces `failedSeeds` (plan 01), but no response field carries them, so D-13 is unproven without a server producer.

Output: Seed-preserving repository traversal, `seedEntities` and count breakdown in the bounded result, `SEED_ONLY` outcome selection with `SEED_FOUND_NO_RELATION`, `diagnostics.failedSeeds` and `diagnostics.stageDiagnostics` with truncation/fallback flags, a committed `MAIN1.EVT_EVENT` fixture with a `WRITES_TO` writer and supporting chunk, and regression coverage.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Neo4j → bounded traversal | Untrusted row shape and snapshot identity cross here |
| traversal → outcome selector | Counts and status decide the user-visible outcome |
| planner → diagnostics | `failedSeeds` URNs and stable codes cross into the response |
| server → client | Response schema is the trust boundary for `SEED_ONLY` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-05 | Tampering | `neo4jRepository.traverse` | mitigate | Seed entities come from the snapshot-scoped `resolveEntities` query; every retained edge/path asserts `graphSnapshotId` equality with the pinned snapshot; no ad-hoc relation expansion remains. |
| T-24-06 | Tampering | `retrievalService` outcome selection | mitigate | `SEED_ONLY` requires graph status `ok`/`truncated` plus positive entity count and zero edge/path counts; error, timeout, and stale statuses can never produce it. |
| T-24-07 | Information disclosure | Response diagnostics | mitigate | Counts are numeric, codes are enums, flags are booleans, and `failedSeeds` carries URN plus code only; `StageDiagnosticSchema` is strict with no message/query keys, so free text cannot be added by construction. |
| T-24-08 | Tampering | `failedSeeds` content | mitigate | Entries derive only from server-allowlist comparison against resolved candidates; URNs pass `UrnSchema`, duplicates are collapsed, and the list is capped at 5. |
| T-24-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages; any proposed dependency stops the task and is escalated. |
</threat_model>
