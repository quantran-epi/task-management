<objective>
Replace hardcoded one-relation-per-kind planning and silent hop clamping with registry-derived per-seed plans and reject-not-clamp validation using stable reason codes.

Purpose: Remove the root causes behind the `MAIN1.EVT_EVENT` regression: `defaultTraversalStepsForKind()` never queries `WRITES_TO`, `buildDeterministicFallbackPlan()` applies the first seed's kind to all seeds, `normalizePlanSemantics()` rewrites impact plans, and `validateTraversalPlan()` silently clamps depth (D-05 through D-15). The Zod depth caps must stop at a model-input ceiling above 3 so over-depth requests reach `HOP_LIMIT_EXCEEDED` instead of dying as `PLANNER_SCHEMA_FAILURE`, and seed validation must be per-seed so one bad seed cannot erase valid evidence (D-13). Prompting improves planner accuracy but never replaces server validation (D-10).

Output: New pure derivation module; relaxed-but-bounded depth schema; rewritten fast path, fallback, per-seed failure reporting, and repair; ontology-complete planner prompt; rejecting traversal validator; stable-code test coverage.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model planner → server validation | Untrusted model JSON (relation, direction, endpoints, depth) crosses here |
| validated plan → Neo4j templates | Only registry-valid tuples may select a frozen template |
| server → client diagnostics | Stable codes, URNs, and counts cross; free text must not |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Tampering | `validatePlanSemantics`, `validateTraversalPlan` | mitigate | Validate every step against `RETRIEVAL_ONTOLOGY_REGISTRY` for relation, direction, seed endpoint, target endpoint, and hop ceiling before any gateway call; return enum codes and `failedSeeds` pairs (URN + code) only. |
| T-24-02 | Tampering | Planner prompt and repair request | mitigate | Prompt lists the closed ontology and bounds; repair context carries only stable codes; no Cypher, secrets, source content, or exception text is interpolated. |
| T-24-03 | Elevation of privilege | Traversal breadth | mitigate | Schema input cap 10 bounds parser work; semantic cap 3, ≤5 steps, ≤5 seeds, per-relation `maxHops`; reject-not-clamp prevents silent execution of over-broad plans. |
| T-24-04 | Denial of service | Loose candidate schema | mitigate | All string fields bounded (`relationType` max 64, steps max 5, seeds max 5); loops are linear over bounded arrays. |
| T-24-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages; any proposed dependency stops the task and is escalated — Phase 24 installs nothing. |
