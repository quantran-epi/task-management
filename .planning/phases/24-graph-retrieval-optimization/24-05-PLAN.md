<objective>
Carry seed-only entities, counts, failed seeds, and content-free diagnostics through evidence packing, grounded-turn routing, and non-web consumers without triggering local fallback.

Purpose: Protocol parity alone does not change client behavior. `groundedTurn` currently treats graph-empty responses as nonproductive, packs chunks rather than entities, and can route a valid found seed into BM25/no-evidence paths. Telegram also returns no-evidence copy whenever grounding has no answer, which is false for a seed-only response (D-01, D-02, D-03, D-13, D-19, Open Question 6).

Output: Entity-aware evidence pack, explicit `SEED_ONLY` branch before fallback, persisted Phase 24 metadata, safe Telegram seed-only formatting, and targeted regression tests. MCP retrieval needs no adapter because its result contract has no `RetrievalOutcome`; the test records this boundary rather than adding unused code.
</objective>
