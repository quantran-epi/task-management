<objective>
Keep valid graph evidence whole through RRF fusion and federated aggregation, and make graph ordering deterministic.

Purpose: Even after planning and seed preservation are fixed, valid graph packages still lose members because RRF ranks individual items, `slice(0, limit)` cuts closure, and federated aggregation sums only `itemCount` (D-16, D-17, D-18, Pitfalls 5, 6, 7). Federation must also surface the D-19 stage metadata and the D-13 failed seeds it receives from per-set responses, otherwise the client cannot show truncation, fallback, or dropped seeds for multi-set queries.

Output: Atomic protected-package admission with a bounded quota, deterministic graph path ranking, deduplicated retained-evidence counts with severe-status precedence, federated `stageDiagnostics` with `truncated`/`fallback` flags and aggregated `failedSeeds`, and test coverage. The client mirror of the federated diagnostics is plan 04's responsibility; this plan defines the authoritative server shape.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| graph modality → fusion | Candidate items and packages from server-side traversal |
| per-set responses → federated aggregation | Multiple snapshots and statuses combine |
| fusion → client | Final item ordering, counts, and stage rows are user-visible |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-07 | Tampering | `fuseRetrievalCandidates` package admission | mitigate | Admit only packages whose every member is snapshot-consistent with the pinned snapshot, ontology-valid, within caps, and citation-closed; drop otherwise. |
| T-24-08 | Tampering | Cross-set aggregation | mitigate | One `setId` maps to one snapshot; duplicate graph identities collapse deterministically across sets before retained counts are derived; severity precedence prevents masking failures. |
| T-24-09 | Denial of service | Package admission | mitigate | Quota `<= 0.6 * limit` and `maxItems <= 200` bound package growth; packages are never split to exceed limits; diagnostics arrays capped at 20 and 5. |
| T-24-10 | Information disclosure | Federated diagnostics | mitigate | Only enum codes, counts, timings, and booleans are aggregated; per-set messages are not concatenated into diagnostics, and `StageDiagnosticSchema`/`FailedSeedSchema` are strict with no message field. |
| T-24-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages; any proposed dependency stops the task and is escalated. |
</threat_model>
