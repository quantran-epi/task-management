<objective>
Bring the client protocol mirror back into lockstep with the server and add backward-compatible persisted grounding fields for seed-only evidence.

Purpose: The client schemas are strict. Without the mirrored `SEED_ONLY` outcome, reason codes, counts, and stage diagnostics, a valid Phase 24 server response is rejected at the boundary and `groundedTurn` silently falls back to BM25 (Pitfall 8). The federated diagnostics mirror is especially load-bearing: plan 03 adds `stageDiagnostics` and `failedSeeds` to the server federated response, so a client that lacks those keys rejects the entire federation result.

Output: Mirrored protocol constants and schemas including `FederatedRetrievalResponseSchema.diagnostics`, optional persisted grounding fields with `schemaVersion: 1`, and parity plus persistence tests.
</objective>

|-----------|----------|-----------|-------------|-----------------|

| T-24-14 | Repudiation | Persisted grounding | mitigate | New fields optional, `schemaVersion` stays 1, provenance superRefine unchanged, so historical records remain readable and auditable. |
| T-24-25 | Information disclosure | Persisted diagnostics | mitigate | Persisted stage rows reuse the strict protocol schema, which has no message or query field; only codes, counts, timings, and booleans can be stored. |
