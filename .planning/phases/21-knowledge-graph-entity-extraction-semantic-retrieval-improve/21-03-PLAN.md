    - Test: resolveQueryEntities resolves candidates for natural language queries when entities have matching Vietnamese step names or aliases.
  </behavior>
  <action>
    In knowledge-server/src/retrieval/queryPlanning.ts:
    1. In extractQueryTokens(query):
       - Clean punctuation while preserving technical characters (alphanumeric, dots, underscores).
       - Extract single words with length >= 2.
       - Generate unaccented counterparts for all words using `.normalize('NFD').replace(/[̀-ͯ]/g, '').toLowerCase()`.
       - Generate bigrams (consecutive word pairs, both accented and unaccented) when words are adjacent in natural language queries (e.g. 'thanh toan', 'doi soat', 'khoi tao').
       - Filter out pure conversational stopwords (e.g. 'cho', 'toi', 'biet', 'la', 'nhung', 'cua') from single-token seeds, but allow domain action words (e.g. 'thanh toan', 'ghi', 'doc', 'chay') to be included in candidate tokens.
    2. In resolveQueryEntities:
       - Ensure that candidate entities matching via canonicalName or aliases are considered valid candidates.
       - If multiple candidates are found across distinct nodes, maintain unambiguous selection if one candidate has significantly higher relevance (exact canonicalName match) or return candidates for plan evaluation.
  </action>

    <automated>npm --prefix knowledge-server test -- tests/retrievalPlanning.test.ts</automated>
  </verify>
  <done>
