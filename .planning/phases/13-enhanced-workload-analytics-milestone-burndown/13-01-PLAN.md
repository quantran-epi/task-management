    - Test 3: calculates actual remaining work (hours or task counts per D-01) for each day up to todayDateString, leaving future days as null per D-03

    1. Define interfaces in `src/types/analytics.ts`: `BurndownUnit` ('hours' | 'count'), `BurndownDayPoint`, `MilestoneBurndownSeries`, `VelocityWindowWeeks`, `WeeklyVelocityBucket`, `ProjectStatusMetrics`, `WorkloadDimension`, `WorkloadDistributionItem`.
    2. In `src/utils/analytics.ts`, implement `calculateMilestoneBurndown(milestone: Milestone, tasks: Task[], options: { unit: BurndownUnit; todayStr: string }): MilestoneBurndownSeries`:
       - Determine `startDate`: earliest of `milestone.createdAt` substring (0, 10) or earliest `task.actualStartDate`.
       - Determine `endDate`: `milestone.deadline` if valid; fallback to latest task deadline; fallback to `startDate + 14 days` per D-02. Guard against `endDate <= startDate` by clamping to `startDate + 1 day`.
       - Compute `totalScope`: sum of task `estimateMinutes` (converted to hours `estimateMinutes / 60`) if unit is 'hours', or count of tasks if unit is 'count'.
       - For each calendar day from `startDate` to `endDate`:
         - `idealRemaining`: linear interpolation `totalScope * (1 - dayIndex / totalDays)`.
         - `actualRemaining`: if date > `todayStr`, set to `null` per D-03. Otherwise calculate remaining scope of tasks that were not yet completed (`status !== 'Done' && status !== 'Resolved'`) on that day, evaluating task completion date (`actualEndDate` or fallback `updatedAt` date per D-08).
    3. Write comprehensive unit tests in `tests/utils/analytics.test.ts`.
  </action>
