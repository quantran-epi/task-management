<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| employee row → prompt | `employee.role` and `skill.description` are model- or user-authored text that decides whether a policy line appears |
| prompt → model | the line tells the model which tool to call and in what order |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-07 | Spoofing | reviewer detection via `employee.role` / `skill.description` | accept | Detection only chooses whether a *permission-neutral* line is printed. `git_read` is advertised to every employee regardless (D-09), and the handler enforces the repo scope. A spoofed role gains an ordering hint, not a capability. |
| T-42-08 | Information disclosure | prompt line leaking a refusal code or repo path | mitigate | The line names the tool and the read order only. No refusal code, no repo path, no system id — asserted by acceptance criteria (`SYSTEM_NOT_LINKED` / `NO_LINKED_REPO` / `INVALID_ARGUMENT` absent). |
| T-42-09 | Tampering | prompt injection through `skill.description` | mitigate | The line is a fixed constant, not interpolated from `skill.description`. The description itself already enters the prompt inside `wrapUntrusted` (:115) and that is unchanged. |
| T-42-SC | Tampering | npm/pip/cargo installs | mitigate | No package is added. The phase forbids new dependencies. |
</threat_model>
