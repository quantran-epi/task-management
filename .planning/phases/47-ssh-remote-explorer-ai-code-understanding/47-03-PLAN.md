<objective>
Thread an explicit remote target from the active remote chat scope into the existing read-only tools and prompt grounding, so a cross-file remote question reads exactly the SSH config/repo/branch the user is looking at — never a global or model-chosen host.

Purpose: D-13/D-14 are the security-critical core of the phase. Today SSH FS tools resolve a single global config and `git_read` resolves a repo through team links/turn hints; neither is driven by the ordinary chat drawer's scope. The drawer never calls `executeAiTool` directly — its turns go through `chatTurnRuntime` -> `dispatchAiToolCall` — so the target must be threaded through `ChatTurnRequest` and `DispatchAiToolCallOptions` too, and `git_read` must be advertised on the remote turn, or the code compiles while the user's actual chat path reads the wrong host or has no git tool at all. Without this plan, a remote turn either reads the wrong host (info disclosure) or loses its tools entirely when global config is absent (Pitfall 6). D-07's cross-file grounding and D-05/D-08's reuse of drawer tabs and scope precedence are wired here, using the `remote:<uuid>` contract from plan 01.

Output: a shared `RemoteToolTarget` type, a `remoteTarget` field threaded through `ChatTurnRequest` -> `DispatchAiToolCallOptions` (both dispatch sites) -> `ExecuteAiToolOptions`, preferred by `resolveSshConfig` and `git_read`, remote-turn `git_read` advertisement, a remote prompt-grounding segment, remote-aware tool gating in `AIChatDrawer`, and focused tests proving target precedence, read-only confinement and scope-tab reuse.

**Artifacts this phase produces (from plan 03):** `RemoteToolTarget`, `remoteTarget` on `ChatTurnRequest`/`DispatchAiToolCallOptions`/`ExecuteAiToolOptions`, `resolveSshConfig(target)` preference, `git_read` explicit-target resolution + remote-turn dispatch/advertisement, remote prompt-grounding segment, remote SSH-ready gate, `registerActiveItem`-based remote scope activation.

<user_decisions>
- **D-05:** Reuse AIChatDrawer scope system; no new chat panel.
- **D-07:** Remote context is folder/repo-scoped and can trace logic across multiple files; not limited to the open file.
- **D-08:** Opening a remote file or selecting text auto-activates that target's remote scope; user can still switch via the picker.
- **D-13:** Reuse git_read + SSH FS tools with an explicit remote target from chat context.
- **D-14:** Read-only, confined, escaped, bounded; one-way safety boundary — no writes.
- **D-15:** No headless explore_repo (deferred).
</user_decisions>
