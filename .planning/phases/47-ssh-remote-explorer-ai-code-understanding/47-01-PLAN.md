<objective>
Make the remote chat scope a first-class, backup-safe `ChatScopeType` and define the structured remote selection anchor that all later plans build on.

Purpose: `remote:<uuid>` is the contract every downstream piece depends on — scope picker, drawer tabs, prompt grounding, explicit tool target, and citations. Adding `remote` to the union without widening all eight whitelists would let the app compile while making its own export unrestorable (the V20 bug class) or silently showing global history (Pitfall 2). The structured anchor (D-11) likewise must exist before the viewer/inline bar can emit cross-file-capable mentions.

Output: `ChatScopeType` widened across all eight whitelists, a target-UUID scope key that round-trips through backup, a remote scope entry in the scope picker, a `RemoteSelectionAnchor.ts` module (target/path/line/text), and a new focused `tests/ai/remoteScope.test.ts` plus extensions to the existing scope-key and backup-schema tests.

**Assumption delta: add-alongside.** Remote is added as a first-class scope kind alongside the existing task/CR/system/document/team scopes; those scopes remain primary for their own domains and none is replaced or narrowed (D-05/D-06/D-07).

**Artifacts this phase produces (from plan 01):** `ChatScopeType = '...' | 'remote'`, `remote:<v4-uuid>` scope key grammar, `RemoteSelectionAnchor` / `extractRemoteSelectionAnchor`, remote `ScopeListItem` entry, remote mention formatter with `path:line`.
