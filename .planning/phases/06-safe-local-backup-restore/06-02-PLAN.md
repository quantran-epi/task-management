<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| File Upload (Untrusted JSON) → Application Memory | User-provided JSON file parsed and validated before touching database |
| Application Memory → IndexedDB Write | Validated records written to Dexie tables in single atomic transaction |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02 | Tampering / Denial of Service | `BackupImportCard` & `validateBackupPayload` | mitigate | Reject files > 50MB before parsing. Reject JSON syntax errors gracefully. Validate envelope app marker and schema version. Validate all records with strict Zod schemas. Check relational integrity to reject orphan foreign keys. Abort completely without touching IndexedDB on any single error. |
| T-06-03 | Tampering / Repudiation | `ImportPreviewModal` & `restoreBackupPayload` | mitigate | Enforce keyword gate requiring user to type exact string "RESTORE" before unlocking danger action. Automatically save current 6 domain tables to `settings.last_pre_import_snapshot` inside the transaction before clearing tables. |
| T-06-04 | Tampering / Denial of Service | `restoreBackupPayload` | mitigate | Wrap table snapshot, table clears, bulk additions, and metadata logging inside a single Dexie `rw` transaction across all domain tables + settings. Any failure causes full database transaction rollback. |
| T-06-SC | Tampering | npm packages | mitigate | Zero new dependencies added; uses native Web APIs (`FileReader`, `Blob`) and existing approved packages (`antd`, `dexie`, `zod`, `dayjs`). |
</threat_model>
