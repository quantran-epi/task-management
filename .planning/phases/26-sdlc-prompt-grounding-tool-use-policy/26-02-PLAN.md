<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Tool policy text → model | Policy must not promise tools absent from payload |
| Dynamic MCP catalog → payload | Server-discovered names are untrusted capability data |
| Tool payload → model | Model may attempt any advertised tool; payload is access-control surface |
| Step contract / grounding → policy layer | Untrusted content must never precede shared policy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-26-02 | Elevation of Privilege | static/dynamic allowlist and `getToolsForTurn` | mitigate | One explicit per-turn set feeds policy/payload; dynamic MCP tools require host-supplied read-only names and Analysis Mode filtering; utility and host-path tests prove equality. |
| T-26-02b | Tampering | Composer layer order | mitigate | `toolPolicy` only between step contract/few-shot; existing order assertions remain plus dynamic assertions. |
| T-26-02c | Tampering | Few-shot exemplars | mitigate | Fixed constants contain no document instructions or approval claims; tests enforce forbidden patterns. |
| T-26-02d | Information Disclosure | Policy text | mitigate | Render normalized tool names/call conditions only; no endpoint, token, path, or secret. |
| T-26-02e | Elevation of Privilege | `useStepChatToolbox` | mitigate | Dynamic names come from exact payload catalog, not prompt text; unsupported names absent from policy and payload. |
| T-26-SC | Tampering | Package installs | mitigate | No new dependency; package audit empty. |
</threat_model>
