  <name>Task 1: Create the pure per-step grounding builder</name>
  <files>src/services/sdlc/groundingBuilder.ts, tests/services/sdlc/groundingBuilder.test.ts</files>
  <action>
Create `src/services/sdlc/groundingBuilder.ts` as a new pure synchronous module: no DB, network, React, or package. Follow serialization/clamp patterns from `src/services/ai/contextGrounding.ts` and budget constants from `src/services/wizard/sdlcWizardRuntime.ts`; use `tests/ai/contextGrounding.test.ts` as test-shape analog.

Export:
- `SdlcGroundingMarker = 'CR_METADATA' | 'PL01' | 'PL02' | 'SOLUTION' | 'CHANGE_PACK' | 'ACCEPTANCE_CONTEXT' | 'IMPLEMENTATION_EVIDENCE' | 'TECH_DOCS' | 'PL03B' | 'PL07'`.
- `SDLC_STEP_GROUNDING_SOURCES: Record<SdlcStepId, readonly SdlcGroundingMarker[]>` implementing D-01 explicitly: INTAKE → `CR_METADATA/PL01/PL02`; SOLUTION → `CR_METADATA/PL01/PL02/SOLUTION`; CODE_GUIDE → `CR_METADATA/SOLUTION/PL02/ACCEPTANCE_CONTEXT`; CHANGE_PACK → `CR_METADATA/SOLUTION/CHANGE_PACK/IMPLEMENTATION_EVIDENCE`; TECH_DOCS → `CR_METADATA/CHANGE_PACK/IMPLEMENTATION_EVIDENCE/TECH_DOCS/PL03B/PL07`; CAB → `CR_METADATA/TECH_DOCS/IMPLEMENTATION_EVIDENCE/PL03B/PL07`. `CR_METADATA` is first in every entry.
- `GROUNDING_CHAR_BUDGET = 80_000`, `SECTION_CHAR_BUDGET = 20_000`, `EVIDENCE_ITEM_BUDGET = 20`, `EVIDENCE_EXCERPT_BUDGET = 2_000`, `MISSING_PREFIX = '[MISSING:'`.
- `SdlcGroundingInput { step: SdlcStepId; metadata?: SdlcWorkflowMetadata; crStatus?: 'active' | 'completed' | 'archived'; artifacts: SdlcWorkflowState['artifacts']; activeVersions?: Record<string, number>; versions?: Record<string, SdlcArtifactRef[]>; evidence?: WizardEvidence; maxChars?: number }`.
- `buildSdlcStepGrounding(input): string` and `hasGroundingSource(grounding: string, marker: SdlcGroundingMarker): boolean`.

Rendering rules:
- Render each source as stable marker on its own line, provenance, then clamped content. For active SOLUTION use `[SOLUTION vN]`, with N from `activeVersions?.SOLUTION ?? artifacts.solution?.version ?? 1`.
- Missing artifact/derived source → marker followed by line beginning `[MISSING: <Tên nguồn> — chưa có dữ liệu cho bước này]`. Never emit an empty section or empty overall output.
- `CR_METADATA` lists `CR`, `Tính năng`, `Đơn vị yêu cầu`, `Tác giả`, `Ngày`, `Trạng thái CR`; omit absent fields, never print `undefined`.
- `ACCEPTANCE_CONTEXT` is a bounded, separately labeled projection of PL02 acceptance criteria/context. If PL02 is missing, emit `[MISSING: acceptance context — chưa có dữ liệu cho bước này]`; do not silently treat unrelated SOLUTION text as acceptance context.
- `TECH_DOCS` is a bounded projection of prior technical refs available in `artifacts.codeGuide`, `artifacts.pl03b`, and `artifacts.pl07`; preserve each source title/version in the section. If none is present, emit `[MISSING: prior technical documents — chưa có dữ liệu cho bước này]`.
- `IMPLEMENTATION_EVIDENCE` is a bounded projection of `artifacts.changePack` content plus serialized `artifacts.driftResult` when present. If both are absent, emit `[MISSING: implementation evidence — chưa có dữ liệu cho bước này]`.
- Artifact body uses `ref.content` when non-empty; when `versions` contains active version with content, prefer that exact body. Otherwise show title/version/hash and `(chưa có nội dung trong bộ nhớ)` as present source, not missing.
- `[RETRIEVED_EVIDENCE]` renders only when `evidence.items.length > 0`: max 20 items, each `- [<documentTitle ?? documentId> · L<lineStart>-L<lineEnd>] <excerpt>`, excerpts clamped to 2,000 chars with `…[đã cắt bớt]`.
- `[EVIDENCE_STATUS]` is always final and non-empty. `EMPTY_SCOPE` → `Không có bộ tài liệu đã publish cho dự án này.`; `PARTIAL` or non-empty `degraded` → `Bằng chứng chưa đầy đủ (nguồn không khả dụng: <codes>).`; absent evidence → `Chưa có bằng chứng truy xuất bổ sung cho bước này.`; any clamp appends `Đã giới hạn bằng chứng theo ngân sách; hãy truy vấn hẹp hơn.`.
- Enforce section and total budgets on final joined string without cutting marker lines mid-line; when total budget truncates, append one limited-status sentence as final `[EVIDENCE_STATUS]` body.
- Builder must never emit `[DỮ LIỆU NGỮ CẢNH` or `[HẾT DỮ LIỆU NGỮ CẢNH]`; composer owns delimiters (D-03). Never read settings, tokens, API keys, or passphrases.
- `hasGroundingSource` returns false when marker section absent or its body begins with `MISSING_PREFIX`; it accepts versioned `[SOLUTION vN]`. Derived markers are checked directly, so 26-03 can gate acceptance/prior technical/implementation evidence without guessing from another section.

Tests in `tests/services/sdlc/groundingBuilder.test.ts`: assert D-01 source sets; empty workflow remains non-empty with `[CR_METADATA]` and `[EVIDENCE_STATUS]`; missing SOLUTION, acceptance context, prior technical docs, and implementation evidence render explicit `[MISSING:` lines; present SOLUTION uses `[SOLUTION vN]`; derived sections preserve source labels; evidence line ranges and caps; a 100,000-char artifact clamps and appends limited status; output contains neither delimiter token nor secret fixture; `hasGroundingSource` covers present, missing, and versioned SOLUTION plus derived markers. Use plain fixtures, no DB/network.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Workflow artifacts / CR metadata → grounding | Stored document text is untrusted and may contain instructions |
| Knowledge server / BM25 evidence → grounding | Retrieved excerpts are untrusted third-party text |
| Grounding → composed system prompt | Only composer may wrap this text as data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-26-01 | Tampering | `buildSdlcStepGrounding` | mitigate | Emit labeled sections without prompt delimiters; composer owns data delimiters; tests assert delimiter tokens never appear (ASVS V5). |
| T-26-01b | Information Disclosure | Evidence/artifact serialization | mitigate | Read only workflow artifacts, CR metadata, and bounded `WizardEvidence`; never settings, tokens, API keys, or passphrases. |
| T-26-01c | Denial of Service | Grounding size | mitigate | Cap 80,000 total, 20,000/section, 20 items, 2,000/excerpt; append limited status. |
| T-26-01d | Tampering | Cross-step/CR evidence | mitigate | AbortController and cancelled flag on step/CR change; reset evidence at effect start. |
| T-26-01e | Elevation of Privilege | Grounding construction | accept | Pure builder cannot call tools or write data; view supplies already-authorized state. |
| T-26-SC | Tampering | Package installs | mitigate | No new dependency in Phase 26; package audit remains empty. |
</threat_model>
