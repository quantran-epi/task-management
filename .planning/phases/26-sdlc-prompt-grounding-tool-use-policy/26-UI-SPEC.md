# Phase 26 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of this phase's UI:** only two surfaces change visually — the shared `AiChatWidget` (terminal tool-loop status + retained tool activity) and the SDLC `StepChatPanel` (explicit artifact-intent actions and the refuse/ask surfaces). Grounding text, prompt layering, and tool allowlists are prompt-internal and have no user-visible UI. No new screens, no new design system.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` light / `#141414` dark (`token.colorBgContainer`) | Chat panel background, workspace canvas, modal surfaces |
| Secondary (30%) | `#fafafa` / `#f5f5f5` / `#1f1f1f` (`token.colorFillAlter`) | Tool badge background, expanded tool detail, toolbox bar, quick-prompt chips |
| Accent (10%) | `#4f46e5` (`colorPrimary`) | Reserved list below — nothing else |
| Destructive | `#ff4d4f` (`token.colorError`) | Clear-thread confirmation only |

Semantic colors (existing Ant Design tokens, no new hex):
- Success `token.colorSuccess`: tool result complete icon.
- Warning `token.colorWarning`: approval wait tag, stopped-evidence inline alert, prerequisite alerts.
- Neutral `token.colorTextSecondary` + `token.colorFillAlter`: terminal "stopped" tag (see §3).

Accent reserved for (explicit, exhaustive):
1. Primary Send CTA button (`Gửi tin nhắn`).
2. Active SDLC step indicator / current-step highlight.
3. Quick-prompt chips in the empty state.
4. Approve action on the mutation approval card.
5. Focus rings on all interactive controls.
6. Spinning `SyncOutlined` icon on a running tool badge.

Explicitly NOT accent: artifact-intent action buttons (secondary/default), terminal stopped tag (neutral), tool badges (secondary), refusal alerts (warning).

## UI Component Contract Specifications

### 1. Artifact-intent action row — `StepChatPanel`

Purpose: satisfy D-09/D-10 (explicit intent before composition; `StepChatPanel` stops hardcoding `artifact: 'SOLUTION'`).

- Placement: directly above the composer inside the SDLC chat lane (below `transcriptExtensions`, above `ChatInputBar`), inside the `StepChatPanel` wrapper — not inside `AiChatWidget`.
- Rendering: `Space size={8} wrap`, default (secondary) `Button size="small"`, 12px label, `borderRadius: 8`, `minHeight: 32`.
- Per-step action set (only valid targets render):
  - INTAKE: none (Q&A only).
  - SOLUTION: `Soạn SOLUTION bằng AI`.
  - CODE_GUIDE: none.
  - CHANGE_PACK: none.
  - TECH_DOCS: `Soạn PL03B bằng AI` and `Soạn PL07 bằng AI` — two separate buttons, never one combined artifact action.
  - CAB: `Soạn CAB bằng AI`.
- Each button submits `submit(<prompt>, 'artifact')` with its own `artifact` kind. The row is the only path that sets `intent: 'artifact'`; typing in the composer always sends `intent: 'qa'`.
- Disabled state: all action buttons disabled while `preludePending || turn.runtime?.isRunning() || turn.status === 'awaiting-approval'` — same guard as `submit()`.
- Read-only/pinned historical version: the row is hidden (not disabled) when `viewedVersion` is set.

### 2. Refuse / ask surfaces — `StepChatPanel` (D-11, D-12)

- Both render as an Ant Design `Alert` **inline in the chat lane, above the composer**, never as a fake assistant message and never as a model call.
- Missing prerequisite / invalid target (D-12): `Alert type="warning" showIcon` with `formatGuardMessage(code)` (existing helper in `src/services/wizard/workflowGuards.ts`) + `action={<Button size="small">Chuyển đến Bước {N}: {Tên bước}</Button>}`. The action calls the existing `onNavigateToStep` callback.
- Ambiguous artifact request (D-11): `Alert type="info" showIcon` with the clarify copy and one button per valid target for the step, each submitting an explicit artifact turn. No default is preselected; dismissing the alert sends nothing.
- Both alerts dismiss on: explicit target chosen, step change, or thread clear. They are not persisted to `chatMessages`.

### 3. Terminal tool-loop status — `AiChatWidget` + `StagedLoadingIndicator` (D-13..D-16)

- New `ChatTurnStatus` member `'tool-limit'` (terminal). Add it to the union in `src/components/ai/runtime/chatTurnRuntime.ts`.
- Header badge: `Tag` with `color="default"` (neutral — deliberately NOT `warning`, which is the approval tag), `icon={<StopOutlined />}`, text `Đã dừng thu thập bằng chứng`. 12px.
- Staged loader: `stagedStageFor('tool-limit')` returns `null` — the staged progress row disappears; it must not keep showing a spinner or an active stage.
- Inline explanation: `Alert type="warning" showIcon` placed directly under the tool-activity list (same `padding: '0 16px'` container), with the terminal copy and a `Thử lại` action wired to the existing `onRetry`.
- Tool activity retention: the existing `mergedToolEvents` list renders fully (collapsed `N công cụ đã gọi / Xem chi tiết`, expandable, `maxHeight: 160`, `aria-expanded`/`aria-controls`) **after** the limit is reached. The last event may remain in `phase: 'call'` (never dispatched); it renders the `SyncOutlined` running icon — this is intentional audit evidence, not a stuck spinner.
- Persistence: a `'tool-limit'` turn is runtime-only. The transcript must show no assistant bubble and no partial text for it. `ChatInputBar` re-enables (`isStreaming` false) so the user can retry or send a narrower question.
- The terminal state must be visually distinguishable from `error` (red) and from `awaiting-approval` (warning tag + card). Neutral tag + warning alert is the distinction.

### 4. Tool activity list — `AiChatWidget` (carried, no layout change)

- Single tool call: one `ToolEventBadge` inline, no collapse header.
- ≥2 calls: collapse header button (`N công cụ đã gọi` + `Xem chi tiết`/`Thu gọn`), collapsed shows the last event only, expanded shows all in a `maxHeight: 160` scroll region.
- Badge: `[Công cụ] {toolName}`, 12px, `colorFillAlter` background, 1px `colorBorderSecondary`, radius 8, `padding: 4px 8px`. `SyncOutlined spin` + `colorPrimary` while running; `CheckCircleOutlined` + `colorSuccess` on result.
- Expanded detail: 12px (raised from 11px), `lineHeight: 1.5`, `maxHeight: 240`, `overflowY: auto`, args label `Tham số` in `colorTextSecondary`.

### 5. Unchanged surfaces (do not restyle)

- `StagedLoadingIndicator` four-stage row (`Chuẩn bị ngữ cảnh → Truy xuất công cụ → Đang phản hồi → Chờ phê duyệt`) keeps its 12px labels and `role="status" aria-live="polite"`.
- `MutationApprovalCard`, `ArtifactEventCard`, quick-prompt chips, toolbox bar, `ResizeSplitter`, and all six step views keep their Phase 25.3 layout.

## Interaction Contract (acceptance-relevant)

| ID | Contract |
|----|----------|
| UI-26-01 | No artifact turn can be sent without an explicit artifact kind; typing in the composer never produces `intent: 'artifact'`. |
| UI-26-02 | TECH_DOCS exposes two distinct artifact actions; one click can never produce both PL03B and PL07 turns. |
| UI-26-03 | An invalid or ambiguous artifact request renders an inline Alert and makes zero model calls. |
| UI-26-04 | Reaching the tool-round ceiling ends with the neutral `Đã dừng thu thập bằng chứng` tag, a warning alert with `Thử lại`, no assistant bubble, and a fully retained tool list. |
| UI-26-05 | The terminal tag is visually distinct from approval (warning) and error (red). |
| UI-26-06 | No text in any Phase 26 surface renders below 12px. |
