    Rewrite `updateSkill` to open `db.transaction('rw', [db.aiSkills, db.aiSkillVersions], async () => { ... })`. Inside: read `existing` from `db.aiSkills` and throw the existing `Không tìm thấy kỹ năng: ${id}` error when absent; compute `now = new Date().toISOString()`; build `updated` by overlaying only the defined fields of `validated` onto `existing` (keep the current three `if (validated.x !== undefined)` lines) and set `updatedAt: now`; compute `const baseVersion = await getLatestApprovedVersionNumber(id, db)`; build the version row with `id: generateId()`, `skillId: id`, `version: baseVersion + 1`, `status: 'approved'`, `name: updated.name`, `description: updated.description`, `body: updated.body`, `baseVersion`, `createdAt: now`, `decidedAt: now`; `await db.aiSkillVersions.add(versionRow)`; `await db.aiSkills.put(updated)`; return `updated`.

    Two details that are easy to get wrong and are the whole point of the task: the version row snapshots the MERGED row (`updated`), not the raw `AiSkillUpdate` patch — an all-optional patch would otherwise write `undefined` into a required string field. And `version` is `baseVersion + 1`, never `latest + 1` over all rows — a pending row must not influence a manual save's number (D-14).

    Import `getLatestApprovedVersionNumber` from `./aiSkillVersionRepo`. Do not import `createSkillVersion` — it refuses non-pending input by design, so a manual approved save must not route through it.

    Leave `createSkill` and `deleteSkill` byte-identical (D-10, D-28). Do not add a version row to `createSkill`; the implicit baseline is what makes "first row = v1" true.
  </action>
