<objective>
Rewrite the skill-version repository so a version number exists only on an approved row, and make the backup schema accept that shape.

Purpose: every later plan in phase 39 reads or writes this table. Getting the numbering model right first means the tool, the pin, and the three UI surfaces all build on one correct semantic instead of three guesses. The two backup landmines (positive-only `version`, duplicate-key guard) are fixed here because a phase that ships an unrestorable backup is worse than a phase that ships nothing.

Output: optional `version` + new `baseVersion` on `AiSkillVersion`, `createSkillVersion` that refuses non-pending input and records `baseVersion`, `decideSkillVersion` that numbers over approved rows and overwrites `aiSkills` atomically, `getLatestApprovedVersionNumber`, `listPendingSkillVersions`, and a backup record schema plus validator that round-trip a version-less pending row.
</objective>
