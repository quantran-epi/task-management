### 1. `PatchDiffApprovalCard` — skill-proposal variant

**File:** `src/components/ai/widget/PatchDiffApprovalCard.tsx` (86 lines, existing). **D-24: extend this component. Do not write a new one.**

**Render site (structural, non-negotiable):** the card is rendered from the transcript extension (§2), **not** from `turn.pendingApproval`. `pendingApproval` is populated only by the parked-patch branch (`chatTurnRuntime.ts:425` → `teamRunCoordinator.ts:1307`), and D-04 forbids parking `propose_skill_version`. A branch inside `AiChatWidget.tsx:484` will never fire. `artifactApprovalState` / `artifactDecision` (props at `AiChatWidget.tsx:75-76`) are **not** the channel for this phase — the host passes `stale` / `decision` directly to the card it renders.

**Props added (all optional; defaults preserve today's note behaviour and all 5 existing tests):**

| Prop | Type | Default | Purpose |
|------|------|---------|---------|
| `variant` | `'patch' \| 'skill'` | `'patch'` | Swaps the stale copy, the tooltip/aria copy, and the decision copy |
| `subtitle` | `string` | `undefined` | When present, replaces the `{target} · {id} · mục {sectionId}` line. **Required for the skill variant** — the default line would print a UUID |
| `evidence` | `string` | `undefined` | Renders the collapsed "Bằng chứng" panel |

**Layout (top to bottom), all existing except the marked additions:**

1. Header row — `DiffOutlined` (accent) + `Đề xuất chỉnh sửa: {patch.sectionTitle}` at 14/600, single line, ellipsis with `title` tooltip. Unchanged. For a skill proposal `sectionTitle` is the **skill name**.
2. Subtitle line — 12px `colorTextSecondary`, single line, ellipsis. **[NEW]** when `subtitle` is set, render `subtitle` verbatim; otherwise today's `{Ghi chú|Kỹ năng} · {id} · mục {sectionId}`. Skill variant subtitle: `Kỹ năng · {skillName} · đề xuất bởi {agentName}`.
3. Counter row — `+{n} dòng thêm` / `−{n} dòng xóa` chips. Unchanged. Counts are the **sum across all three fields**.
4. Stale `Alert type="warning" showIcon role="alert"` — unchanged geometry; copy selected by `variant` (§Copywriting). Only when `stale`.
5. Error `Alert type="error" showIcon role="alert"` — unchanged.
6. Diff region — `role="region"`, `aria-label="Diff đề xuất chỉnh sửa"`, `tabIndex={0}`, focus ring on focus, `maxHeight: 240`, `overflow: auto`, `whiteSpace: 'pre'`, code family 12/20. Unchanged.
7. **[NEW] Evidence panel** — antd `Collapse size="small"`, `items=[{ key: 'evidence', label: 'Bằng chứng', children: <div style={{maxHeight:160, overflowY:'auto', whiteSpace:'pre-wrap', fontSize:13.5, lineHeight:1.5, color:token.colorTextSecondary}}>{evidence}</div> }]`. Collapsed by default. Rendered only when `evidence` is a non-empty trimmed string. **Display-only:** never enters a prompt, never affects the diff, never gates a decision.
8. Decision line (`role="status"`) or button row — unchanged geometry. Copy selected by `variant`.

**Three-field diff (D-11 — the correctness hole this contract closes).** A version row carries `name` + `description` + `body`. Approving changes the user never saw is not acceptable. The host builds one `diffText` from up to three unified hunks, in this fixed order, each included **only when that field actually changed**:

```
--- a/skill:{skillId}/name ({baseLabel})
+++ b/skill:{skillId}/name (đề xuất)
@@ … hunks from createUnifiedLineDiff(base.name, next.name) …

--- a/skill:{skillId}/description ({baseLabel})
+++ b/skill:{skillId}/description (đề xuất)
@@ … …

--- a/skill:{skillId}/body ({baseLabel})
+++ b/skill:{skillId}/body (đề xuất)
@@ … …
```

- `baseLabel` = `bản {baseVersion}` when `baseVersion > 0`; `bản hiện tại` when `baseVersion === 0` (implicit baseline — diff against the current `aiSkills` values, no version row needed).
- One blank line between hunks. The card's `whiteSpace: 'pre'` region renders multi-hunk text correctly.
- `addedLines` / `removedLines` = the sums across included fields.
- `sectionId: 'skill'` (unused at render time because `subtitle` is set; declared so the type stays satisfied).
- If **no** field changed, the tool refuses `NO_CHANGES` and writes **no** pending row — an empty card must never exist.
- If the combined diff exceeds `PATCH_LINE_CAP` / `MAX_DIFF_CELLS`, the tool refuses `DIFF_BUDGET_EXCEEDED` and writes no row. Reuse the existing refusal shape; do not invent a new cap.

**Stale state (D-16).** `stale = (row.baseVersion ?? 0) < currentApprovedVersion`, where `currentApprovedVersion` is the highest `approved` version number for that skill at render time (0 when none). When stale:

- Card surface switches to `colorWarningBg` / `colorWarningBorder` (existing).
- `Alert` renders with the `variant === 'skill'` copy.
- **"Chấp thuận" is disabled** and wrapped in the existing `<span tabIndex={0} aria-label={…}>` so the disabled state is announced, not merely greyed.
- **"Từ chối" stays enabled** — D-16 blocks approval only; a stale proposal must remain dismissible. (Verified: only `applying` disables it today.)
- No auto-reject, no expiry, no countdown (D-16, D-29).

**Decision state.** After a decision the card **stays mounted** showing its `role="status"` line; it is not removed from the list until the panel/drawer closes. Both hosts hold a local `Map<versionId, 'approved' | 'rejected'>` merged over the live query result. Rationale: removing the card on approve drops keyboard focus to `<body>` and gives no confirmation of what happened.

**`data-testid`:** existing `patch-diff-approval` on the `<section>` (unchanged); the host wrapper adds `skill-pending-card-{versionId}`. Tests must scope with `within(getByTestId('skill-pending-card-…'))` because several cards can be on screen.

## Interaction & State Contracts

### Pending proposal lifecycle (both render sites)

```
[agent calls propose_skill_version]
   └─ NO_CHANGES / DIFF_BUDGET_EXCEEDED ─► refusal to the model, NO row written
   └─ ok ─► pending row (no version number) ─► card appears in transcript + drawer
                │
                ├─ Chấp thuận ─► decideSkillVersion(id,'approved')
                │     ├─ ok ─► card shows "Đã duyệt — …" (stays mounted, role=status)
                │     └─ throw ─► card shows the error Alert; row stays pending
                │
                ├─ Từ chối ─► decideSkillVersion(id,'rejected')
                │     └─ same success/error shape
                │
                └─ another pending for the same skill is approved first
                      └─ this card becomes stale: Approve disabled, Reject enabled
```

- **One writer.** Both sites call `decideSkillVersion`; neither resolves a tool promise (D-23). The DB write is the decision.
- **No optimistic removal.** The card persists with its decision line until the panel/drawer closes.
- **Concurrency.** Two clicks on "Chấp thuận" are prevented by `applying` (existing prop) — the button is disabled while the write is in flight. A second decision on an already-decided row throws `ALREADY_DECIDED_MESSAGE`; the card renders it as the error Alert.
- **Stale is recomputed live.** Approving one pending re-renders the others through `useLiveQuery`; their `stale` flips without a reload.

### Version history lifecycle

```
[skill created] ─► no rows (implicit baseline, D-10)
[first manual save] ─► approved v1 (D-09)
[first approval] ─► approved v1 (or max+1)
[every later save/approval] ─► approved max+1
[rejected proposal] ─► rejected row, no number, never in history
```

- History lists decided rows only. A rejected row appears there (it is a decision the user made) with the `Đã từ chối` tag and no number.
- No Restore, no delete-version, no edit-version affordance anywhere (D-12).

### Explorer section lifecycle

```
[no skills] ─► "Chưa có kỹ năng nào"
   └─ "Thêm kỹ năng" ─► SkillEditorDrawer (create) ─► Lưu ─► card appears
[card] ─Sửa─► SkillEditorDrawer (edit) ─► Lưu ─► card + history row update
[card] ─Xóa─► Popconfirm ─► deleteSkill
                 ├─ ok ─► card disappears (version rows cascade)
                 └─ refused ─► warning Alert names the agents / the running turn
```

- Search filters all three sections simultaneously by name + description/role.
- The pending badge on a card updates live after a decision made in the transcript — same query, same DB.

## Accessibility Contract

- **Approve / Reject are keyboard reachable.** Both are antd `Button`s inside the card; the card is inside a scrollable transcript region that is already one focus stop. No `tabIndex={-1}`, no `pointer-events` tricks.
- **The disabled Approve is announced, not just greyed.** Keep the existing `<span tabIndex={0} aria-label={…}>` wrapper around the disabled button; the `aria-label` must be the `variant === 'skill'` stale string. A screen reader user reaching the span hears why the action is unavailable.
- **The stale warning is `role="alert"`** (existing) so it is announced when the card becomes stale mid-session.
- **The decision result is `role="status"`** (existing) so "Đã duyệt — …" is announced without stealing focus.
- **Focus is preserved after a decision.** The card stays mounted (see §1). If the card were unmounted, focus would fall to `<body>`; the contract forbids that.
- **The pending row expand control** (version history `Collapse`) keeps antd's `aria-expanded` / `aria-controls`; the item label is the accessible name, so `v2 · Quy trình review · 12/11/2026 09:30 · Đã duyệt` is read as one string.
- **The evidence panel** is a `Collapse` with a text label (`Bằng chứng`), not an icon-only toggle.
- **The diff region** keeps `role="region"` + `aria-label` + `tabIndex={0}` + the `2px token.colorPrimary` focus ring (existing).
- **Status is never color-only.** Every state carries a text tag or line: `Đã duyệt`, `Đã từ chối`, `Chờ duyệt`, `Dựa trên bản cũ` (via the stale alert), `{n} chờ duyệt`.
- **The new toolbar button** has `aria-label="Thêm kỹ năng"` and a `Tooltip` with the same string.
- **Evidence is plain text**, so a model-authored payload cannot inject markup or a link into the approval surface.
- Contrast: warning text on `colorWarningBg` and success text on white both pass WCAG AA at 12–13.5px in the light theme; do not substitute raw hex.
