## Summary

Phase 12.1 introduces a comprehensive task timing and session logging engine to the Task Planner app. The feature consists of three interconnected layers:
1. **Durable Local-First Time Tracking:** An active timer system running directly in the browser, persisting active timer states in IndexedDB (`activeTimers` table or active session rows in `workSessions`), allowing seamless recovery across browser restarts, page reloads (F5), or system crashes.
2. **Concurrent Multi-Task Timers:** Support for running multiple timers concurrently (e.g. tracking an urgent meeting while simultaneously tracking an on-call debugging task) with an aggregated Header Bar widget in `AppShell`, compact inline row controls in `TaskTable`, and a dedicated timer section in `TaskDrawer`.
3. **Session Logging & Multi-Tier Aggregation:** Manual and automated `workSessions` logging, full CRUD for historical work sessions, spent time rollups across Tasks, Milestones, and Projects, and non-blocking tiered alerts when allocations or daily feasibility bounds are exceeded.

**Primary recommendation:**
Implement a non-destructive Dexie `SCHEMA_V5` adding `workSessions: 'id, taskId, startTime, endTime, date'` and an `activeTimers: 'taskId, status, startedAt'` table (or storing running sessions with indexed `taskId`). Build a centralized `TimerProvider` context with a 1-second interval ticker for active timers, providing real-time reactive elapsed seconds computed from `Date.now() - startedAt`. Update `BackupEnvelope` and validation schemas to version 3 to include `workSessions`.

**Key Schema Design Insights:**
1. `workSessions`:
   - `id`: string (UUID v4)
   - `taskId`: string (Foreign key to `Task.id`)
   - `startTime`: string (ISO 8601, e.g. `2026-09-29T08:30:00.000Z`)
   - `endTime`: string (ISO 8601, e.g. `2026-09-29T09:45:00.000Z`)
   - `date`: string (Calendar date `YYYY-MM-DD` derived from `startTime` for rapid daily indexing and feasibility queries)
   - `durationMinutes`: number (Calculated as integer minutes, rounded or ceil; e.g. `Math.max(1, Math.round(durationSeconds / 60))`)
   - `note`: optional string (Ghi chú nội dung phiên)
   - `createdAt`: string (ISO 8601)
   - `updatedAt`: string (ISO 8601)

2. `activeTimers`:
   - `taskId`: string (Primary key, 1 active timer record per task)
   - `status`: `'running' | 'paused'`
   - `startedAt`: number (Unix epoch ms timestamp when timer started or resumed)
   - `accumulatedMs`: number (Total milliseconds accumulated before the current resume)
   - `sessionStartTime`: string (ISO 8601 string for when the current continuous work session began)

### Real-Time Timer Engine Pattern

To satisfy **D-04 (Reload Survival)** and avoid database thrashing:
- On `startTimer(taskId)`: Write to `db.activeTimers.put({ taskId, status: 'running', startedAt: Date.now(), accumulatedMs: 0, sessionStartTime: new Date().toISOString() })`.
- On `pauseTimer(taskId)`: Calculate `accumulatedMs = currentAccumulated + (Date.now() - startedAt)`. Write status `'paused'` to `db.activeTimers`.
- On `finishTimer(taskId, note?)`: Compute total duration in minutes (`Math.max(1, Math.round(totalMs / 60000))`). Create a new record in `db.workSessions`. Delete the record from `db.activeTimers`.
- On page load / reload: `TimerProvider` queries `db.activeTimers.toArray()`. For any timer with `status: 'running'`, elapsed time is dynamically computed as:
  `elapsedSeconds = Math.floor((timer.accumulatedMs + (Date.now() - timer.startedAt)) / 1000)`.
- A single 1-second interval loop in `TimerProvider` increments local tick counter, causing all active timer listeners to re-render without writing to IndexedDB every second.

### Anti-Patterns to Avoid
- **Writing to IndexedDB every 1 second:** Destroys browser performance and disk I/O. Only state transitions (`start`, `pause`, `finish`) and periodic checkpointing (e.g. every 60s if desired, or strictly on state transitions) should hit IndexedDB.
- **Relying solely on `setInterval` tick count for elapsed time:** Browsers throttle background tabs to 1 tick per minute or pause them completely. Always compute elapsed time using real timestamp delta: `Date.now() - startedAt`.
- **Mutating task entity with `spentMinutes` column:** If `spentMinutes` is a hardcoded field on `Task`, concurrent edits or manual session deletion can cause out-of-sync cache bugs. Instead, compute `spentMinutes` by querying `db.workSessions.where('taskId').equals(taskId)` (or keeping a reactive rollup helper).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Time difference & duration calculations | Custom Date math with modulo | `dayjs` / integer millisecond diff | Edge cases with daylight savings, midnight transitions, and sub-minute rounding. |
| Time input widget | Raw text inputs or separate number inputs | Ant Design `TimePicker` / `DatePicker` with format `HH:mm` | Ensures valid 24h format and standard user UX. |
| Live state reactivity across tabs / components | Custom event bus or window postMessage | Dexie `useLiveQuery` | Guaranteed synchronization with IndexedDB across all open components. |
| UUID generation | Custom math-random generator | Native `crypto.randomUUID()` | Standard RFC 4122 v4 compliance enforced across the project. |

## Common Pitfalls

### Pitfall 1: Background Tab Timer Throttling
**What goes wrong:** User starts timer, switches to another browser tab for 2 hours, returns to find timer only advanced 2 minutes.
**Why it happens:** Chromium and WebKit aggressively throttle `setInterval` / `requestAnimationFrame` in inactive tabs to once every 60 seconds or suspend it entirely.
**How to avoid:** Never increment timer counter like `seconds += 1`. Always compute `elapsed = (Date.now() - startedAtTimestamp)`. When tab regains focus, `Date.now()` gives the exact wall-clock difference.

### Pitfall 2: Cascade Deletion Orphaned Work Sessions
**What goes wrong:** User deletes a task or a project/milestone in cascade mode. The task is removed, but its `workSessions` remain in IndexedDB forever, leaking storage and causing corrupt rollup aggregations.
**Why it happens:** `src/db/repositories/cascadeRepo.ts` handles `projects`, `milestones`, `tasks`, and `plannedAllocations`, but will not automatically know about `workSessions` unless updated.
**How to avoid:** In `cascadeRepo.ts`:
  - When `deleteTaskWithAllocations(taskId)` is called, also execute `db.workSessions.where('taskId').equals(taskId).delete()` and `db.activeTimers.delete(taskId)`.
  - When `deleteProjectWithCascade` or `deleteMilestoneWithCascade` runs in `'cascade'` mode, delete associated `workSessions` and `activeTimers` for all child task IDs.

### Pitfall 3: Backup Export / Restore Incompatibility
**What goes wrong:** Exporting a backup drops all work session logs, or importing a backup fails validation because `workSessions` is unexpected or missing from `BackupEnvelope`.
**Why it happens:** `BackupEnvelope` in `src/types/backup.ts` and `validateBackup.ts` currently has `CURRENT_SCHEMA_VERSION = 2` and strictly enumerates 6 domain tables (`projects`, `milestones`, `tasks`, `capacityRules`, `capacityOverrides`, `plannedAllocations`).
**How to avoid:**
  - Bump `CURRENT_SCHEMA_VERSION` to 3 in `src/services/backup/exportBackup.ts`.
  - Update `BackupEnvelope`, `BackupTableData`, and `BackupTableCounts` in `src/types/backup.ts` to include optional or required `workSessions?: WorkSession[]`.
  - Update `validateBackupPayload` in `src/services/backup/validateBackup.ts` to allow `schemaVersion <= 3` and validate `workSessions` if present while maintaining backward compatibility for v1/v2 backups.
  - Update `restoreBackupPayload` in `src/services/backup/restoreBackup.ts` to clear and bulk-restore `workSessions`.

### Pitfall 4: Sub-Minute Sessions & Zero Duration
**What goes wrong:** A user tests the timer by starting and finishing within 15 seconds. If integer division `Math.floor(15 / 60)` is used, duration is 0 minutes. If 0 minutes is rejected by validation (`min(1)`), the session fails to save.
**Why it happens:** Tasks require integer minutes, but quick sessions take less than 60 seconds.
**How to avoid:** Format: `durationMinutes = Math.max(1, Math.round(durationSeconds / 60))`. If user runs timer for even 10 seconds, record it as 1 minute (or support `< 1m` display while storing 1m minimum in database).

### 1. Active Timer Context & Hook (`TimerContext.tsx`)
```typescript
// Verified pattern based on Dexie + React Context
import React, { createContext, useContext, useEffect, useState, useMemo } from 'react';
import { useLiveQuery } from 'dexie-react-hooks';
import { db } from '../db';
import type { ActiveTimer, WorkSession } from '../types/models';
import { generateId } from '../utils/uuid';
import { message } from 'antd';

interface TimerContextValue {
  activeTimers: ActiveTimer[];
  getTimerForTask: (taskId: string) => ActiveTimer | undefined;
  getElapsedSeconds: (taskId: string) => number;
  startTimer: (taskId: string) => Promise<void>;
  pauseTimer: (taskId: string) => Promise<void>;
  finishTimer: (taskId: string, note?: string) => Promise<WorkSession | null>;
  cancelTimer: (taskId: string) => Promise<void>;
}

export const TimerContext = createContext<TimerContextValue | null>(null);

export const TimerProvider: React.FC<{ children: React.ReactNode }> = ({ children }) => {
  // Live query active timers from IndexedDB
  const timers = useLiveQuery(() => db.activeTimers.toArray()) ?? [];
  const [, setTick] = useState(0);

  // 1-second interval ticker for UI re-rendering
  useEffect(() => {
    const hasRunning = timers.some((t) => t.status === 'running');
    if (!hasRunning) return;

    const interval = setInterval(() => {
      setTick((prev) => (prev + 1) % 10000);
    }, 1000);

    return () => clearInterval(interval);
  }, [timers]);

  const getElapsedSeconds = (taskId: string): number => {
    const timer = timers.find((t) => t.taskId === taskId);
    if (!timer) return 0;
    const currentRun = timer.status === 'running' ? Date.now() - timer.startedAt : 0;
    const totalMs = timer.accumulatedMs + Math.max(0, currentRun);
    return Math.floor(totalMs / 1000);
  };

  const startTimer = async (taskId: string) => {
    const existing = await db.activeTimers.get(taskId);
    const now = Date.now();
    if (existing) {
      if (existing.status === 'paused') {
        await db.activeTimers.update(taskId, {
          status: 'running',
          startedAt: now,
        });
      }
    } else {
      await db.activeTimers.put({
        taskId,
        status: 'running',
        startedAt: now,
        accumulatedMs: 0,
        sessionStartTime: new Date().toISOString(),
      });
    }
  };

  const pauseTimer = async (taskId: string) => {
    const existing = await db.activeTimers.get(taskId);
    if (existing && existing.status === 'running') {
      const additional = Math.max(0, Date.now() - existing.startedAt);
      await db.activeTimers.update(taskId, {
        status: 'paused',
        accumulatedMs: existing.accumulatedMs + additional,
        startedAt: Date.now(),
      });
    }
  };

  const finishTimer = async (taskId: string, note?: string): Promise<WorkSession | null> => {
    const existing = await db.activeTimers.get(taskId);
    if (!existing) return null;

    const currentRun = existing.status === 'running' ? Math.max(0, Date.now() - existing.startedAt) : 0;
    const totalMs = existing.accumulatedMs + currentRun;
    const durationMinutes = Math.max(1, Math.round(totalMs / 60000));
    const nowIso = new Date().toISOString();

    const session: WorkSession = {
      id: generateId(),
      taskId,
      startTime: existing.sessionStartTime,
      endTime: nowIso,
      date: existing.sessionStartTime.slice(0, 10),
      durationMinutes,
      note: note?.trim() || undefined,
      createdAt: nowIso,
      updatedAt: nowIso,
    };

    await db.transaction('rw', [db.workSessions, db.activeTimers], async () => {
      await db.workSessions.add(session);
      await db.activeTimers.delete(taskId);
    });

    message.success(`Đã kết thúc phiên làm việc (${durationMinutes}m)`);
    return session;
  };

  const cancelTimer = async (taskId: string) => {
    await db.activeTimers.delete(taskId);
  };

  const value = {
    activeTimers: timers,
    getTimerForTask: (taskId: string) => timers.find((t) => t.taskId === taskId),
    getElapsedSeconds,
    startTimer,
    pauseTimer,
    finishTimer,
    cancelTimer,
  };

  return <TimerContext.Provider value={value}>{children}</TimerContext.Provider>;
};
```

### 2. Spent Time Aggregation Repository / Utility
```typescript
// Pure rollup calculation helpers
export async function getTaskSpentMinutes(taskId: string, dbInstance = db): Promise<number> {
  const sessions = await dbInstance.workSessions.where('taskId').equals(taskId).toArray();
  return sessions.reduce((sum, s) => sum + s.durationMinutes, 0);
}

export async function getMilestoneSpentMinutes(milestoneId: string, dbInstance = db): Promise<number> {
  const tasks = await dbInstance.tasks.where('milestoneId').equals(milestoneId).toArray();
  const taskIds = tasks.map((t) => t.id);
  if (taskIds.length === 0) return 0;
  const sessions = await dbInstance.workSessions.where('taskId').anyOf(taskIds).toArray();
  return sessions.reduce((sum, s) => sum + s.durationMinutes, 0);
}

export async function getProjectSpentMinutes(projectId: string, dbInstance = db): Promise<number> {
  const tasks = await dbInstance.tasks.where('projectId').equals(projectId).toArray();
  const taskIds = tasks.map((t) => t.id);
  if (taskIds.length === 0) return 0;
  const sessions = await dbInstance.workSessions.where('taskId').anyOf(taskIds).toArray();
  return sessions.reduce((sum, s) => sum + s.durationMinutes, 0);
}

import type { MenuProps } from 'antd';

const { Text } = Typography;

export const ActiveTimerWidget: React.FC<{ tasksMap: Map<string, string> }> = ({ tasksMap }) => {
  const { activeTimers, getElapsedSeconds, pauseTimer, startTimer, finishTimer } = useTimer();
  const { token } = theme.useToken();

  if (activeTimers.length === 0) return null;

  if (activeTimers.length === 1) {
    const timer = activeTimers[0];
    const taskName = tasksMap.get(timer.taskId) || 'Tác vụ';
    const elapsedSec = getElapsedSeconds(timer.taskId);
    const isRunning = timer.status === 'running';

    return (
      <div
        style={{
          display: 'inline-flex',
          alignItems: 'center',
          gap: 8,
          background: token.colorFillAlter,
          padding: '2px 10px',
          borderRadius: 16,
          border: `1px solid ${token.colorBorderSecondary}`,
        }}
      >
        <span
          style={{
            display: 'inline-block',
            width: 8,
            height: 8,
            borderRadius: '50%',
            background: isRunning ? token.colorSuccess : token.colorWarning,
          }}
        />
        <Tooltip title={taskName}>
          <Text
            ellipsis
            style={{ maxWidth: 120, fontSize: 13, fontWeight: 500 }}
          >
            {taskName}
          </Text>
        </Tooltip>
        <Text strong style={{ fontVariantNumeric: 'tabular-nums', fontSize: 13 }}>
          {formatElapsedTicker(elapsedSec)}
        </Text>
        <Space size={4}>
          {isRunning ? (
            <Button
              type="text"
              size="small"
              icon={<PauseCircleOutlined style={{ color: token.colorWarning }} />}
              onClick={() => pauseTimer(timer.taskId)}
              aria-label="Tạm dừng"
            />
          ) : (
            <Button
              type="text"
              size="small"
              icon={<PlayCircleOutlined style={{ color: token.colorPrimary }} />}
              onClick={() => startTimer(timer.taskId)}
              aria-label="Tiếp tục"
            />
          )}
          <Button
            type="text"
            size="small"
            icon={<CheckCircleOutlined style={{ color: token.colorSuccess }} />}
            onClick={() => finishTimer(timer.taskId)}
            aria-label="Kết thúc phiên"
          />
        </Space>
      </div>
    );
  }

  // Multi-timer dropdown
  const menuItems: MenuProps['items'] = activeTimers.map((timer) => {
    const taskName = tasksMap.get(timer.taskId) || 'Tác vụ';
    const elapsedSec = getElapsedSeconds(timer.taskId);
    const isRunning = timer.status === 'running';

    return {
      key: timer.taskId,
      label: (
        <div style={{ display: 'flex', alignItems: 'center', justifyContent: 'space-between', minWidth: 260, gap: 12 }}>
          <Text ellipsis style={{ maxWidth: 140 }}>
            {taskName}
          </Text>
          <Text strong style={{ fontVariantNumeric: 'tabular-nums' }}>
            {formatElapsedTicker(elapsedSec)}
          </Text>
          <Space size={4}>
            {isRunning ? (
              <Button
                type="text"
                size="small"
                icon={<PauseCircleOutlined />}
                onClick={(e) => {
                  e.domEvent.stopPropagation();
                  pauseTimer(timer.taskId);
                }}
              />
            ) : (
              <Button
                type="text"
                size="small"
                icon={<PlayCircleOutlined />}
                onClick={(e) => {
                  e.domEvent.stopPropagation();
                  startTimer(timer.taskId);
                }}
              />
            )}
            <Button
              type="text"
              size="small"
              icon={<CheckCircleOutlined />}
              onClick={(e) => {
                e.domEvent.stopPropagation();
                finishTimer(timer.taskId);
              }}
            />
          </Space>
        </div>
      ),
    };
  });

  return (
    <Dropdown menu={{ items: menuItems }} trigger={['click']}>
      <Button icon={<ClockCircleOutlined />} style={{ borderRadius: 16 }}>
        <Badge count={activeTimers.length} size="small" offset={[6, -2]}>
          <span style={{ marginRight: 6 }}>{activeTimers.length} timer</span>
        </Badge>
      </Button>
    </Dropdown>
  );
};
```

## Security Domain

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V5 Input Validation | yes | Zod schema validation on manual session duration, dates, and notes. Prevent negative durations or NaN values. |
| V6 Cryptography | no | Existing Web Crypto for GitHub backups handles encryption; no new crypto operations in timer. |

### Known Threat Patterns for Local Work Sessions

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Tampering with session timestamps | Tampering | Validate that `endTime >= startTime` and duration is non-negative integer <= 1440 minutes (24h) per session. |
| Denial of Service via unbounded timers | Denial of Service | Cap max active concurrent timers to 20; auto-pause or clamp runaway timers running for > 24 hours. |
| Sensitive data leakage in session notes | Information Disclosure | Keep notes local in IndexedDB; sanitize notes before display with standard React escaping. |
