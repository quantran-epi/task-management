    1. Create `src/context/TimerContext.tsx`:
       Define `TimerContextValue` interface:
       - `activeTimers: ActiveTimer[]`
       - `getTimerForTask: (taskId: string) => ActiveTimer | undefined`
       - `getElapsedSeconds: (taskId: string) => number`
       - `startTimer: (taskId: string) => Promise<void>`
       - `pauseTimer: (taskId: string) => Promise<void>`
       - `finishTimer: (taskId: string, note?: string) => Promise<WorkSession | null>`
       - `cancelTimer: (taskId: string) => Promise<void>`

       - Query active timers from Dexie via `useLiveQuery(() => db.activeTimers.toArray()) ?? []`.
       - Implement 1-second interval ticker `setInterval` only when at least one timer is `'running'`, incrementing an internal tick state to trigger UI subscriber re-renders.
       - Calculate elapsed time dynamically using `Date.now() - timer.startedAt` (wall-clock difference immune to browser background tab throttling).
       - In `startTimer(taskId)`: check max 20 active timers limit. If existing paused timer, resume by setting `status = 'running'` and `startedAt = Date.now()`. If new, put new `ActiveTimer` with `accumulatedMs = 0` and `sessionStartTime = new Date().toISOString()`.

       - In `finishTimer(taskId, note)`: compute total minutes (`Math.max(1, Math.round(totalMs / 60000))`), insert new `WorkSession` via `db.workSessions.add`, remove from `db.activeTimers` inside atomic Dexie transaction.
       - In `cancelTimer(taskId)`: delete record from `db.activeTimers`.
    2. Create `src/hooks/useTimer.ts`:
       Export `useTimer` hook wrapping `useContext(TimerContext)` with guard throwing error if used outside provider.
    3. Create `tests/context/TimerContext.test.tsx`:

       - Verify pause timer updates accumulatedMs and status to paused.
       - Verify finish timer creates workSession record and clears active timer.

       - Verify reload survival (mounting provider over pre-populated activeTimers resumes elapsed count from timestamp).

    1. Create `src/utils/timerAlerts.ts`:
       - `evaluateTaskSpentAlert(task: Task, spentMinutes: number): { shouldAlert: boolean; message: string; severity: 'warning' | 'info' }`:
         Returns warning if `task.estimateMinutes > 0 && spentMinutes >= task.estimateMinutes`.
         Formats message: `Tác vụ "${task.name}" đã dùng ${spentMinutes}m, vượt quá thời gian ước lượng (${task.estimateMinutes}m).` per UI-SPEC.
       - `evaluateDailyCapacitySpentAlert(date: string, dailySpentMinutes: number, dailyCapacityMinutes: number): NotificationItem | null`:
         If `dailyCapacityMinutes > 0 && dailySpentMinutes > dailyCapacityMinutes`, generates a notification item of category `'overload'` with copy: `Thời gian làm việc ghi nhận ngày ${date} (${dailySpentMinutes}m) đã vượt quá công suất làm việc (${dailyCapacityMinutes}m).`
       - `evaluateDailyFeasibilityAlert(params: { date: string; dailySpentMinutes: number; dailyCapacityMinutes: number; pendingTasksEstimateMinutes: number }): { isAtRisk: boolean; remainingCapacity: number; pendingEstimate: number; message?: string }`:
         Calculates `remainingCapacity = Math.max(0, dailyCapacityMinutes - dailySpentMinutes)`.
