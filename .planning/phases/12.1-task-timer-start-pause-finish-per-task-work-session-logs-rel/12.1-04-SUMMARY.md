# Phase 12.1 Plan 04: Gap Closure for Timer Reactivity, Widget Task Names, and Allocation Alerts Summary

One-liner: Resolved 3 diagnosed UAT issues by wiring ticker state into TimerContext memoization, querying task names via Dexie bulkGet, and inverting TaskTable headers with live running timer estimate breach alerts.

## What Was Done

### Task 1: TimerContext ticker reactivity (G-12.1-2)
- Added `tick` state into the `useMemo` dependency array for `TimerContext.Provider` value.
- Guaranteed that each 1000ms tick triggers a new context value reference, re-rendering UI subscribers (`TaskTable`, `ActiveTimerWidget`) with live wall-clock calculations without persisting tick counts to IndexedDB.
- Added automated tests verifying subscriber value reference updates and interval clearing when active timers stop.

### Task 2: Task name resolution in ActiveTimerWidget (G-12.1-3)
- Replaced `db.tasks.where('id').anyOf(ids).toArray()` with `database.tasks.bulkGet(ids)`.
- Added optional `database` prop to `ActiveTimerWidget` defaulting to singleton `db`, allowing dependency injection for tests and isolation.
- Filtered undefined results to safely handle concurrently deleted tasks.
- Added tests asserting task name resolution directly from database via `bulkGet` when `tasksMap` prop is omitted, as well as preserving Map precedence when provided.

### Task 3: Invert TaskTable header and add live timer allocation warning alert (G-12.1-6)
- Inverted column header in `src/components/tasks/TaskTable.tsx` from `'Ước tính / Đã dùng'` to `'Đã dùng / Ước tính'` to match the rendered cell order `formatMinutes(spentMinutes) / formatMinutes(estimate)`.
- Implemented and exported `evaluateLiveTaskAlert(task, spentMinutes, currentRunSeconds)` in `src/utils/timerAlerts.ts` to compute live running duration + historical spent time against task estimates.
- Connected `useEffect` in `TaskTable.tsx` to active running timers, firing `message.warning` once when estimate threshold is breached.
- Maintained a `useRef<Set<string>>` of alerted task IDs to prevent toast alert spam on subsequent second ticks, resetting when timers finish or cancel.
