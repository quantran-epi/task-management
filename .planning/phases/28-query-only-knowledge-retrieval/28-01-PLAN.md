<objective>
Make `POST /api/v1/retrieve` a query-only federated endpoint: the client sends `{query, limit?, setIds?}`, the server resolves every published set from `SnapshotStore`, searches each set with whatever modality is genuinely available, and returns evidence carrying set/snapshot attribution plus truthful coverage.

Purpose: a fresh device cannot retrieve today — the wire schema requires set-tier assignments, and a published set without a graph build has no searchable index. This plan removes both server-side blockers and explicitly wires the all-unknown explicit-`setIds` case so it reports DEGRADED/UNAVAILABLE coverage rather than degenerating to an empty NO_EVIDENCE result.

Output: thin wire schema, internal resolved request, server-authoritative published-set discovery, a server-local snapshot-lexical modality, a per-set coverage ledger contract, and route registration independent of Neo4j.

Per D-01, D-02, D-03, D-05, D-07, D-09 (user-locked in 28-CONTEXT.md); D-07 is user-settled, so no new decision checkpoint is added.

Non-regression: the existing internal fan-out contract (`runFederatedRetrieval`) keeps its shape and behavior; this plan only renames its input type, adds optional fields, and resolves the wire request before it. Per-set 200/400/500 envelopes, auth and exact-Origin checks remain unchanged.
</objective>
