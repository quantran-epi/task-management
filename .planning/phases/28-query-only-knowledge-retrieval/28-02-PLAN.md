<objective>
Switch every client surface to the query-only wire contract: send `{query, limit?, setIds?}`, stop gating remote retrieval on a locally derived catalog, and keep explicit set restriction available as an opt-in caller input.

Purpose: the server can accept query-only requests after 28-01, but three independent client gates still block a fresh device — the strict mirrored schema, the `groundedTurn` empty-scope `clarify_intent` branch, and `fetchSetCatalog`-derived set lists in the tool, drawer and Telegram. Fixing only one leaves the other surfaces broken.

Output: mirrored wire schema, catalog-free default retrieval in grounded/drawer/Telegram paths, attribution in the tool JSON, and explicit restriction converted to the wire `setIds` field.

Per D-01, D-05, D-06, D-07, D-08.

**Scope note (accepted):** this plan sits at the file-count boundary because the wire-contract switch is a single atomic change — mirroring the schema in Task 1 while Tasks 2 and 3 still send `setTierAssignments` would leave the tree in a non-compiling intermediate state, and splitting the plan would require a backward-compat shim, which D-07 forbids. The added `wizardService.ts` / `groundingBuilder.ts` edits are the explicit-restriction honesty fix for the same contract (an empty restriction is a wire-scope fact). Per-task load stays at 4-6 files, and every verify runs focused test files only. Mitigation if execution stalls: run Task 3's wizard cases in the 28-04 focused run rather than the full suite.
</objective>
