<objective>
Give the server-empty case one canonical, application-owned rendering across all surfaces and keep the three empty-ish outcomes distinct.

Purpose: after 28-01..28-03 the server can say `NO_PUBLISHED_SETS`, but if that code reaches the model as prose it will be paraphrased, and if it reaches a surface without a renderer it becomes nothing or a generic error. D-12/D-13 require one verbatim Vietnamese notice, rendered by the app, identical in AI Chat, SDLC step chat and Telegram — including tool-driven paths, where today Telegram passes no tool-result callback at all.

Output: a shared outcome module with the canonical constant and a tool-result detector, a `server_empty` grounded result kind with ordered local fallback, host-side rendering on all three surfaces, and the persisted grounding outcome value.

Per D-12, D-13, D-14, D-15.
</objective>
