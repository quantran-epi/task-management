<requirement_mapping>
`SDLC-RET-02/03` are historical IDs kept for GSD tooling; here they mean: truthful bounded federation over published sets with single-snapshot path closure, citation identity and degraded/unavailable reporting. All verification is on the live Knowledge Server and AI Chat surfaces; no SDLC code is involved.
</requirement_mapping>

<objective>
Make the trust guarantees real for query-only requests and make citations inspectable with zero local documents — without breaking any existing grounded-answer behavior.

Purpose: query-only federates over an unknown number of sets, so latent aggregation defects become live correctness problems: a queued set can outlive the deadline, one oversized chunk can defeat the char budget, all-failed can look like empty success, identical ranges in two snapshots can collapse into one citation, and an orphan path can reach the client. Each is a D-03/D-04/D-09/D-11 violation once retrieval is federated by default.

Output: deadline-aware scheduling, a populated coverage ledger, truthful no-success outcomes, server-side path closure, snapshot-aware client dedupe, and local-absent citation inspection.

Per D-03, D-04, D-08, D-09, D-10, D-11.

Non-regression: local-only packs, MCP evidence paths and existing `SourcesPanel`/`QuickPreviewDrawer` behavior with a local note present must remain unchanged; new fields are optional/defaulted so every existing persisted grounding still parses. The 28-01 all-unknown explicit-`setIds` DEGRADED route case must remain green after the fan-out changes.
</objective>
